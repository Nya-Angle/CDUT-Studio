## 一页实际链路

1. 材料拖入时先作为真实 `attachment` 持久入案；明确选过类别/槽位的材料保持用户选择。
2. C Main 执行本地确定性规则，足以确定则直接 CAS 写角色/兼容槽位；难例最多经现有 OCR、一次短模型 JSON 分类。慢任务后台排队，不专开 Pi、不要求用户逐件确认。模板选择后重检未绑定槽位的机器标签。
3. 案卷 revision、DocumentVersion、模板 ID/版本、活动原件、人工 `classificationCorrection` 均在实际写入时重验；迟到的机器分类不能覆盖人工改类或换版。自动分类不意味着审核通过。
4. 用户在三栏里随时改类/换槽：无计划时直接写 V2；D2/CanonicalPlan 已冻结时转既有 F05 提案、确认、执行，保留源文件和不可变 Receipt。
5. 改类立即改变当前角色/槽位，清除当前机器标签，撤销旧来源有效性，取消旧补件和待办，增加 `remediationGeneration` 使旧 Run 输入哈希失效。
6. D2：旧计划入历史；若原计划来自仍可同源复编译的受控 D4 目录，自动以 C Main 的编译/来源检查重新绑定，用户可开启新一轮 Pi。无法证明同源时案卷留在草稿供重新选方案，绝不复用旧运行。
7. CanonicalPlan：原正式计划入不可变历史、当前绑定撤销、案卷退回未绑定草稿。用户可以选择新的本地技术方案再审；不能靠空 Plan 的旧兜底恢复 `local-business` 权限，也不能用同一案卷假装“首次正式绑定”绕过历史 Check 义务。正式身份需要另建可信案卷重新绑定。
