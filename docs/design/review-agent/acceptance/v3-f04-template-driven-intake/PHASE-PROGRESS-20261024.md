# F04｜材料入口、模板匹配与自动分类｜阶段记录（2026-10-24）

> 独立任务：`fix/v3-f04-template-driven-intake`。固定派生基线：`integration/v3-r02-pr246-249-250-20261024@7773de6afc9c4a16934076b8b5bdb61a2e8bc9a2`（Draft PR #265）。本文件记录 F04 的增量，不代表 #246/#249/#250 已合入 R02 基线或完成真实 Electron 验收。

## 1. 原问题和基线裁决

- 原 #246 的 QuickIntake 要求全局恰好一份申请主件，与 #249 的多份申报原件分类合同冲突。#265 已删除此硬限制，允许 1/N 份原件在选定模板前作为临时材料进入；本任务不重复修复、不恢复旧规则。
- #265 已使用 Main B3 的 20 秒选择窗口、当前会话标识及受控深度匹配，且收敛至 #249 一套 `ReviewV3MaterialClassification` UI。F04 继续利用这些能力，不创建新的倒计时、案卷或分类真值存储。
- 进一步源码复核发现 **#265 未关闭的真实功能障碍**：C11 `buildRouteCandidatesForRead`、深度匹配入口和 D4 L1 分类器仍要求 `application.length === 1`，导致多份申报材料或临时附件即使通过 QuickIntake 仍可能得不到有效路由。
- 尚存缺口：模板选定后分类界面只有手动启动 AI，不能自动先展示模板驱动建议；建议生成到应用间对修订号与文件格式的防串案检查可补强。
- 安全前提：#261 预上传门禁尚未与 #265 完成整合，且其生产授权来源尚未安装。不能为了“自动 AI”直接增加无人值守外部模型请求，向未获授权的服务发送敏感材料摘要。

## 2. 本批实现：为什么、改了什么

1. **取消 Main 残留“一份申请件”门禁。** C11 规则路由读取同案当前多份申报原件；零份已识别申请件时可提供保守候选，不高置信自动选择。模型深匹配证据覆盖同案全部当前材料，移除原先 `C11_NATIVE_DEEP_MATCH_APPLICATION_AMBIGUOUS`。D4 L1 允许多主件同一事项，冲突业务声明不得自动确认。沿用 Main sessionKey/B3 20 秒计时，并未另造选择倒计时。
2. **模板一旦读取完成，本机自动预分拣。** 新增纯函数 `suggestLocalMaterialClassification`，依据当前真实模板的槽位名称、必要要素、格式、角色和 `maxCount` 形成建议；不请求网络、不改原件、不写 CaseAggregate。无唯一证据、歧义、格式不符或超额材料保留原类别，明确请用户确认。人工已绑定的合法槽位优先保留。
3. **单一分类界面承接建议。** `ReviewV3MaterialClassification` 在模板/案卷修订改变时刷新预分拣，逐文件显示理由；用户仍可拖动、手动选择槽位或批次确认，正式写入复用 #249 的 `reclassifyNativeMaterialsV3` 原子入口。没有增加第二套写入路径。
4. **AI 仍可由用户主动深度分类。** 对无法可靠预分拣的材料保留现有模型建议按钮；明确外部模型可能传送摘要。为了避免越过 #261 门禁，本批**不自动触发分类模型请求**。但 #246 已有的路由深匹配仍在未匹配时自动触发，增加多材料支持必须与 #261 Main 出站门禁做联合安全验收，不能因此认为敏感材料外发已安全。
5. **过期建议拒绝。** 本机或模型建议绑定 `caseId / revision / templateId / templateVersion / activeDocumentVersion + role + slot` 快照；模型调用结束前、建议应用前再次读取 Main 案卷核对；有变更则丢弃建议，不以旧快照覆盖新材料。AI 建议额外拒绝与模板 `acceptedKinds` 不符的槽位。

## 4. 残留风险和集成交接

1. **自动 AI 深度分类仍待 #261 安全接线。** 当前实现是“自动本机预分拣 + 经用户主动触发的 AI 分类”，不宣称完整无人值守模型分拣。#261 默认拒绝未知/未授权外发，不能让 Renderer 的同意状态代替 Main 授权。
2. 进入 Main 写入前的 UI 二次读案卷会缩小竞态窗口，但最终原子性仍以 Main C0 的版本/修订校验为准；没有使用 Renderer 快照作为权限或真值来源。
3. 复杂 `requiredWhen`、业务情形、OCR 低置信/解析失败、分组复用和真实 144 模板质量是后续逐模板验收，不能依据文件名建议认定已经满足槽位。
4. D4 历史候选的 `requiresPlanSetup` 仍在安装冻结 D2 Plan 后才呈现完整模板材料槽分类面板；冻结后不能直接重分类。此项需要 F04 与 F05 的计划先后顺序/可信升版协议由集成负责人联合验收，**当前没有宣称此路径闭环**。
5. F05 负责冻结后计划升版/纠错/重跑，F03 负责完整 Plan/Run 可信绑定；F04 只形成确认前的材料分类建议，不绕开冻结计划的写保护。
6. 仓库 `AGENTS.md` 要求变更功能后同步 README/AGENTS，但这两个文件须用户另行许可；本分支未修改，阶段说明在本文件记录。
