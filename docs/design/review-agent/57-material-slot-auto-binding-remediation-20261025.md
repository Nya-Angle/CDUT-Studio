# 材料角色已识别、模板槽位却未自动绑定：修复记录（2026-10-25）

适用基线：`integration/material-auto-apply-review-f05-20261025` / `0a9a917646b87f8b8c2c1f58f544e1053248a0ba`。本次仅修复**材料自动分类第二层的槽位识别**，不修改已有自动选模板、Pi Run、计划冻结/重建和人工纠错的事务合同。

## 1. 问题与实际影响

合并后贯通测试发现：原件 `获奖证书-2026.txt` 中包含“荣誉证书”“获奖等级”“颁发单位”等真实文本，模板需要的材料槽位名称是“荣誉证书”。

旧代码会把文件角色自动改成 `evidence`，但未设置 `materialSlotId: 'award'`。这不是只影响显示：`assessMaterialSlotV2` 只计算绑定到指定槽位且类别、文件类型符合要求的文件，因此必需槽可能被错误判为 `awaiting-supplement`（系统声称缺件），虽然用户已经上传了真实证书。旧 Run 仍可能读取原件，但材料清单与模板检查出现误报。

主要原因：

1. `packages/shared/src/review/material-classifier.ts` 的角色词典已有“获奖证书/荣誉证书”，但槽位排名主要依赖 BM25、文件名直匹配和模板显式 `classificationHints.aliases`。语义相近但字面不一致时可能低于槽位阈值。
2. `material-auto-classification.ts` 本地角色达到高置信度便立即写入并 `return`；即使槽位未命中，也不再调用已有 AI 短请求，缺少第二层兜底。
3. 旧槽位排名未预先过滤 `acceptedRoles`、`acceptedKinds`，不兼容的高分槽可能挤掉真正允许该文件的槽，等 Main 最终检查时只剩“无槽位”。

## 2. 如何修改

### 2.1 本地路径保留低延迟

- 在纯本地槽位排序增加**有限的精确同义词组**，首先覆盖“获奖证书 ↔ 荣誉证书”。不把“证书”“证明”“材料”这类通用词全局视为同义词，以免把成绩证明、资格证书和获奖证明混淆。
- 模板原有 `classificationHints.aliases` 继续生效；带业务专属前后缀的词优先使用模板内置关键词，不强行用通用同义词重写业务规则。
- 在排序**之前**按当前已识别角色、真实文件扩展名筛除不兼容槽位。随后继续要求最低相关度和首二名分差；候选过近时不会为了“自动完成”乱绑。

### 2.2 本地已判明角色时也能后台补槽

- 只有角色已由本地分类/OCR 确定、但没有合法槽位，同时当前模板存在该角色与文件格式兼容槽位、且有现成审核模型渠道时，才触发后台槽位补充；无模板/无模型不额外阻塞。
- 继续使用现有单次**4 秒短模型请求**和全局至多两路并发任务队列；不启动新 Pi，不创建新 Case/Run，上传流程不等待模型给出槽位。
- AI 提示新增 `fixedRole`：只允许从当前模板实际兼容槽位中选 ID；AI 如果返回其他角色、空槽位、非法槽位，则保持当前结果。
- 二次写入复用已有 Main CAS：相同原件版本与模板版本、仍为机器分类、未被人工改类且尚未绑定槽位才能应用。机器最初的分类回执保留在历史；AI 补槽回执明确注明“保留本地角色，仅补充 AI 槽位建议”。

### 2.3 不改变的功能

- OCR 分类仍只抽样最多三页；本次没有实施正式审核多页 OCR。
- 无需用户确认，不增加一个分类页面，也没有额外 Pi。
- 人工拖动纠错仍可覆盖机器标签；迟到 AI 不能覆盖人工改类或旧来源版本。
- 已冻结 Plan、Pi Run、F05 撤回/重建、结果可追溯链均未改变。

## 4. 仍需区分的边界

- 本轮自动补槽 AI 测试使用受控候选验证提示、结果校验和 CAS 写入，**没有假称联网模型或 Electron GUI 实机验收**。模型实际成功率与队列高峰延迟仍应通过真实样本观测。
- 内置同义词只覆盖经反例证实的有限名称；其他业务模板仍可提供别名或由现有短模型兜底。不能把“所有近义词都 100% 自动绑定”写成已实现。
- 如果模型也无法区分多个兼容槽，原件与已确定的角色照常保存，不能捏造一个槽位。这时模板检查仍可能提示缺件，需要后续从真实材料分析中进一步处理。
