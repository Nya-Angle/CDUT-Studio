## 1. 直接采用的结论

将审核模块的全局导航固定为：**审核首页｜案卷｜待办｜审核批次｜审核模板**，默认进入「审核首页」。

**保留原「当前审核」承担的首页作用。** 本文将其命名为「审核首页」，承接新建审核、继续当前审核、查看进度及下一步。案卷列表负责查找和管理案卷，不能代替首页。此前文档中取消首页、默认进入案卷列表的安排已撤销。

打开某个案卷后，在案卷内部显示：**材料与事项｜审核检查｜办理与决定｜报告与交付｜操作记录**。

「当前审核」保留为全局「审核首页」，重组其内容；「结果与办理」的细节迁入单案页面；「导入材料」成为首页和案卷内的新建或补充动作。首页中的完整模板作者工具迁入模板编辑器。

主要整合关系：

| 现有入口 | 目标位置 | 实施决策 |
|---|---|---|
| 导入材料 | 审核首页/案卷列表的「新建案卷」；本案「材料与事项」 | 新建导入与给当前案卷补充材料使用明确的不同文案 |
| 当前审核 | 审核首页，保留为默认入口 | 保留当前审核摘要、继续审核与新建入口；具体核对到单案，模板作者工具到模板编辑器 |
| 结果与办理 | 本案「审核检查」「办理与决定」「报告与交付」「操作记录」 | 分离发现问题、做出决定、交付和追溯 |
| 审核模板 | 全局「审核模板」 | 模板库与模板编辑器分开；本案选择模板使用局部选择器 |
| 批次管理/审核批次 | 全局「审核批次」 | 批次列表与批次详情分开；批量检查与评委评分共用同一个批次上下文 |
| 待办 | 全局「待办」 | 成为跨案卷任务列表，点击后直达具体处理对象 |

**验收目标：用户从一个待办进入后，应立即看到需要处理的对象、判断所需的原件或依据、可执行动作；无需再找一遍案卷和问题。**

本文是一套确定的实施方案。后文中的页面名称、层级、默认落点和操作归属应统一采用，避免各组件自行命名。

   ├─ 案卷
   │  ├─ 案卷列表
   │  ├─ 新建案卷

### 2.1 全局导航与局部导航

- 审核模块顶部只保留一排全局导航。设置和助手是辅助按钮，不参与全局分节高亮。
- 首次进入及没有明确恢复目标时默认打开「审核首页」。点击「审核首页」始终回到首页，不等同于打开案卷列表或某个案卷标签。
- 案卷、批次、模板详情各自拥有一排局部导航，仅在进入对应对象后出现。
- 案卷内不另设「概览」页。案卷摘要和下一步在详情顶部表达；模块级「审核首页」独立保留。
- 补件、申诉、材料详情是对象详情，不扩充常驻标签数量。
- 点击「案卷」全局入口返回案卷列表；案卷详情顶部提供切换案卷的快捷选择器。两个入口行为固定。
- 从首页/待办进入案卷后，全局高亮「案卷」，面包屑显示「返回审核首页」或「返回待办」；从批次进入单案时显示「返回本批次」。
- 用户点击全局模板库时不携带单案操作栏；从本案发起模板编写则保存返回上下文，完成后回到本案确认应用。

### 2.2 什么用整页，什么用抽屉或对话框

| 内容 | 容器 | 规则 |
|---|---|---|
| 案卷/批次/模板列表和主工作区 | 整页 | 支持恢复筛选、选择与滚动位置 |
| 原件、材料详情、单个事实及证据关联 | 侧边详情区；窄窗使用可返回的全宽详情 | 保持正在处理的问题可恢复 |
| 补件、申诉、评分任务 | 所属工作区内的详情视图 | 有自己的标题、状态、返回入口，不叠加多层弹窗 |
| 简短确认、填写归档理由、单次决定提交 | 对话框或当前详情的操作区 | 只处理一个明确动作 |
| 新建案卷、批量导入、模板编辑 | 专用页面/工作区 | 不把长表单塞进小对话框 |
| 技术回执、运行账本、来源指纹 | 对应对象的详情/折叠区 | 从相关任务可达，不常驻业务页面 |

## 3. 信息取舍：保留功能，减少同时出现的内容

每项信息只设一个主要维护位置。其他页面可以显示摘要或快捷入口，但必须打开同一对象、使用同一业务命令。

### 3.1 四类展示方式

| 展示级别 | 内容 | 举例 |
|---|---|---|
| 常驻 | 当前对象、阶段、影响当前任务的状态、当前主动作 | 本案名称、材料变更导致结果过期、保存认定 |
| 按任务出现 | 当前选中问题所需的证据、字段、操作 | 获奖等级冲突时显示两个值及证书原件 |
| 详情中查看 | 对比、历史、全部检查、完整模板标准、诊断 | 历次事实值、运行调用明细 |
| 从业务界面移除 | 重复说明、工程里程碑、实现过程描述 | T03、B1、第 51 套、Main 接线、原生存储、当前分支完成情况 |

移除的是页面上的噪声和重复入口，不删除历史数据、真实错误、技术诊断或受支持的操作。

### 3.2 具体删减与迁移表

| 现有内容 | 调整后的规则 |
|---|---|
| 每页都出现当前案卷概览 | 案卷详情保留公共摘要；首页在「当前审核」区展示同源摘要；模板/批次/待办全局页不挂旧案概览 |
| 顶部全局「导出报告」 | 移入案卷「报告与交付」；其他位置的快捷入口只导航到这里 |
| 各面板重复展示案卷名称、材料数量 | 统一放案卷摘要；具体材料列表保留必要统计 |
| 「候选技术方案并非正式模板」反复出现 | 用「技术预审」性质标识和首次使用说明表达；关键应用/发布动作保留后果说明 |
| 「发布 50 套演示模板」位于普通导航 | 移到模板库的「示例与演示」，显示安装/发布结果明细 |
| 用户手输 caseId、模板 ID 才能重开 | 默认使用列表搜索；技术 ID 在详情可复制，按 ID 定位保留为辅助能力 |
| Run ID、fingerprint、revision、哈希长串 | 默认显示时间、轮次、版本；完整标识进入运行/版本详情 |
| 整份原文和所有观察历史默认展开 | 选中材料、事实或检查项时再打开 |
| 所有问题卡上堆满所有操作 | 选中后显示适用于该问题的操作；仍有用的低频操作放明确命名的菜单 |
| 无条件显示来源缺口、离线包、申诉表单 | 有相关任务时显示摘要；从对应任务进入详情操作 |
| 大量「前往处理」「确认」「通过」 | 使用对象和阶段明确的文案，如「核对获奖等级」「初审通过」 |
| 模型配置全屏抢占首次进入 | 审核首页提供可跳过的就绪提示；只在依赖模型的操作处显示阻断原因 |
| 多处不同文案的开始审核 | 统一检查页命令；其他入口作为同一命令的快捷调用，不实现另一套运行逻辑 |

**以下信息不能因精简而隐藏：**导入失败文件、材料归属不明、检查未执行/失败、材料读取不完整、结果过期、决定被阻断的原因、动作影响范围、保存失败与部分成功。

## 4. 审核首页、案卷列表与新建案卷

### 4.0 审核首页（保留原「当前审核」的首页职责）

页面目的：让用户进入模块就知道「从哪里开始」「上次审到哪里」「接下来做什么」。这是一个可操作的工作入口，必须在本次改版中保留。

首页名称统一为「审核首页」。它与案卷列表使用不同页面和独立路由；不得把首页按钮直接指向案卷列表。

**有当前案卷时，内容从上到下：**

1. 标题「审核首页」；入口「新建审核」，次级入口「从模板新建」。
2. 「当前审核」主区域：明确的案卷名称与申请人、办理阶段、检查状态、一个下一步及主按钮。
3. 当前案卷的必要进度：材料准备、审核检查、人工办理、报告交付。各项显示真实状态并可进入相应页面；它们是入口摘要，不是必须顺序点击的向导。
4. 当前案卷最需要处理的事项，最多 3 条；每条可直达对象，末尾「查看本案待办」。
5. 「最近案卷」，最多 5 条，显示名称、申请人、状态和继续入口；「查看全部案卷」进入列表。全局待办入口可显示可行动任务数量，读取未完成时显示加载/不完整状态。

```text
审核首页                                  [新建审核] [从模板新建]

当前审核：张三 · 2026 年综合测评             [切换案卷]
初审中 · 检查已结束 · 3 项需要核对
下一步：核对竞赛获奖等级                    [继续审核]

材料准备       审核检查       人工办理       报告交付
5 份已登记     3 项待核对     初审待办理     可查看预审报告

本案待处理
获奖等级存在冲突                           [核对]
一份证明尚未完整读取                       [查看原件]
                                          [查看本案待办]

最近案卷                                  [查看全部案卷]
李四 · 综合测评 · 等待补件                  [继续处理]
王五 · 项目申报 · 已形成决定                [查看结果]
```

**没有当前案卷时：**

- 完全没有案卷：主要区域提供拖入/选择材料、从模板新建、先建空白案卷；示例体验为次级入口。
- 已有历史案卷但尚未选择：主要区域显示「继续最近一次审核」的明确案卷名称及按钮，下面保留新建入口和最近案卷。只有用户点击后才选中并打开，不能擅自把列表第一项当成当前案卷。
- 当前案卷已完成：显示真实决定与「查看结果/报告」，同时保留新建入口；有未完成申诉等任务时按第 5.3 节推荐下一步。
- 当前案卷正在运行：展示进度和「查看运行」；允许回首页等待或处理其他案卷。

**首页交互与信息边界：**

- 「当前审核」与案卷详情读取同一 caseId、运行、模板和待办投影，不能再保存一份首页专用案卷数据。
- 「继续审核」进入具体下一步对应的页面及对象；不是每次都打开材料页或候选编辑器。
- 首页「新建审核」和案卷列表「新建案卷」共用第 4.2 节流程；首页拖入文件是新建案卷，当前案卷补件通过明确的「添加材料」入口完成。
- 首页的阶段入口不展示整套材料表单、原文、全部检查或决定表单。进入相关页面后处理，返回首页时摘要及时更新。
- 首页的「查看本案待办」进入待办页并带 caseId 筛选；全局导航「待办」进入未限定单案的待办页。
- 最近案卷只承担恢复入口；搜索全部、归档恢复等管理能力在案卷列表。模板作者和批次配置不进入首页主区域。
- 当前案卷已归档、不可读取或被移除时，显示对应状态并提供切换/新建，不展示另一案卷的数据作为兜底。
- 不把完整跨案卷待办列表复制到首页。首页的当前任务、最近案卷都链接原对象，数量与源页面一致。

### 4.1 案卷列表

页面目的：找到一份案卷并继续工作。

从上到下：

1. 标题「案卷」；主按钮「新建案卷」。
2. 搜索名称/申请人；状态筛选「全部、草稿、审核中、待处理、等待补件、已形成决定、已归档」。这是展示筛选，不直接替代现有领域状态枚举。
3. 案卷表格：案卷名称与申请人、审核性质、办理阶段、检查状态、待办数、更新时间、打开按钮。
4. 空状态或加载/失败反馈。

「审核性质」展示业务办理/技术预审等实际能力，按真实模板和能力判断。不要向用户暴露 V2/V3 作为案卷分类。

案卷行菜单保留：按现有能力归档/移除、恢复、复制 ID。业务案卷归档与普通草稿移除的后果保持现有语义，操作前明确对象；不新增永久删除业务记录的行为。

示例案卷放在空状态次级入口「使用示例体验」，以及辅助菜单中。已归档案卷有独立筛选，恢复操作说明旧结果保留为历史、需要重新核验。

列表默认按最近更新排序。不要默认打开第一份案卷。若存在未完成编辑，离开时按保存策略处理，不能默默丢失。

### 4.2 新建案卷

页面只负责建案与最初接入，不承载全套审核。

两种起点：

| 起点 | 首屏内容 | 完成后 |
|---|---|---|
| 从材料开始（默认） | 文件选择/拖入；可选案卷名、申请人 | 创建草稿并进入该案「材料与事项」，定位导入结果及待确认要求 |
| 从模板开始 | 已发布模板选择、用途说明、最低必要字段 | 创建案卷并进入「材料与事项」，展示材料要求 |

保留次级动作「先建空白案卷」。首屏不要求选择内部模型、材料槽 ID、技术计划或候选编号。

具体行为：

- 一份新案卷只创建一次。导入重试、模板匹配和页面返回继续使用已创建的 caseId。
- 已创建草稿后取消选文件，显示「草稿已保留」及「打开草稿」，不能静默留下用户找不到的案卷。
- 多文件导入逐项显示成功/失败。部分失败进入案卷后仍能查看并重试失败项，不能只依赖瞬时 toast。
- 默认按一份案卷接收。发现多个申请主体时提示进入批量导入确认分组，不自动把不明材料归入一个人名下。
- 材料角色、身份和归属可以待确认；进入检查/办理所需条件仍由现有 Main 校验。
- 首次材料导入成功只表示材料已保存，不显示「审核完成」。

### 4.3 没有合适模板时

在本案「审核要求」详情中，按顺序提供：重新选择已有模板 → 描述本次审核要求 → 创建可复用模板。

用户描述临时审核要求后，可以提取明确要求或使用已授权模型起草，预览实际检查内容，再固定本次技术审核计划。保留当前 D4/B1 技术计划与人工覆盖路径，界面使用业务名称。

技术预审、模板草稿、已发布业务模板保留各自能力限制。不能因使用同一案卷页面，就把技术计划当成可办理全部业务阶段的模板。需要转成可复用业务模板时，进入模板编辑、试跑和发布；对已有案卷是否允许重新绑定，按真实服务能力决定，不承诺无条件原地转换。

## 5. 案卷详情公共框架

### 5.1 内容顺序

```text
返回审核首页 / 返回案卷列表 / 返回待办 / 返回本批次
张三 · 2026 年综合测评                       [切换案卷] [更多]
业务办理 · 初审中    检查：材料变化，需更新
本案新增了 2 份证明，当前检查尚未覆盖。        [更新审核]

材料与事项 | 审核检查 | 办理与决定 | 报告与交付 | 操作记录
────────────────────────────────────────────────────────
当前页面内容
```

顶部只承担身份、状态和行动指引。模板名称/版本在「材料与事项」的审核要求摘要中展示；其他页面需要时可在案卷信息详情查看，避免每页重复。

「更多」放案卷信息、归档/移除等低频管理操作。创建另一份案卷、模板编辑、批次管理不堆在当前案卷工具栏。

### 5.2 默认打开位置

| 打开来源/情况 | 落点 |
|---|---|
| 首页「继续审核」或本案进度入口 | 下一步对应页及对象，保留「返回审核首页」 |
| 待办、批次某行具体动作、报告来源链接 | 按调用方给出的目标页和对象定位，优先级最高 |
| 新建或第一次打开未准备案卷 | 材料与事项 |
| 普通「打开」且本次会话有上次位置 | 恢复该案的页、对象和筛选；若对象失效显示原因并保留返回入口 |
| 普通「打开」、无位置记录、运行中或已有待核对结果 | 审核检查 |
| 无位置记录且待办理、补件往返或申诉待处理 | 办理与决定 |
| 无位置记录且已决定/归档 | 报告与交付；暂无报告时显示真实决定摘要及操作记录入口 |

打开页面不触发提交、运行、决定或导出。状态变化只更新提示，不把正在编辑的用户强行带到另一个页面。

### 5.3 下一步推荐规则

推荐动作带具体目标，不能只切换一个大栏目。多个状态并存时，以当前有效任务及 Main 能力为依据，按下列优先级选择一个推荐入口：

1. 当前操作保存失败/冲突：显示恢复或重新读取动作；保留未保存输入。
2. 运行等待用户输入/授权：定位真实请求。
3. 有当前可办理的申诉、已收到的补件等任务：进入对应任务。
4. 正在执行：查看当前运行。
5. 尚缺少本次检查必要的材料、要求或归属确认：定位第一个实际阻断项。
6. 当前结果因输入变化失效：查看变化并更新审核。
7. 尚无检查：开始审核（条件不满足时展示具体原因）。
8. 有待核实问题/事项认定：进入第一条可行动事项。
9. 当前阶段可办理：打开该阶段决定。
10. 已决定/归档且无新的有效任务：查看决定与报告。

「等待补件」仅显示等待状态及补件详情入口，不伪装成用户必须点击处理的任务。已归档、技术预审、已决定案卷的推荐动作必须先经过实际能力过滤。

### 5.4 统一显示三种状态

- **办理阶段**：草稿、初审、复审、等待补件、已决定等，按模板/领域记录映射。
- **检查状态**：未开始、执行中、部分完成、完成、失败、已停止、需更新等。
- **当前任务**：还需要人工做什么，或正在等待什么。

检查完成不自动把案卷显示成已批准；没有模型不影响查看、整理材料、手工核验或服务允许的规则检查。某次检查失败也不自动变成材料不合格。

## 6. 材料与事项页

页面目的：确认审谁、审什么、用什么依据；整理能够支持审核的材料和事项。

### 6.1 首屏布局

```text
本案审核要求
综合测评 v3 · 8 条标准 · 2 项适用条件待确认       [查看与调整]

查看：材料 | 申报事项                           [添加材料/添加事项]
筛选：全部 / 缺失与异常 / 待确认
────────────────────────────────────────────────────────────
材料或事项列表                     选中对象详情（未选中时不占位）
申请表                             用途、归属、版本、原件
竞赛证书                           或事项字段、证明与识别结果
志愿服务证明
```

材料/申报事项是同一工作区内的视角切换，不再增加一排覆盖全模块的导航。审核依据原件从「审核要求」或检查问题的规则引用打开。

### 6.2 本案审核要求

默认只显示模板/临时方案名称、版本、适用范围摘要、未确认数量。打开「查看与调整」后显示：

- 模板匹配建议及其依据、手动选择。
- 当前适用对象、场景与必要条件。
- 依据文件、手写要求、已固定检查清单。
- 可用时生成/更新规则大纲、查看完整规则。
- 技术预审/业务办理性质，以及当前方案能支持的操作。
- 「编辑可复用模板」入口，带回到本案的上下文。

匹配倒计时、模型辅助识别、公共兜底的能力保留在此详情。自动匹配状态与已应用审核方案分别展示，不能把建议到期解释成用户已授权业务决定。

本案模板更换必须展示对检查结果和材料要求的影响，按已有绑定/冻结限制执行。模板库修改产生新版本，不静默修改历史案卷。

### 6.3 材料视角

每行显示：文件名、用途（审核依据/申请材料/证明材料）、关联事项、解析/核对状态、待处理问题。文件大小、完整路径、版本标识和哈希进入详情。

材料详情负责：预览原件、来源定位、调整用途、关联/解除关联事项、更换版本、移除、读取覆盖/OCR 详情、人工确认已核对或说明忽略理由。

模板要求的缺失材料显示在列表顶部，例如「还缺：申请人签字页（至少 1 份）」并提供「补充此材料」。上传入口自动带入对应类别。多类别时让用户选可读名称，不让用户理解「槽位 ID」。

同一证明支持多个事项时，详情允许多对多关联。解析失败与材料不合格使用不同状态；解析失败仍提供原件预览和既有人工核验路径。

### 6.4 事项视角

每行显示：事项名称、所属分项、关键申报值、证明数量、待核实事实数量。详情提供：

- 修正识别、手工录入事实、查看来源。
- 添加/删除事项，以及现有条件允许的拆分、合并与影响预览。
- 事实候选确认、更正理由、观察历史。
- 证明关联与来源核验。

这里主要维护申报内容和核实事实。事项的「认可/调整认定/不予认定」主入口归属「办理与决定」；检查页提供定位同一认定编辑器的快捷入口。

修改识别事实不能同时偷偷修改最终认定；两者分别保存，展示「申报值、核实事实、最终认定」的差别。

### 6.5 退出条件

满足当前检查的实际启动条件时，下一步为「开始审核」。材料齐全不是所有预审的硬前提；允许预审发现缺件的既有路径应保留。正式提交、通过、定稿所需条件在各自操作处校验。

## 7. 审核检查页

页面目的：运行检查、理解结果、核对问题。整案阶段决定的完整表单归属下一页。

### 7.1 首屏布局

```text
本次检查：2026-10-21 14:30 · 已完成，3 项待核实
规则检查：完成    AI 检查：部分完成             [更新审核] [运行选项]

问题列表                  当前问题与处理              原件 / 审核依据
待处理 3                  获奖等级存在冲突            竞赛证书第 2 页
已处理 12                 申报：国家级一等奖          高亮证据位置
全部检查                  识别：省级一等奖
                          规则要求及判断理由
某条问题                  [确认问题] [人工确认符合]
某条问题                  [要求补件] [调整认定]
                          [保存并查看下一项]
```

保留三栏联动，但围绕一个问题组织。左侧是问题导航，中部是理解和处理，右侧是证据。原件与规则需要同时比较时，允许展开对照；不默认加载所有全文。

### 7.2 运行与结果

- 尚未运行：显示必要准备条件与「开始审核」。
- 执行中：显示真实阶段和已知进度、停止、需要输入的请求。未知总量不制造百分比。
- 已有结果：主动作「更新审核」；次级菜单保留「重新审核全部」「仅执行模板规则」「运行详情」。
- 历史运行：按时间与状态选择；显示历史标识，处理动作按当前有效性判断，不把旧检查当本次结论。
- 技术异常：显示失败对象和原因，提供重试/重新配置/查看详情中实际适用的动作。
- 规则与 AI 的独立运行回执分别展示；统一入口不伪造合并成功。
- 停止、重试、续跑只能映射已有执行器支持的命令；不把「停止」改名为可恢复暂停。

模型、工具调用和用量在「运行详情」查看。依赖模型的动作受配置限制；仅规则检查保持原有独立能力。

### 7.3 问题内容与操作

默认「待处理」，保留「已处理」「全部检查」。待处理可筛选事实/证明、规则问题、材料缺口、执行异常。全部检查包含通过项，不能因为突出异常而丢失审核范围。

选中问题后按顺序显示：对象 → 申报/事实 → 适用标准 → 检查意见 → 来源 → 已有处理 → 当前可用操作。

保留：确认问题、人工确认符合、标记 AI 误报、请求补件、人工忽略/豁免/升级等现有受支持处理。对低频处置使用「其他处理」菜单并显示理由要求，不删除已有 disposition 能力。

只展示适用于当前类型的动作。例如执行失败优先提供重试，不能只给「确认问题成立」。材料未读应打开材料核验，不能让用户误以为它已被判定不合格。

单项问题处理不会自动通过/驳回整案。点击「调整认定」打开对应事项的同一个认定编辑器；完成后返回当前问题。

### 7.4 阅读与连续处理

每次定位携带案卷、检查项、事项、材料版本及来源位置。来源无法定位时说明原因，降级打开完整原件，不能跳到另一版本中相似文字。

保存成功后更新计数并允许进入下一项；保存失败保留输入和当前选择。窄窗默认显示当前问题，列表和原件可全宽查看，返回后恢复问题位置。

当前输入变化后，在页面顶部显示需更新检查，并限制依赖旧输入的处置。保留查看旧结果和历史记录的能力。

## 8. 办理与决定页

页面目的：处理当前业务阶段、认定事项、办理补件与申诉、形成决定。

### 8.1 首屏内容顺序

1. 当前阶段、当前本地办理身份和实际可办理任务。
2. 当前操作的阻断项摘要，每项有直达修复位置的链接。
3. 事项认定列表：申报值、核实事实、最终认定、待认定状态。
4. 当前阶段可用动作，输入理由后显示本次决定的对象、范围和结果。
5. 补件、申诉与已有决定的摘要列表。

```text
当前阶段：初审        当前身份：本机审核员
还有 2 项影响初审通过                         [逐项处理]

事项认定                                      [继续认定]
事项             申报值       核实事实       最终认定
竞赛获奖         国家级       省级           待认定

本阶段办理
[初审通过] [退回补件] [驳回]                  原因：……

补件：1 次等待回件 / 1 次已收到待核验           [查看]
申诉：无                                      [满足条件时发起]
已有决定：最近一次摘要                         [查看详情]
```

事项认定展开后提供认可、调整认定、不予认定以及理由。检查页、待办页使用同一编辑器，不能各自维护一份最终分数。

### 8.2 决定动作规则

- 初审通过、阶段通过、最终通过、部分通过、退回补件、退回上一阶段、驳回、撤回等，以现有能力和模板阶段实际支持为准。
- Main 返回的能力与事务结果决定按钮可用性和成功状态；不能只依靠前端角色下拉框。
- 不同动作分别展示条件。驳回与通过可能有不同前提，不能统一用「待办总数为零」判断。
- 原因输入在动作上下文内展示。提交后读取真实回执并更新阶段，失败保留草稿。
- 决定范围明确写「本事项」「本阶段」「整份案卷」，避免只写「确认」。
- 已决定案卷展示决定摘要和当前仍可用的申诉/重开路径；已归档案卷按已有约束只读。
- 技术预审案卷显示其实际支持的核对/认定能力与业务阶段限制，不因为没有阶段办理能力而隐藏报告和历史。

### 8.3 补件详情

进入时已经确定案卷和补件请求，不再让用户从下拉框重新选一次。

内容顺序：请求原因及关联问题 → 所需材料清单 → 状态与往返历史 → 已收到的材料/说明 → 核验动作。

保留操作：发起补件、登记回件、查看原件、核验满足、仍然不足、说明理由取消请求。当前多条未结请求可显示合并清单；具体写入仍关联各自请求，不抹平记录。

离线操作紧邻当前任务：导出补件任务包 → 导入回件文件/内容 → 预览校验 → 确认导入 → 显示回执。保留重复回件、失效任务、版本冲突的可读反馈。

核验满足后推荐更新相关审核；是否已足够形成决定，继续由有效运行和业务条件判断。

### 8.4 申诉详情

内容顺序：原决定 → 申诉理由和新证据 → 当前复审任务 → 复审意见和动作 → 全部关联历史。

保留发起、撤回、独立角色复审及既有受理限制。页面明确当前办理身份；本机角色选择不是在线账户权限证明。

旧决定与复审结果分别展示，不通过覆盖旧结论让历史消失。申诉进行中仍能查看原报告，并标出其对应原决定。

## 9. 报告与交付、操作记录、审核助手

### 9.1 报告与交付

内容顺序固定为：

1. 选择结果版本：以时间、审核状态、关联决定描述，完整 Run ID 可展开。
2. 选择交付对象：申请人、审核人、组织者。
3. 默认展开可读报告预览，显示报告性质及有效性。
4. 选择格式并导出；显示实际保存结果。

保留 MD、JSON、XLSX、HTML、PDF、只读交接 ZIP 和复制 MD。格式能力按现有导出服务实现，不擅自改变内容或伪造可用格式。

所有报告快捷入口统一到本页并带入准确 caseId/runId。历史报告使用其对应输入快照，不能混入当前未冻结字段。预审报告无需等到最终决定才能查看/导出，但必须说明性质。

没有运行时显示「尚无审核报告」，提供检查入口；存在决定记录则展示决定摘要和记录入口，不生成虚构报告。技术预审、部分完成和过期报告仍可按已有能力查看，状态必须保留。

报告面向对象的选择与既有内容可见性规则保持一致，不能仅更换标题而泄露内部意见。

### 9.2 操作记录

默认按时间倒序显示业务记录。筛选：材料、检查、事实与认定、补件、决定、申诉、交付、授权。

每条默认显示时间、操作者、动作、对象、结果和简短原因。展开后显示前后值、关联来源、材料版本、运行记录、回执和技术标识。

记录只读取已有真实数据；没有持久记录的操作不要补造历史。查看运行详情复用检查页的详情组件。

### 9.3 审核助手与 Agent 指派

助手继续是辅助抽屉，并保留快捷键。打开时明确显示当前案卷；离开单案页面后不得继续暗中以旧案卷作为写操作目标。

建议处理遵循：查看建议 → 查看来源和修改前后值 → 用户应用 → 真实回执。字段修改与补件建议使用现有受控应用路径。

本案「交给 Agent」、有效指派、撤销指派放在助手的「本案指派」区域；授权历史可在操作记录查看。指派不会因为打开助手自动创建。

现有「AI 代批」属于全局审核设置，移入「审核设置 → 自动处理与授权」，保留已有显式确认和专用调用。开启时，受影响的案卷办理区域/助手显示简短有效状态及设置入口，不能只把开关藏起来。

批次自动处理策略属于具体批次；与全局 AI 代批分别展示作用范围，不能合并成一个不明范围的「自动审核」开关。已有终审/评分角色门控继续适用。

## 10. 待办页

页面目的：集中呈现当前能够处理的任务，点击后直接处理。

### 10.1 展示结构

顶部视图：**需要处理｜等待中｜已处理**。筛选案卷、批次、任务类型；不默认增加总览图表。

| 列 | 内容 |
|---|---|
| 待做事项 | 「核对张三的获奖等级」「核验新收到的补件」等可读任务 |
| 所属对象 | 案卷名称；来自批次时附批次名称 |
| 原因 | 一句话说明为何需要处理 |
| 类型/状态 | 事实、材料、检查、认定、阶段、补件、申诉、评分、执行异常 |
| 更新时间 | 用于排序与判断是否新到 |
| 操作 | 核对、核验、办理、评分、排查等具体动词 |

默认按需要用户输入/阻断、已收到待核验、其余可办理任务排序；同组按更新时间排序。当前没有时限数据，不伪造截止日期或逾期。

### 10.2 聚合与去重

- 待办是业务对象的读模型，不建立第二套「已完成」事实库。
- 同一检查引出的补件，补件发起后显示「等待回件」或「核验回件」作为行动任务，检查保留关联状态，不能重复显示两个相同动作。
- 事项认定有独立任务，因为它与事实确认是不同业务动作；不得把二者错误去重。
- 材料第一次进入自动检查前的普通「未读」不一律生成必须人工点击的任务。解析失败、审核后未完整读取、需人工核验等才作为人工待办。
- 每个任务有稳定对象引用，包含 caseId 及相关 runId/checkId/subjectId/supplementId/appealId/assignmentId；对只在一次运行内唯一的标识使用复合身份。
- 任务完成或过期后从可行动列表更新。旧运行任务不能因材料重审而在新一轮重新误用。
- 「待办数量」明确指可行动任务数；等待数量独立显示。整案驳回关闭的事项显示「随决定关闭」，不显示「已逐项核实」。
- 评分任务按真实本地身份/分配能力列出；案卷阶段任务同样按能力投影，不把所有角色任务都称为「我的」。

### 10.3 当前实现缺口

当前 `RightPanel` 与 `buildReviewWorkspaceViewModel` 主要服务当前案卷。全局待办需要增加跨案卷汇总、阶段/申诉/评分任务接入及精准导航。

优先复用现有案卷索引、聚合、任务和运行读取服务。只读汇总可以缓存/按页获取，避免切页时同时加载所有原件正文；不为此新增本地数据库或维护另一份决定数据。

加载失败必须显示「部分案卷未加载」及重试入口，不能把未知状态算成零。实施阶段若尚未接齐全量任务，不把全局待办标为完成，也不能用旧右栏冒充。

## 11. 审核批次

### 11.1 批次列表与新建

列表列：批次名称、模板及版本、案卷数、执行状态、待人工数、定稿状态、更新时间。主动作「新建批次」。

新建支持两条已有能力路径：选择已有案卷；导入一批真实材料。批量导入使用专用工作区，流程为：

```text
选择目录/文件/清单
→ 预览申请人和案卷分组
→ 确认材料用途、归属及模板
→ 查看逐案校验与可导入范围
→ 确认导入
→ 显示逐案回执与创建出的批次
→ 用户启动已导入案卷的审核
```

保留 CSV/TSV 清单辅助身份匹配、模板路由、归属确认、来源预览、部分导入失败与按模板分批。多个模板产生多个批次时，结果页清楚列出每个批次及进入入口，不强行合并。

导入部分成功后，重试使用现存案卷/材料回执辅助识别，不能把同一批原件默认再次当全新导入。

### 11.2 批次详情公共区

顶部只显示批次名、模板版本、案卷数、批次状态；局部导航固定为「案卷与进度、集中处理、评委评分、汇总与定稿」。

批次详情内所有子页接收同一个 batchId。撤销评委面板内独立选批次的控件；切换批次只通过详情公共区进行。

### 11.3 四个页面

| 页面 | 默认信息顺序 | 操作与详情 |
|---|---|---|
| 案卷与进度 | 队列摘要 → 搜索/状态筛选 → 案卷表格 | 启动待审、选中失败项重试、恢复中断、加入/导入案卷、状态 CSV；按实际能力禁用定稿批次修改 |
| 集中处理 | 同类问题组 → 选组后的逐案依据/可适用范围 → 处理预览 | 人工集中处理；批次自动处理配置、候选预览和执行；逐案成功/失败/跳过回执 |
| 评委评分 | 轮次与身份 → 分配/本人任务 → 单个评分任务 | 建轮次、分配与替补、回避、缺评、填写与提交、评分更正/撤销、离线包往返 |
| 汇总与定稿 | 检查/办理完成度 → 评分汇总及排名（适用时） → 定稿缺口 → 定稿记录 | 名额、有效评委人数、N/A/缺评分母、分歧与同分处理、冻结排名、批次定稿、导出、重开轮次 |

没有评分量表的批次在「评委评分」显示未配置原因和模板说明入口，不自动载入示例量表或虚构评分。

批次审核定稿与评委排名冻结保留各自回执、条件和历史，不因放在同一页面就合并成一个前端成功标志。若服务尚无组合事务，应分别显示完成状态及下一步。

集中处理必须先显示逐案适用和排除原因；相同问题文案不等于可以给所有案卷执行相同决定。自动处理继续使用已存在的授权与条件校验。

从批次进入案卷时携带原筛选、所选案卷顺序和返回位置。案卷内提供「返回本批次」「下一案」；用户不必每处理一份就重新筛选列表。

## 12. 审核模板

### 12.1 模板库

模板库只负责寻找、使用和管理模板。默认展示名称、用途、适用对象、状态、版本和更新时间；完整字段、规则与流程不在列表展开。

主动作「新建模板」。次级操作：导入配置、从需求起草、使用参考范本、示例与演示、已删除模板。

已发布模板提供「用于新案卷」「查看」「创建新版本」；草稿提供「继续编辑」「试跑」；参考范本提供「复制并配置」。删除/恢复、版本历史、配置导出保留。

「发布 50 套演示模板」放在「示例与演示」详情，保留已发布/跳过/失败结果和逐项原因。不要把演示模板等同于已核验的本单位制度。

### 12.2 模板编辑器

打开模板后进入独立编辑器，库列表不在上方继续占据整屏。顶部显示模板名、版本、草稿/发布状态、保存状态；「保存草稿」常驻，「发布」归属试跑与发布页面。

| 局部页 | 编辑内容 | 内容整合方式 |
|---|---|---|
| 适用范围 | 名称、用途、申请对象、场景、条件、来源说明 | 先明确何时使用；参考来源可查看原文 |
| 信息与材料要求 | 案卷字段、事项字段、分项、材料类别/数量/格式/要求时间 | 以业务分项为主组织相关字段和材料，共用项单列；内部编号放详细属性 |
| 审核标准 | 标准文字、确定性条件、语义检查、检查范围、证据要求、计分规则 | 以一条标准为编辑对象，显示它使用的字段和材料引用 |
| 流程与输出 | 阶段、执行角色、退回节点、评分量表、输出类型和面向对象 | 先流程，再适用的评分与输出；长对象进入详情编辑 |
| 试跑与发布 | 样例、试跑结果、来源缺口、预览、校验问题、冻结/发布、历史版本 | 每个错误能回到具体字段/规则，不只给总失败提示 |

### 12.3 候选作者能力的落点

- 作者文档编辑、保存修订、读取最新修订、预览：在编辑器中保留「技术候选文档」入口，内容可跨页保存，不在普通审核页常驻。
- 冻结候选、技术计划试跑：放「试跑与发布」内的技术预审区域。
- 转为可编辑业务模板草稿：显示转换结果、需要继续补充的字段/材料/流程；不能显示为已发布。
- D4 现有技术方案的对象/场景选择：本案使用时在「审核要求」，模板试跑时在试跑配置中；共享表单，作用对象明确。
- 使用已授权模型起草和提取明确要求：作为新建模板的起点，输出进入草稿，保留审阅与修改。

冻结技术候选、发布业务模板、应用到当前案卷是三个动作。分别展示结果，不能统一命名为「确认模板」。

编辑已发布模板时创建新版本，不直接修改历史版本。案卷切换到新版本需要明确应用，保留旧版本追溯。用户从案卷进入模板编辑后返回时，只提出可应用版本，不自动给原案换模板或创建第二份案卷。

## 13. 交互与文案统一规则

### 13.1 页面中的术语

| 当前常见表述 | 面向普通用户的表述 | 技术详情保留 |
|---|---|---|
| 原生案卷/V2 案卷/V3 案卷 | 案卷；附业务办理/技术预审性质 | 数据类型、存储标识 |
| 材料槽 | 材料要求/材料类别 | materialSlotId |
| Check/Plan/Run | 检查项/本案审核要求/一次审核运行 | 原始类型、ID、指纹 |
| B1/D4/第 51 套 | 自定义审核要求/预置方案/自定义模板 | 技术方案来源与编号 |
| 结果与办理 | 审核检查、办理与决定、报告与交付 | 旧路由兼容映射 |
| 前往处理 | 核对事实/核验回件/办理初审等 | 目标对象 ID |
| 通过 | 确认本项符合/初审通过/最终通过 | 实际 action/result |
| AI 审核员 | 审核检查（页面）；审核助手（对话） | Agent 运行信息 |

不要把「事项」「检查项」「待办」混成同一个词：事项是申请内容，检查项是一次核对，待办是当前需要执行的动作。

### 13.2 保存、跳转和反馈

- 本轮实施沿用现有显式保存命令，表单显示已保存/未保存/保存失败。切换标签在内存中保留草稿，不表示已写盘。
- 切换案卷或离开存在未保存输入的编辑器时，提供保存、放弃、继续编辑。对话框确认不增加到每次普通导航。
- 路由返回恢复页面、筛选、选中对象及滚动位置；快捷入口不能创建另一份独立状态。
- 成功依赖真实回执。重要失败和部分成功显示在对应对象附近，toast 只作补充。
- 列表为空、加载中、加载失败、当前能力不可用是四种不同状态，禁止统一显示「暂无」。
- 被禁用操作旁边显示简短原因和可解决入口，不能只把原因藏在 hover 提示。
- 运行状态在切页后继续更新；返回时从真实状态恢复，不要求用户刷新才能知道任务已结束。
- 全局设置出现模型异常时，只影响依赖该模型的动作；人工办理仍按业务条件判断。

### 13.3 页面信息预算

首屏优先出现一个当前对象、一个主要任务区、一组相关动作。可有多个必要次级操作，但不要在全局顶栏堆放各页动作。

统计数字只有在能帮助筛选或解释阻断时才显示。不要同时堆「材料数、检查数、通过数、问题数、待办数、已处理数、运行数」而没有清楚含义。

详细表单通过选中对象展开。折叠区只能收纳低频详情，不能把必须完成的任务藏到名为「高级」的区域里。

## 15. 导航和状态实现约定

### 15.1 显式路由对象

保留 Jotai。无需为了本次重组引入新的路由库；使用类型明确的路由状态即可。下面是建议的导航模型，属于待新增前端类型，不是已有 IPC API：

```ts
type CaseTab = 'materials' | 'checks' | 'workflow' | 'reports' | 'history'
type BatchTab = 'cases' | 'processing' | 'rating' | 'finalization'
type TemplateTab = 'scope' | 'requirements' | 'criteria' | 'workflow' | 'publication'

type ReviewRoute =
  | { page: 'home' }
  | { page: 'cases' }
  | { page: 'case-new'; start: 'files' | 'template' | 'blank' }
  | { page: 'case'; caseId: string; tab: CaseTab }
  | { page: 'tasks'; view: 'actionable' | 'waiting' | 'resolved' }
  | { page: 'batches' }
  | { page: 'batch-new' }
  | { page: 'batch'; batchId: string; tab: BatchTab }
  | { page: 'templates' }
  | { page: 'template-new' }
  | { page: 'template'; templateId: string; version: number; tab: TemplateTab }
```

选中材料/事实/检查/补件/申诉/评分任务等焦点使用带类型的对象引用，附属于当前 route。对象引用必须包含其所属案卷/批次及必要版本，不依赖「上一次组件里恰好选中了谁」。

路由初始值为 `{ page: 'home' }`。首页当前审核引用已明确选中的案卷；首页路由本身不等于单案详情，也不在访问时自动创建、绑定或运行案卷。

跨页导航统一走一个导航动作，输入为目标路由、可选对象焦点、返回上下文。返回上下文保存来源路由、筛选、选择和滚动；不做无限嵌套的返回链。

### 15.2 当前案卷数据一致性

当前已存在 `selectedCaseIdAtom` 和按案缓存；应在此基础上整合，不再建立另一套单案数据仓库。

必须满足：

- 案卷详情 route.caseId 与选中案卷一致；业务聚合、模板、运行、来源焦点都能验证属于该案。
- 不再由 `section === 'case-v2'` 等 UI 分支决定读取哪套「当前聚合」。
- 异步请求 A 返回时，只更新 A 的缓存；用户已切到 B 时不覆盖 B 的标题、材料、运行或下一步。
- 打开案卷失败显示该案加载错误，不回退展示前一份案卷冒充成功。
- 修改后统一更新该案缓存并刷新相关派生状态；不能只刷新当前可见面板。
- 规则检查与 AI 运行即使共用入口，也保留各自真实身份和有效性。
- 原生技术案卷与旧业务案卷可共用展示模型，但能力由真实数据和服务确定，不能靠 UI 类型转换伪造兼容。

建议将单例 `reviewV2AggregateAtom` 的消费者逐个迁移到按 caseId 的缓存；过渡适配器若必须存在，只做引用/派生，不能独立保存另一个可能过期的聚合。

### 15.3 页面卸载与后台任务

现有代码部分通过 `hidden` 保留所有大面板。拆页时不能直接改成全部卸载而丢失草稿、监听或执行状态。

先把需要跨页保留的表单草稿放到按对象区分的 Jotai 状态，把运行监听/轮询放到不依赖具体展示页的控制层，再按需挂载页面。业务运行仍由现有 Main 持有。

页面选择、筛选和临时草稿默认保留在会话内；需要重启恢复时使用项目既有配置文件/业务草稿存储机制，不能为本次改版引入新数据库或用 localStorage 保存业务真相。

### 15.4 新增能力与纯重排的边界

| 工作 | 性质 | 完成依据 |
|---|---|---|
| 全局/单案导航、拆页、标题改名、技术信息折叠 | 前端重排 | 入口可达、上下文和原命令不变 |
| 统一案卷状态、草稿保留、精准定位与返回 | 前端状态/导航调整 | 快速切案、异步返回和离页恢复场景成立 |
| 跨案卷待办及去重 | 新增读模型与界面 | 接入真实案卷、阶段、补件、申诉、评分等任务，区分未知与零 |
| 批次共用上下文、评分与定稿拆页 | 前端重排并整合状态 | 所有操作始终作用于显示的批次/轮次 |
| 报告统一入口 | 前端重排 | 全格式、历史版本和受众能力保留 |
| 资料页的智能建议与当前方案能力统一表达 | 前端整合，依赖现有匹配/绑定服务 | 不新增隐式授权或未经支持的转换 |

不把后端不存在的重试、转换、组合定稿能力画成可用按钮。需要扩展服务才能完成的细节，应先明确服务缺口；不能通过删掉原有业务路径掩盖缺口。

## 16. 分批实施顺序

每个阶段结束后都应有可运行的完整入口。临时兼容组件可留在新页面内部，但不能把旧的全局混合导航重新摆出来。

### 阶段一：导航与单案上下文

工作项：

1. 新建全局 route、单案 tab、对象焦点与返回上下文状态。
2. 优先实现审核首页，保留当前审核、新建与继续入口；实现独立案卷列表及案卷详情壳。
3. 全局导航改为五入口，默认审核首页；旧 `section` 调用按发起目的映射，原「当前审核」首页入口映射到 home，具体编辑/核对入口映射到对应对象。
4. T10 提取同源摘要与下一步供首页当前审核区域和单案详情使用；先统一 caseId，再调整下一步规则。
5. 迁移 V2 聚合 atom，统一按案读取；保留既有后台运行。

完成标准：默认进入保留的审核首页，能新建或继续当前审核；从任意入口打开的案卷，其标题、材料、运行、模板和操作目标一致；切到模板/批次列表时不再显示旧案摘要。不能用案卷列表替代首页，也不能只改标签文字就结束此阶段。

### 阶段二：材料准备与候选工作台拆分

工作项：新建页两种起点；材料/事项视角；本案审核要求选择；导入回执；事实/证据对象详情；候选作者能力移入模板编辑器的相应入口。

完成标准：拖入材料后进入本案材料页；有模板的普通审核无需进入作者工具；无匹配模板仍能走既有自定义技术预审路径。

### 阶段三：检查、办理、交付与记录

工作项：问题三栏；运行区和详情；事项认定；阶段办理；补件/申诉详情；离线往返；报告单一入口；操作时间线；助手与授权归位。

完成标准：一份案卷可从创建完整走到检查、人工办理、报告；原 `V2CasePanel` 不再纵向堆叠全部生命周期组件。

### 阶段四：模板与批次工作区

工作项：模板库/编辑器分离，五页编辑和技术候选试跑；批次列表/详情分离，四页操作，同一 batchId 和真实轮次；批量导入专页。

完成标准：普通审核、模板编写、批量执行、评委评分各自有稳定入口；新版本不影响旧案；评分冻结与批次定稿状态可分别核对。

### 阶段五：全局待办与连续处理

工作项：真实任务汇总、去重、等待/已处理分类、精准对象跳转、保存并下一项、批次下一案、返回恢复。

完成标准：从待办能完成任务并返回；相关任务计数同步变化；读取失败不显示为零。此阶段完成前，整体改版不能标为全部完成。

### 阶段六：清理旧入口与信息复核

工作项：移除不再需要的大页容器、旧导航标识与重复表单；核对第 14 节所有能力落点；用第 17 节逐条验收。

完成标准：没有找不到入口的原功能；没有两个动作实际修改同一业务却使用不同状态源；不存在工程编号和长标识占据常规首屏。

实际实现涉及前端逻辑后，应遵守仓库 `AGENTS.md` 的 typecheck 和 BDD 要求；此文档本身不表示这些检查已经执行。功能/架构文档同步按仓库规则另行执行。
