**关键裁决**：国家层面的《普通高等学校学生（研究生）代表大会工作规定》（下称《工作规定》）第十五、三十三至三十六条已对代表提案和立案主体作出规范；校本《章程》与大会新闻证明制度/实践存在，但没有取得成都理工本届正式代表册、征集通知、表格和审查细则。不能据此填写固定截止日、联名人数门槛、复核期限或审批印章要求。

### 事实、程序与决定三层分离

1. **事实层**：验证身份/文件真实性、案名案由建议是否存在、材料版本是否一致、是否提出两件不相干事项、必要证明是否可读。
2. **程序研判层**：提示可能的校权范围、公共性、政策冲突及征集窗口问题，未确证时为 POLICY_UNCONFIRMED 或 NEEDS_HUMAN_DECISION。
3. **有权决定层**：大会筹备工作组**提案工作委员会**作出立案/不予立案并留痕；学生会/研究生会权益工作机构转交与跟进；学校相应职能部门回复具体办理意见。AI 不能替代上述主体。

## 01 唯一审核目的、申请人和负责机构

**唯一目的**：对“具备本届正式代表提案权的人，在规定征集场景内，以个人或联名方式提交的一事一案提案”进行资格与材料程序核验，为提案工作委员会的立案审查提供问题清单和证据链，并延续至该提案的撤回、转办反馈和程序性异议记录。对象是“提案及其所属大会”，不是“学生干部身份认证”，也不是“校园投诉处理”。

- **发起权**：学代会/研代会正式代表的个人提案或联名提案。《工作规定》第十五条、第三十四条。普通在校学生可向代表反映意见，但其本人直接发起的普通建议不自动变成代表提案。
- **资格形成权**：大会筹备工作组代表资格审查委员会核验代表产生程序/资格并向预备会议报告；正式资格由规定程序取得。未经核准的候选代表或列席/特邀者不能仅凭材料自称正式代表。
- **立案权**：大会筹备工作组提案工作委员会负责征集、审查、立案、整理；本模板不可为任何“通过立案”直接写权威结论。
- **办理与答复权**：学生会/研究生会权益工作机构分类转送、跟踪、汇总并反馈代表；学校党政部门或有关职能部处在其权限内处理事项。《工作规定》第三十六条。学校校长/行政机构组织处理学生代表大会有关行政工作提案的校本依据见学校《章程》。
- **指导与治理**：学校党委领导、团委指导，具体学代会和研代会是否各有独立筹备组、复核入口及秘书处，以本届学校签发材料确定。

一个提案的多个办理阶段共享同一个 proposal_id、大会身份和不可覆盖的事件历史；更换办理职能部门不能生成第二份“立案”结论。

## 03 业务生命周期与办理情形矩阵

### 03.1 最小状态机

1. **大会登记** ASSEMBLY_CONFIGURED：可信机构提供本届大会类型、层级、征集窗口、表单版本及有权角色；无证据时只是草拟配置。
2. **代表身份** REPRESENTATIVE_VERIFIED：从有权机构代表名册/资格决定校验；候选、列席、未定不冒充正式代表。
3. **征集/草稿** DRAFT：代表调研同学意见，形成案名、案由、建议；材料可暂存，暂无校方签章。
4. **提交与签收** SUBMITTED/RECEIVED：形成提交时间、文件版本、可验证的接收回执。
5. **程序核查** PRECHECKED：输出 PASS_FACT/问题清单；不代表立案。
6. **委员会审查** UNDER_COMMITTEE_REVIEW：核实合规、校权、公共性，依实际本届程序决定 FILED / NOT_FILED / RETURNED_FOR_COMPLETION / TRANSFERRED_AS_SUGGESTION；这些状态均需要可信签发事件。
7. **转办跟踪** TRANSFERRED/IN_PROGRESS：立案后转权益工作机构，再转相关职能部门；转办不等于部门承诺采纳。
8. **办理反馈** REPLIED：有权部门回复，权益机构汇总并反馈提案代表。
9. **后续报告** REPORTED/ARCHIVED：下一次大会可报告上一届落实情况；不能因为本届提交时没有下届报告而报缺件。
10. **并行例外** WITHDRAWAL_REQUESTED/REVIEW_REQUESTED：撤回或程序异议提出后等待有权决定。若正式撤回获接受则 WITHDRAWN，若复核/更正成立则保留原事件并新建决定版本。

**信任分级**：T0 权威后台/签发记录；T1 本届有验证签章、签发人及版本的正式通知/附件；T2 申请人上传原件及经证实签名；T3 OCR、AI 摘要、截图/聊天转发。资格/立案/撤回/复核最终决定只能来自 T0/T1 授权来源。身份证号、学号、联系方式、心理/医疗/处分/求助事实属于受限个人信息；最小化访问、目的限定、权限和必要脱敏。提案正文涉及多人隐私时，公开摘要和内部附件分别隔离。任何来源不允许因为“看着像公章”升级为可信身份。

## 08 审核规则逐条清单

## 09 触发条件、冲突和复合场景

1. **届次先于材料**：同一姓名出现在往届代表名单，不自动证明本届资格；不同层级的代表和学代/研代类型各自与 assembly_id 严格绑定（R001/R004/R005）。
2. **联名只作条件材料**：仅当 F011 非空才启动 M006/R006；不得给单人提案报“缺联名人”，也不套跨校至少几人联署阈值。一个联名人撤签，重新确认受影响范围，不抹除旧确认事件。
3. **一事一案与多部门办理不同**：同一个议题需多个职能部门配合不一定是多个提案；性质独立的图书馆设备和宿舍餐饮两事原则上分案，由委员会最终判断。
4. **争议性实体内容**：公共性、学校管辖范围、违法/违规风险需委员会及有关部门甄别。模型即使认为“不予立案”，只生成带原文的风险待办，不产生不立案签发。
5. **权限断裂**：如果本届征集通知与全国规范有冲突，记录两者版本与原文位置，暂停相关自动硬判，上报团委/提案委员会与法务；外校期限/附议数仅作为结构启发。
6. **证明冲突**：姓名、学号、届次或材料版本不一致时产生 CONFLICT，不能选最新上传自动覆盖可信代表名册；需要权限拥有者对来源版本作说明。
7. **兼顾一般权益渠道**：公共建议误投 G08 或代表资格未定时可草拟提案，但正式提案通道等待身份核验；不阻断既有申诉和紧急报修，必要时双对象互相引用，不由同一 Run 审批两项权利。
8. **立案后建议触发审批**：提案建议举办活动，后续活动组织者仍须独立取得 S05-T05、G03/G04/G07 相应签发许可；这里只引用决定 ID，不因提案“办理完毕”替代审批。
9. **同案跨年**：下一届委员会接收上届报告时，只消费签发的立案、转办与办复事实，不复制新一届 Case 重新决定上届提案资格。
10. **补件与政策未知并存**：可核事实齐全但校本时限不明，输出 PASS_FACT+POLICY_UNCONFIRMED 并存的逐规则集合；不把整案压成“失败”。

## 10 结果状态、问题与待办输出契约

### 10.1 八类逐规则结论

| 结果码 | 精确定义 | 禁止含义 |
| --- | --- | --- |
| PASS_FACT | 在指定证据版本下，某一可核事实成立 | 学校正式批准/立案/采纳 |
| NOT_APPLICABLE | 规则在该身份/阶段/子类型不触发 | 规则无需记录 |
| NEEDS_MATERIAL | 本阶段**应有**的证据缺失 | 未来委员会决定尚未形成 |
| CONFLICT | 两份可见证据在同一事实上矛盾 | 自动选最新/最清晰者 |
| UNREADABLE | 已有必要资料但当前无法可靠解析 | 按不存在/造假判 |
| SOURCE_UNAVAILABLE | 权威身份/签发服务不可访问 | 申请人责任或否定资格 |
| POLICY_UNCONFIRMED | 校本细则/参数/版本未证 | 擅用外校时限阈值 |
| NEEDS_HUMAN_DECISION | 涉实体裁量、签发、疑难/争议 | 引擎自动判立案/不立案 |

业务状态（SUBMITTED、FILED、NOT_FILED 等）与八类事实/程序结果码属于**不同轴**。仅可信决定事件可改变业务状态；事实结果聚合不生成行政决定。

### 10.2 问题对象（示例）

每个 issue 最小结构：

| 属性 | 合同 |
| --- | --- |
| issueId | 稳定键，例如 proposalId:runId:ruleId:targetId:sourceVersion |
| ruleId, resultCode | Rxxx 和八类之一；不可使用自创“已通过行政审批” |
| target | assemblyId/proposalId/proposerId/cosignerId，可指向确切一人或一份提案 |
| materialRefs | 每条引用 Mxxx、materialId、owner、sourceVersion、sha256；可多份但不合并无关规则 |
| sourceRefs | SRC-xxx + 条款 + 有效性判定；校本配置文件另附版本 |
| observation | 具体事实和冲突两端；OCR结果只能注明“推测” |
| action, nextActor | 补材料/人工核对身份/配置本届通知/委员会裁量/权益部门转办等 |
| evidenceSnapshot | planId、fingerprint、Check×target/sourceVersion、entryRunId、生成时间；旧 Run 不能冒充新 Run |
| terminalDecisionRef | 若业务已作正式决定，只引用后端验证的 decisionId、actor及版本，不允许 Renderer 填写 |

例：R006 的联名人乙仅在 M006-v2 签名与 M002-v4 名册冲突时，报告目标 cosignerId=乙 和两个版本；不能写“整份提案全部未通过”。另一个问题 R013 的政策版本未知，单独给委员会配置待办。前端按材料/方案/运行/问题定位、保留 Case 一套状态。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 事件合同

| 事件 | 可信发出方与必要 payload | 后续动作 |
| --- | --- | --- |
| ProposalDrafted | 登录代表；proposalId、assemblyId、草稿版本 | 记录但不触发正式立案 |
| ProposalSubmitted | 认证代表/正式递交渠道；submitAt、sourceVersion、签收编号 | 建立不可变 submission snapshot，运行 R001–R016 |
| MaterialClassified/Updated | 提案人；slot=Mxxx、target、old/newVersion、checksum | 仅失效依赖同槽同 target/sourceVersion 的规则和下游决策前置视图 |
| MissingMaterialRequested | 有权受理人员；issueId、截止日（若当届规则证实） | 提案人补件；未配置期限不得硬停案 |
| CommitteeDecisionSigned | 提案工作委员会可信 actor；决定、理由、原件/签名、适用规则版本、proposalVersion | 改变 FILED/NOT_FILED/RETURNED；不可由模型或前端生成 |
| ProposalTransferred | 权益机构；决定ref、部门、接收回执 | 更新转办状态，不重判立案 |
| DepartmentReplied / FeedbackDelivered | 承办部门/权益机构；办理意见、代表送达凭证 | 记录办复事实，具体政策办理不由本模板替代 |
| WithdrawalRequested / WithdrawalDecided | 提案人请求；委员会依权限决定 | 仅签发决定后转 WITHDRAWN；已转办须通知涉及部门 |
| ProcedureReviewRequested / ProcedureReviewDecided | 提案人提出原决定及争点；校本授权复核者答复 | 新 decisionId/version 链接被复核决定，不直接覆盖旧决定 |
| ProposalReported | 本届/下届提案委员会；报告范围与案卷索引 | 汇总经核实立案、反馈情况，不能泄露敏感原件 |

**定向重审**：依赖映射 ruleDeps 如 M006→R006/R015，M004→R001/R007/R008/R009/R010/R011/R012/R013/R014/R015，M002→R003/R004/R005/R006/R016/R021。新 M004-v3 只重算受影响 R，保留 R020 等历史签发事实但如关联失效则生成“需人工确认决定是否修订”待办。冻结 V3 D2 Plan（planId+fingerprint+Check×target/sourceVersion）；所有持久写由可信 Main/后端拥有；批量运行 finalizer 绑定 entryRunId。正式决定失效/撤销由有权人出新签发事件，不靠模型删除旧决定。

### 11.2 撤回与复核边界

- 全国规范明确提案提出与办理主体，但**未给出成都理工具体撤回流程、复核时限、哪级有权受理**。本模板只设计申请、校验和决定事件；权限与窗口标 POLICY_UNCONFIRMED。
- 在立案前撤回不等于删除已提交日志。立案后有移交义务及其他涉及主体，是否可直接撤销立案需要本届有权委员会决定，并向权益部门传达。
- 对“不予立案”的程序性异议不等于一般行政复议或纪律处分申诉，也不自动打开校外司法程序；无证实复核渠道时提出人工协商/校内信访权益途径的路由建议。
- 每次补件、撤回、复核均附原案编号、被针对的决定/版本及原因；禁止多个并发请求覆盖同一个 CurrentCase。审核结果先验证，再提交有权 Decision/Outbox。

| 待配置参数 | 当前证据状况 | 要求的签发人/材料 | 未确认时系统行为 |
| --- | --- | --- | --- |
| assembly_id、层级、学代/研代会组织关系 | 学校历届新闻可见，当前公告缺 | 本届筹备组正式公告 | POLICY_UNCONFIRMED |

| 提案不立案细化理由与说明形式 | 上位第35条有四类，不含细分清单 | 提案工作委员会当届程序 | R011–R013 给风险提示，NEEDS_HUMAN_DECISION |
| 校本职责/部门分工和跨部门牵头 | 2026研究生提案交流会显示多部门参与，不等于固化分工 | 学校主管部门权责清单 | 不能自动决定承办部门 |

| 不予立案/办复异议复核及申诉渠道 | 未见具体成理程序 | 有权部门签发的渠道与期限 | POLICY_UNCONFIRMED，人工转介 |

**禁止自动批准**：模型无权生成正式代表资格、立案号、委员会决定、撤回同意、复核结果、具体部门资源/经费/场地许可。政策矛盾与普通建议分流由有权人复核；证据不足也不得随意替学校断言“提案不成立”。新收到校本有效文本后，按 SRC/F/M/R 双向编号修订提案，继续保留旧证据快照。

| E18 部门已回复但问题未解决 | 学校部门说明经费暂不能落实，权益机构已向代表送达 | R020 PASS_FACT仅代表“回复与送达可核”，不代表建议落实成功；后续报告如实体现 |

这些场景专门检验：分流不剥夺普通诉求权、证据独立而非整案一票否决、当前阶段不索要未来决定、立案不替代具体行政许可。
