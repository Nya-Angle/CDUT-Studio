## 01 唯一审核目的、申请人和负责机构

### 01.1 唯一审核目的与决定对象

**决定对象固定为某一具体建设、申报、认证或评估批次的“拟提交材料包之事实及程序前置条件是否具备”的校内预审意见。** 不在模板内对专业设置作最终批准，不授予硕博学位点资格，不公布工程教育认证结果，不给学科评估评级，不替学校签发推荐意见。

核验核心为六类：

1. **对象是否确定**：专业/学科名称及代码、学历层次/学位类型、申报或评估类别、批次与指标版次，能否与该批次权威目录、通知、学校基础数据一致。院系自报名称不是授权存在的证明（SRC-001、002、014）。
2. **发起主体是否匹配**：申报实务通常由院系、专业负责人、学科建设团队准备，是否具有该批次校内组织或受托报送资格，要见学校实际任务分工/授权记录；教师个人不得因上传文件自动被视为学校法定对外申报主体。2026 测绘工程认证由学院统筹、系与科室协作的事实见 SRC-005；2024 “双一流”填报涉及建设单位及职能部门见 SRC-006。
3. **证据是否可追溯**：指标数值及定性陈述至少有指标口径、统计期间、院系/职能部门数据来源、原始证明/发布编号、来源责任人、导出或确认时间、版本与适用对象。2022 校本方案曾明确学院建立支撑材料库，见 SRC-003 第 6–7 页；学科评估框架强调证明核查及学科归属分析，见 SRC-010。
4. **前置程序是否形成证据**：例如院系自评和材料准备、职能部门核验、校内专家论证及会议审定等，以本批次通知及带可信身份的正式记录为准。2024 专项申报曾进行专家论证（SRC-007）；不得由该个案推断所有批次都要求同一会次、相同审批人。
5. **外部决定不得越权归因**：拟申报、校内同意报送、网上系统提交、受理、外部专家评价、批准备案、评估结论各自独立；证明其一不得写成已经发生其二。2025 年学位点资格审核办法将相应授权审批主体规定为国务院学位委员会（SRC-014），与一般学科建设/评估事实预审不是同一种权力。
6. **本科专业设置上位前置程序**：针对拟新增本科专业，2024 教育部原文要求调研论证、党委会或校长办公会审议及学校官网至少五个工作日公示；针对撤销专业，要求校内征求意见和公示并按程序备案（SRC-024 第五、八项）。这些是应核对的真实程序**事实**，非本系统有权批准的事项，也不得扩成学科评估的统一会签链。

### 01.3 申请人、代理人及代理限制

- **组织主体**：学校或校内经授权的申报单位；特定批次的正式对外申请主体待通知核实。个人教师可能是专业负责人、材料编辑或联系人，不能将其姓名当作申报单位。
- **实际操作人**：院系材料填报人员、科室核验人员、校级汇总/报送人员；角色来自可信学校身份服务或有权管理员赋权记录，不接受 Renderer/附件中自称的 `teacher`、`admin`、`approver`。
- **跨单位申报**：同一成果或指标由多个院系共同形成，必须标明源单位、归属分配及核验责任，冲突时仅输出待复核，不凭模型选择归属。

### 03.2 同一模板的办理情形矩阵

**主申请主体始终是学校或按当批授权的校内单位；教师、院系秘书、专业负责人、填报员均是可能的经办人，不是独立的对外申报权主体。** 学段栏的“本科”指专业对象层次而非学生个人申请；学科及“双一流”由学校/建设单位组织，不按学生学籍身份分支。每个场景可按 A→G 走到其适用节点；“未知”是须取得当批文件的真实阻断条件，**不是默认允许**。

### 03.4 证据先后与风险示例

1. 2026 测绘工程专业认证推进会仅证明自评报告分工正在推进（SRC-005），不能证明已完成认证。
2. 2024 “双一流”填报启动会仅证明已对当年度指标、人员及数据任务进行部署（SRC-006），不能把校内数据确认视为外部建设成效认定。
3. 2025 拟设/撤专业公示第三方转载含“学院申报—专家评议—教务专题—学校会议—公示”等描述，但校站原文未直读，**不能据此锁定 CDUT 会议顺序**（SRC-011/012）。然而 2024 教育部通知已明确**新设**专业校级审议、公示最低时长，须在相应阶段核实其正式凭证（SRC-024）。
4. 2025 学位授予资格审核办法具有独立行政授权决定对象；不得把“学科建设申报材料完整”映射为“取得学位授予资格”（SRC-014）。
5. 中国工程教育专业认证协会将**申请受理、自评、报告审阅、现场考查、结论、状态保持**分列为不同步骤；其《2025年状态保持 Q&A》特别说明年度报备复用已有原始归档材料，第三年另有中期报告（SRC-018–020）。院系阶段性完成不等于本轮程序自动完成。

## 05 角色、权限与可信数据边界

### 05.1 角色分层及最小权限（设计原则，待校方身份体系确认）

| 层 | 可做 | 不可凭何者推断 |
| --- | --- | --- |
| 材料提交/编辑人 | 上传、重传、说明、请求撤回和补件 | 上传文件署名、输入框 `actor`、Renderer 传入身份 |
| 院系材料负责人 | 对本院字段/来源提交确认、纠正归属、退回修改 | 个人自称“系主任”或章图片 OCR |
| 职能部门核验人 | 复核其业务领域的权威数据及口径，给出有凭证意见 | 对其他部门来源数据的单方盖章 |
| 校级申报审批人/有权会议 | 按批次文件形成报送决定并确定正式版本 | 系统的事实核验 `PASS_FACT` 或聊天式指令 |
| 外部有权机关/评估组织 | 受理、正式批准备案、认证评估及复核结果 | 内部工作台的“通过”“提交成功”文字 |
| 系统审核引擎 | 事实对照、缺件/冲突定位、提醒人工判断 | 自动执行校内会议表决、行政审批或学位授予资格决定 |

### 05.2 可信数据来源与签批规则

1. **身份**：正式审批动作必须关联学校可信身份认证的主体 ID、岗位/职务的**当时有效**授权和会话审计记录。Renderer 或材料 JSON 的角色字段只作为待核对声明；代理提交还应记录授权来源、代理范围、时限和委托主体。
2. **申请对象**：专业或学科代码要绑定本批次权威目录快照；跨年更新使用新版本而不回写历史，停办、撤销、调整必须对应当期正式文件。行业认证标准、第五轮学科评估指标及学位授权资格标准不能混用。
3. **证据链**：每一事实应记录来源系统/原始文件、院系、统计区间、单位、提取人/确认人、校内主数据版本、文档页码/表格定位、原始文件校验标识、首次/最近校核时间。两部门数值冲突只标 `CONFLICT` 并转责任单位，不能用 AI 选择“更合理”的数。
4. **材料与决定**：所有签批、印章、会议纪要、部门意见和外部批件应为来源明确的权威记录，验章/验签不等于授权合法性审定。AI 从扫描件识别出“同意”二字不得生成真实决定。
5. **版本隔离**：保存拟申报包 `draft_revision`、院系确认版本、校级审定版本、对外提交版本及外部受理版本；任何修改已提交项应触发受影响项重新核验，并判断是否需重新签批（校本权限待核）。
6. **最小数据使用**：人员、学生、科研成果以及敏感学科信息，优先用权威系统提供的最小证明或统计聚合；涉密/不宜公开材料与公开评估材料分开，读取权限、脱敏口径和可对外报送范围交学校人工审核。

### 05.3 输出边界

事实核验通过只能写 `PASS_FACT`；不适用写 `NOT_APPLICABLE`；缺证据写 `NEEDS_MATERIAL`，冲突写 `CONFLICT`，无法读取写 `UNREADABLE`，权威源失联写 `SOURCE_UNAVAILABLE`，现行政策不明写 `POLICY_UNCONFIRMED`，需要裁量、确认资格或签批写 `NEEDS_HUMAN_DECISION`。不得出现“学校审核已通过”“已获备案/认证/学位授权”之类未经权威决定证明的结论。

### 05.4 第二轮责任与授权核验契约（设计候选，未经校方接线确认）

| 动作/字段 | 产生者 | 至少核验的可信凭证 | 系统仅可办理 |
| --- | --- | --- | --- |
| 新建批次 `F002–F004` | 校内归口经办人 | 当期签发通知/官网发布号；学校实际授权的批次管理员；通知版本哈希 | 登记和检查版本；批次政策缺失则 `POLICY_UNCONFIRMED` |
| 院系代拟与源数据 `F006–F008、F021–F028` | 学院/专业、数据拥有部门 | 学校可信主体标识、部门任职、委托有效期；每个指标原系统记录号/签发人 | 实体对象相同与否、材料可读及矛盾提示 |
| 院系/部门确认 `F032、F033` | 原始责任单位各自授权人员 | 可信机构角色、当时有效授权、针对固定 `F029–F030` 的电子/纸质原始确认 | 确认存在、对应版本与签发资格待复核；不得替代签发 |
| 专家结论 `F034` | 该批次依法/依校规组织的专家组 | 委任或会议名单、回避、纪要、签发版本 | 记录专家意见“有/无/未知”，绝不生成专家意见 |

| 外部受理及结论 `F037、F038` | 教育主管机构/评估认证机构 | 机关公示或官方平台通知的真实编号、原始来源与对象代码 | 查询/录入可溯证据；不得模拟外部回执或评价 |

可信来源优先级：**当批发布机关政策与学校正式授权记录**→**归口机关/校级业务主数据或可验证源记录**→**校内授权人员对固定版本作的正式确认**→**院系带责任声明的上传原件**→**OCR/文件名/人工输入待核声明**。优先级不意味着高一级可擅自修改数据归属；遇同等级可信资料相互矛盾，均保留并进入 `CONFLICT`。学校 SSO、教务和学科系统接口**未实证**，接入之前只能要求获取可核验的官方证明或人工复核，绝不声称自动调用成功。

同一人既是教师又担任学院负责人时，仅其**当前受权职务及本次动作权限**有效；身份实名、岗位属地、对象所属院系三项均应绑定。同名同姓不得仅靠姓名合并，学生名单和教师成果应使用源系统稳定 ID/已脱敏映射，不在 AI 日志留明文身份证。已撤职、离岗或代理过期不应继续批准。签章 OCR 检出的校名属于待核文本，不是验签结果。

## 06 业务对象与字段字典

### 06.1 对象模型和字段通则

只设计**业务语义**，不假设 V3 客户端 API 或学校业务接口已实现。对象链：`ReviewCase`（一个事项/批次/目标）→`BatchPolicy`（通知、指标版本）→`Target`（专业/学科/专项）→`ActorGrant`（可信身份/代理）→`IndicatorClaim`（口径、时间、数值、归属）→`EvidenceItem`（M 材料、文件定位、哈希）→`InternalDecision/ExternalRecord`（只读权威决定、与报送版绑定）→`RevisionAction`（补件/撤回/复核）。多指标重复为数组明细，多个文件不挤进一个“万能附件”。

隐私标记：`P0` 已公开业务信息；`P1` 校内工作信息；`P2` 带身份的受限单位/个人数据；`P3` 学生学业明细、未公开科研/财务或涉敏评估数据，仅授权最小可见且禁止无依据外发。`证据位置`采用 `SRC / M / 源系统路径或文号 / 页码、单元格、字段路径 / 内容哈希`，不要求存在特定集成接口。`首需` 中 A–G 与 03 节同义；“条件”需满足触发且有当批政策，A 启动不自动要求 B、E、F 的未来文书。

## 07 材料槽与证据目的

### 07.1 槽位语义

- `当前必需` 指**进入该槽标明的阶段且适用该业务情形**时的最小事实资料要求；不是所有案件初始 A 阶段必传。`条件必需` 还须当批通知或具体条件触发；`后续产生` 只能在相应决定真实发生以后读取，不作为前序缺件。
- `学校/官方可直接提供` 的权威目录、通知、校级报送回执，优先**引用原系统、网站或权责部门现有证明**，不假设接口已经存在，也不无理由让院系重传。可信接口缺失时留凭证索引并请求归口代核，标明 `SOURCE_UNAVAILABLE`/待人工；不得反向把源系统故障算成院系漏件。
- 每个文件必须绑定 `case + target + batch + stage + F029 revision + F030 hash + owner_unit`，多指标文件逐个给页/表格定位；合法替代只包括**同一签发权、同一业务对象、同等证明力**的权威电子记录/盖章原件或校内被确认的既存档案。OCR 截图、自写解释与未验签扫描章不等效。

## 08 审核规则逐条清单

### 08.1 规则执行和证据层级公共契约

本节 `R001–R043` 是**研究性可审查规则**，不是经成都理工大学正式批准或已在 V3 客户端接线的计算机代码。每个 R 只核对一个独立事实对象或同一事实的必要阶段条件；**不计算专业评审得分、学科排名、项目立项批准或外部认证结论**。没有校本当期原件的资格阈值只给事实比对建议并转人工；正式可执行前，须按批次冻结 `F002/F003/F015/F018` 的政策版本和每条规则的来源。

**统一三值触发解释**：以下“真”指案件处于所列业务类型、阶段和条件，才实际执行该 R；“假”指可证明该条件不成立，本规则为 `NOT_APPLICABLE`（并非业务事实不符合）；“未知”先核 SRC/正式批次，输出 `POLICY_UNCONFIRMED`，若仅可信来源暂不可访问则 `SOURCE_UNAVAILABLE`。触发真后，比较**吻合且证据充分**才为 `PASS_FACT`；实际两个有效证据不一致为 `CONFLICT`；本阶段本应存在的申请方材料缺失为 `NEEDS_MATERIAL`；已有文件无法解析为 `UNREADABLE`；需要专家或权责决定而证据非客观比较可得时为 `NEEDS_HUMAN_DECISION`。按 10 节“一次核验对象恰好一个结果码”输出多条独立结果，不强行折叠为一条“通过”。

**证据层级**：`L0` 当批有权发布机关原始通知、正式授权/决定或官方签发状态；`L1` 学校/主管部门可验证的主数据、带编号原始业务台账；`L2` 当前有效授权者对固定对象和哈希签发的意见；`L3` 责任人上传的可信来源材料；`L4` OCR、姓名显示文字、自由输入或模型推断。`L4` 只能定位线索，不可代 L0–L2 形成身份/行政决定。多份 L0/L1 冲突也不能自动“谁更新谁赢”，须保留时间、版本与各自权责范围。现行性判断按 **发布机关+有效批次+修订/废止+目标类型** 四维比较，不按搜索排序。

### 09.2 冲突归因、证据层与重审传播

1. **同人不同身份**：`F007` 为校内可信用户稳定 ID，姓名是显示标签；教师甲上传带“副院长签名”的 `M025` 扫描页，若 `M002` 无该时点受权身份，不得将其与真正受权副院长合并。此时上传事实可收，批准动作 `NEEDS_HUMAN_DECISION`。
2. **跨部门同指标不一致**：学院在 `M004` 写“专任教师 60 人”，人事源 `M006` 同统计期为 58 人，或两边统计期/单位不同：先比较 `F020、F021–F024`；源记录均保留、问题定位具体表格页格，`CONFLICT` 转人事和建设归口，禁止取平均或以文件更新时间排优先级。
3. **复用成果与归属冲突**：一篇论文或一个项目同时进入两个学科，`F022` 原成果唯一号、`F025` 归属范围必须对齐；缺双方正式共享许可 `M008` 时不默认各算一份，也不让本模板重新认定论文等级/项目立项，引用科研业务权威结论。
4. **名称与代码跨年漂移**：2025 公示“拟新设专业”与 2026 目录的真实备案状态不同，保留 `F011` 代码、`F014` 正式状态及变更文件。没有当年权威专业目录的别名变更，字符串同名也只标冲突，不自动认定同一批准对象。
5. **旧指标/标准误套**：把 SRC-010 第五轮学科评估指标用于未知新轮、把 SRC-016 2024 工程认证标准强加给被允许采用 2022 版的过渡期案件、把 SRC-020 2025 报备截止误作 2026 年度截止，均输出 `POLICY_UNCONFIRMED`，不视申请人迟报。
6. **报送和签批版本错配**：院系材料 `rev-4` 由学校 `M025` 针对哈希 `H4` 同意报送，后把数值换成 `rev-5/H5` 而沿用旧“同意”页；即使新文件齐全，`F029/F030/F035/F036` 不一致，必须转原签发权主体确认是否重签，旧结论不能自动迁移。
7. **材料不可读与来源失联不同**：上传 `M018` PDF 损坏是 `UNREADABLE`；学科管理部门官方查询平台宕机导致取不到 `M003` 则是 `SOURCE_UNAVAILABLE`；仅有过期 2020 指标导致现行要求未知则是 `POLICY_UNCONFIRMED`，三者不互相覆盖。
8. **工程认证改进材料过度索取**：专业已认证但仅处有效期第 1 年，若请求 `M017` 第三年报告、强要 `M016` 年度总结和全体学生试卷扫描，属于**不适用/过度收集**而非缺件；按 SRC-019 引用已有原始材料和归档索引。
9. **建设专项与经费支付错权**：`M021` 学科建设论证被评审接受只说明材料或建设项目进入后继环节；预算调整、采购或财务实际付款应引用对应 T03/T04/财务系统的权威结论，不能在本模板生成“经费可支付”。

### 09.3 版本与旧结论失效规则（设计候选）

- `evidence v1` 原件哈希→`claim v1` 指标数值/归属→`review_run v1` 事实预审→`unit_ack v1` / `school_decision v1`（如确实发生）→`submission v1`（如确实发生）。这些记录各自**单独拥有生效主体**；系统不得把审批机关的原决定物理删除。
- 当 `M006` 数值、`M008` 归属、`M007` 指标版本或 `M013` 报告被替换：保留旧文件与结论的历史快照，以 `F039` 指明替换前后哈希；只标记**依赖该数据的自动事实核验**为 `STALE_NEEDS_RECHECK`（内部中间语义，正式对用户输出 `NEEDS_HUMAN_DECISION` 或相应证据状态）。无关指标不因一处改动被全面无效化。
- 如改动落在已由 `M022/023` 确认或 `M025` 审定的包内，标为“**原确认仅对旧版有效，是否需新签由原签发机关决定**”；已由 `M026` 对外送出，不能靠本地覆盖更改外部平台提交稿，需经正式补正/撤回/重报程序及外部回执重新关联。
- 对历史旧 `run@rev` 只可作旧视图/旧事实，不得在 V3 伪装成新 `ReviewRun`。案件与版本建立单一权威链，外部决定和院系证明的“写权”绝不转交审核 Renderer。

## 10 结果状态、问题与待办输出契约

### 10.1 一项事实核验恰好一个结果码

| 唯一结果码 | 精确定义与最低证据 | 不可误用为 | 默认责任/下一动作 |
| --- | --- | --- | --- |
| `PASS_FACT` | **此项 R 的适用性及客观事实**由可核对来源确认，并与相同对象、期间、文件版本一致；附 SRC/F/M 与页格/记录号 | 整个案卷“合格”、学校同意申报、认证通过、学科已获评级 | 将事实结果呈送本案归口核验人，仍可需要其他未完成 R |
| `NOT_APPLICABLE` | 有权通知或可核场景显示该 R 的触发条件确认为**假**（含尚未进入未来阶段），写明不适用的证据/条件 | 缺材料、无证据或政策不明 | 该项不产生补件，保留触发依据；进入后继阶段重新判断 |
| `NEEDS_MATERIAL` | 触发真、该阶段已明确应由提交责任人提供的材料未取得，且非系统来源故障 | 学校源系统不可访问、未来阶段批件尚未出现 | 发给该院系/材料持有人：指定 `M`、所属主张、可用替代与截止依据 |
| `CONFLICT` | 至少两份可追溯证据对**同一对象、期间、口径或签发版本**给出不一致事实；保留双方指针 | 模型不赞同专家评价、政策时效未知或 OCR 不可读 | 发给双方源部门/学科归口，要求正式归属与版本核对 |
| `UNREADABLE` | 材料实体已存在，但文件损坏、授权格式不可解析、OCR 不足以确定被引用页格 | 材料未上传或所主张事实为假 | 给材料持有人/读取组件支持人定位页码、文件 hash，重传可读版 |
| `SOURCE_UNAVAILABLE` | 政策/事实权威源链接中断、无权限/接口、当下不能获取原记录；保留失败查询时间、来源名 | 院系材料漏交；也不能凭无法获取推断“未批准” | 归口或数据源管理员提供授权查询/同等证明，必要时人工取证 |
| `POLICY_UNCONFIRMED` | 缺乏**当前有效且适用于该批次**的原始通知/指标/授权阈值，只有历史版、外校制度、二次转载或相冲规定 | 数值或资格不符合；不是允许继续自动审批 | 归口政策核验人冻结硬条件，补齐当批原文和有效期 |
| `NEEDS_HUMAN_DECISION` | 事实或来源已展示，但授权真伪、专家裁量、是否认可撤回/重签/申诉、是否对外发布等**必须由有权人决定** | 模型已代理完成人工审批；不应被渲染成“通过” | 精确派给有权校内签发者、原受理机关或外部机构，记录正式决定来源 |

这些码是每个原子 `check_instance` 的**互斥值**，不是全案只允许一个问题。若同一材料既损坏又版本不一致，拆成“可读性”和“版本对应”两个独立 R 实例分别标 `UNREADABLE` 与 `CONFLICT`，绝不悄悄取一个“最严重”总码。`NOT_APPLICABLE` 必须是**有证据的触发条件为假**；未知触发不能写 NA。`PASS_FACT` 只证明对应事实，不能在总页转换成“学校已批准”。

### 10.3 案卷汇总与“准备报送”边界

- 按当前阶段和本轮合法适用的 R 实例计数 `PASS_FACT / NA / pending`，不可简单算通过率作为行政结论。`ready_for_human_review` 只表示**已可提交有权人审阅的事实资料集合**；即使全部 R 为 PASS/NA，也必须显示 `school_decision=NOT_ISSUED` 直到 `M025` 真正产生。
- 当年政策未知却结构字段吻合，可并存 R010 对数据一致性的 `PASS_FACT` 和 R001/R007 的 `POLICY_UNCONFIRMED`。总状态必须显式显示“本批政策未核/不可自动判断资格”，不得使用绿色“已批准”。
- 真实外部 `M027` 或 `M032` 只以 `external_record=VERIFIED_SOURCE` 展示其来源与内容；系统自身不生成审批批准、认证结果或学科等级。
- 结果保留 `check_instance` 的读版本依赖；新版本的旧事实结果只能作为历史记录，不作为新提交材料的有效通过证明。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 办理状态与信任前置条件（业务合同，非现有客户端实现声明）

| 状态 | 可触发的真实事件 | 有权操作/来源 | 可再进入的状态及边界 |
| --- | --- | --- | --- |
| `DRAFT` 院系草稿 | 批次/对象建立，M004 起草；当前批次政策可能未核 | 经可信校方身份/委托的材料操作人，不能对外报送 | `FACT_REVIEW` 或 `WITHDRAWAL_PENDING`；此阶段的事实 PASS 仅针对草稿 |

### 11.2 补件、材料替换与定向重新核验

1. **发起**：每次补件必须指向 `findingId + ruleId + M + target + oldHash + requestedChange`，确认是本阶段**确有需要**的材料；因官方系统失联先转 `SOURCE_UNAVAILABLE` 而非要求申请人再扫所有档案。
2. **接收**：新材料为新 `evidenceRevision`，保留旧文件、原问题、签发时间、来源单位和 hash。`M028/F039` 指出是改文书排版、指标数值、归属、标准版本，还是授权状态；要有源持有人责任和更改原因。
3. **差异传播**：通过原版依赖索引 `M→F→R→finding` 得到 `affectedRuleIds`；例如仅 `M006` 某个 `F023` 数值变动，重核 `R009/R010` 及以该成果归属为依据的 `R011/R025/026`（按具体情形），未引用该指标的 `R003` 身份与 `R005` 代码仍保留结果。批次 M001/M007 口径改变才扩到所有依赖该政策的检查，不无理由全案重跑。
4. **失效而非删除**：旧事实 `PASS_FACT` 的适用键包含旧 `sourceVersion`；新版本不能沿用旧 PASS，给受影响项创建新 check 实例并标 `PENDING_RECHECK`（**内部调度状态，不是第九种面向用户结果码**）。旧结果保留 `supersededBy` 审计。对外展示新事实在重核前为对应的 `NEEDS_HUMAN_DECISION` 或真正证据缺口码，而不是复制旧 PASS。
5. **签批与公示依赖**：若变更影响 `M022/M023/M024/M025` 已确认版、`M026` 外部已递交版，或专业新增/撤销适用的 `M034/M035` 已公示版，执行 R014/R031/R032/R035，并按实际触发重核 R040/R041/R042；提示“须原权责机关确认是否重签、重新公示或补报”，将旧审批/公示仅保留为旧版历史。**系统绝不可自行作废或重新签发学校决定**。

### 11.4 人工决定的唯一可信落点

- 决策请求只包含**来源归属、事实预检摘要、当前政策缺口、全部反证和冻结 `evidenceRevision`**，不得写出 AI 推荐“批准”冒充会议审定。角色必须由学校实际 SSO/岗位/委托记录及**签批当时的授权**绑定，不能由附件/Renderer 声明决定。
- 有权人作决定是**外部于本事实引擎的行政行为**；当真实 `M025/M027/M032` 原件产生，系统可依 `R031/R034/R038` 检查文号、身份、对象和版本。不得用 API 返回 `200 OK`、AI 事实 PASS 或学校新闻报道生成审批结论。
- 若受权人员变动，历史签批原记录保留当时身份/权限快照；新代理不能未经委托追加旧人签名。决定如何撤销、修改或复核由原权责机关确认。

### 12.2 各来源时效与判定权限边界

1. `CDUT-VERIFIED` 对**该篇学校已发生事件**可信，不自动升级为常设现行规章：SRC-005/015 为 2026 院系认证筹备，不能推导学校已获认证；SRC-006/007 是 2024 监测/论证实例。
