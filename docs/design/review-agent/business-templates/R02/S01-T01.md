## 01 唯一审核目的、申请人和负责机构

### 1.1 事项存在性、决定对象

**事项真实存在。** 《成都理工大学全日制普通本科学生学籍管理办法》专列“休学与复学”；《成都理工大学研究生学籍管理办法》专列同名章节；教务处还公开“申请休学（保留学籍）办理流程”。这证明有校内业务，并**不证明存在单一线上审批入口**。[SRC-001、SRC-002、SRC-005]

本 ID 唯一决定对象为：**某已注册、可由适用校本规定覆盖的在籍学生，所申请或被校方要求办理的某一次休学**。事实预审围绕：

- 申请人及**权威学籍**（在籍/休学中/已退学/尚未取得学籍等），学段、培养形式、外国国籍/中外合作办学等适用规则选择；
- 所述事由（病伤、出国出境或学习、创业、其他确需休学等）及能证实该事由的材料；
- 病伤停课治疗/休养的预计时长、**本学期请假累计时长**等需按归口规则核对的事实；
- 申请日期、学期开学日期、过往休学批准次数/期限、拟休学时段、最长修业期限剩余量；
- 申请阶段已有的学校表单、证据、核验意见与冲突项，输出给有权机关裁量。

“休学资格与材料预审通过”只表明可继续流转。正式休学批准、学籍状态变更、后续退宿及资助调整属于学校权威办理/执行，不得在模板输出中自行生效。[SRC-004 §25、§28]

### 1.2 申请人与授权边界

- **普通全日制本科在籍学生**：适用成理校教〔2019〕18 号第 2、38–42 条；该办法说中外合作办学等类别“参照执行”，但后续另有专门规定时应优先核其现行适用关系。[SRC-001、SRC-014]
- **按国家招生政策录取的全日制或非全日制研究生**：成理校研〔2021〕13 号第 2 条覆盖两者；同一模板使用研究生情形分支，不推定所有研究生与本科审批一致。[SRC-002]
- **持外国护照且在校注册接受高等学历教育的来华留学本科生、研究生**：成理校发〔2022〕26 号第 3 条设专门规定；来华留学本科有专章休学条款，来华留学研究生与一般研究生政策的优先关系须复核。[SRC-003]
- **港澳台侨学生、非学历留学生、中外合作办学、联合/双学位、成人教育等**：不能仅由“学生”二字直接套用普通本科阈值。港澳台侨与非学历留学生在 SRC-003 §3、§71 存在“参照”线索，其他项目适用仍待对应制度及归口人员确认。
- **代理人**：查得的休学校本规则与 2018 公开指南均未明确代理提交的授权形式、核验和代理权限。不得自行假定家长、辅导员、导师可代表学生同意或撤回；代理业务先标待确认。

### 1.3 责任机构与正式批准

| 情形 | 已有校方原文可证明的角色 | 不得推断的权限 |
|---|---|---|
| 普通本科 | 2018 公开办理指南称**学院办公室**为承办单位，学生到所在学院办公室办理；2019 学籍办法明确学生向学院申请**复学**，学院审查合格后报**教务处备案**；教务处负责在读学籍档案的建立维护。[SRC-005、SRC-001 §40、§57] | **本科休学的最终签批人/签批顺序未从现有条文完整确认**；学院“承办”、教务处“备案”不可冒充休学批准权限；复学程序不能倒推休学程序 |
| 研究生 | 第 23 条明确：研究生申请或学校认为应休学，由**党委研究生工作部、研究生院批准**；培养单位承担学籍档案建立维护，第 42 条。[SRC-002] | 不把导师、研究生秘书、培养单位经办人与最终批准人混同；第 31 条“退学”审批链不挪作“休学”审批链 |
| 来华留学本科生 | 国际交流与合作处承担留学生管理职责；第 37 条写休学期满**复学**由学院审查、报国际交流与合作处备案。[SRC-003] | 第 35–38 条不能独立确定**休学初次批准**的完整授权签批链；不得挪用复学备案身份 |
| 涉及资助、住宿、财务 | 休学批准之后，财务处线下学籍异动办理线索需休学通知单/证明；研究生国家助学金变动以培养单位报告并经党委研究生工作部、研究生院确认的学籍异动为前提。[SRC-009、SRC-010] | 财务和资助机构并非本 ID 学籍休学批准者；暂停/恢复发放不属于休学申请的先决材料 |

**上位法**：教育部令第 41 号第 25 条明确申请休学或学校认为应休学的须经学校批准；具体次数和期限交由学校规定。不得用 AI 判断取代该批准。[SRC-004]

## 02 适用、排除与邻接模板路由

### 2.1 本 ID 包含

1. 学生**主动申请休学**：病伤、创业、出国出境/出国学习及其他原因；但“家庭困难”是否构成学校可受理的其他原因，不预设为当然资格。[SRC-001 §38；SRC-002 §21]
2. 学校认为**应当/必须休学**所需事实核验：有权部门提出的触发事项、病伤医疗事实、请假累计天数或教学秩序风险。模板提供材料清单与待核证据，不自行发出强制处理决定。[SRC-001 §41；SRC-002 §22]
3. 同一次或再次休学的政策版本、期限累计及学籍权威记录核验；创业特例按研究生规则单独记录，不能扩展到所有学段。[SRC-001 §38；SRC-002 §23–24]
4. 申请补充材料、撤回意向、改期申请、复核或申诉意向的**过程信息**；它们是同一案件的后续节点，不将复学、退学、保留学籍本身伪装为休学批准。

### 2.2 明确排除、只取权威结果

| 邻接事项 | 本 ID 的处理 | 对照依据/冲突处理 |
|---|---|---|
| 新生保留**入学资格** | 排除；需要“取得学籍”的可信证明才能进入休学。新生复查期间不宜在校学习，可能走保留入学资格。 | [SRC-001 §5–6；SRC-002 §5–6；SRC-004 §10–11] |
| 入伍或学校组织跨校联合培养而**保留学籍** | 路由至适用的保留学籍事项（具体 R02 编号待总账核实）。因同一旧表把两者放在一起，须读取“申请类型”而非以表名当休学。 | [SRC-001 §39；SRC-002 §25；SRC-004 §27；SRC-005] |
| 短期请假、续假、销假 | 只读取已批准请假及累计天数；不是休学申请本身。达到条款所列条件时提示**转休学核办**，不是自动改变状态。 | [SRC-001 §20–21、§41；SRC-002 §13、§22] |
| 复学（含康复审查）、退学、最长修业年限延长、结业后换证 | 只引用既有权威决定及累计期限，后续的复学、退学另由独立授权流程处置；延长修业年限和结业后换证不在本 ID 决定范围。 | [SRC-001 §8–9、§40、§44–45、§60；SRC-002 §19–20、§28、§30–35] |

| 申诉处理及复核实体决定 | 本 ID 收集申诉/复核意向和原决定引用，不冒充学校学生申诉处理委员会；特别注意不同年份校本申诉制度的引用冲突。 | [SRC-001 §59；SRC-002 §44；SRC-003 §70] |

**G50 与 R02 实际目录核对**：本轮已从持久整合包读取 `ST-CANDIDATE-MASTER-CATALOG-R02.md` 和 `ST-CATALOG-AUDIT-R02.md`。相邻事项准确为：`S01-T02` 学生复学及退役复学；`S01-T03` 保留入学资格、保留学籍及应征入伍保留资格；`S01-T06` 本人申请退学；`S01-T08` 提前毕业、延期毕业及修业年限调整；`S04` 请假业务；`S07-T08` 结业后达标换证。`S04-T06` 仅为纪律处分申诉，不得冒充休学处理申诉。G50 `g01-student-identity-correction` 只消费真实身份更正结果。编号按 R02 正式名称列而非旧目录映射列；所有邻项只消费已签署、带来源版本的权威决定，不重复批准同一事项。[SRC-011]

### 2.3 冲突优先级（待归口确认）

1. 国家现行有效规定是合法性边界，具体学段规则依学校当期有效文件；如果不同文件“参照执行”、专门规定或修订关系不明，先输出 `POLICY_UNCONFIRMED`，请求教务处、研究生院或国际交流与合作处确认。
2. **请假批准单**不等于**休学批准单**；**医疗诊断**不等于**学校认为必须休学的正式认定**；**申请材料齐全**不等于**决定成立**。
3. 2017 年本科旧试行办法已被 2019 文件明文废止，不能因学院于 2023 年重复发布“试行”标题就把旧规则当作更新版本。[SRC-001 §60；SRC-013]

## 03 业务生命周期与办理情形矩阵

### 3.1 阶段和证据先后

| 阶段 | 触发与业务动作 | 本阶段可要求的已有证据 | 不可提前强求 |
|---|---|---|---|
| L0 路由识别 | 识别在籍状态、学段、培养形式、适用校本规定及申请类型 | 权威学籍/招生类别快照、申请意向、申请人身份核对结果 | 休学批准、学校已更新的状态 |
| L1 申请成案 | 本人提出或校方发起必须休学核办；记录事由、拟起止时间与申请时点 | 申请表/书面申请（现用版本待核）、申请事由说明、现阶段已有支持材料 | 学籍异动通知单、离校证明、复学证明 |
| L2 事实与材料核验 | 核对医院证明、请假累计记录、创业或外出计划、期限、历史休学 | 已提交的诊断或官方/学校权威记录，来源和时间戳；读取上一轮批准状态 | 假设必须有某一统一诊断模板或医院等级适用于所有原因 |
| L3 补件/冲突/人工判断 | 告知缺口；核实特殊原因、材料矛盾、政策冲突，交有权限人员处理 | 新补证据、发出/收到的意见，版本关联 | 用 AI 认可不真实的医疗证明，或自动否决特殊原因 |
| L4 有权决定 | 学校有权单位以校本授权程序批准/不批准，形成可验证决定 | L0–L3 结论、办理系统留痕、真实签批文书 | 让 Renderer 提交任意 `approverId` 充当批准 |
| L5 决定生效后 | 依已签批学籍异动办理通知、学籍状态变更、离校退宿、财务与资助转办 | **已存在**的决定文号、签章/电子签、状态变更记录 | 将 L5 文件倒填为 L1 必交项；反向把财务办结当作 L4 证据 |
| L6 到期或争议 | 复学申请、延期情形、退学程序、复核/申诉等按各自权限办理 | 原休学决定、到期日、后续申请/决定引用 | 本 ID 自动作出复学或退学决定 |

撤回、补件、申请内容改动是可返回前一阶段的事件；不得覆写旧证据。复核/申诉须引用被争议的**真实决定**；未正式决定时应区分普通材料复核与行政申诉。

### 3.3 各阶段共同约束与跨情形优先顺序

1. **先 L0 学籍与项目身份，再按 P/R/I/X 分支；多重身份不靠国籍、学院名称单字段推断。** 来华留学研究生与中外合作办学者落入 I2/X1 政策确认通道；已有明确特殊条例时不以普通本科学制兜底。[SRC-002、003、014、015]
2. **L1 必须是当前有可能存在的材料**，而不是表格最终版签批结果。申请人已认证、本人或发起机关可识别，取得学生申请/校方启动依据和现阶段事实说明；医、请假、创业等材料按条件触发。具体详见 07.3。
3. **L2 计算与 L3 裁量分离**：大于六周的比较应由有来源的“治疗休养需要时间/本学期已批准请假累计”承载，计算结果只是建议转交有权者；“特殊原因”“继续学习可能影响秩序”没有机器可判的政策枚举。[SRC-001 §41；SRC-002 §22]
4. **L4 不能逆造**：审批权、签名/章、作出时间来自受控学校决定系统或实际签署文书验核。L5 资助/退宿与 L6 复学证明必须在相应后续阶段再提供；L4 决定被复核、撤销、变更需新权威事件，历史版本不得消失。
5. **撤回路径**：L1–L3 可提交撤回请求并保留身份和时间戳；学校是否允许、如何销案未知。L4 以后用撤销/申诉/复核专门手续，不允许前端“撤回按钮”抹除有效决定。材料补件仅替换当前证据引用，保存旧版本及依赖规则失效清单。

**短期请假到休学转换**：本科第 21 条规定请假的层级与累计上限，第 41 条列“累计超过 6 周”为必须休学；研究生第 22 条亦设累计超过 6 周。阈值的表达是**超过**而非**达到**。累积数据应取正式请假记录，必要时交辅导员/培养单位确认；不能仅凭日历天数推断休学已批准。[SRC-001、SRC-002]

### 5.2 可信数据与事实判断界线

1. **学籍现状、就读层次、培养形式、历史休学次数和期间**须从学校权威学籍系统或有验证路径的正式决定读取；申请人填写、拖入的 PDF 和 Renderer 客户端状态均只能作为证据主张。
2. **Actor 可信性**由 Host/Main 后端会话认证、组织岗位授权、案件所属关系和不可篡改的真实操作日志共同证明。Preload/IPC/Renderer 只能发起请求或携带交互材料，绝不可让客户端任意提供 `teacherId`、`approverId`、`role=admin` 或签章截图而跃升为批准身份。此处是业务安全要求，**不是声称现有客户端已具备该机制**。
3. **政策配置**必须带来源 `SRC`、版本、生效范围、学生类型以及可用性状态。现行性未知时即使模型识别所有材料“齐全”，仍须输出 `POLICY_UNCONFIRMED`，不能借用另一学段阈值。
4. **医疗和家庭事实**：自动提取只产生“文件声称、证据页/字段、可信度、待核验点”；学生病伤是否要求休学、特殊家庭原因是否充分、教学秩序是否受影响均是受控的人工作业，不应给“AI 已正式认可”的措辞。
5. **决定链**：材料初核意见、学院办理记录、审批意见、学校最终决定、学籍状态生效是不同对象。必须链接决定 ID、签批 Actor、有效时间与学籍变动版本；没有决定不得反向标记“休学中”。
6. **敏感信息最小化**：只核与申请目的有关的医疗摘要、必要日期和证明出具主体，避免在普通待办中暴露诊断详情、家庭隐私或完整证件号；显示与访问权限应由正式岗位控制。
7. **信息冲突**：当申请表姓名/学号与学籍权威数据冲突，标 `CONFLICT` 并转 G01 身份更正权威流程；当请假累计与学校记录冲突，交归口人员复核；当诊断证明无法识别或来源不可用，分别标 `UNREADABLE` 或 `SOURCE_UNAVAILABLE`。

### 5.3 结果语义的先行冻结（非第 1 轮正式规则）

- `PASS_FACT`：某条证据支持的**事实核验通过**，永不等于批准休学。
- `NOT_APPLICABLE`：某条有出处的规则对当前已确认学段/情形不适用。
- `NEEDS_MATERIAL`：可明确说明的阶段性补件需求；不能要求未来批准后才会出现的凭证。
- `CONFLICT`：两份事实来源或权威状态互相矛盾。
- `UNREADABLE`：提交文件不可读取或关键字段无法辨识。
- `SOURCE_UNAVAILABLE`：权威数据或核验接口无法取到。
- `POLICY_UNCONFIRMED`：校本版本/适用身份/阈值/例外及授权关系未确认。
- `NEEDS_HUMAN_DECISION`：需学校正式权限、行政裁量、专业医学判断或申诉审理。

本轮不产生正式 `R001` 规则集；后续每条规则至少给出 `SRC`/`F`/`M` 交叉关联、条件真/假/未知三值、岗位、异常、建议状态及对人工决定的影响。

### 5.5 证据可信等级、版本和流程边界

1. **来源不等于可信**：被上传的“学校系统截图”与医院章图像，仍是附件主张；可信学籍/请假状态须经校方受控系统或由有权人员核实的原始决定确定。原始系统不可访问时是 `SOURCE_UNAVAILABLE`，而不是“学生必须截图补齐”。接口是否存在尚未核实。
2. **签发权必须按动作判断**：请假、休学批准、学籍变更、资助、宿舍、申诉为不同权限集合，签署者只能在相应决定类型、组织、学段、有效时间和案件范围内有效。`M017` 应有签批来源、决定 ID、时间、适用学段以及不可由前端伪造的校验结果。
3. **归属与版本**：所有附件需绑定 `caseId+studentKey+applicationRev+materialSlot+materialVersion+receivedAt+issuer`；旧版本不可抹除。替换 `M004` 时原诊断关联的 `F027–F029` 及其检查结果转为过期待重审；`M001` 校方状态快照过期时必须重新抓取，不由客户端固化旧状态。
4. **敏感信息**：`F027–F029/M004/M005` 是健康敏感数据，`M010` 可能含家庭困难和亲属隐私，`M015` 可能含代理身份；用途限资格材料核验，普通问题卡只写“证明有效期/出具主体待核”，不展示完整诊断、证件号或亲属材料。
5. **两种人工层次不可混写**：L2 经办核验 `M024` 是证据事实意见，L4 具有正式校本授权的 `M017` 才是有效休学决定；同一自然人在不同岗位、不同时间的操作也必须分别记录。

### 6.3 空值与可信条件的使用规则

- **空值不是零，也不是“否”**：`F023/F024/F026` 未读到校内记录时既不能写 0，也不能判断未超过 6 周。`F036–F040` 在 L1 合法为空，这是尚未到达阶段而非缺材料。
- **字段同名不代表证明力度相等**：学生写在 `M002` 的姓名仅为匹配主张；`F004` 的权威值来自 `M001`。上传的旧 `M011` 决定截图可辅助查找，却不能独立将 `F023` 写成已核实。`M002` 的“预计休学期间”不会覆盖 `M017` 批准的有效期间。
- **同一学生多个休学申请**：旧申请的 `F002/M023` 与新申请不能混用；只可在可核时以真实 `M011/M017` 作为历史决定参与累计。禁止从其他案卷直接复制医疗附件且不重核目的、归属、有效性与授权。
- **隐私默认最小化**：仅向必要归口角色展示可识别健康/家庭材料；问题输出引用 `F/M/SRC` 与页/字段，不在界面透出诊断全文或身份证号码。

## 07 材料槽与证据目的

### 7.1 M 材料槽共同规则

- 一个 M 是**证据目的槽位**，不意味着“必须由学生上传一份扫描件”。如果学校可信源已有 `M001/M006/M011–M014/M016`，应优先在授权范围内读取或请有权经办核对；**不假定 API 已存在**，来源不可达先提示工作人员核源，不能无理由要求学生重复上传。
- “当前必需”指核实该事实时**必须有可靠来源**，可以是学校系统记录，不等于已确认学校最新表单将此纸件列为必交。“条件必需”应仅在该事由、身份、代理或历史真正触发时出现；材料形式尚未由现行校本指南确定者写**形态待核**。L4/L5/L6 形成的文书均为“后续才产生”。
- 通用版本键：`(F001 caseId, F003 studentKey, F002 applicationRev, M编号, sourceId, sourceVersion/hash, issuer, receivedAt)`；权威源凭读取得到真实版本，附件凭哈希留存。每一条材料须具体标页、段/签发栏并能单独撤销效力与重审。材料已替换不删除历史。
- 下表“缺”=当前确实需要且确实无证据时 `NEEDS_MATERIAL`，如果本应从学校权威源取则优先 `SOURCE_UNAVAILABLE`；“糊”=图片不能识读时 `UNREADABLE`；“冲”=与权威记录矛盾时 `CONFLICT`；“后”=相应节点前 **NOT_APPLICABLE** 而非缺件。需要专业确认的加 `NEEDS_HUMAN_DECISION`。

## 08 审核规则逐条清单

### 8.1 规则计算的统一约定

`R001–R030` 是**30 个独立事实核验对象**，不是行政审批算法或已上线 V3 配置。所有 R 统一保存：`ruleId + conditionId + stage + caseId + applicationRev + subjectKey + policySource(SRC/version) + evidenceRefs(M/version/page/issuer) + fieldRefs(F/value/sourceTimestamp) + guard(T/F/U) + proposition(T/F/U) + resultCode + nextActor + checkedAt`。输入必须绑定 L0–L6 和办理情形；“真实 SRC”代表有校方可核原文或**明确标注未核**，绝不能把 SRC-011 技术目录变为校本授权依据。

- **三值含义**：`T`=在已确认**适用的政策版本和证据来源**下，所述事实命题为真；`F`=命题可证伪；`U`=不能可靠确定。先判断 guard（适用条件），guard=F 输出 `NOT_APPLICABLE`；guard=U 输出 `POLICY_UNCONFIRMED` 或 `SOURCE_UNAVAILABLE`（按原因），绝不把 U 当作 F。
- **同一命题的 F 不等于学校“不批准”**：例如“已批准请假累计超过 6 周”为 F，仅表示该**强制休学触发**不成立，可给 `NOT_APPLICABLE` 并继续其他事由；“申请起止时间前后颠倒”为 F，产生待纠正 `CONFLICT`。只有政策条文清楚、当前性获确认、比较口径确定才允许实质阈值结论；否则可记录算术候选，结果仍 `POLICY_UNCONFIRMED`。
- **证据层级**：A=有权校方主系统记录或可验正式校方决定；B=有权签发机构可验原文/纸件，且经校方验真；C=申请人声明/上传的未核附件；D=模型 OCR/摘要。A 与 B 可支持对应事实但须核**签发对象、时点、用途、权限**；C/D 不能升格为学校事实或决定。医院医疗意见属 B 类专业证据，**不是学校休学审批**。
- **时间效力**：每条检查同时锁定 `policyEffectiveRange + evidenceEffectiveRange + applicationRev + reviewedAt`。源发生变更时只失效依赖的规则；已有 L4 真实决定本身不能因重算事实而被客户端删除。适用版本仍未知的判断输出 `POLICY_UNCONFIRMED`，不以“查到历史官网 PDF”自动解除。
- **输出表约定**：每行最后一列列出“命题 T 时的建议事实码；F/U/异常时的差异码；下一办理主体”。所有场景的 `PASS_FACT` 都只代表**该 R 的事实核验成立**，绝不是休学获批。源码接口可用性未确认的 A 类来源如果失联，只能标 `SOURCE_UNAVAILABLE`。

### 8.5 规则相互依赖、范围和消重说明

| 依赖组 | 必须先具备 | 才可判断的事实 | 不可推得的结论 |
|---|---|---|---|
| 身份/依据 | R001–R006 | R007–R020 中适用的原因与时限 | 不因身份自述或外校条款硬判某学段阈值 |
| 当前证据 | R007–R009、R011、R021–R022 按条件通过 | R010、R012–R020 的可证事实 | 不能由 OCR 抽取成功推定证明真实或行政许可有效 |
| 申请修订 | R023/024，锁定新 F002、M023 与差异字段 | 仅重算依赖更改 F/M 的那些 R | 不能以新材料自动推翻 R026 发现的真实校方决定 |
| 真正批准 | R025 的身份/权限认证 + R026 的真实决定核实 | L5 R027–R028，下游服务待办 | 不可从 L5 财务/退宿成功反推出 L4 签批权限 |
| 争议 | R026 的原决定或 R024 的申请阶段请求 | R029 正式申诉或材料层复核，分开路由 | 不以本模板作申诉实体决定 |

**无重复规则检查**：R001 查真实 Actor，R025 查**审批事项权限**；R002 查权威学籍存在，R003 查**附件是否属于该学籍主体**；R011 查医学证据属性，R012 查**医学建议是否严格超过 6 周**，R013 查**已批准请假是否严格超过 6 周**；R014/R015 分本科硬件与研究生“一般”例外；R026 查**已经存在的决定**，R027 查**已经执行的学籍变更**。R021 是跨源矛盾、R022 是单证可读/来源可达，R023 是旧依赖失效；三者不同。每个 R 为一个独立对象而非拆同一检查凑数。

## 09 触发条件、冲突和复合场景

### 9.1 场景选择和政策触发的三值门禁

1. `F005` 已确认在籍、`F006–F009` 确认学段/特殊项目后，选择 P/R/I/X。缺一项决定性身份、或 `M014/M016` 不能证实特殊政策效力时，分支条件=**未知**，不要强行判断为真/假。
2. `F013` 为“休学”且 `F014=本人` 时适用主动申请流程；若为学校认为“应休学”，须有真实 `M007` 和受控发起人 `F011`；家长短信、老师聊天、学生转述不能取代校方认定。`F013=保留学籍` 时本模板只做 X5 排除路由。[SRC-001 §39、SRC-002 §25、SRC-005]
3. 只有明确 `P3/R2/I1` 对应学段，并有 `M006` 的批准请假、`M013` 学期边界时，才计算 `F026` 与“超过 6 周”。**恰好 6 周不满足该特定“超过”触发**，不代表其他事由或校方裁量被排除。[SRC-001 §41、SRC-002 §22、SRC-003 §38]
4. `F027` 来自可读医疗证据且 `F028` 达到适用条款出具机构条件时，才可报告“医学材料**载明**需要超过 6 周停课治疗/休养”；疾病真实性及必须休学最终认定由有权人员决定。因病首次申请不足 6 周不因未触发“必须”条款而自动被认定无申请权。[SRC-001 §38、§41]
5. `P2/I1` 非病因申请的开学两周计算，至少需 `F017` 可信受理时间 + `F019` 本学期受理起点 + `F032` 对应政策版本。临界时刻、节假日顺延、非病因逾期例外未找到现行办理说明，不能擅自使用“14×24 小时”硬拒绝。[SRC-001 §38、SRC-003 §35]
6. `R1/R3` 的“两次、累计一般两年”不是对研究生无例外的全自动拒绝：要求 `M011/M012` 的历史/学制事实及归口机关对“一般”与创业特例作权限内解释。[SRC-002 §23–24]

| **C16 申诉不同于补件**：学校已有不批准决定，学生申诉 | `F037/F038/F042`, `M017/M022` | 读取真实被争议决定、适用申诉制度与收件时点；由有权申诉机关处理；现行程序/时限未核不下确定性结论 | 普通申请“重新上传”被当作自动复议并覆盖原决定 |

### 9.3 证据替换、冲突解决与相邻决定复用协议

1. **建立依赖图**：例 `M004 v1 → F027/F028/F029 → 病伤超过六周候选事实`。当 `M004 v1` 被标替换时，仅这些受影响字段和检查的旧 `PASS_FACT` 必须失效，状态返回待核；学校真实 `M017` 决定如已存在不得被普通补件逻辑删除，是否重新处理交有权者。
2. **主从材料**：`M001` 的学籍主体优先于 `M002` 自填身份；`M011/M017` 真实决定优先于申请人口述的休学历史；`M006` 正式批准请假优先于请假申请/宿舍出入记录；`M013` 当期校历优先于学生截图。若主来源不可用，保存从材料作线索但标 `SOURCE_UNAVAILABLE`，不能静默升权。
3. **横向交叉**：同一日发生医疗建议、批准请假、外出项目，分别匹配 `M004/M006/M009` 的时间与目的；一份证据可能支持多个事实但不可把“休养时长”写入“批准请假累计”。主张与校方记录有矛盾则记录双方可核来源与版本，并交归口人工。
4. **跨模板复用**：学籍姓名更正仅引用 G50 `g01-student-identity-correction` 的有效校方身份结果；请假、保留学籍、复学、延期、申诉分别只引用其**真实生效决定**与编号/版本。R02 相邻 S/T 总账尚未取得，不编造 ID，也不在本案内给其他事项补办“伪决定”。
5. **权限边界**：不同部门的医疗事实验证、请假批准、休学终审、学籍维护、资助/宿舍转办及申诉签发必须分别核授权；同一上传 PDF 即使有多个章，也只有在决定类型与签批权限匹配时才提升为 `M017`。

## 10 结果状态、问题与待办输出契约

### 10.1 逐条 R 的互斥主结果（一个 Check 严格一个 `resultCode`）

| 结果码 | 唯一语义/充分条件 | 典型 R、应发任务 | 不得包含的含义 |
|---|---|---|---|
| `PASS_FACT` | 在已确认的适用范围、所需证据级别、相应版本和时间点下，**本条被核事实成立**；可继续下一 R | R003 已核申请人与学籍一致、R013 已核批准请假确实超过六周；向下一经办传事实引用 | **绝不是“学校批准休学”**；不能用来表示待批事项“通过” |
| `NOT_APPLICABLE` | 适用 guard 已证**假**，该规则当前不应运行；也用于已核证某特定“必须休学”阈值**未触发**，但不判其他依据 | R006 事项属于保留学籍；R013 恰为六周；记录分支理由或相邻路由 | 不等于学生无资格、不可申请、不予批准；不得因资料缺失输出此码 |
| `NEEDS_MATERIAL` | 当前阶段确有证据需求、申请人/发起机关有能力合法提供，但缺少该槽或必要字段 | R007 本人申请事实缺失、R009 拟起止没填；向具体提交人发有限范围补件 | 不要求校学籍系统故障由学生自己填补，更不要求未来批准书 |
| `CONFLICT` | **已有两份可定位的事实/版本**不一致、明显错人错案、签批身份不符、旧结论与新材料错配 | R003 同名异号、R021 请假记录互斥、R023 旧结果未失效；向证据主管提两方对账 | 不等同模型对真伪最终裁定；不能无追溯地任选一份 |
| `UNREADABLE` | 材料实际存在，但关键页面/字段无法可靠读取（OCR 失败、图像破损、字迹无从辨识） | R011 医疗休养时长看不清；引用**具体附件版本与页位**要求清晰件 | 与“没有交材料”不同；不应静默补猜 |
| `SOURCE_UNAVAILABLE` | 应从可信主数据或签发端核实，但该权威来源/接口/原决定不可访问 | R002 校学籍状态断连、R015 历史休学决定调不到；发归口核源任务 | 不能转成“申请人必须上传截图并视为权威” |
| `POLICY_UNCONFIRMED` | 校本现行条文、适用对象、特殊项目冲突、阈值算法或代理/复核程序尚缺权威确认 | R005 2026 合作办学办法附件未读、R010 逾期顺延争议；发制度主管核规任务 | 不是证据“缺件”，不可引用外校政策进行硬拒绝 |
| `NEEDS_HUMAN_DECISION` | 原因/专业真实性/教学秩序/例外/签批等**实质裁量**必须由特定学校角色形成决定，或有效性尚需授权核验 | R016 研究生创业期限例外、R019 特殊家庭原因、R025 本科签批；发正式有权角色办理 | 本模板不能替人作“同意/不同意”或“确认疾病符合准予休学” |

以上八码互斥且仅描述**单条检查**。另有独立维度 `propositionValue=T|F|U`、`guardValue=T|F|U` 和学校决定引用 `authorityDecisionRef?`；一条检查 `PASS_FACT` 后，仍可在案卷层出现其他 R 的 `NEEDS_MATERIAL`，而只有真实 `M017` 可报告“学校作出了何种决定”。

### 10.2 单条检查的确定性结果选择序

1. 若已确认 `guard=F`，直接 `NOT_APPLICABLE`；`guard=U` 先查**适用学段/政策问题**还是**权威学籍源失联**，分别 `POLICY_UNCONFIRMED`、`SOURCE_UNAVAILABLE`，不得为兜底而认为不适用。
2. 对 guard=T 的当前证据，先判**当前阶段是否应有**：未到 L4 时 `M017–M020/M022` 不运行相应 R，输出 `NOT_APPLICABLE`；若应有且缺申请方可合法提供的材料，`NEEDS_MATERIAL`。
3. 材料存在但不可读则 `UNREADABLE`；可读但真实权威源不可取得则 `SOURCE_UNAVAILABLE`；来源可读且相互矛盾/错主体则 `CONFLICT`，保留所有冲突的证据引用。
4. 当前事实足以比较但**校本适用标准或版本仍未知**，输出 `POLICY_UNCONFIRMED`，可以在内部保留不用于硬判的算术候选（例如恰好六周）。
5. 已核事实仍需学校专属行政裁量/专业判断时，以**该 R 的命题**决定主码：若核“证据是否存在”，可 `PASS_FACT`，另开**独立的人工作业任务**；若核“是否符合有权裁量”，主码 `NEEDS_HUMAN_DECISION`。一个 R 不同时保存两个 `resultCode`。
6. 只有适用依据、要求的证据与验证方式充分时，才能输出 `PASS_FACT`。如身份确证与校本条例现行性分属 R004/R005，即使 R004 通过，R005 仍可停在 `POLICY_UNCONFIRMED`。

### 10.4 案卷事实预审与学校决定的双轨状态

| 事实预审工作态（本模板建议） | 进入条件 | 可做动作 | 与学校决定的关系 |
|---|---|---|---|
| `ROUTING_REVIEW` | L0 新案或事项身份不明 | R001–R006；确认 P/R/I/X | 绝不含批准语义 |
| `EVIDENCE_PENDING` | 存在 `NEEDS_MATERIAL/UNREADABLE/SOURCE_UNAVAILABLE/CONFLICT` 且仍在 L1–L3 | 受控补件、核源、解决冲突、定向重审 | 材料缺口有/无不决定行政结果 |
| `POLICY_OR_HUMAN_HOLD` | 现行校本政策、专业核验或行政裁量仍未解决 | 指向实际有权机构办理；记录 M024 | 事实检查只能待人工，不能伪造批准 |
| `READY_FOR_AUTHORITY_REVIEW` | 当前适用 R 可核且无阻断证据问题，仍需要学校授权 L4 | 移交有权单位查看 F/M/R/SRC 与版本 | **只是可提交正式审批，不等于将获批准** |
| `AUTHORITY_DECISION_REFERENCED` | R025/026 仅核实有真实 M017 | 记录学校真实的批准/不批准等决定引用与生效时间 | 显示为“校方决定：以原文为准”，绝非模型生成 |
| `DOWNSTREAM_OR_DISPUTE` | L5–L6 有真实决定和后续转办/复核事件 | 路由学籍变更、财务、退宿、复学/申诉 | 不改变原决定；新决定由学校另行形成 |

`CaseReviewSummary` 的汇总次序：先用 `latestApplicationRev` 过滤当前有效 Check；若决定已核实，**单独显示学校决定与核验状态**，不让事实预审重算改写；若尚无决定，则按政策/人工作业与证据待办汇总。不同 Check 可同时给多个问题卡，而一个 Check 只能有一个主结果码。`dueAt` 只从现行校方通知/决定/法定时限获取；尚未核明不得虚构“3 个工作日补齐”等期限。

### 11.2 撤回、重提、材料复核与学校申诉的分界

1. **“撤回请求”不是撤回已有效**。L1–L3 记录 `M021/F041` 后等待校方确认当前审批是否允许撤回、是否已进入不可撤回节点。2026 现行程序未核，不能把用户界面点击等同官方许可。代理人必须经 R001/M015 核具体动作授权。
2. **“重提”不是恢复旧结论**。如果学校确认前案撤回，重提可建新的关联申请及 `applicationRev`，引用仍在有效期内的 A/B 级权威记录，但旧申请口述、医疗材料、事由/校历时效须复核；不复用旧 `R012 PASS_FACT` 作为本次医疗时长结果。
3. **“事实复核”不等于法定申诉**。L2 对错字/OCR/请假累计提出复核，受理者只是材料核验人；L4 后对**真实学校决定**异议，才进入学校申诉/复核授权通道，引用 `M017/M022` 和现行申诉办法，模板自己不处理实体结论。学生申诉处理委员会的职责与当前适用期限另需原始文件确认。[SRC-001 §59；SRC-002 §44；SRC-003 §70]
4. **“再次休学/续休”不等于复学**。`M011/M012` 的真实上游决定是累计依据，续期程序与是否允许连续办理未知；如其当前状态为“休学中”，先向学籍归口确认应走改期、再次申请或其他独立授权，不能在本案中伪造复学再休学。
5. **“申请事实达标”不等于校方同意**。即便 30 条 R 均为 `PASS_FACT/NOT_APPLICABLE` 且没有阻断问题，工作流也只能进入 `READY_FOR_AUTHORITY_REVIEW`；校方真实签批 M017 可能同意、不予同意或另行处理，均不得从机器结果推断。

按 `ruleDependencyIndex(ruleId, F, M, policySRC, scenario, stage)` 查询依赖；从旧 M/旧申请修订先找到受影响 F，再只失效直接/传递依赖的 R。示例与最低覆盖：

### 11.4 必须人工签发的边界

正式作出批准、不批准、撤销既有决定、确认创业期限特例、认定特殊原因、判断教学秩序影响、医学专业验真、处理正式申诉，均需相应学校或法定有权主体。根据已核学校条文，研究生休学批准机关明确为党委研究生工作部、研究生院 [SRC-002 §23]；本科和国际生首次休学详细签批链目前未核，**不能配置固定虚构“校长/辅导员/教务处一键审批”**。真实 Actor 必须由后端信任边界与校方岗位授权证明；`Renderer` 携带的 `role`、手写章、纸面影印章一律不能独立完成 R025/R026。

### 12.2 永不由本模板自动裁定的事项与应持有者

### 12.3 人工确认的回写边界

人工核验必须回写 `actorTrustedRef, dutyScope, decisionType, linkedF/M/SRC, sourceVersion, factOrDecision, effectiveAt, signedAt, auditTrace`。`factOrDecision=事实核查` 只能解 R 的证据/政策未决，`factOrDecision=正式休学决定` 必须满足校方真实 L4 权限并形成 M017。若政策主管仅回复“采用某版本学籍办法”，其作用是使 R005 的适用范围可核，不意味着其他 29 条自动通过，更不能改写申请人学籍。
