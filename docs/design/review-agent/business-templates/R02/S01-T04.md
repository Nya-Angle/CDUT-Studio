## 01 唯一审核目的、申请人和负责机构

**唯一业务对象**：一个学生（可信学号）在一个招生/办理周期向学校提出从正式 `source_major_code` 转为 `target_major_code` 的**申请及其最终身份变化**。系统先核验申请事实、适用条件、材料有效性与流程节点，再对接学校有权决定。`拟接收` 与 `正式批准`、`学籍主数据已生效` 是三个不同状态。[SRC-001][SRC-005][SRC-008]

- **发起人**：本人通过认证账号、自愿且在有权渠道提交；受托代提交须另有可核代理权限，不能因为 OCR 识别到姓名就取得本人发起权。学校因专业调整发起群体转换，应以学校正式指令启动行政分支，本人“申请”字段不得伪造。[SRC-001]
- **本科事实归口**：原学院/拟转入学院对本阶段资格与专业考核负责，教务处指导并承担校级复核或正式决策流程中被授权的职责。2026 文法学院发生了学生申请、资格审核、专业考核、学院会议、拟接收公示的阶段；教务处首页出现正式同意转专业决定。[SRC-005][SRC-008][SRC-013]
- **真正的签发者**：仅以当期校级有效规则和本人授权身份确认。学院面试老师、AI、材料上传者、客户端渲染进程不能签发学校转专业决定；研究生分支应按研究生院/培养单位有权文件另配，不从本科流程推断。[SRC-009]
- **边界产物**：事实核验报告、材料与问题定位、推荐转送阶段、决策引用、主数据变更完成校验、业务申诉记录；不产生“AI 同意转专业”的法律或校内行政决定。

## 03 业务生命周期与办理情形矩阵

### 03.1 状态与阶段

`DRAFT`（可编辑草稿）→ `SUBMITTED`（可信接收）→ `ELIGIBILITY_REVIEW`（资格初审）→ `ASSESSMENT_PENDING / ASSESSMENT_COMPLETE`（专业考核）→ `PROPOSED_ADMISSION`（拟接收）→ `PUBLIC_NOTICE`（公示/异议）→ `SCHOOL_DECISION`（有权校级决定）→ `REGISTRATION_PENDING`（下发与学籍变更）→ `EFFECTIVE / NOT_ADMITTED`（生效或未录取）。任一未完成分支可能进入 `NEEDS_MATERIAL`、`POLICY_HOLD`、`HUMAN_HOLD`、`WITHDRAWAL_REQUESTED`、`REVIEW_PENDING`；这些是待办/挂起，不是学校实质决定。

- 每次提交生成唯一 `application_id`，绑定 `student_id + admission_cycle + application_track + target_major`；是否可填多个志愿、第一/第二志愿是否同案内轮转，由 2026 校级通知和学院方案控制，不预设允许任意多次提交。
- 从成绩/资格初审到公示均需独立的**阶段完成事实**；学院名单不得升级成学校正式录取；正式批准后还要查可信主数据的 `major_change_event`。[SRC-005][SRC-008]
- 截止点、撤回生效节点、放弃考核的后果、异议窗口按 `policy_config_version` 生效；若与个人申请时间有争议，保存两端可信时戳与校方裁决。[SRC-003]

## 08 审核规则逐条清单

**规则评估约定**：每条结果含 `applicable`, `fact_value`, `evidence_status`, `disposition`, `next_actor`。`T/F/U` 分别指单一核验命题的证据为真/假/未知；已证事实为假不自动等于 `CONFLICT`，而是 `PASS_FACT + fact_value=false`，是否构成不予受理由**已确认**的政策条件决定；真正矛盾的证据才是 `CONFLICT`。若根本不适用为 `NOT_APPLICABLE`，指定当前阶段材料未提交为 `NEEDS_MATERIAL`，OCR/文件不能解析为 `UNREADABLE`，可信后端/签发源访问不到为 `SOURCE_UNAVAILABLE`，制度生效或数值未核为 `POLICY_UNCONFIRMED`，要求裁量或正式决定为 `NEEDS_HUMAN_DECISION`。任何 `PASS_FACT` **都不是学校转专业批准**。

**优先级**：越权/签名不可信先隔离；同一事实版本冲突→`CONFLICT`；文件确实不可读→`UNREADABLE`；权威来源不可用→`SOURCE_UNAVAILABLE`；制度未知→`POLICY_UNCONFIRMED`；当前规定明确须补的用户材料才→`NEEDS_MATERIAL`；最终裁量→`NEEDS_HUMAN_DECISION`。保留多个问题的独立输出，不把相互独立问题压成一项总失败。

`R004/R005/R006/R007/R008/R010/R016/R018/R021/R022/R023/R024/R025/R027` 均显式依赖 `F022 + M021`。当前缺完整 2026 校级通知、具体方案、当年招生类别限制以及研究生当期程序，**不得给这些规则填“默认通过/默认不通过”**。`R011/R012` 认可上位优先考虑的存在，但是否免考、是否占一般名额、与专业能力/招生限制如何协调，仍由有权机构说明。

## 09 触发条件、冲突和复合场景

1. **通常本科申请**：先 `R001/R002/R003/R027` → `R004–R010` 条件核验 → 资格签发 `R014` → 专业考核 `R015` → 排序拟录取 `R016/R017` → 公示 `R018` → 学校正式决定 `R019` → 主数据 `R020`。下游尚未发生只记 `NOT_APPLICABLE`/等待阶段，不生成假“缺材料”。
2. **第一志愿未接收再进入第二志愿**：`R023` 先检查本年度志愿规则、第一批次的可信结果，重新绑定 `F012 + F008 + M004/M005/M021`；原始成绩单可复用相同签发版本，**前一目标专业的面试成绩、拟录取或审核结论不得跨目标沿用**。2026 有第二志愿事实，但完整志愿政策未取。[SRC-005]
3. **退役或休学创业复学**：先消费 `S01-T02` 官方复学决定，再运行 `R011/R012`，优先考虑作为人工作业，不叠加普通不利标准而不解释；不能借用 S03 资助名单反向证明退役复学有效。[SRC-001][SRC-007]
4. **招生类别、校区及合作项目**：`F014` 或 `F006` 显示约定限制，先 `R004/R021` 核对原始录取约定与当年专门办法；如果首页旧《学籍办法》与 2026 专项公告不一致，冻结对应规则转教务处核当期效力。不得擅自判断“合作办学绝对不可转”。[SRC-002][SRC-004]
5. **同一事实多份材料**：正式学籍后台 `M002` 与学生上传学生证专业不同，标明字段与版本 `CONFLICT`；不同公告的接收名额不同，先按签发机构、适用周期、生效修订与授权范围排查，不以发布时间或文本相似度自动选胜。
6. **政策改变或附件追补**：任何已冻结的 `policyVersion/sourceVersion` 改变触发 `R027/R028`；仅重审依赖该版本的 R，旧 Observation 不得冒充当前 `run@rev`。如有更高位效力冲突需人工裁定，禁止默认沿用 2019 阈值。
7. **成绩与名单的竞争性阶段**：成绩真实仅证明测评事实；名额、排序、特殊优先通道与公平性争议是授权计算/组织决定。即使 `R015` 真也不推出 `R016/R019` 真；`拟接收公示` 不等于 `学校发文生效`。[SRC-005][SRC-006][SRC-008]
8. **学校主动调整专业**：C07 排除自愿竞争性排序，把受影响名单与 M022 正式命令做交集；无本人申请不能据此判 `NEEDS_MATERIAL`，但不得免校方真实决定。专业信息入账后历史版本保留，不当作姓名字段勘误路由 G01。

```json
  "materialTargets": [{"slotId":"M007","materialId":"synthetic-mat-7","fileVersion":"v2","ownerStudentId":"SYN-001"}],
  "sourceTargets": [{"sourceId":"SRC-005","sourceVersion":"2026-06-11"}],

  "officialDecisionRef": null,

```

**状态字典与排他原则**：

| `evidenceStatus` | 意义 | 默认待办 |
| --- | --- | --- |
| `PASS_FACT` | 某个命题的真/假已用可信证据确定，可独立记录 `factValue=true/false`；不意味被录取 | 更新该核验项；若为不满足条件的事实，给主管人工处理，不自动签拒绝书 |
| `NOT_APPLICABLE` | 该阶段或身份不触发此项 | 不生成缺件待办 |
| `NEEDS_MATERIAL` | 当期已核政策确实要求且**现在**应由材料持有人提供，但未提交 | 定位槽/附件/学生与截止日，请指定持有人补交 |
| `CONFLICT` | 两个可信来源/版本不一致，或材料与权威数据相反 | 指向具体两份版本与差异字段、数据归口核实 |
| `UNREADABLE` | 应有文件已上传但文件、OCR 或有效签章区域不可核读 | 原件持有人重传/人工阅原件，不等于缺件 |
| `SOURCE_UNAVAILABLE` | 官方学籍、校级通知或签发平台失联、权限不足、签名不可验证 | 后台重试/按授权人工查档，不索取学生伪替代 |
| `POLICY_UNCONFIRMED` | 无当期有效条款、限制阈值或公示/撤回办法证据 | 政策归口校验并绑定可执行版本，不作实体判断 |
| `NEEDS_HUMAN_DECISION` | 名额/专业能力/特殊原因、是否录取、异议处置等权力性判断 | 交对应授权学院/教务处/研究生院/复核机构 |

**每个 Issue 必填**：`issueId, ruleId, caseId, applicationId, stage, targetStudentId, targetMajorCode, materialSlotId?, materialId?, fileVersion?, sourceId?, sourceVersion?, factKey, expectedFact, observedFact, evidenceStatus, severity, nextActor, nextAction, createdAt`；不要把“材料问题”和“名额决定”合为 `总体不合格`。同一案有多个问题各自保留来源、版本与处理人；已签的学校决定作为 `officialDecisionRef` 独立于事实结果。允许 `eligibilityEffect=ELIGIBLE/INELIGIBLE/INDETERMINATE/NOT_EVALUATED`，但 `INELIGIBLE` 是核验事实对已核政策的关系，不是行政拒绝书。

**信息展示**：学生只见本人有权查看的事实/补件/决定状态；公示名单仍以校方合法公开范围为准。对 `POLICY_UNCONFIRMED` 说明哪份具体校本制度缺失，不能给出看似精确的自动判定概率、学号隐私或“AI 已批准”。

**持久化与可恢复性**：`CurrentCase/ReviewRun/BatchAttempt/Decision/Outbox` 写权仍归 V3 可信 Main/后端所有者；Renderer 不能伪造 `teacher/registrar` actor；新案只 CAS 创建一次，同一申请冲突提交幂等归同案；批量最终化绑定 `entryRunId`；撤回、再提交和复核事件带幂等键。来源更新后的旧 Run/Observation 只能做审计历史，**不得复用为当前签发**。不在本研究稿改 V3 运行代码。

### 14.1 本轮编号与引用约束

### 14.3 R02 总账变更请求

`CATALOG-CHANGE-REQUEST: NONE`。本稿建议维持唯一 `S01-T04`，把普通、第二志愿、特殊身份、学校组织调整、研究生子情形作为同一 ID 的条件分支。若校方确认研究生正式转专业权属为另一个独立业务且有完整材料与决定链，再向总账负责人申请拆分审议；本轮不自行改号、不新增模板。对 G01 的姓名/证件字段纠错与专业正式变更永不双重批准。

### 14.4 交接可用性

`authoring_status=RESEARCH_HANDOFF_READY`，表明单份 00–14 节文稿、来源强弱、字段/材料/规则及合成场景可以进入业务专家审阅与 V3 后续转换；`policy_status=PARTIALLY_VERIFIED`，不能把本研究稿直接作为成都理工现行正式审核规则上线。最终行政决定的执行条件是校方或经授权后端确认，**不是**当前 ZIP 交付。
