## 01 唯一审核目的、申请人和负责机构

### 1.1 审核目的与法律关系

本模板唯一审核对象是**一个主科研项目下、一个拟合作/外协任务包、一个外部合作对象、一个拟签合同版本**所构成的立项关系 `OutsourcingProposal`。要回答：主项目是否真实且允许此任务；为何需外部完成；合作方能否履约、有无利害关系；任务、成果、成本与计划是否匹配；采购或外拨资金是否需要另外的授权；合同签署、保密与成果权利义务是否进入正确审批路径。

这里的“委托研究”主要指**成都理工作为委托/对外协作出资方**。若外部企业委托成都理工开展研究、学校是承接方，首个项目/横向合同立项应路由 `T03-T03`；若后续需要将该项目的一部分科研工作委托第三方，再建立关联的本模板案卷。不得把横向收入合同和外协支出合同合并为一份不明性质的审批。

### 1.2 发起主体与最终权力

- **发起**：经过学校可信科研项目台账确认的项目负责人、获其书面或系统授权的经费/子课题负责人、项目承办单位指定的科研秘书。拟合作方和未获授权的普通教师/学生可以提供资料，但不能代学校形成审批申请。
- **初核/监管**：项目所在教学科研单位及科技/社科归口（自然科学以科学技术发展研究院、社会科学以社会科学处为候选归口）；科研管理、合同归口、采购、财务、保密、依法治校等依本案触发会签。2024 校本诚信文件明示科技研究院及社会科学处为科研管理部门（SRC-004）。具体科室、阈值和签批顺序仍为配置参数。
- **有权决定**：必须使用学校当期正式授权链和单位业务权限记录。学院负责人、归口部门、依法治校部门、校领导/校长何者签发，按案类/金额/学院规定确定；不能套用某学院的 2026 阈值给全校（SRC-005、SRC-008）。
- **执行关系**：T03-T08 形成外协科研立项决定或对外协关系的条件性业务意见；采购方式决定由 T04，预算调整由 T03-T04，外拨/报销由 G07，最终合同签署取独立授权/用印决定。系统只引用这些决定的可信 `decisionId` 和有效版本。

## 02 适用、排除与邻接模板路由

| 进入/转交情形 | 路由与唯一决定边界 | 不得重复的事项 |
| --- | --- | --- |
| 有主科研项目、拟与外部承担具体研究目标、明确交付、分工与费用 | **T03-T08**：外协必要性、研究任务、合作方能力/风险、科研立项条件 | 不替代合同签署或付款 |
| 已在纵向申报/批复中列为联合承担单位的合作任务 | `T03-T02` 先识别主任务书/授权；T03-T08 核实施工/合作落实中的外协任务，不重复批复联合承担资格 | 不把计划内转拨当成“新采购”当然处理 |
| 外部主体付费委托学校承担横向研究 | `T03-T03` 主合同立项；其后另签对外委托任务再进入 T03-T08 | 避免方向倒置 |
| 主项目预算总额、外拨预算或科目需另行调剂 | `T03-T04` 签发预算调整决定；本模板引用其 `decisionId` | 不自主调拨/改变经费科目 |
| 主项目负责人、承担单位、期限或研究内容本身变化 | `T03-T05`；本模板仅审外协任务内部版本变化是否依赖已签主项目变更 | 不越权改变主项目 |
| 阶段检查、中期、整项目结题/绩效 | `T03-T06/T07` 消费外协履约记录 | 不重复评价主项目 |
| 对外已签科研合同交付/违约目标 | `T03-T10` 对合同成果交付作专门核验；T03-T08 仅跟踪外协决定关联性 | 不以外协立项自动确认验收 |
| 涉密科研立项、定密责任 | `T03-T09`，以及 G 类保密或信息安全流程；本模板只接受授权后端“可审/可共享”状态 | 不接收国家秘密明文至普通模型 |
| 专利许可、成果权利处分、伦理审查 | `G06`（尤其 `g06-t09`、`g06-t07/t08`）；本模板核合同中是否**提及**知识产权/伦理条件，仅引用独立决定 | 不做成果处分或伦理批准 |
| 委托测试、常规加工、设备物资、一般采购服务、工程 | `T04-T01/T02/T03` 采购需求、方式、合同决定；如仍有实质科研协作，T03-T08 保留科研任务评价并引用采购裁决 | 不能通过写成“科研外协”逃采购；不直接判定免采购 |
| 外拨实际付款/发票/报销、采购结算 | `G07`（采购前财务预审 `g07-t03`、履约结算 `g07-t04` 等）；本模板不碰银行付款 API | 不双重审批支付 |
| 非科研合同和一般对外用印 | `T07-T02`；科研合同实质按 `T03-T03/T03-T08`，采购合同按 T04；统一合同管理可会签 | 不能同一合同两次“实质签订批准” |
| 档案证明、跨单位个人证明、场地/安全/出行 | G01/G03/G04/G05 等按独立决定引用 | 不因研究外协一揽子批准所有相关事项 |

**分流原则**：先识别“合同的实质”与“经费来源”，再匹配规则。名称为“技术合作”但没有可测的外部研究任务、仅为无资金框架合作的，不能为了占用 T03-T08 而虚构外协立项；涉及真实学校科研合同审核，视情况交 T03-T03 或 T07。系统若无法辨别科研任务与标准服务采购，生成 `ROUTE_UNCERTAIN`，并列相关两个入口供有权归口确认，不自动视为采购豁免。

## 03 业务生命周期与办理情形矩阵

### 3.1 阶段及允许事件

`DRAFT`（提议录入）→ `PRECHECK`（分证据/事实核验）→ `PENDING_REFERRED_DECISIONS`（依赖采购/预算/保密等签发）→ `SUBMITTED`（归口受理）→ `UNDER_REVIEW`（学院/科研/合同与条件会签）→ `DECIDED`（有权决定）→ `CONTRACT_PREPARATION`（签署与用印，非本模板自动行为）→ `EFFECTIVE_MONITORING`（按真实签署版本跟踪）→ `ACCEPTANCE_LINKED`（验收/成果交付另案确认）→ `CLOSED`。`RETURNED` 可补件回到原阶段；`WITHDRAW_REQUESTED`、`WITHDRAWN`、`REVIEW_REQUESTED`、`REVIEWED`、`TERMINATED/CHANGED` 是带权限的事件及状态，不覆盖历史决定。

**通用前置**：先校验主科研项目、申请身份、资金类型、外协任务对象和期限；未取得未来阶段合同专用章/验收报告时，状态是 `NOT_APPLICABLE` 而不是 `NEEDS_MATERIAL`。外协成果不允许在“拟立项”阶段先要求完成。真正签署和转拨均在可信签发链之后。

## 05 角色、权限与可信数据边界

| 角色/数据提供方 | 可读/可写界限 | 不可代理的权力 |
| --- | --- | --- |
| PI/授权经费或子负责人 | 可创建草稿、上传科研任务/必要性/报价/外协合作证据；身份经 Main/服务端可信账户 + 项目台账核验 | 不能通过前端参数声称自己是 PI、校领导或审查人 |
| 科研秘书/承办单位 | 协助核原始资料、建议修正、形成学院意见；授权范围由后端核 | 不能私自改变经费总额或主项目事实 |
| 科技/社科归口 | 权威项目类别/项目状态/任务审批/研究外协归口决定 | 未授权不得签学校合同或制造第三方付款 |

| T04 采购归口、G07 财务、保密/G06 归口 | 分别签采购方式、付款、保密/伦理/权利处分等 `decisionId` | 本模板不得重复他们的决定或自动触发转款 |

**可信来源顺序**：学校科研管理/合同/采购/财务/保密后端的签发式记录 ＞ 带校验标识的外部监管/资助项目正式记录 ＞ 具有证书验证的原始外部文件 ＞ 申请人提交扫描件/合同草案 ＞ OCR/AI推断。后一类不能覆盖前一类。所有授权决定要求 `issuer`, `roleAtTime`, `decisionId`, `issuedAt`, `scope`, `artifactHash`, `validity`, `revocationStatus`，无法查询时 `SOURCE_UNAVAILABLE`。

**敏感性**：银行账户、身份证件、关系人参股/亲属关系、未公开成果/专利、商业秘密与科研数据按最小可见范围；项目涉密标识是访问控制输入，不代表将秘密材料发送给模型。国家秘密任何正文/载体不进入普通云审查；只接可信保密审批令牌和脱敏任务元数据。商业秘密也需授权、最小化、加密和审计。查看日志仅保留必要代码与哈希，禁止明文扩散。

## 09 触发条件、冲突和复合场景

1. **外协 vs 采购**：由 `F017/F018/F033` 以及资金来源、合同的实际交付对象识别。购买标准检测服务、加工、软件/设备或工程可能是采购，不能因技术性强就自动认作科研外协；如既含独立科研研发又含采购，分拆为可溯源任务和对应 T04 采购决定，禁止人为拆合同逃避门槛（SRC-014/015/018）。
2. **纵向 vs 横向**：纵向按资助计划/任务书、合作单位、预算和调整权限；横向按主合同约定、2024 校内支出管理及资金范围。`50%` 仅为 SRC-003 第3条的横向外协总额**原则**，不等同“单笔 50%”“到账经费 50%”“所有纵向 50%”。当超原则，输出待政策核例外+人工决定，保留分母和已承诺金额来源。
3. **不同证据冲突**：后端项目状态与自传任务书冲突、合作方营业名称与合同抬头不同、预算审批与合同金额不同、合作关系声明与登记关联矛盾、正本合同与修改件哈希不同，一律分 `issue` 锁定 F/M/版本；不得自动选择对申请人有利的一份。
4. **时间序**：项目已结题/终止却追认先前外协，或合同签署日期早于必要立项/采购程序，提出倒签风险并人工处理；禁止自动“补发过去日期的批准”（SRC-005/008）。
5. **知识产权/伦理/保密**：一个科研合同可能同时触发三者，业务上分别得到可信 G06/T03-T09 等决定，T03-T08 只检查是否具备前提，不重写其他专业审查结果。
6. **院级差异**：SRC-008 的 1万/20万/100万区间仅对其适用学院，并须核该合同是否确属其办法范围；其他学院默认 `POLICY_UNCONFIRMED`，不能用 2026 局部规则通用派发。全校科研合同归口另待 2024 校级合同办法正文核实。
7. **合作方变更**：换合作方不是仅换上传文件：F024/F028/F030/F031/F038 与采购/保密决策可能全部失效，创建新外协对象版本及受影响任务重审，不偷换已签决定。
8. **审批冲突**：同一项目多个资助规定、主合同、2024 校规、旧 2017 外协管理正文可能冲突时，明确 `policyConflict`（适用对象/时间/条款），由科研归口和法务确认，不自动宣布旧规则废止；SRC-003 第13条只对与其**不一致的学校既有文件**规定处理，并不消灭其他独立合法条款。

## 11 补件、撤回、版本更新、复核与人工决定

1. **补件**：PI 对单一 `issueId` 补 M003 等，写 `MaterialSubmitted(docId, owner, object, sourceVersion, hash)`；旧文件留历史，重试权限/病毒/文件读取后重审其依赖的规则。较少非关键缺件允许先完成事实预审、形成可提交待办；不能仅因缺一份未来签章阻塞整个案卷。
2. **定向重审**：定义规则依赖索引，例如 `M008→F028→R010`，`M007→F012–F016/F030→R006/R007/R011`，`M010→F031/F032/F038→R012/R013/R017/R019/R021`。任意源版本或项目台账变动，撤销相应旧 `Observation` 有效标记，冻结新 Plan `planId+fingerprint+rule×target/sourceVersion`，仅对受影响规则重跑；其余有签发版本的可信事实可保留。不能以旧 V2 Run 顶替新 V3 Run。
3. **撤回**：签约前 PI 递交可追溯撤回请求；真正 `WithdrawAccepted` 只能由按流程有权的学校主体签发。签约生效后应走变更/解除/终止与 G07 资金回收/结算，不能删除既往立项批准与合同记录。
4. **人工决定**：依据权限矩阵，逐节点签发同意、退回、否决、暂缓、提请会签；`NEEDS_HUMAN_DECISION` 仍是事实层，最终决定是另一可信事件。校本裁量可能带条件批准，但条件必须由真实签发机构给出，而非模型自拟。
5. **复核/申诉**：申请人通过有权渠道对具体外协立项决定/处理申请复核，核身份、决定 ID、送达和规则规定的期限。未取得当期复核期限不能自动判逾期；有权机关签发 `ReviewAccepted/ReviewDecisionIssued`，如纠正则更新可信决定关系和受影响问题，不暗改已签合同。
6. **重传不可借旧结论**：同名 PDF 只要哈希/归属/版本不同，原 M/F/R 对应观察失效。源项目任务书或资金规则新版本生效时做依赖闭包重审，保留过去审核快照供审计，不跨 `Case` 任意复用个人/企业敏感资料。
7. **边界操作**：`T03-T08` 无权发起真实外拨、银行转账、采购合同用印、秘密资料对外发送、成果权属处分或科研诚信处分。有关权限/保密异常仅产生转交与风险待办。
