## 00 元信息与研究状态

**固定身份。** `T02-T12` 属于 `T02｜人事、聘任与教师发展`，唯一目的为“离职、辞职、解聘与离岗手续审核”。沿用 R02，不因辞聘、单位解除、合同到期或交接而另拆模板。旧 R01 同号仅用于追溯。

**第 1 轮事实等级。**

1. **事项确实存在。** 成都理工大学党委教师工作部（人事处、教师发展中心）官网“服务指南”列出《成都理工大学教职工申请辞聘工作流程》（SRC-001）。仅核实了**入口名称**；该流程正文、发布时间、适用身份、签批顺序及当前有效性尚未取得，不能据此声称学校存在某线上“辞职审批”系统。
2. **管理依据确实存在。** 学校章程载明依法聘用、考核、解聘及救济安排（SRC-002）；校内公开的成理校人〔2019〕35 号包含事业编制聘用合同样式及解除/终止条款（SRC-003），但后续学校报告显示相关岗位聘用制度已修订（SRC-004、SRC-011），**不得将 2019 版视为 2026 年唯一现行硬规则**。
3. **身份必须分流。** 2026 年学校一项教辅选聘公告明确其为事业编制外、签订劳动合同（SRC-006）；2025 年学校党委会议公开通报涉及编外聘用管理办法（SRC-005）。故不能将事业编制聘用合同条款套到全部教职工，也不能以“教职工”三个字判断法律关系。
4. **离岗交接客观存在。** 学校图书馆说明有教职工离校清还借阅资料环节（SRC-008），档案馆列有调出、退职、离职类归档材料（SRC-007）；这只能证明有关环节，**不能推出各环节是人事关系解除的先决审批条件**。
5. **总账实物已读、技术资产仍有缺口。** 第四轮从整合 ZIP 实读 `ST-CANDIDATE-MASTER-CATALOG-R02.md`、`ST-CATALOG-AUDIT-R02.md`、`RESEARCH-TO-BUSINESS-MD-PROMPTS-R02.md`、144 项台账及审阅；G50 `catalog.json` 未包含在整合包内，指定 GitHub 固定 SHA 的原始 JSON 在线读取受阻。因此已核精确 S/T 邻项，G50 仅能依 R02 审计的固定 ID/描述作**目录级**去重，不能称为源码逐规则映射。

## 01 唯一审核目的、申请人和负责机构

**决定对象界定。** 本模板只核验四类事实：①申请或单位发起的人事动作及发起者；②被处理人现有任职/合同关系、期限、类别和必要的前置决定/通知；③程序通知、意见、送达、交接等证据是否对应同一人、同一合同、同一版本及事件；④已形成的有效解除/终止决定与实际离岗手续是否相符。输出“事实核验结果、材料问题和人工待办”，而不是“批准辞职、决定解聘或认定赔偿”。

**主体与发起权（按情形、待校本流程核准）：**

| 主体/发起动作 | 可确认的制度层次 | 本模板能做什么 | 有效决定的保留权 |
|---|---|---|---|
| 教职工本人主动书面通知解除聘用合同 | 《事业单位人事管理条例》第 17 条存在提前 30 日书面通知规则及双方另有约定例外（SRC-009） | 核对身份、文书、日期、签收、对应合同与约定是否可见 | 法律后果依据法规与真实合同认定；不得把“学校未批准”机械转为无效辞职 |
| 双方协商解除、合同期满终止 | 校内 2019 合同样式有相应情形（SRC-003，版本待核） | 核对双方签署/期满事实、与最新协议是否冲突 | 学校有权签署方及劳动者本人依法形成协议/终止事实，机器不代签 |
| 单位发起解除、解聘 | 《条例》第 15、16、18 条分别涉及不同法定情形（SRC-009） | 核对起因证明、通知/送达、考核或处分的有效来源 | 学校/有权机关依据真实授权作出处理；不得由业务模板作纪律处分或解聘决定 |
| 编外劳动合同人员提出离职或单位解除 | 学校 2026 一批编外教辅采用劳动合同（SRC-006）；劳动合同法是一般依据（SRC-010） | 先识别合同相对方、合同法适用及签约主体，再核证通知和交接 | 用人单位依法授权人员及劳动者；不得复用事业编制规则 |
| 辞聘、解聘决定后的离校交接 | 校图书馆清还与校档案归档线索（SRC-007/008） | 核对各责任单位分别出具的清还、交接、档案去向回执 | 各业务主管部门完成本部门确认；不倒置为本人申请时的必交签章 |

**归口机构。** 校方人事处服务指南与人事科联系方式能证实其是本事项**主要咨询与业务归口线索**（SRC-001）；是否由二级单位初审、党委组织部、校长办公会、党委常委会、分管校领导、主管部门或省级人社部门决定，按人员类别、干部管理权限和事项性质核定，目前**不能指定统一最终审批人**。2019 合同样式由学校法定代表人或其委托代理人签署（SRC-003 第 10/16 页），说明需核真实授权，不足以推断所有解聘决定一律由某签字岗位作出。

**两条不同的权利路径。** 事业单位人员的人事争议适用《事业单位人事管理条例》第 37–39 条的争议/复核/申诉安排（SRC-009），劳动合同人员可能适用劳动争议路径（SRC-010）；具体事项是否落在正式“复核/申诉”受理范围要另校验，不得为任何离职人自动套用统一申诉天数（SRC-014）。

**双时点/双主体。** 每案至少区分“通知到达/决定生效的时点”与“后续手续办结时点”；区分“合同签约单位/法定雇主”与“日常工作所在部门”。若两者冲突，输出 `CONFLICT` + 人工核验，不能用文件标题或者经办人的自由文本补齐。

**人事数据可信与最小化。** 人员法律身份及在编/编外属性以人事主数据和实际合同为准；处分、考核、涉密、薪酬及健康信息按最小访问权与证据目的读取。图片、扫描件和个人自述均不自动升级为人事系统事实。对当事人产生重大不利影响的程序，必须保留依据版本、原件散列/定位、签发主体、送达回执、人工决定人和撤回/复核事件链；争议期间原决定的效力由适用法规和有权文书判断。

**状态占位约束。** 第 08–10 节已有研究性 R 与结果契约，但本轮不发布实际可执行规则或校方审批功能；事实预审用 `PASS_FACT`、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`。`PASS_FACT` 只能说明某事实核对通过，不能转义成“批准离职”。`POLICY_UNCONFIRMED` 或涉及法律性质、行政裁量、处分实体判断时，只能走有权人工节点。

**可信来源优先级（不是软件接口现状断言）：** `人事/用工系统已鉴别记录及合同原本 > 合同签约机构核真记录 > 有权机关正式文书/可核签名回执 > 有权部门出具的书面证明 > 当事人上传原件扫描件 > OCR/人工转录`。不同源若法定效力不同不按分值投票，而是保留两者、查有效时间并交人审。学校系统暂无法访问时可由人事处核真/提供权威摘录；除个人自持的通知或协议外，不无理由强迫当事人重复上传学校自有记录。

**审计和撤销链。** 所有 L1/L4/L7 事件记录可信主体 ID、代理范围、实际发生时间、提交时间、文书来源、签发权限快照和 sourceVersion。更正/替换只建新证据版本，旧版不得被物理抹去；受其支持的事实结论失效并局部重审，未受影响的材料和先前正式决定保持原始历史。可信权限来自后端受控机制，不接受 Renderer 的角色参数、图片中的公章或 LLM 猜测。高敏感字段按第 06 节 `P2/P3` 分级处理，依据 SRC-016 评估必要性与访问范围。

**条件分层复核。** `NEEDS_MATERIAL`=本阶段按可信依据已经应有但缺失的具体 M；`UNREADABLE`=存在文件但 OCR/原件关键信息无法判断；`SOURCE_UNAVAILABLE`=本应由校内/外部权威系统或单位给出的事实暂无法查到；`POLICY_UNCONFIRMED`=规则版本、身份适用或时效无法核；`CONFLICT`=同一合同/人员/时点的多源证据不一致。以上只输出审查问题，不自动产生“拒绝解除”或“拒绝离校”的行政后果。

**覆盖表读法与最小性。** `F` 栏是该情形在对应阶段需要**检查可得性**的业务事实集合，尚未发生的可选事件（例如通知到达 F024、已生效决定 F032–F034）为 `NOT_APPLICABLE` 或“待后续产生”，绝非本阶段强制要求全部非空；`M` 栏才是按照身份、触发事实与实际进度分层的**最小当前材料集合**。M001/M003 等属于学校或雇主本应保管的权威材料，取得可信查询/核真摘录即可，不默认要求申请人上传。上位法已明确的通知形式不能任意替换；具体校本表单、合同核真、交接清单的允许替代范围由有权人事部门进一步核定。任何 `M015/M016/M018–M024` 若尚未进入相应阶段，都不触发“缺件”。

## 08 审核规则逐条清单

**第四轮研究规则，`R001–R032` 连续。** 这是事实预审设计，**不是**成都理工大学已批准上线的规则集。每条只判它所定义的一个事实目标，不能把任一 `PASS_FACT` 扩写为“同意辞职/合法解聘”。共同执行约束：

1. **三值触发独立于事实判定。** 表中 `T`=本阶段此对象确实适用，进入证据比较；`F`=可靠事实证明此情形不适用，输出 `NOT_APPLICABLE`（不要求材料）；`U`=无法确认触发，按表列 `POLICY_UNCONFIRMED` 或 `SOURCE_UNAVAILABLE` 等待核实。触发为 `T` 时，表中的“证实→”才是 `PASS_FACT`；若缺失、不可读、冲突，必须输出相应问题码，绝无“默认通过”。
2. **时间双轨。** `created_at`/`uploaded_at` 只证明材料操作时间；`signed_at`、`received_at`、`effective_at`、`handoff_at` 均须按对应有权来源确认。法定期间仅在 SRC-009/010 有明确依据、身份与适用条款确认后用于**日期事实提示**；法律效果、特别约定和本校办事时限仍交人审。`as_of` 与 `sourceVersion` 是每次运行的冻结快照，不能用后到新政策悄然改写旧审查。
3. **证据层级。** 业务机关/真实合同相对方核真的原记录与签发、送达状态为核心；经鉴别的原件其次；当事人扫描件可作核真线索；OCR/LLM 仅提取候选字段。**不以所谓置信分数、两份低等级材料“票数”压过一份可信正式记录。** 公共 OCR、哈希及签章检测能力交 G50；以下 R 仅处理离职事件的特定含义和权责，具体 G50 ID 待正文核对。
4. **未知处理优先看未知的性质。** 没有此阶段法定/校本必需性依据，不可报 `NEEDS_MATERIAL`，而是 `POLICY_UNCONFIRMED` 或 `NOT_APPLICABLE`；事实本应由权威机构确认却暂不可达为 `SOURCE_UNAVAILABLE`；收到文件但关键页无法读取为 `UNREADABLE`；可信来源相互矛盾为 `CONFLICT`；涉及法律评价、处分、解除资格、撤回效力、赔偿或真实签发一律保留 `NEEDS_HUMAN_DECISION`。

**冲突裁决不靠“材料多数表决”。** 对同一合同，主从关系采用“权威合同原本/补充协议及双方有效签署状态 → 正式通知与送达 → 有权处理文书 → 各专责交接回执”的**法律与业务关系链**；这个箭头表示核验依赖，**不是**签发效力的自动优先级。若 M003 被真实补充协议 M004 替代，绑定旧 M003 版本的 F011/F013/F015 和相关事实结果变为“须重审”；通知是否送达（F024）等独立证据如未受影响则保留。若有新 M024 纠正旧 M015，只追加纠正事件、人工认定新法律效果，不暗改旧人事状态。版本键至少为 `人员主键+真实合同号+事件 ID+来源机构+文书版本/哈希+时间`（F001/F009/F018/F044/F046）。

**跨 G50/S/T 消费契约（待见目录再定准确规则映射）：** G50 的身份/可读性/签章一致性仅能生成证据线索，不能越权作 T02-T12 的法律判断；T02-T05 年度与师德事实、T02-T06 聘期和续聘结果、人才/项目归口及处分机关的真实决定，只以其签发机构可验证的 `decision_id + status + version + subject + time` 作为 M009/M010/M025 输入。T02-T08 校内岗位流转结果不能充当校外离职决定；G05 外事审批、T06 教学资格仅消费相关**已确认**人事变化，不反向裁断聘用关系。R02/G50 实物尚未取得，具体名称和字段映射保持研究假设，不伪造接口。

**异常状态路由（仅事实层，不是最终决定）：**

| 状态 | 何时给出 | 下一步责任与限制 |
|---|---|---|
| `PASS_FACT` | 本阶段对应 F/M/SRC 可核真且无冲突 | 记录事实通过；仍等待真实有权决定/法定效果判断 |
| `NOT_APPLICABLE` | 明确身份或阶段不需要该材料，例如 L1 不需 L5 交接回执 | 说明不适用的法定/阶段原因，不伪造“通过” |
| `NEEDS_MATERIAL` | 当前阶段依法/有效校本办法已有的必需材料缺失 | 指向具体 M、持有人和可选权威查询/补件；不让个人重复上传校内可取记录 |
| `UNREADABLE` | 文件有但关键签名、日期、合同对象无法辨认 | 指明页码/区域，申请权威重出或人工验原件 |
| `SOURCE_UNAVAILABLE` | 必须外部或校内权威核实，但查询/证明暂不可得 | 标记取证责任部门与重试/线下核真，不推断为不合格 |
| `CONFLICT` | 不同版本、主体、时点、正式决定相抵 | 保存全部来源，暂停受影响事实结论，交有权人审 |
| `POLICY_UNCONFIRMED` | 校本办法修订版本、授权或适用范围不能确认 | 不计算旧阈值、不触发单方拒绝，申请校本确认 |
| `NEEDS_HUMAN_DECISION` | 有行政/劳动法效果、法定禁止解除例外、签发裁量或争议 | 唯一有权机关/当事人依法作出决定或取得救济；AI 不代办 |

**临界反例。** ① B2 劳动合同没写有效试用期而只凭人事系统“试用”文字，不能套 3 日；② A1 已签的书面通知只有本地草稿，不能据 F023 算 30 日；③ D1 考核公示但尚无有效结论，不能填 M009 `PASS_FACT`；④ E1 被调查与被开除不是同一事实；⑤ G2 图书馆已盖章但科研资产无人接收，图书项通过不等于整案交接通过；⑥ H2 校办企业的办理表不能替代学校人事表单；⑦ 申请人补上传后新文件改变合同截止日，旧自动结论不能继续标现行。这些反例在第 13 节后续轮做完整演练。

## 10 结果状态、问题与待办输出契约

**第四轮事实结果契约（研究性、非运行 DTO）**。审核一次 `caseId/eventId/planFingerprint/sourceVersion` 只能生成**证据绑定事实结论**和待办；正式法律/人事决定必须来自有权机关的可信写入通道。`PASS_FACT` 不得译为“材料齐全就同意离职”，`NOT_APPLICABLE` 不得译为“无问题即批准”。

| 事实结果码（同一 R/事实目标/冻结证据版本仅一个主码） | 互斥含义/触发条件 | 必须携带的原因和下一动作 |
|---|---|---|
| `PASS_FACT` | 所问**事实**经相应等级可信证据核对可确认；不评价合法性或是否批准 | 具体已核事实、证据版本/页码/签发人、SRC 条款；如果 R020 涉及法律效果，只能记录其**日期基础事实**通过，综合效果需独立人工结论 |
| `NOT_APPLICABLE` | 触发条件已证实为假，或当前事件确未到该后续阶段且未产生必须核的任务 | `reason=wrong_scenario/stage_not_reached/confirmed_no_task` 等、可信排除依据；不能以“缺材料”推断不适用 |
| `NEEDS_MATERIAL` | 触发为真且此阶段依据可靠法源/已确认业务任务应有的**某一特定材料**缺失，且不能从已知权威来源直接取得 | `missingMaterialId`、本来持有人、查询/补件二选一路径、合法替代、是否已达生成节点；不得让申请人在 L1 补交 L4–L6 文件 |
| `CONFLICT` | 至少两个可定位来源对同人、同合同、同时间或决定状态存在实质矛盾，或确有冒用/错绑证据 | 冲突双方的材料版本、字段及页码、受影响 R；暂停该事实，提交原权威部门核对，不按数量/算法置信度投票 |
| `UNREADABLE` | 文件已提供，但关键页、字迹、签章或机器提取无法支持事实核验 | 具体文件页/区域、不可读字段、是否可人工查原件；不等于申请事实不存在 |
| `SOURCE_UNAVAILABLE` | 需要人事/外部雇主/处分机关等权威来源，但该来源尚未提供可鉴别记录或临时不可访问 | 权威机构、请求时间、替代核真路线、下一次核验责任；不是 `NEEDS_MATERIAL` 的申请人缺件 |
| `POLICY_UNCONFIRMED` | 适用的校本政策版本、条款、人员范围、授权或要求本身无法确认 | 待查 SRC/制度正文、版本冲突、政策 Owner；不得以旧 2019/2022 文件自动硬判期限/损失 |
| `NEEDS_HUMAN_DECISION` | 事实虽可提取，但解除/终止法律效果、保护限制、处分关联、撤回效力、有效签发、争议处理需依法有权主体确定 | 判断对象、可用事实和例外、真实决定权限要求及理由；**不能由模型拟造“决定人已同意”** |

**确定主码的决策顺序：**

1. 先检查 R 的业务情形与阶段：**可证实不适用**，结果 `NOT_APPLICABLE`；条件尚未查明，记录 `POLICY_UNCONFIRMED` 或 `SOURCE_UNAVAILABLE`，不继续假定触发为真。
2. 已触发时，优先查**证据属于谁/哪个合同/哪个事件、真伪及时间版本**。存在相互冲突记 `CONFLICT`；已有文件但无法读记 `UNREADABLE`；原权威系统或机构不可达记 `SOURCE_UNAVAILABLE`。
3. 若材料义务本身未有现行依据，记 `POLICY_UNCONFIRMED`，不能强迫补交；若现行规则/实有任务确认且缺特定材料，记 `NEEDS_MATERIAL`。
4. 事实核验通过才 `PASS_FACT`；涉及法律效力、签发、特殊保护或争议实体判断的**另一个目标**由对应 R 给 `NEEDS_HUMAN_DECISION`。多重异常可在 `relatedIssues` 保留，但 `resultCode` 只有一个主码，并以 `dominantBlocker` 明示当前处理优先级，不能覆盖其他独立 R 的结果。

**单条问题与待办结构（字段名仅供后续 V3 契约映射，不是已经存在的接口）：**

| 输出层级 | 至少包含 | 不可省略的关系 |
|---|---|---|
| `factCheck` | `ruleId, trigger(T/F/U), scenario, phase, factTarget, resultCode, rationale, checkedAt, sourceVersion, planFingerprint` | 一条 R 对一个独立事实目标，先冻结同一证据视图；可列相互关联的单项事实但不能混成审批结论 |
| `evidenceRefs[]` | `SRC-ID+条/页+policyEffectiveStatus`、`M-ID+materialVersion+owner+page/anchor+originIssuer`、`F-ID+observedValue+origin` | 每条可审查问题至少追溯对应 F/M/SRC；高敏证据只提供权限可访问引用，不全文复制 |
| `issue` | `issueId, ruleId, caseId, eventId, targetPersonKey, contractRef, resultCode, conflictGroup?, supersededBy?, materialIds[], evidenceRefs[]` | 问题归属绑定真实人/合同/事件，`issueId` 不可由截图中的名字生成；旧版问题不能当现行未决 |
| `workItem` | `ownerRole, action, requiredEvidenceOrPolicy, lawfulAlternative, dueBasis, openedAt, status, issueId` | `ownerRole` 仅建议路由（申请人、人事、单位、专项机构等）；`dueBasis` 不知道校本时写 `UNKNOWN`，不能自造逾期 |
| `reviewSummary` | 每 R 主码及本阶段材料覆盖、争议/条件项、待办组与 `noDecisionByAI=true` | 不提供总 `APPROVED/REJECTED`；“事实全部可核”仍不同于正式决定 |
| `authorizedDecisionRef?` | `decisionId, issuer, legalAuthorityBasis, authenticatedActor, signatureVerification, effectiveStatus, signedAt, servedAt, recordedAt, documentVersion` | 只由真实有权人事/签约机关的受控记录进入；不得由 `factCheck` 统计、Renderer、PDF 图片章或旧 `run@rev` 合成 |

**按责任主体的待办映射。** 本人：个人书面意思、真实补件/撤回或代理授权配合；学校人事归口：人员类别、合同、现行校本流程、权责表、决定来源及答复；二级单位：本部门事实与真实工作移交；原考核/处分/人才机构：其原始决定 ID 与生效状态；图书馆/资产/保密/信息化：各自回执；档案/社保/财务：后续转移/结算；争议受理机关：有权复核/裁判。前端不得指定有权决定人。

**业务状态与事实结果分轨：**

| 案卷/事件的业务阶段标签（研究建议） | 进入前提 | 退出条件及禁止事项 |
|---|---|---|
| `FACT_REVIEW` | L0–L2 有真实发起事件 | 发出证据问题/送达核验/政策待确认，不改变人事关系 |
| `WAITING_MATERIAL_OR_SOURCE` | 存在真实当前阶段缺件、不可读或权威来源不可用 | 取得新材料版本后定向重审 R；不能自动视为不准辞职 |
| `WAITING_POLICY_OR_AUTHORITY` | 现行制度/身份适用/签发权限未核 | 校本负责人确认来源、权限和适用范围；不得使用旧规则默认值 |
| `READY_FOR_AUTHORIZED_ACTION` | 相关事实已核，法律/校定动作仍需有权人核 | 人审并留记录；对依法通知路径是**法律效果核实**而不是新增“准辞职”审批 |
| `EFFECT_RECORDED` | 有真实合同/法定事实及有权人员核定记录支持 F034 | 可开启对应后续交接；不得凭这行状态自动制造解除证明 |
| `HANDOFF_IN_PROGRESS` | 已进入 L5，至少一个真实部门办理项 | 每项由其负责单位签收；未完成不逆向改 F034 |
| `POSTPROCESS_RECORDED` | L6 各适用的转移/结算状态已如实登记 | 可有财务争议或独立待办，不能推断所有权利义务终止 |
| `DISPUTED/CORRECTED`（并行标志） | L7 有可核争议/纠正事件 | 原决定是否停止、变更生效按真实权威文书处理；不能因提交申诉就自动撤销 |

`WITHDRAWAL_REQUESTED`、`MATERIAL_REPLACED`、`REVIEW_REQUESTED` 是**追加事件标志**，不是可覆盖历史的统一案卷结果。案例显示可说明“撤回已提出、待有权确认”，但不能显示“撤回成功”而没有可信确认。审查问题和事项最终法律效果分开展示，原则上对本人只暴露其可访问的依据与事项，不泄露处分、病历和涉密项目原文。

## 11 补件、撤回、版本更新、复核与人工决定

**第四轮生命周期事件（契约，不声称现有客户端已有按钮或 API）：**

**冻结和定向失效原则。** 一个事实结论存 `ruleId + target(person_key, contract_ref, event_id) + stage + sourceVersion + policyVersion + materialVersionRefs + issuedAt`。发生替换时先对**材料/政策版本与 F 实际依赖图**求直接命中 R，然后只沿实际依赖传播；其余 R 和可信正式决定历史原样保留。重新审核得到新 R 记录，不在旧 R 上改码；下表为设计时的预期依赖，最终以逐 R 声明为权威：

|---|---|---|---|

**撤回、纠正与救济的状态保护：** `撤回已提交`、`被接收`、`是否有效`、`已重新发起`、`复核申请中`、`有权纠正生效` 是不同事实；只用可核事件/文书更新对应标志。某些法律权利行使不以学校“批准”发生效果，不能设计一个通用“审批拒绝即辞职无效”按钮。若处理所需权利告知、申诉渠道、异议期限未核，结果是 `POLICY_UNCONFIRMED` 和专责人工待办，不是申请人自动逾期。

**可信决定写权与人机边界。** 研究契约假定 V3 案卷 Owner 保存决定/事件、可信身份由 Main 受控源鉴权；**尚未验证指定技术 SHA 的实际实现**。Renderer/LLM/OCR 只输出候选、问题与证据指向，不得把前端传来的 Actor 或扫描公章转成可信 `Decision`。当实际后端无法取得合法 Actor/权限证明时，只能登记“拟提交有权人”的待办；不生成真实决定、Outbox 或具有学校法律效果的状态。任何所谓旧 `run@rev` 不能被当成真实 ReviewRun 或法律决定。

**不自动裁定（高影响保留人工）的最小清单：**

1. 什么法律关系、哪一条法定解除/终止/特别解除路径适用；具体通知期间的起算点有争议、试用期与另约效力不明时（R002/R004/R008/R020）。
2. 单位是否满足依法可解除条件，是否存在法定保护、争议中的年度考核或正式处分，及当事人程序权利是否得到保障（R009–R012/R016）。
3. 谁有学校或真实雇主的决定权、签署权、复核权；历史授权和伪造 Actor 均不可替代（R005/R017/R018/R028）。

5. 服务期、保密/涉密、人才计划及经济补偿/违约金的合同效力、合法范围和金额（R015/R023/R027）。

**配置缺失时的降级方案。** 可以继续作可核的文书存在性、同人同合同归属、材料可读性、后续部门反馈等事实预审，但与未知校本政策直接有关的 R 输出 `POLICY_UNCONFIRMED`；与法律评价/批准有关的节点输出 `NEEDS_HUMAN_DECISION`。不补造伪“可运行标准”；也不因配置缺失阻断其他互不依赖的事实核对。
