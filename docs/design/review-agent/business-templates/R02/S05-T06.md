## 01 唯一审核目的、申请人和负责机构

**唯一业务对象**为 `appointment_record`：`personId + organizationId + positionId + termId + appointmentDecisionId` 所指向的一段任职事实，以及这段任职的 `performanceAssessment` 和 `experienceAttestation` 版本。任职批准、岗位变更、在任履职、届满评价、出具经历证明、证据更正，是这一对象的不同状态/用途，不另拆 S05 模板。

1. **发起人**：本人申请认定/出具经历证明/更正；班团/学生组织负责人或主管老师依合法职责发起岗位登记、考核与退出；毕业生可申请历史证明（是否允许补办及程序待校本配置）。普通学生不能替他人任命，也不能凭上传公示照片取得后台管理写权。
2. **在任事实有权来源**：产生任职的选举/任命机关、组织指导部门、授权组织档案管理员及其可信任免记录。校学生会主席团产生与工作部门负责人任免程序可能不同；校团委学生兼职副书记亦有专项遴选与考核。必须按 `organizationType × level × position × applicableTerm` 配置，不假定“辅导员一签全校有效”。[SRC-003][SRC-004][SRC-005][SRC-013][SRC-016]
3. **履职有权来源**：该任职岗位的指导教师、组织考核主体和正式述职评议记录；个人述职、活动签到和同学评价仅为输入证据，不能代替正式评价或授予“合格”结论。[SRC-008][SRC-013][SRC-014][SRC-021]
4. **经历证明有权签发人**：原任职组织或已获授权保存档案的部门；是否由学院学工办、学院团委、校团委、班导师/辅导员/学院党委等分别出具，必须凭校本授权矩阵落地。`S05-T06` 可草拟证明，签发状态只能消费可信签发结果。
5. **三个互不替代的输出**：A 任职身份/起止事实，B 某考核期履职评价事实，C 证明签发事实。`A=PASS_FACT` 不推导 `B=合格`，`B=合格` 不推导 `C=已签发`；三者都不直接授予奖项、推免加分、第二课堂学分。[SRC-009][SRC-010][SRC-011]

## 02 适用、排除与邻接模板路由

| 用户表达/已有事实 | 此模板仅处理 | 路由/不得重复处理 |
| --- | --- | --- |
| 班委、团支委、校院学生会/研究生会、团委学生兼职干部等任职登记 | 来源确认为有效学生干部岗位的任职/履职/证明记录 | 原组织资格、岗位权限按配置核实；党支部任职由相应党组织确认，不以团委取代 |
| 学生社团会长等岗位任职 | 有已有效社团实体下的个人岗位与任期证据 | 社团成立、年检、换届的**实体资格**归 `S05-T04`，仅引用其生效决定；不能以个人经历认证替代社团换届批准 |
| 组织具体活动、策划成果 | 可引用经核实的本人角色/工作日志作为履职证据 | 活动责任及立项归 `S05-T05`；场地/宣传空间 `G03`、群体安全 `G04`、经费许可/付款 `G07` 分别出独立决定；不在这里重批 |
| 学代会/研代会代表、提案 | 某人另有正式学生干部岗位时仅认其任职 | **代表资格与提案征集/立案**归 `S05-T07`；代表身份不等于干部任职，提案不是 `g08-t03` 一般投诉 [SRC-016] |
| 评优、优秀学生干部、奖学金、推免加分 | 仅提供被签发的任职及考核事实供引用 | `S03-T05` 荣誉、`S03-T01` 综测、`S03-T02/03/04` 奖助、`S07-T09` 推免各审自己的资格、期限、计分和去重；不得直接复用其加分门槛为此处任职门槛 [SRC-009][SRC-010][SRC-011] |
| 第二课堂、志愿/劳动服务、实践 | 不把干部任职自动换算任何学时 | `S05-T01/T02/T03` 及 `S06-T05` 各基于自己正式记录独立认定；只消费可验证事实 |
| 干部申请任职而实质涉及普通人事用工 | 此处只处理学生组织兼职/志愿性质岗位的学生干部经历 | 教师/编外人员聘用、专职岗位不归此处；不能冒充劳动关系或社会保险证明 |
| 档案调阅、证明用印、基础身份纠错 | 输出任职经历核实结果 | 普通个人证明末端用印 `G01`，系统身份数据纠错 `G01`；任职单位确认记录后下游只引用记录，不重验岗位 |
| 公共诉求、处分异议 | 任职/履职决定的更正或复核仍在该任期事件链；仅核其受理条件 | 一般行政服务投诉 `g08-t03`；纪律处分申诉 `S04-T06`，处分解除 `S04-T07`；不得用本模板裁判纪律事实 |

**去重主键**首先以任免决定/任期对象去重，不是“同一年一个人只能认一项”。同一组织的不同岗位、多次连任可能对应不同任命；不同组织可同时任职；只是**不能把同一任免事实或同一工作日志复制成两个互相矛盾的任职或加分结论**。学校推免批次中的“同一组织取最高职务”或“每类别只记最高分”是下游特定评价口径，不是本模板全局删档法。[SRC-009][SRC-010]

## 03 业务生命周期与办理情形矩阵

**状态图（研发契约）**：`DRAFT → SUBMITTED → IDENTITY_CHECKED → APPOINTMENT_FACT_CHECKED → (ACTIVE ↔ CHANGE_PENDING) → ASSESSMENT_PENDING → ASSESSMENT_FACT_CHECKED → SIGNATURE_PENDING → ATTESTED`。旁路 `WITHDRAW_REQUESTED / WITHDRAWN`（仅允许未签发的申请撤回，历史任命不因撤回申请而消失）、`CORRECTION_PENDING / CORRECTED`、`REVIEW_PENDING / REVIEW_RESOLVED`、`SOURCE_BLOCKED`。终态由有权人的有签名决定事件形成，不由模型判断。

| 情形 | 发起人与适用身份 | 阶段/前置 | 当前应有证据 → 后续才有 | 结果/有权人；撤回与复核 |
| --- | --- | --- | --- | --- |
| C01 学生会/研会主席团候选与选举 | 有资格学生；本/研分流 | 选拔期；届次、选举资格规则已配置 | 当前 `M001–M005` 中按实际公开/选举流程启用；**未来任命/聘书、期满考核不得提前报缺** | 候选资格及选举任命由有权组织；无权申请者 `POLICY_UNCONFIRMED` 或转主管；异议交选举机构 |
| C02 校团委学生兼职副书记选任 | 相应学段学生 | 专项公开遴选/公示/聘任 | 专项通知、报名、选任公示/聘任事件；中期、任期考核**后置** | 校团委真实选任与考核；2026 批次可引用 [SRC-003][SRC-004]，不能推广到所有岗位 |
| C03 班委/团支委等岗位登记 | 在读或可追溯历史在读身份 | 班级/支部程序及有权记录 | 选举/任免和班导师/团组织可信确认；无统一全校表单时替代证明待主管核 | 班/团有权组织决定；无章程时 `POLICY_UNCONFIRMED` |
| C04 社团负责人登记 | 组织依法存续、换届记录已产生 | 引用 `S05-T04` 生效组织/换届状态 | 人员任命/社团备案；不要求申请人再办社团成立 | 原主管/指导单位；与社团状态不一致 → `CONFLICT` |
| C05 在任中期履职 | 已生效任命 | 考核周期已到、组织有考核制度 | 期间述职、服务记录、监督意见；期满证明未到期 | 有权考核组评定；未到考核期 `NOT_APPLICABLE` |
| C06 任期届满经历认定 | 任期已结束或允许区间证明 | 有权任命记录与届满依据 | 原任免、变更记录、期末述职评议、任期合格结论；签发件后置 | 组织考核/签发人；复核按现行程序 |
| C07 提前辞职、免职、调岗 | 在任者或原组织 | 实际退出/变更事件 | 本人申请、原组织解除/调整决定、交接及实际截止日；未来补证不作为前置 | 未签退出决定不得自动改写任期；拟退出可撤回申请 |
| C08 连任、跨届重任/兼任 | 同一/不同组织多记录 | 要求各任命对象可分辨 | 每届/每组织独立任职依据；在时间重叠时核履职矛盾 | 不因时间交叠自动拒绝；重复申请合并事实、去重签发 |
| C09 毕业后补开历史证明 | 曾在任学生/合法代理 | 仅可读历史证据 + 申请授权 | 旧档案、编号/组织名迁移证明、当期归档权限 | 无历史档案→`SOURCE_UNAVAILABLE`，不以“毕业了”自动否认经历 |
| C10 更正任职起止、职务、成绩 | 本人、有权管理者 | 错误记录已定位 | 原版与更正证据、修正原因；原记录留审计 | 有权记录主管签更正，回滚下游依赖事实，不更改原文 |
| C11 补件/材料重传 | 待办目标申请人 | 证据缺项/不可读 | 仅重新提交与问题相连 `M` 和来源版本 | 只重跑依赖的 R，不补无关申请 |
| C12 申请撤回、复核/申诉 | 本人/有权代理 | 正在办理或已有有签名决定 | 撤回请求/复核理由、原决定及证据快照；复核结论后置 | 撤回仅终止待办流程；已生效任免/考核须通过正式变更或复核纠错 |

**组合强制项**：`C02 + C05 + C06` 仅在考核期间到达后启用考核材料；`C04 + C08` 同时取社团备案和独立岗位任命；`C06 + S07-T09` 下游拿经历记录单独计算本届推免，禁止反向把推免一年门槛写进历史任职事实；`C10 + C12` 复核应绑定原决定版本。

敏感信息只收学号、必要姓名、岗位/任期事实、核验联系方式；身份证号、政治面貌、纪律、成绩详情、同学评议原话和投诉人身份应在特定合法用途、最少范围、分级授权且已告知/取得相应合法处理依据时才能触达。私密评价可由有权源返回 `assessmentDecisionRef` 与最小状态，不要把全量原始意见给下游。[SRC-018]

**禁止越权例**：学生活动合照≠活动负责人任命；指导老师微信同意≠学生会主席团选举；OCR“学院团委章”≠签章验证；签发对象不一致/被撤销版本不可重用；交叉组织的另一部门不能凭“看到材料齐全”替原主管签发。

## 08 审核规则逐条清单

**判读契约**：以下每个规则仅有一个主核验对象。`T` 为证据能支持该事实；`F` 为证据明确否定/互斥事实；`?` 为未能判定，进一步分 `NEEDS_MATERIAL`（当前应有、申请人可补）、`UNREADABLE`（已交而无法识读）、`SOURCE_UNAVAILABLE`（学校/签发方可信来源不可达）、`POLICY_UNCONFIRMED`（适用标准或权限未核）、`NEEDS_HUMAN_DECISION`（冲突、效力/裁量只能由主管决断）。`CONFLICT` 指两个有效候选证据不一致，不能隐式择一。`PASS_FACT` 只确认目标事实，`NOT_APPLICABLE` 不表示否定任职。下列规则引用的 `SRC` 只能支持其限定部分；涉及“待配置”的事实校验依据来自正式配置后绑定的 `M016/F033`，没有配置时**不得凭下表硬判**。

## 09 触发条件、冲突和复合场景

1. **先路由，后分槽，再核事实**：拖入一个聘书或多份材料先抽 `F003,F007,F011,F013` 的候选，不据“优秀学生干部”字样直接认定为任职；若可能是 `S03-T05` 荣誉则列歧义让用户选。没有覆盖业务则 G50 通用兜底，不为它创建伪 S05-T06。
2. **缺少少量当前阶段证据**：对已满足证据的规则照常返回 `PASS_FACT`，缺件细化 `NEEDS_MATERIAL`；初审后补件。不能因未提交将来才生成的期末评议、证明印章而报缺或拒绝任职登记。
3. **两个原件冲突**：比如校级选举结果与任命档案对同一届日期不同，输出两个来源引用、版本和冲突字段，交同一任命主管；学院指导教师证明不能自行“调和”校级源。原任命已撤销或更新，触发依赖重审而非直接采用旧截图。
4. **跨组织兼任**：校团委兼职副书记与院学生会工作部门负责人可能同时存在。分别保存任免 `ref`，不得自动认作重复骗分。若同一时间的实际履职记录互斥则 R026 出问题；“可否兼任”“是否允许重复计分”由各自当前制度决定。[SRC-009][SRC-010][SRC-014]
5. **历任岗位的升级**：干事→部长或副部长→主席团，须有变更/新聘任记录及实际起止。不能拿最高头衔回填此前整学年的起止，更不能把一个聘书复制成三届记录。特定推免“同组织取最高级”只在下游合并计分，不删原始履历。
6. **提前退出**：若有正式辞职或免职决定，仍可存“曾任该岗位至某日”的事实；是否在某用途视为“完成任期”须当期规则。撤回“证明申请”不意味着撤销原组织任免。辞职申请未批准时不擅自改任期。
7. **考核结果冲突**：学生自称优秀、教师邮件称合格、正式台账记不合格，以有权签发台账为拟采用权威；但原台账若有可信更正证据需 R021/R030 复核。模型不能自动改考核分级。
8. **制度与证据分离**：2025 计算机学院 2026 推免规则可用来说明某届次证明的接受方式，2026 机电公开表 **2027-01 才实施**，不能用来计算 2026-10 的本案任期或评分。[SRC-009][SRC-010] 当前校本没有统一认定门槛时输出 `POLICY_UNCONFIRMED`，但可已核事实不回退为缺件。
9. **社团换届/活动相互独立**：若当届社团组织资格失效，S05-T04 的决定只是组织状态事实；原任职经历是否仍可证明由原档案主管核。活动被 G04 安全退回或 G07 经费未批，不自动抹除合法任职，也不在本模板重新批活动。[SRC-002]
10. **公示、个人证明和不同截图**：拟任公示、履职报道、证明草稿均可成为旁证，只有签发角色/文号/版本可证实后才成为其所述决定；缺少签发接口时 `SOURCE_UNAVAILABLE`，不依据水印或 OCR 自判有效。

优先级：`越权/身份失败` 停止敏感访问 ＞ `源撤销/错误版本` 使旧结果失效 ＞ `CONFLICT` 标明来源差异 ＞ `UNREADABLE` 与 `SOURCE_UNAVAILABLE` 区分可控责任 ＞ `NEEDS_MATERIAL` ＞ `POLICY_UNCONFIRMED`/`NEEDS_HUMAN_DECISION` ＞ 可核项目 `PASS_FACT`。这是问题呈现优先级，不是跨所有规则的单一“整案总分”。

## 11 补件、撤回、版本更新、复核与人工决定

**幂等与 CAS**：决定事件使用 `eventId + actorScope + aggregateId + expectedVersion`；重传使用 `slotId + materialId + sha256 + sourceVersion`，完全相同的重传不导致双份经历；不同 hash 产生新证据版本并标明影响图。冻结 D2 Plan 时以 `planId + fingerprint + Check×target/sourceVersion` 复核；若 sourceVersion 更改，旧 observation 失效。批量的真实 entryRunId 与 finalizer 绑定，Renderer 的 actor 字段永远不可信。

**补件例**：一张聘书可读且与档案一致（R007–R009 PASS），但只有个人述职、无评议签发（R018 SOURCE_UNAVAILABLE）；本轮可交事实预审并把唯一“考核结论核实”待办派给主管，不索取未来正式证明（M014/M018）。取得新的考核决定后仅重跑 R017–R018、依赖的 R020/R024/R025，任命事实不重复跑。

**撤回例**：本人撤回“补开就业用经历证明”的请求；系统停止签发流程，但原班委任职记录保留。若要撤销“班长任命”则必须由原任命机构按校规决定，不能通过本人的申请撤回事件直接删除任期。

## 14 完整性自检、遗留缺口与变更请求

### 14.1 受控编号、双向引用与状态

- 当前索引：`SRC-001–SRC-021` 共 **21**，`F001–F036` 共 **36**，`M001–M020` 共 **20**，`R001–R030` 共 **30**。四组各从起点连续至终点，不继承不存在的旧编号。
