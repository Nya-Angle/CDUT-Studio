## 01 唯一审核目的、申请人和负责机构

### 01.1 事项是否真实存在

**存在。** 学校官网“学生”栏目明确设有“学生请假系统”入口（`SRC-007`），本科学生学籍管理办法第 20–21 条设请假、续假、销假程序（`SRC-001`）；研究生学籍管理办法第 13、22 条等涉及请假及长期请假转休学（`SRC-002`）；学校 2024 年研究生外出通知附《研究生外出（请假）申请表》（`SRC-004`）；2026 年春季开学通知要求对未按时返校者联系、核实原因并履行请假手续（`SRC-005`）。这足以确认业务事实，**不能仅凭网页入口推断所有身份均用同一线上流程**。

### 01.2 申请人、代理人与决定对象

- **通常申请人**：有相应在校学生身份、因事／病等不能按时参加学习或须离校的学生本人。应先以校方可信学籍／培养关系确认所属学院、学段和管理类别。2019 本科办法第二条适用全日制普通本科生；2021 研究生办法第二条覆盖全日制及非全日制研究生；2022 来华留学生办法需单独辨别“本科生”条文的适用范围（`SRC-001/002/003`）。
- **代为通知不等于代理审批**：本科生在获准后不能直接报告任课教师时，可委托同学报告；不可抗力时可先口头报告、事后补手续。这是特定通知／补办行为，不等于任何同学、家长、Renderer 字段可以作为申请人或审批人（本科第 21 条，`SRC-001`）。正式代申请权限、监护人代交机制尚无校本完整依据。
- **本模板决定对象**：只核“请假及后续阶段的申请事实、材料、流程与权限是否匹配”，生成有凭据的建议与待办。实际有效的“准假／不准假／续假同意／销假记录”须来自学校对应授权者与流程；本模板的 `PASS_FACT` 只表示所核事实成立，**不是准假**。

## 02 适用、排除与邻接模板路由

### 02.1 本模板内统一处理的情形

1. 在读学生因事请假、因病请假（短期／长期仅为期限情形）、不可抗力事后补假。
2. 已批准请假在到期前或到期时提出的**续假**；不在原申请中预收续假才会产生的证明或审批单。
3. 到校后的**销假**、返校事实确认，及返校情况与请假台账不一致的查证。
4. 同一学期累计请假接近或跨越本身份适用的休学转办门槛：本模板只核事实并发出**转办提示**，不审批休学。
5. 校本来源明确涉及的研究生因私外出与普通离校请假，但因公科研实践、团队出行的独立任务授权仍由相应外出安全／活动审批事项处理。

**最终暂不提出 `CATALOG-CHANGE-REQUEST`。** 事假、病假、续假、销假共同指向同一人同一请假链，适合在一模板内按状态／学段区分。G50 已核实有关活动／出境／费用事项的独立技术目的，但它们并非另一个个人准假模板；研究生因公外出独立权力仍待 `SRC-012` 明示，必要时再提目录变更，保持本 ID 不变。

### 05.2 可信数据分层与校验边界

1. **身份可信来源**：校方登录态和服务端可信身份映射（人员标识、学生类型、学院／培养单位、导师关系、职务和委托权限）；具体 API 未调研。Renderer、OCR、表单上传文本中的 `actorId`、`role=teacher`、`approved=true` 均作**不可信主张**。
2. **原始证据**：请假单、医院证明或相关材料、研究生外出表、续假附件、返校记录；保留文件版本、提交人、获取方式、时间、签署及原文件引用。OCR 对“日期”“医院”“签名”只做识别，不作真伪鉴定。
3. **校方权威结论**：有效准假／联署记录、正式续假审批、销假确认、课程考勤更正、休复学状态；必须能追溯到系统签名事件或人工核实的文书原件与有权签署者。没有事件来源不得写 `approved=true`。
4. **导入与跨业务**：对 G50、S01、S02 的外部结论，记录来源事项／记录 ID、决定类型、适用学生、适用期间、发布者及验证状态；不能拿 AI 摘要替代原决定，也不因旧案卷“曾经通过”而沿用到新时段。
5. **时间与版本**：原申请、批准、续假、返校应为分阶段事件，各自独立记录；原文书和历史审查结论不可静默覆盖。真实学期边界和累计请假规则须由校方配置／确认，不能由截图或模型补算固定有效性。
6. **敏感信息**：医疗诊断、紧急联系人、外出地点属于高敏感个人材料；后续字段设计应作最少必要获取、分级展示、审计与保留期限核实。当前**未取得**校本保留期限、知情授权机制，不得编造数值。
7. **高风险转办**：累计请假触发休学调查、未准假旷课、可能退学、涉及病情是否适宜复学等均是**政策与人判断**。Review V3 只提示 `NEEDS_HUMAN_DECISION` 或相关问题，不可用 AI 事实预审伪装正式决定。

### 05.3 待核验的权限与流程细节

- 2026 年实际“学生请假系统”与 2024 年研究生线下表的覆盖关系，是否已上线并有可靠审批日志／销假功能；通用“砚湖易办”委托操作与专门请假审批委托的关系。
- 研究生院、学院、国际教育学院对**不同学段、时长、病假、跨学期**的最新签批矩阵；越权签批如何纠正。
- 撤回已提交未批准申请、撤销已批准请假、异议复核及纠错记录的授权人和生效时点；不可简单把第 44 条涉及学籍处理决定的申诉流程套用于所有普通请假。

### 05.5 版本、来源与最小披露

- 主键建议为“学生可信标识＋本次独立请假链 ID＋阶段事件 ID”；续假保留 `F036` 指向旧批准，不能把先前的申请日期、意见、原材料覆盖掉。一个附件被替换产生 `F047/F048` 新版本关系，原核验结果标**历史失效**，仅重算依赖该证据的事实检查和受影响下游决定建议；**不得撤销校方已生效决定**。
- `F050` 标来源版本／政策生效日；当旧校规被新规取代，重审时先判断“该业务行为发生于何时”，不直接以 2026 规则追溯否定历史合规申请。
- 母表、身份系统与实际电子审批之间没有既定 API 证据。`T3` 是**可接受的校方权威记录形态**，不是声称 Review V3 已接入教务、学工或统一身份系统。失联应作人工查证而非强迫学生上传所有后台台账。
- 病历正文、家长联系电话、外出住址按 `P3` 最小披露。Reviewer 只处理“诊断或相关材料能否支撑请假期间”所必需片段，非有关医疗细节不进入普通问题摘要；保存期限与访问授权待校方核实。

### 07.2 阶段最小集原则与优先级

1. **对申请人当前必须交的，只有当期申请载体及该身份／假别已明确要求的当期证明。** `M001/M017/M020` 是校方核验事实源，不是普通学生应“补交”的纸质证明。`M006/M007/M014/M015/M023` 都存在产生时点，不得在 L1 求齐。
2. 同一证据目的可**引用而不复制**：正规线上申请与有效纸件 `M002` 可择一；2026 国际学生新表 `M024` 是否替代 `M012` 尚不能判断，绝不要求同时交两份。病假 `M003` 中“医院证明或相关材料”由学校裁量等价；学生本人拍照、平台提醒、OCR 识别结果不是天然权威证明。
3. 对 `M006/M018/M020` 这类校方决定或权限凭证，处理原则是先尝试可信受控查询／人工向主管部门核实；只有校方明确规定需要申请人提供可核原件时才请求材料。接口不可用记 `SOURCE_UNAVAILABLE`，不记申请人未交。
4. 版本绑定为 `(F001, student F002, phase F012, episode F015–F016, M-ID, F047, F050)`；一份诊断证明可能支持多个相关区间，但**复用必须再次核有效覆盖范围**。没有合法版本关系的“覆盖文件”不自动销毁原件、旧结论或已生效批准。

## 08 审核规则逐条清单

### 08.1 规则执行口径与三值条件

以下 `R001–R038` 每个 ID 对应**一个独立的事实对象或流程权属问题**，不代表学校批准。表中 `T` 为触发条件成立并执行核验，`F` 为该规则不适用（`NOT_APPLICABLE`），`U` 为触发条件无法证明；在触发为 T 时，核验结果又分事实成立、材料缺失、相互冲突、不可读、权威来源失联、政策不明、人类裁量。不能把“T=触发”误当作“PASS_FACT”。`P` 表示阶段；`T0–T3` 信任等级见05.4；`S` 表示签发部门或校方受控来源，`A` 表示申请人可提交材料。所有规则必须存原文证据槽／文件版本／页位／时间与目标人；引用多文件者记录每个独立证据的版本，不只引用文件夹路径。

**共同异常优先级（每 R 都执行）：** (1) F 明确不适用→`NOT_APPLICABLE`；(2) T/U 无可信适用政策且关系到强制性条件→`POLICY_UNCONFIRMED`；(3) 必需校方或原业务来源不可用→`SOURCE_UNAVAILABLE`；(4) 当前必需的申请人材料尚未提交→`NEEDS_MATERIAL`；(5) 已提交但关键部分不能读取→`UNREADABLE`；(6) 两份可读证据互斥或可信身份不匹配→`CONFLICT`；(7) 需要验证真实性、当事人合理性、签发权限或行政裁量→`NEEDS_HUMAN_DECISION`；(8) 所有本规则可机械比对的事实都得到足够证据且无上述阻碍才→`PASS_FACT`。顺序用于同一目标多个阻塞原因时确定主码，其他不同根因可作独立问题；不得因第(2)项政策缺失，掩盖已可证实的其他事实冲突。**正式学校批准的唯一载体是另行可信 `M006` 决定事件，绝非上述任一结果码。**

**引用简写解码**：规则单元格的 `SRC-001/003/017` 表示分别引用 `SRC-001`、`SRC-003`、`SRC-017`；`F002–F005` 表示含首尾的连续字段，每项均在第06节定义；`M002/M003` 同理。执行解析时须展开为完整 ID 后验证，不允许创建 `SRC-003/017` 这样的未定义新ID。**缺原文的 SRC 可作为政策失联的追踪目标，不能充当支持硬性结论的证据。**

### 09.2 版本、材料归属与证据层级规则的准备约束

1. **唯一归属**：`caseId + studentPersonId + episodeId + materialSlotId + sourceVersion` 共同定位一次材料事实；一个文件可被多个槽引用，但每个核验结论必须标注其具体所依赖的槽、页面／条款、字段、来源版本及产生时间。
2. **主从关系**：原申请 `M002/M009/M012` 与批准 `M006` 是不同权力事件；续假 `M008` 引用原批准，不把原始审批单复写成“新批准”；返校与销假 `M014/M015` 又属于后续阶段。含多个病假段时，诊断材料 `M003` 的覆盖日期逐段关联，不能跨段推定有效。
3. **证据冲突阶序**：可信校方业务系统的原始决定事件／核实文书优先于申请人填报；文件签发原件优先于转述或 OCR。**优先级不是无条件覆盖**：校方记录也须校验本人、时效及有权签发；两份权威来源互冲时保留双证并交授权部门解决。
4. **覆盖与失效**：替换 `M003/M008/M014` 时仅使依赖旧材料版本的**候选预审结论**失去当前效力，并触发受影响 F／后续 R 重新评价；保留历史审计链。对已生效正式决定只可提出复核或更正待办，不能自动删除、重写或追认。
5. **最小数据处理**：可从学校权威来源取得 `M001/M006/M017/M020` 时保存可信引用与必要字段即可；不得以“对机器好识别”为理由强索完整医疗病历、无关家庭隐私、其他班级学生的集体出行名册。

### 09.3 五个材料／字段级反例

- **反例 A｜一日病假误强索**：`F005=国内本科、F013=病假、F017=1天`，流程却强制缺 `M003` 即拒绝。`SRC-001` 的病假“超过一天”触发被误扩大；应先查精确天数口径，当前不直接按大于一天处理。
- **反例 B｜同名与越权混用**：上传名为张某的签字请假单，`F003` 学号对应另一名同名学生，且 `F033` “辅导员”仅来自图片 OCR。两个独立问题：`M001` 身份归属冲突、`M020` 审批权未获证；不得因签名像真而记为已准假。
- **反例 C｜续假覆盖旧证**：原假期 1–3 日已批准，学生 3 日提交延至 7 日的新单；后续以 1–7 日合计作已批，且重复计入 3 日。正确做法是保留原决定，仅把 4–7 日作为待批新增期间并对重叠计数去重，具体学期算法待校方确定。
- **反例 D｜医嘱与返校相撞**：医生材料只覆盖至 8 日，学生申请至 12 日，学校门禁显示 10 日进校，本人 8 日上传返校说明。`F027/F016/F040/F041` 相互冲突；既不把医嘱冒充全段证明，也不把入校等同正式销假。
- **反例 E｜来华留学本科与研究生混用**：国际研究生按 `SRC-003` 中留学本科“一周以内”流程要求其提交 `M012` 并默认相关人员批准。`F005/F006` 人群不一致；应标 `POLICY_UNCONFIRMED` 并由国际教育／研究生归口确认，不强索 2026 未读表单 `M024`。

## 10 结果状态、问题与待办输出契约

### 10.1 八种结果语义（每个 R × 目标 × 当前证据版本恰有一种）

| 结果码 | 严格成立情形 | 典型后续动作／不得推断 |
| --- | --- | --- |
| `PASS_FACT` | 可核现行政策与适用人群；规定所需事实在对应原件版本／可信记录可复核且彼此一致；**仅该条事实核查通过** | 交下一校方经办人继续，**不是准假或销假决定** |
| `NOT_APPLICABLE` | 该 SC、阶段、假别或条件触发被**可靠证据证明为假**，而非信息缺失 | 不索取本分支材料；不得把未来 `M006/M015` 当当前缺件 |
| `NEEDS_MATERIAL` | 明确适用于本阶段、责任归申请人、未由可信系统提供且**政策已确证必需**的材料尚缺 | 指向某一 `M` 与学生／材料持有人，列合法替代；未知规定不得选此码 |
| `CONFLICT` | 同人同阶段同假段的两个可读取版本或来源，其身份、时间、结论或角色互相矛盾 | 展示双证据与来源，交有权部门核实，不自动选较新文件覆盖 |
| `UNREADABLE` | 应读的实际文件缺页／损坏／OCR 无法可靠识别必要片段，而非实际没交 | 仅要求可读原件或人工复核该页；不得据识别失败推“证明不存在” |
| `SOURCE_UNAVAILABLE` | 本应从学校／跨业务权威来源读取，但接口、原件或受理台账当前不能取得 | 发校方核源待办，不能把校内权限材料转嫁学生 |
| `POLICY_UNCONFIRMED` | 没有对该人群与发生日有效的校本条文／算法／审批程序，或有新版但尚缺正文 | 请求主管部门核现行版本及具体条款；**不得套旧版自动阈值** |
| `NEEDS_HUMAN_DECISION` | 事实已可表达但适格性、不可抗力、诊断真实性、签批、合法撤销等属有权人员判断 | 发人审待办；仅在校方签发正式决定后才能记录对应权威事件 |

这些结果只适用于**一条事实规则**，一个案卷可以有多条不同码，不设“全案自动 PASS=校方批准”。在**同一 R 同一目标同一证据版本**出现多个障碍时，按08.1的固定顺序显示主结果、保留可追溯的次级原因；不同目标独立出码。例如一份损坏的学生医疗附件为 `UNREADABLE`，另一个学校学籍接口失联应另发 `SOURCE_UNAVAILABLE` 问题；已确认的身份冲突不因别的规则政策未知而消失。不得把“缺件”泛化成所有错误，也不得用优先级覆盖已有校方权威决定。

### 10.3 案卷状态与校方决定是两条独立轴

| 预审／协作状态 | 学校正式决定状态（仅可信来源可写） | 意义 |
| --- | --- | --- |
| `DRAFT`／`NEEDS_INPUT`／`FACT_CHECKING` | `NOT_ISSUED` | 新案／缺当期资料／核事实；绝不缺 `M006` |
| `FACT_READY`／`WAIT_HUMAN` | `NOT_ISSUED` | 事实可审阅或有裁量待办；**材料齐≠批准** |
| `FACT_READY`／`WAIT_AUTHORITY` | `ISSUED_APPROVED`、`ISSUED_DENIED` 或 `ISSUED_RETURNED` | 必须有 `M006`、有效审批人 `M020`、签发时点／对象；拒绝也是**校方**决定 |
| `RETURN_PENDING`／`CANCEL_PENDING` | 原决定状态保持 | 学生声称返校与正式销假不同；`M014`／`M015` 时点错开 |
| `SUPERSEDED`／`RECHECK_NEEDED` | **不自动改变**原正式状态 | 新证明只使依赖它的旧预审失效；法定改批另发新 `M006` |
| `WITHDRAW_REQUESTED`／`REVIEW_REQUESTED` | 原决定不变直至有权新事件 | 不能将“提出”当“同意撤回／复核成功” |

决定事件由学校权威持久化主体独占写权；Review V3 模板只提出事实与建议。不得用客户端 `renderer.actor`、上传文书内“approved”字样或技术 run 记录制造校方 Decision。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 事件驱动闭环与时序约束

| 当前阶段→下一事件 | 允许的事实输入及产生的记录 | 权属与不可跳过的门槛 | 对已存在决定的效力 |
| --- | --- | --- | --- |
| L0→L1 建案提交 | 校方身份 `M001`＋本人当期申请 `M002/M009/M012` 或校方核准渠道，建立 F001 与原件 `F047` | 学生及可信受理员；身份未知先核，不自动拒件 | 尚无 `M006`，不得标缺批准 |
| L1→L2 事实预审 | 仅当前触发 `F/M`、现行 `SRC`，按 R 输出逐条状态及待办 | 规则核验器可提出事实，归口人员决定适格性 | 不产生“批准” |
| L2→L3 补正／不可抗力追认 | 学生或校方按所有权提供新 `M`，`M022` 记录替换；初报 `M004` 与书面 `M005` 独立 | 补件被接受不表示不可抗力获认定；本科两工作日需学校校历核 | 旧预审定向失效，不改正式决定 |
| L2/L3→L4 可信批准／不批准／退回 | 形成 `M006`，绑定具体 `F001/F002/episode/申请版本/签字岗位/签发时点` | 本科三种分级按 `SRC-001`；其他人群现行权限不足停人工；两签不可复用同 actor | 原始申请保留，决定独立不可变 |
| L4→L5 通知／续假 | `M007` 教师报告；续假 `M008` 新申请引用原有效 `M006` | 续假**再次审批**，不能用旧准假日期自动延长 | 新 episode 对未来时段生效，以新决定为准；原决定历史不改 |
| L5→L6 返校／销假 | `M014` 的本人申报、校方核实；学校后续形成 `M015` | 本科向辅导员或批准人销假、研究生按外出表到培养单位；国际本科具体收件规则待核 | 销假记录不等于改写请假审批文本 |
| 任意适当阶段→L7 转办／撤回／复核 | `M018/M021/M022/M023` 关联原案与接收时点 | S01/S02/G50仅原业务有权决定；普通请假撤回复核程序无现行原文即停人工 | 不删除原 `M006`，有权新决定应形成新事件及生效关系 |

所有 L 阶段不是一条必须顺序完成的“UI 流水线”。突发先口头告知（L3）可以发生于纸质申请（L1）之前，但应保留**发生时间与录入时间**两个时点；续假可能在返校前重复 L2–L4；返校后异议可再进入 L7。未收到权威决定，最多记录 `WAIT_HUMAN`。

### 11.2 撤回、重新提交、复核与错误批准

1. **决定前请求撤回**：可信本人或有合法代办授权者提出 `M021`，记录 `F045` 和申请版本。正式能否撤销受理、由谁点“中止”、是否允许重复提交，尚无 S04 专属现行条文（`SRC-008` 只是通用平台指南），故 `R037=POLICY_UNCONFIRMED`；原申请标“撤回请求待学校接受”，不能径自删除。
2. **决定后改变主意**：该行为可能是提前返校销假、要求改期、或请求撤销已生效准假，性质不同。系统须先校验原 `M006` 状态，交原有权部门判断；生成关联更正事件，不以修改 `M002` 文件覆盖签批。
3. **重提与重复**：对同一学生、重叠假段、同一理由既有决定，应提示关联原案和重复期间；新申请分配独立 F001 或新 episode，保存 `supersedes/relates_to`。**不是**靠新上传自动“复活”原已撤回申请，或把历史旧 `PASS_FACT`当作新批准。
4. **普通准假争议复核**：`R038` 收集 `M021` 的主张、原决定及受理事实，但不虚构复核机关、法定期限及暂停执行效力。不同于由已核学籍制度明确规范的“学籍处理决定”申诉；若实质请求是学籍处分救济，路由相应有权程序。复核最终结论只可来自校方 `M023`／新的 `M006`。
5. **身份冒用、越权或双签缺一**：`R004/R014` 阻止模板写正式决定，暴露签发身份与受控 `M020` 比对事实、请校方核实。AI 不得擅自宣布学籍惩戒或认为原校方决定当然无效；有权机关依法处理错批与效力更正。
6. **应急病假与个人隐私**：健康紧急情形允许先保留口头通知事实；不能因为无法上传隐私医疗全文自动定性旷课，须学生处／学院依真实规定人工协调必要片段。

### 11.3 定向重审：只失效被依赖的旧事实结论

| 变化事件 | 定向失效的候选 R | 保留现时效力的独立 R／官方事件 |
| --- | --- | --- |
| `M003/M013` 医疗证明替换，`F024–F027` 变化 | `R010/R011/R017/R027`（若确依赖该证明），后续 `R031/R032` 在时长范围改变时重核 | 不重跑无关 `R002` 身份；已有 `M006` 保留正式状态 |
| `M002/M008` 修改起止时点 `F015/F016` | `R005/R009/R011/R016–R018/R024/R027/R031–R033` 中**引用同一 episode**者 | 其他学生、其他假段和无关事实不失效 |
| `M001` 学段／学籍变更 `F005/F007/F008` | `R001–R004`、各身份分支规则、`R031–R035`，按影响图重评 | 原始上传历史与原学校决定仍记载，效力由归口机关处理 |
| `M020/M019` 岗位／委托变更 | `R004/R009/R014/R027` 对涉及的决定**签发时点**重核 | 不能用今天岗位去追认过去无权签署，也不覆盖原签批记录 |
| `M014` 返校记录补正或新 `M015` | `R019–R022/R030` 中相关学生与假段 | 医疗证明、原申请事实及批准不自动改写 |
| 新 `SRC-019` 正文或 2026 学校程序获得 | 重审 `R001/R023/R024/R028/R030/R033/R037/R038` 中适用学段／时期规则 | 历史办件按**当时有效制度**而非新公告一刀切倒查 |
| 外部 `M018` S01/S02/G50 决定改版 | `R003/R031–R035` 中引用该 sourceVersion 的目标 | 本模板没有对外部决定的更改写权 |

**执行契约**：冻结审阅方案时记录 `planId+fingerprint`、每条 `Check×target/sourceVersion`；更换证据必须先建立 `M022` 关系，再仅标依赖的历史 Fact Result 为 `SUPERSEDED` 并产生新检查。重审后的 Run 必须是真实新 Run 与旧版本可链接，**禁止伪造 `run@rev` 或假设代码已实现该行为**。审批实体与审查运行分存；最终 Decision 只能由真实可信 Main／有权校方写入。

### 12.2 必须人工处理的事项

- 突发不可抗力能否接受迟报、医院“相关材料”的证明力、医疗诊断真伪、个人困难理由是否正当；模型只比较外观和事实覆盖。
- 身份或监护关系复杂的代办、两人联署实际有效、现任岗位委托，以及研究生外出所需独立安全审批。
- 2024新版研究生请假条款、2025国际学生工作办法及港澳台专项制度、国际学生2026表单跨学段适用、2026真实请假系统流程；证据缺失不可用外校制度补洞。
- 已有正式批准的更正/撤销、普通请假复核、课程旷课处分、休学或退学、缓考免考与差旅安全准入；各归口保留唯一签发权。
- 跨来源冲突无法确定哪一来源有权或存在无效签发；只保存冲突及校方核查记录，严禁“AI 审批已通过”。

### 12.3 生效控制建议

**发布阻断条件**：现行研究生正文缺失时停研究生期限自动门槛；2025国际工作办法和2026新表未得时停将2022国际请假链当作当前唯一签批规则；日历算法未确证时停临界分级机器判定；校方可信审批接口／授权无法核时停任何“已批准”展示。可保留材料结构化、来源核对、权威待办与人审建议功能。未取得校方授权的数据不得以为“完成模板”而调用或收集。正式投入自动审核前应由校规归口、学生处／研究生院／国际教育学院确认适用版本与发布权限。

### 12.4 可交接的参数冻结与禁止上线开关

研究模板的可交接状态不依赖学校开放内网、提供学生隐私或事先正式批准。集成方可先使用合成数据实现 `M/F/R/SRC` 和八结果码；但未来需要校方实际发出准假、续假决定与销假确认时，须校方授予受控可信身份、记录签发者授权和制度生效版本，满足真实审批工作流。

| 配置键（研究默认） | 当前可信程度 | 生产接线前要求的证据 / 失败处理 |
| --- | --- | --- |
| `leave.authoritative_policy_revision` = `UNKNOWN_BY_COHORT` | **公开仅部分已证** | 每一国内本科/研、国际本/研、港澳台、中外合作项目分开核有效校文号、法定适用事件日与废止链；否则`POLICY_UNCONFIRMED` |

所谓“冻结”仅指每次纸面审查和未来每个真实运行都绑定当时选用的 `policyRevision + policyEffectiveDate + calendarRevision + roleGrantVersion`，不宣称这些值已经从学校受控服务获得。提交研究稿不产生任何学校的行政决定或上线授权。
