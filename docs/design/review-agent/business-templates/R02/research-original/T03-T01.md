## 01 唯一审核目的、申请人和负责机构

### 唯一决定对象

**一案一申请批次：**`某申报人/负责人 + 校方依托/推荐主体 + 资助机关 + 项目类别 + 年度/批次 + 一份拟报申请`。本模板审核该案能否送交**校内有权人员进行本批次推荐/报送决定**所需的可证明事实，不自动授予项目负责人资格、不代替学校用章/报送，也不触发资助机关立项。

如校方只是合作参与单位而非牵头/依托单位，仍在本 ID 中作为同一办理矩阵的“合作申报/参与”分支，先核该批次是否要求我校出具同意、合作协议或证明，**不得**擅自将“参与项目成员”认定为“项目负责人”。国家重点（重大）项目的项目/课题/专题分层与负责人认定依任务书，属于后续执行阶段的独立事实，申报阶段不能以未来任务书认定预判。[SRC-003 第二、七条]

### 申请人范围

- **通常情形：**符合该资助机关、项目类别和批次规定的成都理工大学在职教师/科研人员及其他获准依托学校申报的人员。任职/聘用有效性须由学校人事或授权单位的权威记录核实；自填工号、职称或劳动关系不充分。[SRC-005 第一部分（二）7, SRC-007 第四、五项, SRC-010 第二部分]
- **非通常身份：**兼职、联合聘用、博士后、外籍/访问人员、在读学生等，按具体指南核定是否可为负责人、合作参与者或只能由其他依托单位申报。校本诚信办法适用于学生和以学校名义科研的其他人员，**不意味着**这些人员自动具有每类项目申报资格。[SRC-001 第二条, SRC-007 第四项]
- **代理/协助：**二级单位科研秘书可组织名单、检查材料、代为传递，但不得因此取得申请人法律/学术承诺权或校级推荐批准权。2026 国自然科学基金校内通知索引记载由二级单位统一报送申请名单、学院初审及科发院复审；原站核验仍待完成。[SRC-004]

### 最小可信记录原则

- **身份与授权：**前端 Renderer 传入的姓名、`teacherId`、角色、学院、审批人字段均为不可信陈述。服务端必须由可信会话取得真实操作人、组织隶属和权限，校内推荐以独立可追溯人工决定事件持久化；后续 IPC/DTO 映射需由技术线核实，不在本研究稿虚构当前代码实现。
- **人员身份：**身份字段对应学校人事/学籍记录的权威查询时间与有效版本；如跨单位任职、兼职、博士后出站、学生转聘，冲突时 `CONFLICT`，不能由 AI 根据简历判断真实聘用或在读状态。[SRC-005、007、010]
- **限项：**同时需要当前批次权威规则版本、国家/省市或学校科研项目台账、项目负责人/参与者角色、实际在研与结项效力和时间快照；单份自述或过期导出不足以自动给出“不限项”。不同主管机关互斥条款亦须逐批次核。[SRC-005、007、010]
- **科研诚信：**本科生、研究生、教职工及其他研究者在校本诚信管理中的归口可能不同。系统只读取有权机关已经形成且目前生效的禁申/惩戒结论；“涉嫌”“线索”“举报”必须停留在人审流程，不由模型认定失信。[SRC-001 第九、二十至二十四条]
- **伦理与保密：**是否需科技伦理审查由项目内容与当期主管机关规定触发，引用专责审查结果。国家重点（重大）项目校本制度要求涉密项目线下闭环，普通客户端不得读取、上传、导出涉密材料。[SRC-003 第九条；SRC-005 第一部分（二）11]
- **校内推荐：**以决策人、机构、批次、权限版本、决策时间、原始材料指纹及签章/报送凭据形成不可由普通申请人覆写的记录；撤回或复核不改写旧记录，只追加状态和事实版本。材料被修改后应重核受影响事实，不自动继承原审核结论。
- **外部结果：**保留资助机关受理号/通知原文与时间，并明确 `校内事实核验`、`学校正式推荐`、`外部受理/立项` 三种不同结论来源。科研申请书中的“拟批准金额”“拟承担单位”不是实际批准。

**服务端事件最低审计字段（设计需求，不声称代码已实现）：**可信 `actorId`、认证提供方、组织/岗位、直接授权或委托链及有效期、操作能力、案卷 ID `F005`、主管计划和批次 `F001–F003`、申请书版本 `F018`、依赖的 `M` 版本和散列、UTC 时间及本地业务时区、动作前后状态、原审批/签章凭据及其作废/退回关系。Renderer、导入表单或 OCR 得到的审批人姓名只能是**待核字段**，不得回填可信 `actorId`。

**证据效力与冲突裁决：**对同一事实优先采用**有权形成该事实的机关**在该业务时点生效的正式记录，而非机械地依“最新上传”排序。资助机关发布的类别/限项规定与校方通知分别约束外部申报资格与**校内更早截止/推荐程序**，二者并存；同层级规则发生抵触或更正链无法确认时 `POLICY_UNCONFIRMED` 并交归口人核。本人签署证明其声明，不能替代人事、科研项目存量、伦理、诚信或校级推荐结论。任一权威记录失联也不意味着事实不存在。

**复用边界：**已取得的 G50/G06 科研伦理/诚信、G07 财务事实、T02 人事任职、T07 合同签署、T04 采购、相邻 S/T 项目资格结论，只有在**来源机关、对象、作用范围、时效、版本均可核**时才作只读引用；既无来源又无法明确 G50 与本 ID 的边界时标“待总账核映射”，不得新造平行审批结论。课程/毕业等学生身份以该领域有权部门的人事或学籍事实为准，不因申报人为学生就改变本 ID 的唯一审查目的。

### 滚动关键证据缺口（第四轮继续核 7 项）

1. **校本旧总则的效力与逐条范围：**取得 SRC-012（2017 年纵向管理办法）正文及修订、废止链，对照 2024/2025 两部专门制度，核一般纵向申报的组织、授权和流程；不预设旧规依然全文生效。
2. **当期校内通知、附件及更正：**向科发院、社会科学处获取 SRC-004/006/008/009/011/013 全文和原始附件，确认截止时点、格式、推荐名额、二级单位审签及撤回操作。尤其不可把 SRC-009 摘录中的“63项”作为今后年度定值。
3. **谁是可签署的“校级推荐人”：**取得自然科学、社科项目类别分别适用的学校授权矩阵/用章规程、审批岗位及代理制度，并确认学校系统可信操作人来源；Renderer 声明不具备身份效力。
4. **限项跨平台事实与例外：**确认国自然、国家社科、教育部、省市项目的在研/结项/申报记录查询渠道、更新频率与跨单位项目计数边界；单靠提交人申明不做通过判定。
5. **科研诚信与伦理权威结果：**核取得哪些部门可依法反馈当前有效禁申结论、何种授权/脱敏方式可只读引用；待调查线索不可按负面裁决处理；涉密材料如何隔离普通审核环境。[SRC-001/003]
6. **R02/G50 邻接精确映射：**取得两份 R02 总账和 G50 `catalog.json` 原始快照，逐项查 G06 伦理诚信、G07 经费、T04 采购、T07 合同以及 T02/S 身份事实，不创建平行结论。
7. **行政裁量/复核的有效权限：**查校内限额竞争性推荐是否有公示、异议与复查规程，以及省市等申报撤回/复核程序。2026 国自然“不予受理”与“不予资助”复审已分得 SRC-018/019，其他批次不能套用；系统只提示与转办，不自行给排序、复核成立或最终行政决定。

### 一致性与缺失的共通约束

1. 每个 F 存储**事实值、来源 `SRC/M`、来源位置、抓取/核验时间、来源文档指纹、业务适用时间**；字段无需重新上传“证书”才能得到值，但绝不能丢失可追溯原件。
2. 同一个人以 `F006` 的**校内可信主体 ID**关联人事/学籍；姓名 `F007` 只是展示与对账，单纯相同姓名不合并，也不允许凭前端 `teacherId` 接管另一人的申请。
3. `F022/F023` 的旧项目不是“申请人承认了几个”就等于权威限项结果。跨国家/省市、负责人/成员角色、终止/撤项、同年申报应按批次做时间化集合，而非无差别计数。
4. `F018` 的申请书内容改动后，触及 `F015–F029` 的核验结论必须随旧证据版本失效；`F030–F034` 的正式意见/回执保留历史且必要时重走签审，不偷偷覆写。
5. `F025–F027` 不传递未经授权的处罚详情、伦理敏感正文或涉密正文；只传有权部门许可读取的结论状态、有效期和引用键。

### 材料状态及归属约定

## 08 审核规则逐条清单

**ROUND4 事实核验规则复审清单**，从 `R001` 连续编号至 `R037`，仍非成都理工大学已发布的自动审批规范。每一行的 `T/F/U` 分别是**该规则适用性触发条件**被证实为真、假、未知；不是审核结论真/假。若 `T` 且事实符合权威条件，可为 `PASS_FACT`；`F` 为 `NOT_APPLICABLE`；`U` 按未确认的原因输出 `POLICY_UNCONFIRMED`、`SOURCE_UNAVAILABLE` 或 `NEEDS_HUMAN_DECISION`，不能按“假”忽略。下文“负事实”指已查明某条件**不满足**，须记录原始值及差额/原因，并交有权机关处理，不能凭模型直接否决。

**每条规则的共同失败分流与证据等级：**当阶段申请人负责、政策明确的必要件未交 → `NEEDS_MATERIAL`；已交但内容不可识别 → `UNREADABLE`；有权部门本应提供的历史/身份/决定数据无法获得 → `SOURCE_UNAVAILABLE`；同一对象相互矛盾的有效证据 → `CONFLICT`；当期准入门槛、例外、签署权限或校内通知效力不明 → `POLICY_UNCONFIRMED`；存在利益冲突、科研伦理、签名真实性、实体资格解释或正式推荐等只有有权人能决定的问题 → `NEEDS_HUMAN_DECISION`。不能用某单一材料缺失覆盖同时存在的另一个问题；每个问题独立关联规则及来源。对同一事实优先采用产生该事实的**有权机关有效原始记录**，其次为可核原件/签章证明，再次为申请人声明，最后仅是 OCR/模型推断；下级来源不得推翻上级有效决定。

## 10 结果状态、问题与待办输出契约

### 八个互斥的事实核验结果码

**一个 `ruleId + targetId + 输入版本指纹 + 审核执行号` 只产生一个主结果码**；同案多项问题分别保存，不把全案压扁成一种“通过/不通过”。`factSatisfied`、`evidenceFinding`、`workItemStatus`、`formalDecisionStatus` 是**独立维度**；主结果码并不隐含有效校内推荐、签章或外部立项。

| 结果码 | 精确定义和使用条件 | 不能误作 | 指向的下一动作与责任主体 |
| --- | --- | --- | --- |
| `PASS_FACT` | 适用条件为真、当期有权证据完整可读且某项**明确事实**已完成核对，记录 `factSatisfied=true`；若事实证明未满足准入门槛，记录 `factSatisfied=false` 并改走有权资格解释/决定的 `NEEDS_HUMAN_DECISION` | “学校已批准”“正式推荐”“基金委立项”、对其他 R 的通行证 | 事实核验完成，继续下一个依赖；涉及 R027/R034 的真实正式决定必须另存独立事件 |
| `NOT_APPLICABLE` | 批次规则明确不触发该材料/条件，或本案**尚未到产生该证明的阶段**（`reason=FUTURE_STAGE`，存重新触发节点） | 缺失必需件、不合格、永久免审 | 保留条件与证据，触发时重新评估；模板规则引擎 |
| `NEEDS_MATERIAL` | 当前阶段有明确依据要求、由本案申请人/材料持有人可提供的件**确实未到**；列合法替代与补件目标 | 主管机关系统不可用；将未来决定提前索取 | 申请人或材料真正持有人补交；校方可直接读取的材料优先内部查 |
| `CONFLICT` | 两个以上针对**同一业务时点和对象**的可识别证据内容不一致，或从材料所签版本与主申请版不一致 | OCR 看不懂、尚无签署人、自动认定本人撒谎 | 指定证据链冲突双方及页面，交原出具机构/科研归口查证 |
| `UNREADABLE` | 有材料且版号可定位，但扫描/OCR/原文关键页、签字或表格无法可靠识读 | 已经缺材料、政策不存在 | 返回具体文件版本、页段及失败原因，交材料持有人补清晰原件或有权人员人工核原件 |
| `SOURCE_UNAVAILABLE` | 已知应向有权源查询，因接口、网页 412、访问授权或服务故障**无法取得权威结果** | 源中的事实为否、限项为零、未处分、未获资助 | 学校归口/对应信息系统管理员恢复访问或按合法替代路径出具查验记录 |
| `POLICY_UNCONFIRMED` | 现行性、当期规则正文、例外阈值、名额/截止/签章要求、撤改链无法确认 | 任意启用旧批次门槛、模型自行推定政策 | 科发院/社科处政策管理员取得现行权威通知、按批次冻结配置；期间不自动拒绝 |
| `NEEDS_HUMAN_DECISION` | 事实显示可能不满足准入条件，或涉及资格解释、诚信处分效力、伦理/保密、评委排序、签名真实性、校内正式推荐、外部复审等**专属权限** | 模型“人工通过”、由管理员代资助机关决策 | 交对应**有权**人/机关；须核 actor、代理有效期、签署版本和正式决定来源 |

若一个 R 同时存在不同原因，输出各自有证据目标的子问题；**同一子问题**选择最直接阻断其核验的主码，优先确定政策是否可用、权威源是否可取、材料是否到位与可读、证据是否冲突，再讨论需人审的事实。绝不在 `UNREADABLE` 的文件上猜字段值，亦不可因为缺旧版本签章而替当前有效版本自动盖章。

### 问题指向规则及显示规则

1. **一问题一定位：**例如 R019 匿名页异常 → `I-...` 关联 `M021@v2` 第2页页眉与 `F018@v3` → 申请人“更换与主申请同版匿名活页”；如果真实校本通知仍未核，另发 R001/R002 的 `POLICY_UNCONFIRMED` 政策待办，不混用两种问题。
2. **待办直达案卷内目标：**材料类指向“案卷工作区/材料槽 M”，事实争议指向“问题/R+证据”，正式决定指向“当前案卷/结论与审批”。不另建外部六页状态，不让用户处理 JSON。
3. **时限并列：**`dueAt` 必须来自相应 SRC 的可核本批次时间；未知存 `null` 并显示“校方确认”，不得从以前的批次推算；超时提示不自动撤销学校合法决定。
4. **输出摘要：**展示 `适用规则数/已核事实数/缺件数/冲突数/不可读数/源断数/政策未核数/待人工决定数`，且另外展示**正式校方决定状态**与**外部资助状态**；`PASS_FACT` 达 100% 仍可以 `SCHOOL_DECISION_PENDING`。
5. **同一事实多来源：**记录出具机构、法律/业务权限、时间、证据原始位置和关联外部权威决定 ID；跨 G50/S/T 复用时保存“引用其决定”，禁止将其内部规则并行重跑并形成第二结论。

### 只重审受影响规则，不全案重跑

1. 使用 `dependencyMap: R → (F, M, SRC, batchVersion, roleAuthority, stage)` 建逆向索引。材料版本变化先确认该材料的真实 `ownerId`、本案/人员/项目 ID，再计算 `affectedRules`；改动只是扫描画质而值和指纹未明确一致时，也应重核该证据直接支撑的 R。
2. 例如 M007 出生日期来源版本变更 → R008（及若影响资格例外则 R009）；M010 项目结项记录更新 → R012/R013（及配额材料若以资格筛选为依据则 R026）；M021 更换匿名活页 → R019/R029；M015 合作协议更新 → R010/R018/R029，若已签推荐则另发 R027 人工有效性复审待办。**未受影响的 R014 诚信结论不因换匿名页重跑。**
3. 所有旧 `FactCheckResult` 留原执行编号与输入散列，新的依赖输入不得沿用旧“当前有效”标记；旧正式决定永久保留审计事件，校级原签署人/有权岗位确认是否需要撤回、重签、补报，平台状态由其有权机关决定。不得用“旧结论已过期”冒充“机关决定已撤销”。
4. 申请人退回主页、切换案卷或线下离线导入时，仅允许**可信身份和案卷键**关联已有审核；不能因同名材料/旧 `run@rev` 复用正式 Run、决定、Outbox；离线文件不可直接携带可信审批人身份。
5. 复核与补件属于当前案卷 `P6/P7` 的事件，不新造另一个同目的模板。复核请求包含 `challengedDecisionId`、理由、送达/截止、受理主体和签署人；**申请复核 ≠ 复核成立**。
