## 01 唯一审核目的、申请人和负责机构

### 1.1 事项成立依据与对象

- `SRC-001`：成都理工大学体育学院 2025-11-06 发布的《【成理体测进行时】@所有成理人，这份体测指南请查收！》明确：确因身体原因不能参加体测的学生，通过“体适能”APP提交免测申请并上传医院证明等材料；经校医院审核、开具免测证明后，由管理员在系统确认。文中对不适者提示按程序申请缓测；对不合格及办理缓测学生安排统一补测；大四补测大二/大三往年缺测为特定窗口。**这些是2025年度的事实，不等于2026通知。**
- `SRC-005`：教育部《学生体质健康监测评价办法》第五条确定全体学生年度测试的基本制度，并允许因病或残疾学生依申请暂缓/免测。`SRC-004` 的 2014 年修订标准发布公告确立上位标准；标准实施说明中的申请、医疗证明、体育教学部门核准和同学年不及格补测一次的细则，在 `SRC-006` 外校公开转载文本得到交叉核对，待进一步取回教育部原附件逐字比对。
- `SRC-002`：学校《全日制普通本科学生学籍管理办法》第二十九条将体质健康测评和登记卡纳入学籍管理；第十六条则处理**体育课保健课替代**，不属于体测免测自动批准依据。

### 1.2 唯一决定对象

同一学生、同一适用学年/体测批次，申请对《国家学生体质健康标准》测试实施**免测、暂缓测试或补测资格/安排**。本模板只核对：

1. 学生与在册适用对象、目标学年及测评批次的关联是否由权威学籍/体测系统证实；
2. 属于免测、缓测、当学年不及格补测、缓测后补测、历史学年补测等哪种**业务情形**；
3. 健康/残疾或其他通知规定事由的证明、证明与申请本人和时段是否对应，是否已有校医院或体育管理人员出具的**真实记录**；
4. 是否存在正式结果、重复申请、版本变化、时间冲突或需人工裁定的情形。

**模板不得决定**具体病情可否安全运动、不能运动期限、医院诊断真实性、特殊事由能否通融、最终免测批准、官方补测排期、体测成绩更改、毕业/评奖资格。尤其不能以 OCR/LLM 推断取代医学或校方判断。

## 02 适用、排除与邻接模板路由

### 2.1 适用

- 明确为成都理工大学组织的《国家学生体质健康标准》年度测试，且学生身份、学段、年度能够核实。`SRC-001` 对“全校各年级学生”的2025测试公告、`SRC-002` 对普通全日制本科的校规范围可证明**部分场景**；不能据此默认研究生、留学生、联合培养、宜宾校区等各群体均按同一流程办理。
- 免测：疾病/残疾相关事实与证据核验，涉及校医院证明、体测系统确认；`SRC-001`（2025）、`SRC-005` 和 `SRC-006`（上位原则交叉文本）。
- 缓测：身体不适等不能按当期安排测试时的申请/先行处置，医学与排期依据待校本补证；`SRC-001` Q3。
- 补测：2025年度明确的不及格、已办理缓测统一补测及大四历史学年缺测补测；`SRC-001` Q6/Q7。是否存在其他补测资格/窗口由当期公告决定。

### 5.3 权限与人工裁量阻断清单

1. 医院证明可读≠诊断真实≠校医院医学审核完成≠体育部门已批准；各自只由其签发者确认。
2. 疾病是否适合跑步、单项还是全项免测、是否足以缓测、是否超期通融必须医疗/校方人工处理。
3. 2026审批人、代理人、复核机关、截止日、隐私保存期均不明。未取得规则前可提示事实齐备，最终仍停在 `NEEDS_HUMAN_DECISION`。
4. 未经本人/授权者请求，不将旧案的健康信息或其他模板数据直接复用到不同学年新案；即便有合法读取，也要核对用途与有效期。

## 07 材料槽与证据目的

### 7.1 材料取证口径与阶段约束

- 下表“**C 当前需要**”指业务事实在当前阶段需可供核对，**不代表学生必须另行上传**；能够从授权的学籍/体测系统取得时仅保存可信记录引用。`K` 表示仅指定情形条件必需；`L` 为办理后才出现，首次提交不得强索；`U` 表示具体校本材料条件尚不明，待人工确认。
- “材料”既包括原始文件，也包括以查询ID、时间戳和来源授权取得的**权威记录**；记录不可达不能伪造成缺件。在真实系统无接口的情况下，可由有权岗位出具可验证回执或受控查询凭证；不能假设接口已经存在。
- 公开的国家免予执行申请表**样表**在 `SRC-009` 可找到存在性线索；当前未获成都理工大学表格或强制纸表要求。`M007` 因此不能在 C01 无条件设为学生必上传。
- 已有 `M008/M009/M010/M013/M020` 为后续生成证据，应用“等待生成/核验”状态，**不能要求申请初次提交时提供尚未发生的核准、签章或成绩**。

## 08 审核规则逐条清单

### 8.1 规则执行协议与证据等级

本节是**研发用事实核验规则**，不是学校批准条件的自我立法。每条规则输出单一 `resultCode` 及其 `ruleId/target/evidenceVersion/nextActor`；同一案可以同时有多条不同结论。以下 `T/F/U` 表示该规则的触发谓词为真/假/未知，**不是**申请是否被批准。`F` 多数情形意味着 `NOT_APPLICABLE`（该规则不触发）；若触及独立的实体事实相反或证据冲突，按各行说明处理。`U` 按缺少的实际对象区分材料缺失、源失联、政策不明与人工核定。

- 来源强弱：**现行成都理工大学主管单位政策/可信受理与签发记录** ＞ **同校历史批次通知（仅当年事实）** ＞ **教育部明确适用的上位规范** ＞ **外校示例/国家样表线索（只能作反例或待核线索）**。同一事项的真实医学结论由医疗签发机构/校医院作出，资格决定由有权校方岗位作出；文书 OCR 不提升证据等级。
- 所有记录均比较 `student_key + academic_year + test_batch_id/target + sourceVersion`；历史补测增加 `prior_year`，代理增加 `actor_id/delegation_ref`。无学生标识的医疗文书由医务人员核对真实对应关系；仅同名不成立。
- 时间效力：评价时使用规则所指明的**目标学年与申请/签发/决定时点**，而不是当前设备日期；2025通知只适用其2025事实，2026校本阈值不明则不得评定达标、逾期、医院等级或是否可部分免测。
- 阶段：A识别、B申请、C事实核查、D补证、E有权决定/排期、F同步归档、G撤回/复核；`L` 表示只有此前阶段产生正式记录以后才触发，**在B阶段不运行缺件检查**。`NA`=不适用而非否定批准。

### 8.3 源失联、缺件与规则非阻塞条件

1. `M002`现行政策缺失→`R005=POLICY_UNCONFIRMED`，但不阻止`R002/R007/R015`等**独立事实预审**；只阻止对需要该政策的时限、等级、申请效力作确定结论。
2. `R012–R014/R019/R025/R027`只有阶段到达才运行；申请刚提交时记录`NOT_APPLICABLE`（尚未触发），**绝不**返回`NEEDS_MATERIAL`要求学生提交未来的`M008/M009/M010/M013/M020`。
3. `R020`的安全处置优先于材料审核，不以证明完整或系统在线为条件。实时安全信号应由现场人员执行；模型输出只是提示，**不是医疗处置指令的自动执行机制**。
4. 本轮未获得2026年成都理工大学主管部门发布的统一现行细则；规则中的“资格触发事实”均以可核官方记录为限，医学适格、政策例外、行政通融与最终有权决定均不由模型判。

### 9.2 跨材料主从关系、同人同年匹配和版本

1. **权威主键**：至少使用 `F002`（可信学生键）+`F009`（目标学年）+`F010`（体测批次/任务）+`F011`（情形）定位申请；C05另加 `F034`（历史学年）和 `M014`。对授权代理再加 `F004/F005`。相同姓名不同学生不能自动合并；同一学生不同年度也不可当同一审批。
2. **姓名/身份冲突**：学籍姓名 `F003` 与医疗材料 `F018` 不一致，先看合法曾用名或医院更正的可核证明；无权威关联时 `CONFLICT`，不能以模糊匹配或手填学号强行通过。不得要求所有学生无条件上传身份证复印件；已由校方认证的可重复取得的身份不应强迫上传。
3. **医学主从关系**：`M004` 为核心医疗证明，`M005` 是因需要才补充的检查/病历，校医院 `M008` 是独立审核记录而非 `M004` 的附件页；`M009` 为独立校方核准，`M010` 只说明系统状态。任一阶段的缺失均按该阶段处理，不倒推初次申请缺件。
4. **版本替换**：同一个 `M004` 被新版诊断证明替换时，旧版内容及 `F042` 散列/时间、基于旧版的真实性核验、校医院意见（如明确绑定旧版）、资格预审结论均标记“须重核”；与之无关的学籍事实 `M001`、年度通知 `M002` 不必重审。若已正式核准，**旧决定不会被模板自动撤销**，须通知有权机关决定是否重新审批。
5. **重复申请**：同人同年度同情形出现两份 `M003`，先根据 `F001/F012/F042` 判断是否同案新版本或两个独立申请；不能悄悄覆盖、也不能自动认定恶意重复。不同年重新申请不能直接继承旧年健康证明有效期。
6. **权威回执可达性**：`M011/M012/M014` 查询失败是 `SOURCE_UNAVAILABLE`，不是“从未测试/未缓测”；成绩数据还可能异步上传（`SRC-001` Q4）。 `M002` 的当期政策缺失是 `POLICY_UNCONFIRMED`，不能与文书不可读 `UNREADABLE` 混同。
7. **G50/S/T结果复用**：必须校验 `F041` 的签发机关、对象、学年、效力、被引用的业务目的和当前版本；课程保健课批准（`SRC-002` 第16条）只能作为有条件的健康/课程背景，**不能代替体测部门单独核准**。 `SRC-008` 未取得，具体公共能力项仍未核对。

| `PASS_FACT` | 此版本、此目标、此时点下，**该规则的事实命题**由合适来源核对成功；**绝非学校批准、体测安全或资格已生效** | 记事实证据与校验者；涉及行政裁量仍等待原有权岗位 |
| `NOT_APPLICABLE` | 规则触发条件经可信事实证实为假，或业务阶段尚未来到；**不是免测申请被驳回** | 保留跳过原因和阶段依据，不向学生索取该规则材料 |
| `NEEDS_MATERIAL` | 确认当前阶段确需、由申请人可提供且尚缺的必要材料/事实；**不是校方后台接口断开** | 精确指向学生或原持有者、缺页/缺字段；仅阻断依赖规则 |
| `CONFLICT` | 两个具有可比目标的材料、主键、版本或权威记录出现实质不一致；**不是模型择其一胜出** | 双方证据并列，交原持有者/授权核验员核实，阻断冲突依赖结论 |
| `UNREADABLE` | 当前已提交且需读取的文件/页面损坏、缺页、字迹或影像无法辨认；**不是没上传** | 指定文档ID和页码/区域，允许局部清晰替换；只重跑依赖它的R |
| `SOURCE_UNAVAILABLE` | 理应由学校/医院/主管机关持有的记录系统无法访问、同步延迟或回执真伪无法在线核对；**不是证明不存在** | 指向来源Owner与查询时间、错误/重试入口；禁止学生截图替代权威记录 |
| `POLICY_UNCONFIRMED` | 必需的当前校本规则、学段/年度适用性、窗口或授权层级未证实；**不是申请逾期或不符合** | 交体育主管部门/政策维护人查现行文本；不由AI填医院级别、日期等阈值 |
| `NEEDS_HUMAN_DECISION` | 来源可能齐备，但医疗专业判断、证据真伪争议、实际程序受理、豁免/例外、授权决策仍需真人；**不是“自动拒绝”** | 指定校医院/体育有权审批或申诉机关，明确所求裁决和现有事实 |

**互斥算法（单规则）**：先检查是否达到规则的业务阶段和可信触发条件；确定不触发返回`NOT_APPLICABLE`。对触发的事实，遇到来源本身不可取得用`SOURCE_UNAVAILABLE`，有文件但不可读用`UNREADABLE`，可读权威证据互斥用`CONFLICT`，申请人当前应给的证据不存在用`NEEDS_MATERIAL`；只有条款和窗口无合法当前版本用`POLICY_UNCONFIRMED`；需要医学/行政判断用`NEEDS_HUMAN_DECISION`；其余经真实来源证实的事实才是`PASS_FACT`。若**一个规则同时**有两类独立问题，输出一个最直接阻断该事实核验的主码，并把其他具体问题拆为独立有证据的issue/规则结果；不得把多码串入同一个`resultCode`。`SOURCE_UNAVAILABLE`与`POLICY_UNCONFIRMED`的区别是“有明确权威源但查不到记录”对“没有可证现行政策”。

### 10.2 结果记录、问题单、待办的逻辑契约（非现行客户端已实现声明）

每次规则结果至少保存下列对象；私密材料不在公共问题摘要暴露诊断全文：

```json

  "caseId": "case-reference",
  "ruleId": "R009",
  "target": {"studentRef": "trusted-subject-id", "academicYear": "2026-2027", "batchRef": "official-batch-if-known"},

  "factStatement": "医疗证明限制时段能否覆盖申请测试时段待校医院确认",
  "fieldRefs": ["F009", "F020", "F021"],
  "materialEvidence": [{"materialId": "M004", "sourceId": "verified-or-uploaded-document-id", "fileVersion": "v2", "digest": "hash-ref", "pageOrRecord": "p1", "holder": "medical-issuer"}],
  "policyRefs": ["SRC-001", "SRC-005"],
```

- 示例中`caseId/studentRef/batchRef/version/digest/timestamp`均为**字段形状示例，非真实生成的学校数据**。所有 `issue` 绑定具体`ruleId`、当前材料/权威记录的拥有者、页码或记录ID、版本、目标办理岗位、触发事实；若纯系统失联，待办指向系统Owner而非学生。
- `PASS_FACT`输出只能称“事实核验已通过”；案例聚合可列“已核实n项/尚待n项”，不能产生 `APPROVED`、`REJECTED` 或“准予免测”等官方性质结论。是否有官方准予/拒绝，由独立的、校方**原始真实签发** `officialDecision`（ID、机关、实际签发人、授权证据、决定类型、适用目标、时间、版本、回执）展示；`R013/R027=PASS_FACT`只能证明**外部签发记录已被验证存在**。
- 事实输出关联 `planId+fingerprint` 与每个 target/sourceVersion（技术设计建议）；`Case/Run/Decision`需要唯一可信Owner、原子版本检查和不可变审计。Renderer上传 `actorRole`、`approved=true`、签名图片都不构成审批权限。未验证的技术运行链不得宣称已经实现。
- 同一目标同时存在`CONFLICT`和`POLICY_UNCONFIRMED`等时保留**多条规则独立问题**；概览显式显示“仍待学校决定”，而不是把所有`PASS_FACT`简单取AND生成“通过”。

### 11.2 补件与版本更新的最小变更原则

1. 每份材料包含`materialId + owner + subject + academicYear + sourceId + sourceVersion + receivedAt + digest`。同一材料出现新件则新增版本并标明`replaces`；不可静默覆盖原件、旧OCR结果、旧校医院/审批记录。`F042`为证据散列，`F037/M017`定位旧案。
2. 建立**规则依赖图**：以`ruleId`关联输入`F/M/SRC`的具体版本。`M004`由v1替换v2，触发`R007/R008/R009/R010`，如变动涉及附加病历/单项范围再触发`R011`；已经审核的`R012/R013/R027`如绑定旧版，标记“需要原签发岗位复核”，不将已有行政决定自动改为无效。`R002`和`R015`等不依赖该医学内容的核验继续有效。
3. 仅`M002`政策更新时，重跑`R005/R009/R011/R016/R018/R026/R027`等依赖当期范围或门槛的规则；已历史签发决定由原有权机关判断新规是否溯及，模板不得批量推翻。
4. `M011`成绩同步或纠正触发`R015/R016/R019`，且若异议目标相关再检查`R024/R025`；**不得从本案直接修改成绩**。`M012/M014`变动分别触发`R017/R019`和`R018/R019`。身份主键变动可能关联更多规则，应按实际字段依赖图扩展，不以固定“仅重跑三项”掩盖连锁依赖。
5. 不可读改清晰件只替换受影响页；有合法源回查的后台记录不要求学生重复上传。若版本链损毁，冻结覆盖，交案卷Owner人工恢复，并保存此前规则运行引用而非伪造连续性。

### 11.3 撤回、重提、复核与最终有权决定

- **补件/修改**：`R021–R023`先核本人/代理权限及旧案版本；请求可以记录，但其能否在已批准后更改，以**本校2026规定及原决定机关**为准。已批准材料被替换时，旧批准继续作为历史权威事实保存，**不自动延展也不自动撤销**。
- **撤回**：提出撤回`M016`不等于学校接受。尚在本地草稿的申请可按系统权限停止提交；有正式接收或决定后，需校方有权受理/签发事件明确是否撤回成功和生效时点。校本截止、撤回范围未知→`POLICY_UNCONFIRMED/NEEDS_HUMAN_DECISION`，并向本人说明状态仍在官方处理中。
- **重新申请**：原案是撤回申请、已批准或已经拒绝，均需保留旧案与新申请的`caseId+target+version`关联，重新核学年、校本公告、健康证明时段，不能让2025体测结果变成2026年资格。申请次数/能否重提须官方规定。
- **异议/复核**：`R024`须指明实际原决定或成绩对象`M018`、理由`M019`。若异议针对成绩录入，把原成绩记录交体测数据Owner；若针对免测/缓测裁量，把有权决定交其规定的复核机关。`SRC-002`第59条仅为校规一般线索，不能把课程成绩复核期限和机关移植到体测。正式受理和复核结果只有真实`M020`证实，`R025`才可核。
- **正式决定唯一来源**：最终效力由**校方真实可验证的签发/备案系统**确立，包括决定类型、主体、授权岗位、绑定学年/批次/项目、原申请及证据版本、生效/终止时点。校医院`M008`与体育主管`M009`、管理员`M010`分权且步骤先后未完全核实；`R012–R014/R027`只能读取，不可通过本地自动化假冒签发或“模拟批准”。

**来源权限约束**：每个配置条目需记录`SRC-ID/发布机关/原文条款/适用校区学段/目标学年/版本/生效日期/审核者/复查日期`。外校同APP并不意味着同材料要求；`SRC-007/010`只能帮助发现错用。任何未知阈值不得设置默认为零、常量医院等级、默认超期或默认“批准”。

### 12.2 不可自动裁量与明示阻断

1. 医学诊断真实性、病残程度、是否能进行某一项目、缓测后安全复测：`NEEDS_HUMAN_DECISION`，医务人员/校医院。
2. 免予测试是否符合政策、单项/全部范围、特殊学籍对象是否适用、期限内申请、迟交能否补救：**先查2026政策**，否则`POLICY_UNCONFIRMED`；取得政策后仍涉及例外由校方人工。
3. 是否已有学校正式批准/拒绝：若`M009/M012`等权威决定不存在则只能称“未取得决定”，不能代为签发；系统管理员的`M010`不自动补成授权。
4. 复核是否已受理、是否超过申诉期、裁决是否生效：没有体测专项正式渠道与`M020`原件不自动判断。
5. 源系统在维护、成绩晚同步、旧案迁移失败：`SOURCE_UNAVAILABLE`，不是对学生不利事实；经授权线下证明可以人工核验但必须保留来源和版本。
6. 可达与可用的区分：`SRC-001`2025网页经索引确认是真实校本历史公告，不等于可作为2026政策版本；`SRC-004`官方通知可读但附件未完整取回，不等于标准全文已校对；`SRC-008`不可读取则去重仍开放。
