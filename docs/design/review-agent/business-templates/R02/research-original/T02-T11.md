## 01 唯一审核目的、申请人和负责机构

### 1.1 决定对象（冻结）

本事项的业务问题是：**对一名属于学校适用人事管理范围的教职工，其事假、病假等劳动人事请假、续假和返岗销假事项，核实身份、请假事由类别、时间记录、证明事实和审批前置条件是否足以交有权人员办理。** 同一请假事件在不同阶段形成的材料可以分批到达；不能把尚未产生的批假单、销假确认或工资结果列为初始申请材料。

独立审核输出仅可表达：事实一致、需要补件、来源无法读取、适用政策待确认、存在冲突或需要有权人员决定。**不输出“已准假”“应发/应扣工资”“旷工成立”等行政人事效力结论**。该区分符合事业单位依法健全人事管理制度及适用国家休假制度的上位框架 [SRC-006]，但具体成都理工大学请假权限仍以待获取的校本规定为准。

### 1.2 申请人与相应身份

- 候选申请人：成都理工大学教职工本人。学校章程在第 68 条列有教师、其他专业技术人员、管理人员、工勤人员等教职工类型 [SRC-003]；**章程所称教职工不直接等同于所有类型人员均可使用同一请销假流程**。
- 具体可使用该事项的人：事业编/聘用制、校聘劳动合同、人事代理、退休返聘、博士后、项目聘用和其他身份等，须以**校方人事权威名册及适用制度**区分；此处仅列待确认维度，不作资格推断。对外单位派驻、劳务派遣、项目临聘人员亦不能只凭“在校工作”即认定学校为准假主体。
- 申请代理：病重、急症等无法亲自提交时是否允许单位经办人、受托人代填或事后补办，尚无成都理工大学明确依据。拟支持“提交者≠请假人”的记录结构，但代理人的权限与签名真实性必须经校方审批链确认。

### 1.3 归口与最终决定者

- **可确认归口联系：**党委教师工作部（人事处、教师发展中心）官网列有专门办事指南和人事科电话 `028-84078920` [SRC-001]。此事实不能推出人事科对所有假期都有最终批准权。
- **业务参与角色待查：**所在二级单位经办/负责人、人事科、按人员管理权限可能涉及的组织管理部门、实际批准者、销假确认者、薪酬社保经办者。每一角色的法定/校本职责、代理与回避条件须进一步取证。
- **最终决定（尚未核实）：**须由成都理工大学现行制度和校内可信审批记录确定每种请假类别、人员身份、请假期限对应的有权决定人；不能从其他大学的分级权限倒推，也不能把平台上的普通“通过”按钮或本模板的 `PASS_FACT` 等同于批准 [SRC-001][SRC-002][SRC-009]。
- **权益救济：**学校章程可检索文本第 70、79 条确认教职工申诉/救济的原则性权利 [SRC-003]；具体“请假审批复核”“人事争议”“考核或处分申诉”应按其各自程序区分，上位《事业单位人事管理条例》第 37、38 条亦不使本模板获得作出申诉处理决定的权限 [SRC-006]。

## 03 业务生命周期与办理情形矩阵

### 3.1 阶段框架（研究设计，非校方现行流程复刻）

1. **建案/身份定位：**请求建立请假事件，使用可信人事记录确认本人、用人/管理单位、当前聘用关系及身份适用规则；代理另证其授权。身份未知时停止自动套用条款。
2. **申请与材料预审：**记录请假类别、拟起止时间、事由摘要、已产生证明及对应出处；核对文书归属、时间和可读性，异常送补件或核验。病假不默认收集完整病历、病种或检查细节。
3. **单位核验与有权审批：**根据未获取的校本制度确定路由；系统仅提供 `PASS_FACT` 等事实结果和证据指向，由有权人员在学校可信审批环境中作出正式准假/退回等结论。
4. **在假期间变更：**延期、续假、改期、补证或撤回申请均通过同一案卷内的子阶段/新版本办理；应区分“申请撤回”与“已经生效的批准被撤销/变更”，后者不得由申请人单方消除。
5. **返岗销假：**到达返岗阶段后核对实际返岗日期及原批准范围，之后才产生销假确认/考勤衔接记录；不能在首次请假时强制提交“销假已批”证明。
6. **后续关联与争议：**关联人事考勤、薪酬、年度考核等有权结论；异议及复核由校方确认受理部门、时限、方式。本模板仅呈现结果来源，不独立复判劳动工资或处分。

上述阶段框架借鉴校本通用“待办—处理”技术手册能承载多阶段办理的能力 [SRC-002]，**不是声称已经核实成都理工大学请销假的阶段顺序**。跨校成都大学流程确有“先请假审批、后返岗销假”的安排 [SRC-009]，仅作设计线索，不可直接移植。

1. **分区访问：**医疗诊断/病历附件应单独受控；普通路由助手、教务、模板作者、非本案经办人和通用 G50 处理器不应默认获得诊断全文。以“有无适格病假证明/载明需休息期间”等必要事实最小输出，并留授权访问审计 [SRC-007]。
2. **敏感信息合法处理：**以《个人信息保护法》第 13 条选定合法处理基础、履行必要告知与第 28–30 条敏感信息条件；如依同意处理，按法律处理单独同意；如依法属于无需同意的情形，应核明依据。执行影响评估和严格保护，禁止将诊断数据任意复用为训练样本或无关考核 [SRC-007]。
3. **拒绝 AI 医疗与人事裁量：**模型不得评价疾病真假、诊断合理性或未经法定授权推断请假人劳动能力，也不得仅凭病假频率自动扣薪、推定旷工或否决续聘；重大权益决定须有有效人工处理及解释机制 [SRC-007]。
4. **跨模板出站最小化：**向考核/薪酬模块只关联最终有权请假结果、假别、批准起止、实际销假时间、事件 ID 及必要的更正记录；是否允许提供诊断类型取决于现行必要性及授权，不作为默认字段 [SRC-006][SRC-008]。
5. **保管与删除：**档案馆历史归档范围 [SRC-004] 不能替代医疗文件在 V3 系统中的分类存储、期限、访问审计和删除规则；须由校方人事、档案、网信/法务确定具体政策。

### 5.4 本轮冻结的“不可自动定案”清单

- 病事假可用身份、最高/累计天数、证明等级与出具期限；
- 正式审批路径和“单位负责人/人事科/校领导”等各层签批权限；
- 急症先离岗、委托办理、事后补件、追认、续假及超期责任；
- 病事假期间工资/绩效/津贴发放、社保、考勤和是否构成旷工；
- 已批假撤销、销假签署人、复核时限与正式申诉处理。

凡涉及这些条件，缺少适用的现行校本文件与可信原始记录，统一保留 `POLICY_UNCONFIRMED`、`SOURCE_UNAVAILABLE` 或 `NEEDS_HUMAN_DECISION` 的研究语义；材料齐备最多表明事实预审完成，**绝不等于准假生效**。

### 5.6 后端认证、代理与来源失联

1. 正式决定至少核对**真实登录主体、组织任职/有效授权、动作权限、案卷版本**；授权来自可信 Host/Main 及学校授权源（概念上对应 M015），**不接受 Renderer 传入的 actor/role**。目前并未证明已存在可调用接口。
2. 受托办理如获校规允许，须能核对授权人、受托人、授权事项、有效期间；“某部门联系人”“本人姓名相同”都不足以授予批假权。
3. M002/M007/M011/M015 如系校方已经持有的真实人事、决定、销假或政策记录，优先引用权威源；接口未核实或失联时记 SOURCE_UNAVAILABLE，交人事岗位人工查核，**不无理由要求教职工重复上传**。
4. 医疗证明使用单独权限域，普通模板路由、教务和其他审核人不得默认查看诊断全文；如确需自动化抽取须先确认合法性、处理必要性和影响评估 [SRC-007]。
5. 对关系变更、跨单位、干部职位变动使用行为发生时和当前的授权快照分别判断；已生效人事决定的撤回/改动必须由真正有权机关签署，模型绝不回填伪造的批准人。

## 06 业务对象与字段字典

本节是**业务数据契约研究稿**，不是宣称 V3 已实现的 DTO、IPC 或数据库字段。编号 F001–F040 连续且只在本 ID 使用；“阶段需用”表示本情形进入后应处理该事实，并非全部初始材料必填。字段值由其原始证据与产生阶段确定，旧值更正不得隐式覆写原本生效决议。

### 6.1 对象模型与可信等级

| 业务对象 | 定义 | 权威性边界 |
| --- | --- | --- |
| CASE 请假事件 | 同一教职工的一次请假及其更正、续假、销假、异议的总关联 | 案卷 ID 由可信后端发放，不赋予请假效力 |

隐私等级：P0=业务结构与不含身份的规则索引；P1=一般可识别教职工数据；P2=受限人事/干部/薪酬/权限数据；P3=医疗健康等敏感个人信息。所有 P2/P3 均需最小授权与审计 [SRC-007]。

### 6.3 必填与未知口径

- **业务事实最低集**：初次申请仅要求可信人员关联 F002、本人声明 F011–F014、真实操作主体 F008/F016，以及系统生成 F001。F015 并非用户填的真实“天数”，要依校历和适用规则派生，政策未核只能显示“未知”。
- **强制权威引用不等于强迫上传：**F002–F007、F017、F027/F028、F033/F034、F039 首选有权人事/OA/考勤源；没有接口时可以进入人工核实，不能把学校本来持有的记录一律变成申请人必须上传的扫描件。
- **姓名匹配：**同名不足认定；证件号码或医院就诊编号如需使用，须合法且仅在受控区域比较，界面显示必要部分。F021 只有可证明的人员关联，而不能因 OCR 的姓名一字不同自动判定造假。
- **F 与 M 的归属：**一个 F 可由多个不同版本 M 证明，每次取值须携带 F040 所定义的来源、位置、版本与有效性。更新 F013/F014 或 M003 后，受影响的日期重叠、证明期间、一致性结论必须重新核验。

## 07 材料槽与证据目的

本节材料槽 M001–M015 连续，区分**当下申请产生、条件触发、校方权威已有、未来才形成**。这里的“必需”只表示业务阶段所需的事实/权威记录，不宣称校方最新表单全部要求相同上传件。每个 M 绑定请假事件 ID、材料持有人/签发者、sourceVersion、采集时间、受审版本及 F040；材料在学校可信系统内时应优先引用，不假设现成 API。

## 08 审核规则逐条清单

### 8.1 规则运行前提与三值条件

本节 R001–R023 是**独立事实核验/流程守卫**，不模拟学校现行审批细则。先以案卷已触发的阶段及可信业务动作计算触发条件：**真（T）**执行该规则，**假（F）**返回 `NOT_APPLICABLE`（须有可追溯的未触发理由），**未知（U）**不得当作假；须按未知原因分别给出 `POLICY_UNCONFIRMED`（校规/适用性未证实）、`SOURCE_UNAVAILABLE`（应由学校掌握的权威事实缺位）、`NEEDS_MATERIAL`（已证实当前应提交的请求缺失）或 `NEEDS_HUMAN_DECISION`（权限与事实尚须人工判断）。

**证据层级：**L0=经学校认证、带生效时间与版本的本人/人事/权限/审批/考勤源；L1=经有权部门核验录入的线下原件或医疗机构权威记录；L2=当事人提交的申请、医疗电子文书及合法复核证明（仅证明声明或需进一步验真的内容）；L3=截图、OCR、上传文件名或外校制度线索。L3 不能提升为批准事实；L0/L1 无法取得时不得假定已有接口。医疗材料的真实效力需专人和现行学校标准确认。**所有 R 的证据定位均包含 CASE/F001、M 槽、sourceVersion/F040、页/区域或事件字段、采集时间、引用 F 和 SRC，且应在每次规则评估时冻结快照。**

**状态分配约定：**表中“结果”描述触发为 T 后的核心事实比较；每行另有 U 与 F 的出口。若同一事实同时存在独立问题，拆成不同 `ruleId` 的问题，不用一个“通过”掩盖未闭合校本政策。 `PASS_FACT` 仅表示该独立可观察事实一致，绝不代表校方准假、销假、撤销或申诉成立。凡备注“PU”者，即使其他事实通过，正式办理仍受校本政策核实门禁约束。

### 8.5 适用边界与禁止凭空成规则的事项

- 上述 R006 的时间算术只检查**输入区间自身是否一致**，不能在缺 M015 校本依据时自动判定“超过 X 天不准假”；R009/R011 不评判疾病真假或医疗建议的专业适当性。
- 一个规则可对不同 `targetId` 产生独立 Check：例如 R006 的“起止顺序”在输入自洽时可为 `PASS_FACT`，但“按某校规计算的期限合规性”因缺 M015 仍须 `POLICY_UNCONFIRMED`；两个状态不能压缩成同一个结果或生成虚假合规结论。
- R022 只核对外来**已经签发**的权威决定的来源和权限，不生成“同意/拒绝”的业务事件；审批拒绝是否成立、退回程序和正式复核均由经查明的有权机构处理。
- R019 的 `PASS_FACT` 仅表示已查得原机关真实销假记录，不能使用一次打卡或者用户上传“销假成功”截图代替。
- 所有涉及 **SRC-001** 的请销假专属权限与期限规则仍为待证；**SRC-009** 只能出现在跨校误用拦截和调查说明，不能充当 R 触发阈值。

### 9.2 冲突类型、归属和决策权

1. **身份冲突：**F003 与 M003 的 F021 不一致时，先用可信 F002 结合受限证明中的合法身份标识核对；同音、曾用名、婚后更名、排版差异不能自动判假。医疗原件隐私级别仍为 P3；交有权人事/医疗核验角色处理。
2. **日期冲突：**F013 晚于 F014 是字段自相矛盾，可要求申请人更正。M003 医疗建议 F022 与申请 F013/F014 仅部分相交时，输出冲突区间和原文位置，不自行审批超出医嘱的天数。F028 原批准区间只来源 M007。
3. **时间与先后：**F020 证明出具日在申请之后并不必然属于虚假，可能先申请后诊疗；允许追补的前提和期限由校方确定。F016 是可信收件时刻，不可用手机拍摄时间替代。
4. **签发和权限冲突：**扫描决定 M007 的“同意”与 M015 授权快照不一致，进入 HU/SU，不推定审批人有效；仅真正有权校方记录能确认生效结论。HR 当前领导不必然是历史事件时的有权领导。
5. **跨材料冲突：**同一申请版本下 M001/M009 日期与 M003 建议冲突时保留两者，定位具体页/字段及版本；M010 返岗时间与 M007 已批期不同，不直接视为违规，而是转有权人事核验。
6. **跨业务冲突：**M014 的 G05/教务或考核结论若与本案日期重叠，只记录“待两业务有权机关确认”；G50 非人事授权者不能把技术匹配结果变成上游有效决定。
7. **隐私与事实无关字段：**病历上未经授权获取的疾病史、家属信息或检查项目，不因为文书同页出现就收集到 F012 或推送给普通待办。过度材料应限制访问，不能被模型无限制复用 [SRC-007]。
8. **真实缺件和来源失联：**未提交当前必需且已产生的 M001，可 NM；OCR 读不清 M003 是 UR；校方 HR 记录不能访问是 SU；没有专门校本规则是 PU；有权裁量尚未作出是 HU。不得将五种状态合并成“拒绝/不合格”。

### 9.3 更正、主从版次与受影响项重审

- 每个材料至少记录：所属 CASE/F001、材料槽 M、证明对象、签发/持有人、来源通道、源版本、采集时间、当前取用版、F040 指纹与可回指的页/区域。**申请人新上传的同名文件不是旧文件的隐式覆盖**。

| 返岗打卡 17 日、原计划 15 日、无销假结果 | M010、M011 未形成，F032/F034 | 比对日期并通知人工，不自动认定旷工或销假完成 |

| 学校 OA 正式请假决议与 G05 因公行程冲突 | M007/M014、F028/F038 | 标明两权威决定时间重叠并交双归口核实，不私自使任何一个无效 |

## 10 结果状态、问题与待办输出契约

### 10.1 每条核验结果的互斥语义

**每个 `Check × targetId × sourceVersion` 同时只能拥有一个当前主状态**，每条问题保留独立事实/证据引用；案卷可同时存在多条不同状态的检查，不可强行把所有检查合成一个“批准/驳回”。下面是**概念合同**，不是已验证可直接运行的 DTO/IPC。

| 主状态 | 可确定的条件 | 不可混同的情况 | 下一办理动作/角色 |
| --- | --- | --- | --- |
| `PASS_FACT` | 适用条件 T 且该规则指定的事实在适格证据中一致 | **仅事实通过**；校规阈值、行政裁量及正式准假仍可能未知 | 可供有权业务人查看事实及出处；不得自动同意 |
| `NOT_APPLICABLE` | 适用条件经可信证据确认 F，或明确属于未来尚未到达的阶段 | 未知不能算 F；暂未拿到应有校方记录不算 F | 保留触发判据和阶段，后续阶段变化时重新检查 |
| `NEEDS_MATERIAL` | 当前阶段按**可核明要求**应由申请人/单位出具的材料缺失 | 未来决定件、未知的医疗证明义务、学校系统持有件失联 | 给对应材料持有人补件待办，含 M 槽及实际期限来源 |
| `CONFLICT` | 两项可定位证据的身份、时间、签发范围、版本或归属实质不一致 | OCR 不可读不等于矛盾；重大裁量意见不同不等于已经证实虚假 | 有权限的单位/人事/医疗核验员核实，并通知真实申请人 |
| `UNREADABLE` | 已有材料，但文件/页/字段因损坏、遮挡、识别失败而不能合理取得必要事实 | 不把 OCR 抽取失败描述为申请人“未提交” | 先人工读件/请求清晰版，保留原件与异常位置 |
| `SOURCE_UNAVAILABLE` | 应由学校或外部权威源提供的身份、批假、考勤、授权或受理记录不可取得 | 不让教职工默认重复上传学校掌握的全部档案 | 向对应源系统责任岗发可信查核待办，记录查询尝试 |
| `POLICY_UNCONFIRMED` | 现行 CDUT 条款、适用范围、时限、证明门槛或授权路线尚不能由原文证实 | 不能套 SRC-009 成都大学或过期校规“先行判定” | 人事处/有权制度解释岗确认文号、版本和适用条款 |
| `NEEDS_HUMAN_DECISION` | 事实可见但需医疗专业判断、代理例外认定、审批/撤销/复核等真实行政人事裁量 | 不是 `PASS_FACT` 的别名，也不是自动驳回 | 定向交有权岗位或其真实授权代理，系统仅保留待办 |

优先判断：① 先核触发 T/F/U；证据可证明 F 时 `NOT_APPLICABLE`。② U 依据“政策未知/权威源不可用/个人请求未提交/真实人事裁量”等原因转相应阻断状态，不能默认 `PASS_FACT`。③ T 时先检查引用证据的正确案卷/版本；若错案为 `CONFLICT`；若未产生则依阶段定 `NOT_APPLICABLE`，已产生但不能读为 `UNREADABLE`；当前依法/校规明确应交却未交才为 `NEEDS_MATERIAL`；权威源失联为 `SOURCE_UNAVAILABLE`；证据间实质矛盾为 `CONFLICT`；事实一致但仍需裁量为 `NEEDS_HUMAN_DECISION`；已明确的事实一致才 `PASS_FACT`。若多项独立原因同时存在，应拆出**不同规则/不同目标**的待办，不以人为排列的单一状态掩盖冲突。

### 10.2 规则结果、问题与待办所需字段

| 输出对象 | 必须保留的字段与约束 |
| --- | --- |
| 核验快照 | `caseId` (F001)、`caseRevision`、`templateId=T02-T11`、`runId`、`planId/fingerprint`（若真实技术合同支持）、`ruleId=Rxxx`、`checkTargetId`、`applicability=T/F/U`、`status`、评估时间、所用政策版本 F017；以上均由可信后端冻结，不宣称现已实现 |
| 证据定位 | 每个引用含 `Mxxx`、`Fxxx`、`SRC-xxx`、持有人/签发者、原件位置/页码或事件字段、`sourceVersion`、F040 指纹、取得渠道、签发时间与有效区间；涉及医疗内容只向授权角色展示最小片段 |
| 问题条目 | 独立 `issueId`、`ruleId`、`targetId`、发生阶段、问题主状态、期望证据 M/字段 F、现有证据定位、冲突两方或不可读原因、可补件性、截止依据（不明则“未核实”）、建议处置，不虚构已审批事实 |
| 待办路由 | `assigneeRole` 为**待校本确认的职能角色**、处理动作、所需权限、可见数据级别、关联 `issueId`；派给具体人的真实性必须通过 Host/Main 和校方授权源校验，不由 Renderer 提供 |
| 处置与重审 | 关联 `issueId`、原 `ruleId`/目标、提交人可信身份、替换的 M 槽及新旧版本、回应时间、操作痕迹；仅受影响 R 重跑，旧核验快照保留 `superseded` 关系而不删除 |
| 正式学校决定引用 | 若实际有权机关已有决定，只保存决定 ID、类型、签发角色及授权快照、时间、生效/撤销版本、关联原申请/原决定和可验证源地址或线下核验事件；由真实权威来源提供，模型不能生成 |

每个 `ruleId` 的“证据归属”是 **CASE + 被审核人员 + 业务事项阶段 + M/F/SRC + sourceVersion** 的联合校验，不仅是“文件名相似”。问题界面可跳转到对应原材料、目标字段、版本差异及人工办理入口，但本节不承诺目前客户端已经实现这些跳转或 JSON 结构。

### 10.3 案卷摘要与正式决定分离

- **事实层**：呈现适用规则数、`PASS_FACT` 数、未闭合问题及各自状态、材料数和版本，明确“事实预审已完成/仍有待办”。个别 `PASS_FACT` 不得抵销未解决的 `POLICY_UNCONFIRMED`。
- **权限层**：只有经可信身份/授权校验且校本政策版本有效，才把案卷交至真正有权者办理；当前本校授权正文未得，待办应标“需校方核权”，不能显示为“已完成审批”。
- **决定层**：正式准假、撤回生效、销假确认、复核结论都是**外部权威决定**，须关联真实原始记录后才可展示生效状态。未有权威事件时状态是“尚未取得有效决定”，而非 AI“拒绝”。
- **下游层**：仅在权限、目的和最小数据范围成立后向考勤/工资/考核提供被授权引用；不要把 `PASS_FACT` 或医疗诊断全文推送为最终考核、扣薪、旷工结论。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 生命周期和允许动作（概念状态，不声称学校 OA 已有同名状态）

| 当前阶段/事件 | 允许的事实层动作与对应角色 | 进入下一阶段的条件、阻断与不可逆边界 |
| --- | --- | --- |
| `DRAFT` 初稿 | 本人提出 M001，可信后端建立 F001；代理仅存其提出的代办请求 | 无可信身份或没有申报意图仅保留草稿；不得出现学校签批结论 |
| `SUBMITTED` 已收件 | 受理经办核 F008/F016，触发 R001–R007；有条件时核医证、交接、代办 | 校本适用政策不可得时仍可列事实待办，禁止直接流转“校方已批准” |
| `FACT_REVIEW/NEEDS_INPUT` 事实核验或补件 | 申请人补交 M，校方权威源查核 SU；核验岗记录冲突/不可读及限定 R 重审 | `PASS_FACT` 是规则局部事实；补件关闭问题不等于许可离岗 |
| `AWAITING_AUTHORITY` 待有权决定 | 确认政策、签发权限、审批对象；有权人按校本制度办理 | 缺授权或来源时保留 `POLICY_UNCONFIRMED/SOURCE_UNAVAILABLE`；模型不得代签 |
| `DECISION_LINKED` 已关联正式决定 | 经授权服务引用 M007 决定 ID、范围、时效；保留原版及后续合法变更链 | 有效决定由学校真实流程产生；不因申请新版本而自动改写 |
| `CHANGE_OR_WITHDRAWAL_PENDING` 改期/续假/撤回中 | 本人提出 M009；R014/R015/R017 比对旧决定和新意图；原有权者处理变更 | 撤回待审请求可否即时生效尚待校规；已有批准永不被本人单方删除 |
| `RETURN_REPORTED` 返岗已报告 | 本人/单位形成 M010、F032，单位核实 R018 | 未返岗不得催交未来 M010；考勤不等于销假许可 |
| `CANCELLATION_LINKED` 销假结论已关联 | 校方实际有权岗位产生 M011 后核 R019/R022 | 仅引用真实决定，才能展示销假生效；不在初请时强制索要 M011 |
| `REVIEW_REQUESTED` 异议/复核请求 | 本人提交 M012、关联 M013；真实受理部门决定是否受理并出具回执 | 本模板不得改写被申诉原决定，复核程序、期限及结果另由权威机关决定 |
| `CLOSED/ARCHIVED` 事实归档 | 保留案卷事件、规则快照、源版本及有权决定链接；访问与保存期限由校方定 | “关闭”只说明本工作区的流程终态，不推断工资、纪律或学校已批准 |

### 11.2 补件、撤回、重提、复核的具体守卫

1. **补件**：仅对指定 `issueId/ruleId/targetId` 发 M 槽需求、理由和证据定位；问题责任人的确是申请人时才要求其提交。校方 M002/M007/M015 失联由有权部门查核，不转嫁给教职工。
2. **撤回未决申请**：记录 F031 的“本人请求撤回”及其时间；学校是否允许撤回及何时生效未核明，先留 `POLICY_UNCONFIRMED`。原提交/补件版本和评估快照不可删除；重提须建立**新的申请版本和真实收件时间**，不复用旧“已提交”结论。
3. **已生效批准的变动**：F027/M007 已存在时，R017 只能说明撤销请求存在；待原有权机关签发有效撤销/变更记录，才可更新实际有效决定关联。个人撤回绝不自动消灭原批准。
4. **复核**：M012/M013 按原决定 ID 绑定，F037 只在正式受理/收件后形成；请假审批、考核申诉、劳动争议的程序可能不同，按学校和上位制度另行分流 [SRC-003][SRC-006]。
5. **正式人事决定**：只有符合 R007/R022 权限版本和可信身份的审批事件才能被引用。任何来自前端 `actor/role`、扫描公章、OCR“已同意”的主张都必须待真实授权源核实。

### 11.3 材料变动到规则的精确依赖（全 M 覆盖）

以下为单材料变动时的**最小候选重审集**；实际还须检查该材料影响的其他字段和跨案共享引用。始终对变动的单个 M 目标重新运行 R001，M008 补件时还运行 R016；不得整案无差别重审。

| 变化的 M 槽 | 必须检查的依赖 R | 不该自动影响的决定 |
| --- | --- | --- |
| M001 本次申请 | R004/R005/R006；病假期间关联 R011；身份声明改变关联 R002；有原案时 R014 | 已有 M007 正式批准不得被申请文本覆写 |
| M002 人事关系 | R002/R003/R010/R013/R022；涉及单位交接时 R008 | 原医疗证据不因关系变化而被改写；须重判归属 |
| M003 医疗证明 | R009/R010/R011/R023 | 已签 M007 仍需原批准机关依法判断效力 |
| M004 紧急通知 | R012 | 不自动改变正式准假 |
| M005 代理授权 | R013 | 不使代理人成为真正审批人 |
| M006 工作交接 | R008/R021 | 不自动批准私人请假或调课 |
| M007 正式请假/变更决定 | R014/R015/R017/R018/R022；若与外部冲突再 R021 | 不由本模板生成替代审批事件 |
| M008 补件版本 | R016，及被替换的目标 M 所绑定的 R | 不因提交补件恢复过时的事实核验 |
| M009 新的变更/撤回请求 | R004/R005/R006/R014/R015/R017；涉及医证再 R011 | 原 M007 权威决定继续按其有效链存在 |
| M010 实际返岗/考勤 | R004/R018/R019 | 返岗记录不是销假 M011 |
| M011 正式销假结果 | R019/R022 | 不改写初始批准 M007 |
| M012 复核请求 | R004/R020 | 不冻结或自动推翻原被争议决定 |
| M013 被争议决定 | R020；签发真实性有疑再 R022 | 不让申诉材料取代原决定 |
| M014 相邻业务结果 | R008/R021；含跨域 P3 风险再 R023 | 不执行 G05/T01/T02-T05 的决定 |
| M015 现行政策与授权 | R003/R005/R006/R007/R008/R009/R012/R013/R015/R017/R019/R020/R022 | 已生效决定如需重新评价，由有权学校机关启动合法程序 |

单个 sourceVersion 替换导致的流程：将旧 `Check × target × sourceVersion` 标为 `SUPERSEDED_FACT_RESULT`（**仅历史核验快照标签，不是新增业务结果码**）→ 找出此 M 的 R 依赖→ 冻结新资料和被取用的其他 M 版本→ 只重新执行受影响 R→ 重新计算相应 `issueId`→ 通知有权岗位。若替换触及正式学校决定，只能发起“需有权变更核查”，不能模型自动撤销。

### 11.4 可信身份与数据出站守卫

- **主体**：后端可信认证、学校人事关系及行为当时有效授权共同确认；Renderer 只传动作意图，不传权威 actor。特殊干部或临聘人员不可自动继承普通教师审批路径。
- **证据可见性**：P3 医证仅对授权核验角色开放，待办可仅显示“证明归属/建议期间待核”，不可展示完整诊断；操作与访问保留审计。未经授权调用先阻断数据流，由隐私岗处理 [SRC-007]。
- **批次与离线**：一次 ZIP/文件夹导入可生成多个待建案事件，但这些是技术输入批次，不能替代每个 F001 的人员/决定归属；离线重导不得覆盖较新源版本或把旧 R 快照视为现行结论。
- **G50/S/T**：只复用通用解析和已有**有效权威结论**；不复制他模板审批业务，不把 T02-T11 的预审推给薪酬、考核或教务直接作决定。最终接线形式须与实际 V3 版本合同核对。
