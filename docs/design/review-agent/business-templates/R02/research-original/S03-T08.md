### 00.2 重要研究发现及其限度

1. 成都理工大学财务处 2026—2027 学年缴费通知，明确区分国家开发银行/中国银行的**回执校验码**、四川农信的**应用二维码**、其他银行的**纸质回执经学院汇总上报**；生源地资助中心审核及经办银行放款发生在校外，财务处再办理缴费抵扣/到账核对。来源 `SRC-001`。
2. 学校资助管理中心负责指导、协助生源地贷款以及校内资助数据和手续管理，不等于银行审贷机构。来源 `SRC-004`。2024 年学校通知曾规定部分银行需要学院及学工部门用印、校方核验回执；其**当期适用范围仍需复核**。来源 `SRC-005`。
3. 2025 年学校本科与研究生资助政策一致明确当时未开展校园地国家助学贷款；同学年两类贷款互斥。来源 `SRC-002`、`SRC-003`。本模板不以此推断 2026 年开放状态，也不代办银行授信。
4. 金融账户、家庭财务、共同借款人信息具有明显敏感性；学校材料核验应采用目的限定、最小必要、授权访问、留痕和独立的人工决定机制。来源 `SRC-011`。本稿不要求个人银行流水、征信、密码、完整贷款合同、家庭成员身份证正反面等作为一律必交材料。

## 01 唯一审核目的、申请人和负责机构

### 01.1 真实事项与审查对象

学校确有助学贷款配套事务：入学/返校时回执登记、信息和证明核对、特定银行纸质回执和用印协助、后续资助中心确认，以及资金到达后的学费住宿费缴纳状态核对。2026 年度证据见 `SRC-001`；学校自身职责见 `SRC-004`；较早的例外证明链见 `SRC-005`。这些事实支持建立一个**校内配套核验的候选模板**，但不能证明学校另有完整的「贷款授信资格审批」流程。

本 ID 的**唯一决定对象**是：针对某申请人、某学年/批次、某生源地贷款办理事项，核对校方有权知悉或出具的**学籍/录取状态、收费标准、身份关联、回执/证明形式与归属，以及需要校方确认的办理动作**，形成校内事实核验记录或转交有权经办人的待办。不得将「贷款已经获批」「放款成功」写作本模板的结果。

### 01.3 以事实为对象的有限核验

- **可核**：申请人是否对应学校的录取/在校学籍底账（当前学段及学年），校方要求的回执类型是否与经办机构类别相适配，材料上的姓名/学号/学年/院系关联是否一致，学校收费标准引用是否来自当期财务处，回执是否清晰完整、需要学院转交或校方盖章的情形是否已有可信办理记录。
- **不可直接裁定**：家庭贫困程度、征信水平、申请金额能否由银行批准、共同借款人资格、合同效力、资金何时到账、重复申贷是否成立（没有可信银行结果时）、贷款利率、个人还款能力。
- **条件未知**：学籍底账/银行回执系统不可用时标注待核，不能据「系统未查到」认定申请人失实。

## 02 适用、排除与邻接模板路由

### 02.1 适用范围（候选，待核现行配置）

1. 本校录取新生、在读本专科生及研究生办理**生源地信用助学贷款的校方协助材料**；本科及研究生在校公开政策均提及助学贷款（`SRC-002`、`SRC-003`）。真实学段、学籍或录取结论须来自相应权威系统，不因该叙述自动确认为符合银行条件。
2. **首贷、续贷、不同经办银行、不同学年批次**仅是同一 `S03-T08` 的办理情形；原始外部贷款申请表、合同签署和银行审贷属于上游步骤，不是学校统一必填项。
3. 校内需要配合开具或确认的学费住宿费、学籍、回执、特定银行表格，可作为本模板的目标材料；**证明的具体出具权和用印流程**需按学校现行规定及表单单独确认，不能照抄 2024 年通知为 2026 年硬门槛（`SRC-005`）。

### 02.3 校园地申请的当前处理

2025 年学校本科与研究生简介均说明「我校暂未开通校园地国家助学贷款项目」（`SRC-002`、`SRC-003`）。因此对 2025 批次不能模拟学校内部校园地贷款审批。对 **2026 批次**必须请求学生资助管理中心确认是否仍未开通；未知时输出 `POLICY_UNCONFIRMED` 并人工转介，**不得凭 2025 文件永远拒绝申请**。

### 02.4 现阶段目录变更判断

现有材料未证明贷款下的「首贷」「续贷」「回执」「其他银行用印」「不同学段」具有各自独立的**行政授权目的**，均保留在同一 ID 情形矩阵。暂不提交 `CATALOG-CHANGE-REQUEST`；只有后续取得原始现行规章证明另有独立授权目的，再提出变更而不改 `S03-T08` 编号。

## 03 业务生命周期与办理情形矩阵

### 03.1 阶段模型（概念框架，不声称已实现）

| 阶段 | 触发和实际来源 | 学校可见/可做的工作 | 本阶段**不得提前索要** |
| --- | --- | --- | --- |
| `L0` 咨询与路由 | 学生准备申贷，确定生源地/校园地及当期学校服务状态 | 提供真实途径、校内证明需求指引；如确需，核学校学籍/收费事实 | 还未签署的银行合同、尚未生成的贷款受理回执 |
| `L1` 外部申请/首贷或续贷 | 学生在生源地机构/经办银行申请；首贷、续贷材料由机构决定（`SRC-012`） | 在有正式要求时提供学籍、在读、收费或特殊用印证明 | 银行后台授信结论、家庭金融账户明细作为学校一律必交 |
| `L2` 外部受理后取得回执 | 经办机构签约/受理产生回执码、二维码或纸件 | 在校园学工系统/学院相应路径核回执类型、学年归属与真实性线索 | 放款凭证、学校到账票据 |
| `L3` 学校确认与报送 | 学工中心/学院按经办行和批次处理（`SRC-001`、`SRC-005`） | 经真实权限进行校内确认、修正、补件、转交；附经办动作和来源 | 将「校内确认」解释为银行审批 |
| `L4` 外部审贷、放款 | 生源地资助机构和银行决定；结果可能迟于学校回执 | 若获可信结果，引用其状态；财务处以到账记录抵扣/核对 | 要求学生在 L2 提交尚未出现的放款结果或缴费电子票据 |
| `L5` 结案/异议/更正 | 发现信息错配、撤回校内请求，或经办机构更新结果 | 依保留证据版本处理校内更正及人工复核申请；外部合同变更仍走银行程序 | 自动撤销银行合同、自动改变财务流水 |

**性质区分**：这是研究用生命周期，不代表学校已公布统一六阶段，也不代表软件存在完整状态机。`L2` 与 `L3` 可多次迭代；外部机构并不保证与学校数据同步。

### 03.3 独立决定的时序约束

- 必须区分 `贷款申请意愿 → 生源地机构受理/签约 → 学校回执确认 → 银行审批/放款 → 财务入账/缴费`。时序由资料表述为**典型过程**，不同银行可异步或采用不同形式；不得把它当单一不可逆流水线。
- 校内补件、撤回、异议仅处理学校有权限控制的材料及处理动作。能否撤销已录入银行系统的回执、期限和法律效果需当期联络主管确认。
- 对真实提交的每个学生/学年/经办机构分别留版本；历史结论不得凭时间或名字相似复用于新贷款事件。

| 经济困难认定 | 具有签批来源、学年和状态的独立 S03-T06 权威结论；确需时最少量引用 | 根据家庭职业、户籍地、消费、获奖/未获奖情况推断困难等级或借款可获批 |
| 校内回执办理/用印 | 学校资助中心有权限的经办日志、正式签章或权威流转记录 | 由软件画出的签名图片、Renderer 身份字段和材料中的印章 OCR 冒充真实批准 |
| 银行终审、合同、放款 | 银行/县级贷款中心外部正式状态，按必要授权读取最小字段 | 以学校核验结果改写贷款状态；以银行短信截图单独确认资金已记入学校账目 |
| 收费到账与学费抵扣 | 财务处可信账务记录 | 从贷款审批通过自动标记学杂费已缴清 |

敏感数据如确因单次银行或校务要求需要处理，应另行确认合法处理依据、告知、数据保留期限、访问范围及审批人；安全技术、权限审计须符合《个人信息保护法》第 6、17、19、28、51、55 条（`SRC-011`）。

### 05.4 预留结果语义，不定义正式决策权

后续规则统一可用：`PASS_FACT`（某具体事实已核对）、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`。`PASS_FACT` **不等于贷款获批/学校正式通过**。应用状态与校务决定状态严格分开。

## 06 业务对象与字段字典

本节是**研究设计的数据契约**，不是声称已接入学工系统。最小聚合：`caseId → studentRef + academicYear + loanEventId → receiptArtifactId + schoolAckId + feeEventId`；不同学年新建事件而非覆盖。每个字段应存 `sourceSystem/sourceRecordId/observedAt/version/evidencePointer`，正式身份和结论仅信任后台认证或机构可验证的记录，学生填报仅作声明。缺失策略 `待补` 仅限当前适用且已有法律/校本依据的材料；`待源` 指权威服务不可用；`待策` 指适用规则未核；`后续` 不可提前报错。敏感级：P0 非个人、P1 普通个人、P2 敏感金融或身份信息（尽量不存原值）。

## 08 审核规则逐条清单

统一计算：触发 `T` 执行指定单一事实、`F` 返回 `NOT_APPLICABLE`、`U`（无法确定触发条件）按证据原因返回 `SOURCE_UNAVAILABLE` 或 `POLICY_UNCONFIRMED`，不把未知当假。表内「异常」按优先级 `CONFLICT > UNREADABLE > SOURCE_UNAVAILABLE > NEEDS_MATERIAL`（但政策缺失独立为 `POLICY_UNCONFIRMED`），事实匹配才 `PASS_FACT`。授权签批、政策例外统一 `NEEDS_HUMAN_DECISION`。每个结果是**该规则的结果**，不是银行贷款或校方最终行政决定。以下 `T/F/U` 中 U 具体原因必须写进 issue。

## 09 触发条件、冲突和复合场景

### 09.1 分组与顺序

1. 先定 `studentRef + academicYear`，只以可信身份源关联；首贷、续贷、预申请只影响外部进度与当前可有的材料，不改变校内真实性标准（R001–R006）。
2. 生源地且已形成回执后，按银行类别三选一触发 R007/R008/R009，再独立触发 R010、R011；银行未定时三条皆不能推断「无材料」。
3. 校方证明与章权仅在收到外部机构当前要求时触发 R017/R018；困难认定仅在当期确需时 R019；代理和特殊学籍是条件分支 R026/R027。
4. 校内确认、银行放款、财务到账、抵扣是四个不同节点（R012–R016）；任一事实不得自动填补后一节点。2026 年在校生财务通知支持收款路径，不代表银行已经签约。
5. 校园地若无 2026 正式开放证据，R024 停在 `POLICY_UNCONFIRMED`，人工转资助中心。2025 旧文不得导致自动拒绝；若同学年双类疑似，以 R025 留出核验与外部沟通。

### 09.2 冲突和例外裁决

| 组合 | 处理 |
| --- | --- |
| 同一学年多次提交回执 | 按签发时刻和外部确认版本保留历史；未经权威更正不自动选最新截图，R011/R021 可能 CONFLICT |
| 回执正确但银行接口故障 | R007/008/009 可 PASS_FACT，R010 SOURCE_UNAVAILABLE；保留待办，不推进校方已确认 |
| OCR 学生姓名一致但银行号属于他人 | R011 CONFLICT；人工安全核查，禁止跨案合并或自动纠正 |
| 银行显示放款、财务暂未到账 | R014 PASS_FACT，R015 待源或未到账事实，非互斥矛盾；向财务查询，不擅改账 |
| 校本学费显示已减免或缓缴 | 仅引用 S03-T11/T13 有权决定，不改造贷款外部状态；收费数依财务源重算 |
| 困难认定已撤销或版本更新 | 仅当 R019 的当期必要条件成立时定向失效；不据此自动终止银行合同 |
| 非全日制/预科/专升本/学籍变更 | R027 校本政策未取得则待策，转教务/研工和银行确定适用性；禁止名字匹配即拒绝 |
| 校方声明与银行正式记录冲突 | 外部签约/放款由银行负责，校内身份/收费由学校负责；分别创建 Issue，不强行合并成最终结论 |

### 09.3 归责边界

G50 通用证明只处理一般性用印形式，不重复作贷款事实决定；S03-T06 困难认定、S03-T07 助学金、S03-T11 学费减免、S03-T12 服兵役资助、S03-T13 缓缴、S07-T07 基层就业贷款代偿各自独立。其记录仅作有效版本引用。年额度、利率、特殊人群政策不从历史通知推导自动拒绝门槛。

## 10 结果状态、问题与待办输出契约

每条问题强制结构：`issueId,caseId,studentRef,academicYear,loanEventId,ruleId,triggerState,resultCode,fieldIds,materialSlotIds,artifactIdsAndVersions,sourceIds,sourcePointer,comparisonSummary,policyEdition,createdAt,assignedRole,nextAction,stalenessKey`。不存身份证号或完整贷款码在提示词、日志或可见 Issue。

| 互斥结果码 | 解释与下一办理动作 |
| --- | --- |
| `PASS_FACT` | 该规则的一个事实成立，提供来源和版本；**绝不**翻译成银行或学校最终批准 |
| `NOT_APPLICABLE` | 明确触发条件为假，如农信贷款不要求国开行码；留触发依据 |
| `NEEDS_MATERIAL` | 当前阶段、现行政策要求的证据尚缺；指向单一材料槽和学生/学院 |
| `CONFLICT` | 两个可追溯来源的学生、学年、银行、版本不一致；不得自动选优；指派经办 |
| `UNREADABLE` | 文件已上传但指定页码/二维码无法识别；请求重传同槽新版本 |
| `SOURCE_UNAVAILABLE` | 学籍/银行/财务权威服务或真实性回查不可用；由数据源 Owner 恢复或人工确认 |
| `POLICY_UNCONFIRMED` | 当前学年/学段/银行的校方规则、签章或校园地开放状态未核；不能以旧稿作否决 |
| `NEEDS_HUMAN_DECISION` | 需要有权人员签章、争议处置、撤回/例外/复核；提供待决事项和角色 |

待办示例（合成）：「案卷 C-102，2026—2027 学年，R011：M004 v2 的回执学年为 2025—2026，与 F003 冲突；请申请人提供本学年回执，学院核验后仅重跑 R007/R010/R011」。结果看板应分别展示 `事实核验`、`校内经办签署`、`银行外部状态`、`财务到账抵扣`，不得出现单一无来源「审核通过/放款成功」。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 事件状态与闭环

`DRAFT → SUBMITTED → FACT_CHECKED/ISSUES_OPEN → SCHOOL_PROCESS_PENDING → SCHOOL_ACTION_RECORDED → EXTERNAL_STATUS_LINKED → FEE_RECONCILED`。这些是并列记录进展，不存在「FACT_CHECKED 自动跳贷款批准」的转移。`WITHDRAWAL_REQUESTED`、`CORRECTION_PENDING`、`REVIEW_PENDING` 可从任何适用节点衍生事件；学校是否允许撤回或是否已经无法撤回由有权岗位决定。

- 提交：冻结 `caseId+studentRef+academicYear+materialVersion` 快照。后端确认 Actor 身份，保留政策版本；没有真实签发权只运行事实检查。
- 补件：Issue 指向具体 M 和版本；新文件产生 `supersedes` 关系，旧记录只读可查。材料归属或来源不一致先 CONFLICT，不让模型悄悄改学生编号。
- 定向重审：M004 更新重跑 R007/R010/R011，及依赖回执版本的 R012；M011 财务更新仅重跑 R015/R016；M014 他项困难认定更新仅在 R019 条件有效时重跑。学籍 F002/F004 发生权威变更则受影响所有依赖规则失效，须重新确认关联。
- 校内撤回：申请人只能请求停止未完成的本校转报/证明流程，学校确认已提交外部银行的边界；保留外部机构状态不变，不能通过删除本校回执撤销银行合同（R022）。
- 纠错：已向银行送达的错码、错学年，记录原确认编号、新证据、人工签名、银行接收/拒收回执。无接口或银行不承认撤回时生成待办，不声称外部同步成功。
- 复核与申诉：学生指明事实或程序异议、目标规则/版本；经办岗位以外、按校内真实权限分配复核，形成有权签署决定。期限、层级、渠道目前待核，不以想象期限自动逾期拒绝（R023）。银行授信争议路由银行/生源地机构，财务入账争议路由财务。
- 结案：保留校内动作决定 ID、外部状态最后核时点、财务最后核时点、未闭事项及敏感数据保留策略；学校签署与银行签约是不同签发域。任何重新打开均新建事件而非改写既有签名。

### 11.2 不可越权的执行检查

`Actor` 必须由服务端鉴权并与当期角色权限及岗位授权表相交；Renderer 提交 `teacher=true`、OCR 识别的公章、AI 摘要、批量操作入口、Run 状态均不赋予审批权。实际外部更正需机构确认后才记为 `ACCEPTED_BY_BANK`，未获得回执记为 `PENDING_CONFIRMATION`。
