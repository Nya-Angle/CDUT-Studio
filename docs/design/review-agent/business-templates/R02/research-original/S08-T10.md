## 01 唯一审核目的、申请人和负责机构

### 1.1 审核决定对象

为一个确定的 `申报年度/批次 × 报考培养单位 × 招生方式 × 学生身份`，核对材料中的身份与学籍、招生路径、前置推荐/导师意见、课程或成果等**可举证事实**，并将“已核实、缺材料、矛盾、来源不足、须人工裁量”的事实送交有权机构。辅助审核结论不是学校对“获准硕博连读”“拟录取”“正式录取”或“博士学籍形成”的决定。[SRC-001][SRC-002][SRC-003][SRC-004][SRC-005]

### 1.2 真实存在的申请人分支

1. **硕博连读（在读硕士→申请博士招生资格）**：2026 年博士招生章程列示本校全日制一、二年级学术型非定向硕士，以及全日制三年级非定向硕士，报考学术型博士且为非定向就业；学院 2026 实施细则要求本人申请，经硕士导师、拟报考博士导师同意后提交资格申请表及附件。具体年级条件、成果、英语等只能关联**同年度、同学院**文件。[SRC-001，第三节][SRC-002，第 1–2 页]
2. **直博（应届本科推免→直接攻读博士）**：2026 年研究生院工作办法限定普通全日制应届本科、在本科就读校取得推免资格等，并由有关学院组织复试；2027 年省级公告已确认继续使用全国推免服务系统。直接攻博**不是**把已入读硕士生转身份；2027 年本校申请材料义务仍需读取原办法。[SRC-004，第一至四部分][SRC-001，第三、七至八节][SRC-012/013]
3. **培养层次“转段”**：“全国推免服务系统”包含的“转段”亦可指**强基计划学生进入研究生阶段**（四川省 2027 公告有独立日期），不构成成都理工大学存在独立“硕转博学籍转段审批”的证据。不能以硕博连读初审合格直接改写博士身份。校内若有独立的培养层次转换批准文书，待有权部门出示后再评估；此前标记 `POLICY_UNCONFIRMED`。[SRC-005/013]

## 02 适用、排除与邻接模板路由

### 2.1 适用判定

- 仅在申请或核验对象是 `硕博连读资格`、`推免直博申请资格`，或后续有权文件确认属于同一目的的 `培养层次转段资格` 时使用。必须保存 `admission_year`、`school_unit`、`admission_route` 和匹配到的文件版次，不得凭“研究生”“读博”关键词默认路由。[SRC-001][SRC-004]
- “一年级/二年级/三年级”“课程正常/成绩不足以成果补充”“特殊学术专长人工放宽”“校内本科推免/校外本科推免”等优先在**本 ID 同一模板的情形矩阵**处理，不增新模板。[SRC-002][SRC-004]
- 2026 年确有独立招生的第三种路线“申请—考核制”，但其决定对象是常规博士招生，并非当然属于 `S08-T10` 的硕博连读/直博/层次转段；识别为邻接业务或人工路由核对，**不能用本模板里的硕博连读阈值审其资格**。[SRC-001，第三、六、八节]

### 5.2 来源优先级与审计要求

1. 以**具体招生年度、招生路线、招生学院**绑定政策快照；研究生院当年章程和公告、学院当年细则分别用于其授权层级，发生冲突时标记 `CONFLICT` 并交权责部门，不自行“以学院从严”为最终法则。[SRC-001][SRC-002][SRC-004]
2. 申请人身份证/学号、学籍年级/类别、课程计划与成绩、推荐资格、报名号、拟录取及学籍变更，须以有授权的学校主数据或国家官方系统校验。上传文件只能作为**待查证据**，不是这些事实的写入来源。[SRC-003][SRC-004][SRC-005]
3. 导师签字、学院章、推荐专家职称、招生指标、成果等级、“突出科研能力”等存在真实性或裁量问题；可提取并核验外观/关联，但不以 OCR 命中或 AI 评分即判真。[SRC-002][SRC-004]
4. 记录 `source_id`、政策年度与版次、材料原件指纹/版本、学校主数据来源与核验时间、是否原件可见、事实结论、问题、操作人经主进程可信身份验证的 actor、审批记录 ID/签章校验结果。前端/Renderer 自报 `actorId`、`teacher`、`approver` 只作不可信输入，不授予任何审核/批准权限。
5. 同一个案卷不得产生多个互不一致的“当前资格/录取/学籍”状态：前端仅显示本地事实预审状态，并**只读关联**校方正式系统决定。补件或材料修订保留旧版本、只重新核验受影响事实；旧 `run@rev` 不伪装为真实学校 Run/行政决定。

## 06 业务对象与字段字典

### 6.1 字段解释与数据对象

- 业务对象：`Case`（案卷/批次）、`Applicant`（申请主体）、`Program`（报考目标）、`MasterStudy`（硕士学业）、`DirectPhD`（本科推免直博）、`Evidence`（单条证据）、`Process`（阶段事件）、`DecisionRef`（外部有效决定只读引用）、`Audit`（版本与经可信验证的操作人）。

### 6.3 字段落地限制

上述 48 个是**审核事实/接口期望的数据字典**，不是宣告 CDUT 或客户端已经存在同名 API。严格区分字段的“申报值、证据提取值、可信核定值”；三者可能不相等。每个 `F` 的校验都要留 `sourceRef`、`materialVersion`、`verifiedAt` 与 `authorityRef`，缺任何一项不能声称由学校主数据确认。2026 各学院成绩阈值、英语换算、专业名单和补件期限不是固定 `F` 常量，而是需要当期来源确认的配置；`F025/F044` 等专业裁量始终只能引用外部人的决定。

## 07 材料槽与证据目的

### 7.1 材料槽原则

材料槽包括**申请人上传文件、校方权威记录及系统内部证据**，不等于要求每项都上传。阶段代码 `N`=本情形当期需有事实依据、优先官方取；`C`=触发时必要；`L`=后续产生、当前绝不索取；`P`=适用政策尚未证实。持有人是**原始证据权利/管理主体**，不是本工具拥有原始数据。文件类型按 DOC/PDF/图片/国家或校方数据库记录，但若系统没有合法可用接口，可接受有权主体签发的等效纸质/电子证明经人工核验；不得假定学信网/研招网/学校主数据库均已接入。

每项证据维护 `caseKey + applicantIdentityLink + purpose + admissionYear + college + sourceIssuer + sourceRef + materialVersion + fingerprint + receivedAt + status`。默认缺失：当前必要 → `NEEDS_MATERIAL`；受控源不可访问 → `SOURCE_UNAVAILABLE`；仅未来生成 → `NOT_APPLICABLE`；政策未核 → `POLICY_UNCONFIRMED`；不可读 → `UNREADABLE` 并保留原件，禁止转化为“没有该资格”。下表“缺/损”用简称 `N/S/P/L/U/H/C`，含义分别为前述缺材料、源失联、政策未知、未到节点、不可读、人工裁量、事实冲突。**每个槽均有 U 路径**，不能用猜测 OCR 补全。

## 08 审核规则逐条清单

### 8.1 规则执行的前提、证据层级与三值语义

1. **规则粒度**：`R` 的结果回答“某一时点某一证据事实是否得到核实”，不是“学校是否批准申请”。每条保留 `applicability=true/false/unknown`、`observed=true/false/unknown`、`reviewStatus`（下述八码之一）三个不同字段；`observed=false` 不得被无损转换为某个并不存在的“AI 拒绝”状态。当政策确认且可信来源明确证明某条件未满足时，展示“不符合该事实条件/待有权处理”，`reviewStatus=NEEDS_HUMAN_DECISION`，学院决定是否不予受理、补正或按制度例外处理。
2. **适用判定**：本案的 `录取年度 + 招生方式 + 学院 + 专业 + 截止日 + SRC 快照指纹` 全部匹配，规则才可适用。年份不符/学院不符时该政策条件不得运行；具合法且证实的另一分支则 `NOT_APPLICABLE`，无当期完整校本政策则 `POLICY_UNCONFIRMED`。仅 2026 环土学院 B/C 的具体阈值来自 SRC-002，其他学院和 2027 均不得复用。**来源字面冲突**（如 2026 直博推荐人职称）虽分别为官方文本，仍需政策 Owner 有权解释，不能机械以新/专门法“择宽”产生 PASS_FACT。
3. **证据层级**：可验证的有权学校/国家系统当前事件或正式签章档案 `A` ＞ 经有权部门核验的官方原件及登记 `B` ＞ 申请人上传签名扫描件或第三方来源待核 `C` ＞ OCR/模型抽取/本人陈述 `D`。`C/D` 只能发起核验和待办，**不能覆盖 A/B、不能独立驱动 `PASS_FACT`**。A 与 B 冲突也不得机械择一，先检查签发权限、业务时点、撤销更正链；未澄清 `CONFLICT`。
4. **异常优先顺序（同一规则）**：未证明当期政策/适用条件 → `POLICY_UNCONFIRMED`；对应文件已交但读不到关键页/签章 → `UNREADABLE`；相斥的可信事实 → `CONFLICT`；本应从校方/国家源查但无授权通道或失联 → `SOURCE_UNAVAILABLE`；当前应由申请人或签发人提供但尚未提供 → `NEEDS_MATERIAL`；证据齐仍属专业判断/授权事实为假/权限未知 → `NEEDS_HUMAN_DECISION`。未到阶段或已证实适用条件为假 → `NOT_APPLICABLE`；事实和来源均核实且比较满足 → `PASS_FACT`。不同 R 可以同时产生不同码，聚合不把其互相覆盖。
5. **比较时点**：本科应届/推免资格、硕士身份与年级、课程成绩、导师/专家资质、材料出具时间等必须按所属 `admissionYear/batch/college` 的对应事件时点冻结；2026 环土 A/B/C 申请至 2026-03-13，B/C 成绩截至申请截止时，后续初审/网报/复试另取其本阶段时间。时效为未知的文件不得计算自动“过期/未过期”；R034/R035 处理更正和替换。所有本表“2026”条件对 2027 均失效。
6. **T/F/U 记法**：以下每条 `T`＝可信证据确定满足所述比较；`F`＝可信证据确定不满足（只记录可核反事实、转人工，不自动驳回）；`U`＝待补、不可读、源失联、冲突、时效不明之一，按上述优先顺序细化。`后继` 是问题的责任接收人，不代表该角色已在客户端实现。`SRC` 均指 §04 中同名编号。`L` 为 §03 阶段；“未来尚未生成”永远输出 `NOT_APPLICABLE`，不是 `NEEDS_MATERIAL`。

### 8.6 跨规则组合与「不自动批准」门禁

- `R001` 为所有年度业务条件的**前置门禁**；`R002` 决定 A–L/X；`R003/R033/R034/R038` 横切所有可信证据与人为动作；`R039` 判本阶段材料需要；`R035` 管依赖失效。没有任何 R 的 `PASS_FACT` 等于学校初审“通过”、拟录取或学籍转换。
- A：R004–R009、R014 不适用；B：R004–R007,R010，且 R010 平均成绩为 F 时才触发 R011，此外 R014；C：R004–R007,R012–R014；D：继承本年级并走 R017，**未得合法放宽文件前不得因 AI 判断豁免某 R**；E：R018–R023；F：R001 政策门禁未过时，仅允许做身份/文件读取预审，不运行当年条件的“通过/不通过”。
- L3–L6 依次产生 R024–R032 与 R041–R043 的**外部权威事件**，并非 L1 申请必交文件；K 的 R036/R037/R044 仅引用处理和平台事件，不能自行批准撤回。R040 保证不重做邻项决定。任何政策页更正先由 R001 令相关条件 `STALE_RECHECK_REQUIRED`（内部），查新适用版后再逐项复核。

## 10 结果状态、问题与待办输出契约

### 10.1 八个互斥的单条结果码

同一 `ruleId + checkTarget + policySnapshot + sourceVersionSet` 的**当前一次核查**仅有一个主码；不同 R 可并存不同码，不强行聚合成“合格/不合格”。下表只定义事实核查，不产生学校审批权限。

| 码 | 严格含义 | 禁止混淆、页面显示与后续处理 |
| --- | --- | --- |
| `PASS_FACT` | 对**此规则此事实**已有适用当期政策和足够权威证据，比较为真；同样可用于“有效的外部决定记录确实存在” | 文案“此项事实已核实”，不得写“资格通过/已录取”；可继续下一条，不自行推进学校审批 |
| `NOT_APPLICABLE` | 根据确定的身份/阶段/路由，该规则不在本阶段适用，或当前要求属于未来才产生 | 不标缺件；需留下不适用原因和再次触发节点。**政策缺失不等于不适用** |
| `NEEDS_MATERIAL` | 当前有效且有明确材料义务，由持有人应提供而未提供；不含已交不可读 | 指向材料槽、合法替代及持有人；不得向本人追要后续官方形成件 |
| `CONFLICT` | 同人同批同事实存在相斥来源、错误归属或更正链争议，不能自动择真 | 列双边证据与源 Owner，冻结依赖该事实的结论，不将后上传材料自动视为权威 |
| `UNREADABLE` | 材料**已交**但关键页、字段或印鉴无法安全提取/核验 | 反馈具体页/区域/损坏类型，保留原件并请求可读版本；不推定条件为假 |
| `SOURCE_UNAVAILABLE` | 必须由有权校方/国家系统或签发机关核实的事实因授权缺失、网络故障、无可信接口等不能核得 | 保留“源不可核”的性质，交源管理岗或可信人工线下核验；不以截图自动提升可信等级 |
| `POLICY_UNCONFIRMED` | 目标批次政策版本、适用机构、有效期或独立转段授权不能证明 | 阻断相应资格阈值自动运行，找学校政策 Owner；旧年规则和外校规定不得回退套用 |
| `NEEDS_HUMAN_DECISION` | 事实有可信反例、存在专业/行政裁量、权限或签发真伪待决定，即使材料都齐也不能由模型批准 | 明确问题和建议权责人；需要有权学校独立作决定。本系统只能保存确认/决定**引用** |

`STALE_RECHECK_REQUIRED` 只允许作为**旧结果内部失效标记**，不列第九个对外结果码；旧结果不可作为当前通过，重新执行对应 R 后才形成以上八码之一。

### 10.2 问题、证据、待办与决定引用的数据契约（设计稿，非已实现 DTO）

| 结果 | `reviewStatus`（八码之一）、`reasonCode`、`humanReadableFinding`、`unknownReason`、`checkedAt`、`dependencyVersions` | 显示“已核/缺件/冲突/源不可达/政策待核/人审”，而非一个无法解释的总分 |
| 待办/动作 | `issueId`、`assigneeOrg`、`assigneeRole`、`requestedEvidence`、`allowedAction`（补交、核验、核政策、复核、只读引用）、`dueAt`（只有政策证实才填）、`status` | 待办点击可直达当前案卷、受影响材料、规则和原始来源；超时不可凭系统自创期限 |
| 人审/决定 | `actorSubject`、`roleGrantRef`、`decisionType`、`decisionRef`、`issuerOrg`、`issuedAt`、`effectiveAt`、`revokedAt?`、`sourceVersion` | 仅校方有权渠道签发有效行政决定，本模板只保存只读引用及可信操作审计 |

最小 `Issue` 命名约束：`issueId = caseKey + ruleId + checkTarget + sourceVersionSet` 的稳定派生键（具体算法待技术合同），必须能归属唯一 Applicant/具体页/来源事件。重复运行相同证据版本**更新同一问题的观测时间**，不爆炸创建重复待办；材料变化时旧 issue 留审计、新 issue 绑定新版本。P3 数据原则上只向具职务授权角色展示脱敏摘要。

### 10.3 总览、闭环状态与不可混用的决定类型

- `FactReview`：草案 → 证据待核 → 部分事实 `PASS_FACT` / 各项问题 → 有权人员处理待办 → 重核 / 结束。**“所有适用 R 均 `PASS_FACT`”只意味着该次材料事实预审的核验项无待处理异常**，并不意味着自动给校方“资格合格”。
- `AdmissionAuthority` 独立只读状态：未形成／学院初审结果（M022/M023）／报名与复试结果（M025–M027 或 M021）／拟录取公示（M028）／正式录取（M029/M030）／取消或更正。由 R024–R031 检索源事件，按原机关决定展示，不受本地规则状态直接驱动。
- `StudentStatusAuthority` 独立只读状态：未报到／已报到待复查／复查记录／博士学籍正式注册或取消（M031）。R032 只读；未找到权威注册不得展示“转段成功”。
- `RemedyProcess`：本人提出 → 待有权核授权/受理 → 调查/补正 → 学院答复 → 如合规且仍有异议，研究生院处理 → 正式决定引用/归档。撤回仅在**有权处理记录**到达后改变相应行政程序状态；复核不会自动抹去此前决定。
- 结果汇总采用“待办集合 + 已核事实集合 + 外部决定引用”的三轨显示；冲突/不可读/源失联/政策不明可同时存在于不同 R。任何封存/导出都保留规则、来源、版本、actor 和生效时点，不能把 AI 建议写进 `DecisionRef` 的签发字段。

### 11.2 受影响规则重审算法（业务契约）

1. 版本收件：为变化的每个物理文件或权威事件建立 `materialId + materialVersion + issuer + sourceRef + fingerprint + subjectLink`；记录被替代版本与原因。若 ZIP 只替换其中一位考生附件，先 R003/R033 判具体页归属，避免影响另一个人的案。
2. 依赖索引：从 §08 R 表取得 `materialId → fieldId → ruleId` 的精确边，此外**当任何规则触发条件改变**（年级、招生途径、批次、学院、政策生效区间）重算当前情形的适用 R 集；不能单靠同一文件名匹配。
3. 失效：旧结果只在其证据、政策或触发条件依赖变化时标记 `STALE_RECHECK_REQUIRED`；新 R 检查必带固定 Plan/政策快照与输入版次。一个材料能供两个 R 时，两个都重算；没有被依赖的 2026 学籍/录取外部事实不因无关材料变动而被覆盖。
4. 分支重核示例：A 的 M009 奖学金正式更正 → R008、R034（若跨源）、R039 该槽重审；不重跑 R014（仅 B/C 英语）、R028（尚未复试）或独立的导师 R006。C 的 M011 成果更正 → R013、R014（**仅原走论文英语替代**）、R034/R039；不重算 R012 的课程。M023 公示更正 → R025，若影响初审合格前提则进一步触发 R026/R041；不凭更正直接改国家报名。M026 的支付新回执 → R027 和依赖的 R039，不在校验/确认记录未变时重跑 R042/R043。M021 待录取取消官方事件改变 → R044、相关 R023/R030，**不改 R019 来源校推免资格**。M001 政策跨年更改 → R001/R002 和受影响的所有资格 R 重评，不沿用旧年 `PASS_FACT`。
5. 接收人：源不可用指向签发系统 Owner、纸件补正指向有义务的材料持有人、政策冲突指向研究生院/学院、材料冲突指向双方源 Owner、需要裁量指向有权招生组织。只有重新完成当前版本的 R 核验后，原问题可标“已通过重审/已由有权处理”，历史不删。

### 11.3 行政裁量与合法人工决定的硬边界

- **允许辅助事实确认**：教师/学院被认证身份审阅证据、记录可读性/归属、请求补件和给出“需学院确认”建议；必要时记录可信线下核验证明。能验证的单项事实由 R 给 `PASS_FACT`。
- **不得凭辅助审核自行形成学校决定**：硕博资格初审通过、例外放宽、教授资质最终认定、英语论文“高水平”、复试分数或思想品德评议、拟录取、正式录取、博士学籍注册、撤回准许、申诉结论。所需 `decisionRef` 必须来自真实有权学校/国家权威来源且在生效期内。
- **无法证明签署权限**：即使材料齐、老师头像姓名匹配或用户自报管理员，也保持 `NEEDS_HUMAN_DECISION`/`SOURCE_UNAVAILABLE`，拒绝任何学校决定写入；宿主/Main 的可信 actor 授权与校方签发权**两层均不可省略**。
- **撤回后重提**：校本何时可重报、是否影响本批次初审/网报及历史决定均未获得现行全文，必须设置人工确认门禁。重新受理不允许把前案 `PASS_FACT` 或旧学籍决定当新案已批准；可引用未失效的源材料事实并重新检查批次适用性。

### 12.2 禁止模型硬判和政策冲突裁决

1. 无当前学院原文、文件废止/修订不明、公式/换算表缺失、招生计划/导师名额无法查验，只输出政策或来源问题；不以 2014 试行版、其他学校做动态兜底。取不到政策时不能借高校通用经验“补完”阈值。
2. 委员会是否同意特殊学术专长放宽、论文是否“高水平”、成果是否具有规定署名/专业相关性、英语替代的跨语种比较、思想政治与身体健康结论均由法定/校定有权机构作实质判断。本模板最多保存正式结论的只读证据引用。
3. 源数据可查但与申请表冲突，不能用来源优先级直接吞掉差异，应向发出矛盾事实的各源 Owner 发待办；姓名改名、证件号变更、材料译名不同等可合法解释情形，须核更名/身份链并保留前后版本，不要求系统自己裁断法律身份。
4. 已实际读取 R02 `ST-CANDIDATE-MASTER-CATALOG-R02.md` 和 `ST-CATALOG-AUDIT-R02.md`，完成**业务授权对象级去重**：来源本科推免资格归 S07-T09；导师选择归 S08-T01，导师任职/招生资格/指标归 T06-T01/T02/T03；培养计划归 S08-T02；成果登记、署名更正与权属归 G06，成果申请条件认定归 S08-T05；开题、中期、预审/评阅、答辩、学位归 S08-T03/T04/T06/T07/T08，联合培养另归 S08-T09；博士录取和学籍由学校权责机构形成。本 ID **只读有权事实**。G50 源码 `catalog.json` 未取得，故尚不能声称逐条源码去重。
5. 没有可信来源时可提供**材料清单整理、证据抽取、问题生成、人工确认待办、只读历史**，但不能输出伪造的资格批准、复试通过、正式录取或学籍转换记录。
