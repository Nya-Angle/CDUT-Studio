## 01 唯一审核目的、申请人和负责机构

### 01.1 核验决定对象（冻结方向）

对一个可定位的科研项目及**有权签署且有效的合同/任务书及合法变更版本**，针对指定履约节点核对：

1. 合同约定的成果名称、形式、数量、指标、交付期限、交付地点/渠道及验收方式（以合同真实条款为准，不自设学校统一阈值）。
2. 当期已有的交付清单、版本、发出/送达记录、接收方签收或回执，以及签收人与合同相对方身份、授权的可核实程度。
3. 需验收时当期已有的测试/评审/验收意见及其范围、签章、日期、条件保留、补正项；区分“签收”与“技术/合同验收”。
4. 交付物与指标、接收意见与争议/异议、合法变更与原合同是否相互一致；对部分交付、拒收、待整改、逾期或争议作事实标注。
5. 是否存在应当引用的有权部门/合同相对方正式决定。若尚未产生，只能输出“尚无后续决定”，不能把申请阶段判为材料缺失。[SRC-001][SRC-002][SRC-005]

**本模板可作材料证据事实预审及人工办理建议，不作实质质量鉴定、违约责任裁断、合同价款核销、产权处分、终结验收结论。**

## 03 业务生命周期与办理情形矩阵

> 本节是 T03-T10 的事实预审办理模型，并非学校已上线的独立服务或官方流程。状态 A–J 是同一模板内部情形，不新增 template_id。期限若无现行校本依据，仅取实际合同/任务书约定；正式撤回、复核受理机关仍待核。

### 03.1 对象、申请身份与阶段

- **项目类型轴：** 横向委托科研、纵向科研任务、校级科研项目、国家重点研发/科技重大专项的参与项目、课题或专题。以校内项目台账、正式合同/任务书而非上传者自选标签核实。国家重点重大专项适用 SRC-002，校级专项适用 SRC-003；普通横向合同按约定与待取得的 SRC-006 正文核定。
- **身份轴：** 校内教职工项目负责人为主要提交主体；科研助理、博士后、研究生、本科生及其他项目成员可协助整理证据，但是否有权代办须经实际项目台账/授权关系验证。学生的学段本身不构成合同签署或验收决定权。合作企业或校外单位是合同相对方、证据持有人，不自动成为校内流程申请人。涉密参与人员按保密专门规则。
- **客体轴：** 一个项目—一个生效合同或任务书版本—一个约定节点—一或多批交付—多个成果与接收/验收事件。存在补充协议时每个节点应映射适用的生效版本。
- **生命周期：** 有效履约依据 → 选择当期节点 → 登记/提交 → 证据核对 → 补正或形成交付记录 → 对方签收 → 依约开展验收 → 人工确认/转相关归口 → 引用正式结论与归档。撤回、变更、争议、复核是可并发的事件，必须保留先后版本；不可把尚未产生的后续意见当成初审缺件。[SRC-001][SRC-002][SRC-005]

### 03.3 截止、阶段要求和校本表单的真伪边界

1. 2026-07-10 科发院通知 SRC-009 要求一个特定“横向项目纳入四川省科技计划管理体系”申报批次提交技术开发合同、登记材料、已完成验收材料和绩效佐证，并将 2026-07-16 作为该批次截止日；这一要求**只属于该通知申报条件**，不作为 A–J 通用必交材料或通用时限。该网页检索索引文字较全，但直接正文/附件仍未完成可访问核验。
2. SRC-002 第三十–三十二条明确国家重点研发/重大专项的自评、验收、延期时点；只有 F003 与项目主管规则一致时使用。所有其他项目期限缺权威依据时保留“未知”，由人员按真实合同核定。
3. 科发院“资料下载—横向项目”原始目录确列出 2021-11-25《横向项目线上审批流程说明》与 2020-10-30《授权委托书模版》[SRC-013]，但点击附件页仍返回 HTTP 412，**不能判断该线上流程是否处理合同成果交付，也不能视其为本模板的认证/代办规则**。本轮没有找到对 T03-T10 适用的统一“合同成果交付核验申请表”“送达签收表”“校内复核表”。SRC-006 横向办法正文仍缺。M004/M016/M017 是拟采用的请求记录槽，不宣称校方已有同名表单。
4. 对来自校方可信台账/合同系统的 F/M，只引用其权威记录 ID、版本和核验时间；在尚未证实接口可用前，提供上传经核实原件或人工补录核对的后备路径，不强制师生重复提供已可取得的材料。

### 03.4 阶段资料原则

A 不需签收/验收，B 不需全部最终成果，C 不需技术合格结论，D 不需未来整改完成证明，E 需整改证据而不需尚未形成的复验结果，F 未获批时只收变更申请而不推定生效，G 不需终审裁决，H/I 不以补齐原申请全部材料为受理请求的前提，J 只能引用已有有权结论。各情形的 F/M **最小当前集和异常覆盖**在 07.3、09.3；阶段条件触发后才追加材料。

### 04.2 核查优先级与禁止引用

- **可以引用为有原文支持的事实：** 校本规章对科研负责人、教学科研单位、科研管理部门职责及项目指标、科研诚信、特定项目验收程序的规定（SRC-001–004）；上位制度关于合同约定验收的原则（SRC-005）。

- **效力复核方法：** 对每份相关校本制度在科发院/社科处/党政办获取正式文号及原文首页、适用对象、附则施行条款、后续修订/废止公告；对单个项目另取合同及所有补充协议、任务书和审批档案。搜索引擎摘要不能替代正式政策原件。

### 05.2 数据可信级别与访问原则

- **T1 校内/主管机关权威记录**：项目台账、合同原档、合同版本、审批变更、权威验收/结题决定，只有在实际存在可信访问通道、当前登录者可见且返回带权限的来源标识时使用。接口未证实时登记为“拟接入权威源”，允许经办人提供正式文件后人工对照，不假装能访问。
- **T2 对方原始可核记录**：原始签收凭据、可信电子签约验证结果、验收机构出具的文书、原始邮件/系统回执；即使形式完整，也需核发件/签署主体的权限与作用范围。
- **T3 项目组申报资料**：交付清单、成果文件、手填日期、截图、扫描签章，初始均是主张及待核证据。OCR/AI 抽取只附在对应原文件页码、段落、表格单元、文件哈希和版本上，不提升其法律效力。
- **T4 外部搜索与工程目录**：仅作政策发现和能力参照，不能代替 SRC-006 原始校本政策或实际合同。SRC-010 外校表单绝不变成校内必交件，SRC-012 的 G50 候选状态不是学校决定。
- **敏感性标识：** P0 一般过程元数据；P1 校内项目、人员及组织信息；P2 未公开合同、经济条款、个人签名与成果技术资料；P3 涉密、国家秘密或合同严格限制披露信息。P3 普通客户端不得上传/提取，只记录安全转办指示；具体定密由有权主体决定。[SRC-002][SRC-004]

### 05.3 角色、姓名和权限匹配规则（事实层）

### 06.3 字段使用约束

- F001/F006 属可信运行环境产生，不能要求申请人提交身份证照片来代替；F002–F005 原则优先权威项目记录；F009–F018 必须逐项溯源合同/任务书条款。

## 07 材料槽与证据目的

> **研究材料模型，非成都理工大学已发布的统一材料清单。** M001–M023 为连续材料槽，既容纳原文文件，也容纳可授权查询的权威电子记录和程序事件；**槽存在不等于该情形必须上传**。关系必须记录 projectId、contractVersion、nodeId、batchId、artifactVersion、holder/issuer、原始定位及 sourceVersion。下文材料缺失处置的共同约定：确属当前阶段必需且无法从权威来源取得时为 NEEDS_MATERIAL；文件已有而损坏/扫描无法识别时为 UNREADABLE；权威系统已声明有记录但暂不可连通为 SOURCE_UNAVAILABLE；规范是否要求不明为 POLICY_UNCONFIRMED；绝不将“不适用/尚未产生”当作缺件。

### 07.1 条件与合法替代

- **当前必需（C）**：为核当前主张须有该项事实证据，可为可信系统记录，**不等于申请人必传文件**；不需要的具体指标（如合同未约定量化值）可由原文明确“不适用”来证明。
- **条件必需（T）**：只有对应主张、争议、合同特别约定或身份疑点触发才收；需要人工确认触发条件是否成立。
- **后续才产生（L）**：到下阶段且该事实实际形成时才核。不能为 A/B 的首次预审强制提交最终签收、专家意见或正式决定。
- **安全优先（S）**：先判断是否可进入普通客户端；涉密及合同限制披露材料经有权人员走专门渠道，只留最少转办元数据。任何“替代”不得削弱真实签发权或合同证明力。

## 08 审核规则逐条清单

> **第四轮可审阅事实核验规则 R001–R034。** 规则是拟供 V3 使用的业务设计，不声称现行校内已按此流程上线。每条 R 除写定对象外均持有 [projectId F002, contractBasisVersion F010, nodeId F013, sourceVersion, planFingerprint, applicablePolicyVersion, assessedAt]；无适用节点时记录 null 与原因，禁止跨案复用。每条的成功 `PASS_FACT` **只说明该规则指定的证据事实可核**，绝不表示校方批准、技术达标、合同履行完毕或付款到期。

### 08.1 三值条件、共同异常和时间规则

- **T 真**：存在本行写明的当前事项及前提，执行核验；**F 假**：条件经可信资料证实未触发，产出 `NOT_APPLICABLE`（附理由，不要求未来件）；**U 未知**：前提无法判定，按本行“U/例外”给出具体问题，不能当 F。R001、R002、R003、R004、R005、R007 等通用基线规则在有效案卷阶段原则上为 T；如果根本不属于科研合同事项，转 R029 路由，不作全局“审核通过”。
- **证据层级**：T1 有权限的学校/主管原始记录；T2 对方/机构可核原始回执和验收；T3 项目组提交，初始仅为主张；T4 搜索片段、外校表单、工程目录仅发现线索。高层级证据必须核签发主体、业务范围和版本，不是“文件越新越权威”。缺权威校内接口时可由核实的正式原件替代并留人工核验轨迹。
- **共同异常适用于以下每一个 R**：条件 T 但本阶段应有材料确实缺失且无可用权威替代 → `NEEDS_MATERIAL`；材料存在而字节、OCR 或结构不可读 → `UNREADABLE`；需要访问的权威源不可达/当期校验失败 → `SOURCE_UNAVAILABLE`；两个有效来源在同一对象/版本上实质相斥 → `CONFLICT`；适用政策/生效阈值无现行有效文本 → `POLICY_UNCONFIRMED`；身份授权、合同解释、技术质量、争议或行政裁量不能自动决定 → `NEEDS_HUMAN_DECISION`。每个异常附 F/M/SRC、文件定位、版本和目标人。
- **时间效力**：事件 F024、F028、F039、F043 用原始时区/签署时点；比较合同义务须以事件当日真正有效的 F010/M015 版本为基线，现时检索到的新政策不可自动追溯。只有 SRC-002 真正适用的专项使用其规定期限；SRC-009 是特定 2026 申报批次，不能通用。超期差异可记录，违约性质必须人工判断。
- **统一读表方式**：“U/例外”同时列阶段不可达、合法替代与责任主体；表内“通过”均表示本行特定事实 `PASS_FACT`。正式决定由原主管机构记录，见 R025，不存在自动 `APPROVED`。

### 08.6 执行与出处限制

1. 同一 R 仅对指定项目/合同版本/节点/批次/成果产生一个主要事实结果；不同 R 可分别为 `PASS_FACT`、`CONFLICT`、`POLICY_UNCONFIRMED`。所有规则结果都有 `ruleId`、`SRC`、`F`、`M`、`evidencePosition`、`sourceVersion`、`policyVersion`、`conditionTruth` 与下一责任主体；不允许聚合成单一“校方已同意”。
2. 规则执行采用 **M 槽可用性 → 三值条件 → 精确比对 → 异常/事实状态 → 人工归口** 的依赖顺序；一个规则的未知不阻塞无依赖的其他规则。R001 的安全拦截优先于普通内容读取；R003 的可信认证优先于撤回/复核写入。
3. 当合同没有某量化目标或未来验收文件未产生时，R010/R015/R016/R025 可为 `NOT_APPLICABLE`；不能为了提高通过率补造数量/天数/签名。项目没有获批变更时 R021 为 `NOT_APPLICABLE`，但 R007/R011 仍以原合同/节点计算事实差异。
4. 具有正式法律/行政效力的结论不能由 T03-T10 计算而来；R016/017/025 仅检查**已经签发**的文书与权限线索。即使全部事实 R 为 `PASS_FACT`，输出也必须写“事实预审可核，正式结论尚待有权主体决定或引用”。
5. 本规则清单不代表政策现行性已全部确认：SRC-006/008/009/011/013 仍有原文或权限空缺，SRC-010 外校不适用，SRC-012 仅工程参考。所有相应硬门槛冻结在 12 节待核配置，不进入默认机器拒绝条件。

### 09.2 主从材料、覆盖和来源失败的处理次序

1. **确定主依据：** 项目台账 M001 负责“这是哪一个项目及负责人”；有效合同/主管任务书 M002 负责“履行什么义务”；M003 只是从 M002 提取的可追溯映射。项目组写的 M005 不可修改 M002 的目标，外部签收 M008 不可修改 M011 的验收意见，R02 编号不产生合同权利。
2. **建立多维归属：** 每条 M005/M006/M007/M008/M010/M011/M012/M013/M022/M023 的声明均有 F002 项目、F009 合同、F010 版本、F013 节点、F020 批次、F021 成果（可选批次时须注明“整节点”）及 F022 哈希或物理样品号，实测数据再绑定 F045，通知事件再绑定 F046–F048。对不具备映射的材料保持孤立待归属，不因同名文件自动吸收。
3. **允许并列冲突：** 合同版本与台账不同、双方发送/签收日期不符、两份有权验收意见相互矛盾时保留全部原文、时间和签发权限，输出 CONFLICT + NEEDS_HUMAN_DECISION；不存在“新文件时间更晚就覆盖”或“AI 评分更高就通过”。
4. **替换触发选择性失效：** 先标记 M013 所指的新旧 F021/F022；依赖旧版本的成果存在性、数量、指标实测、回执覆盖、时序核验（包括 R030/R033/R034）标 STALE，等待有证据的新 Run；不依赖此成果的其他节点事实仍保留。不能将旧 run@rev 当成真实本次 ReviewRun，不自动改写外部签收、验收或主管审批。
5. **证据与政策双状态：** 材料当前缺失 NEEDS_MATERIAL；来源系统故障 SOURCE_UNAVAILABLE；材料不可读 UNREADABLE；学校规定的适用/效力未知 POLICY_UNCONFIRMED；证据实质冲突 CONFLICT。它们可同时存在且各自有具体 F/M/SRC、责任持有人和建议待办；不能把“缺材料”与“尚未应当产生”混淆。
6. **复用权限：** G50 的通用路由、文件读取、来源定位和问题记录可以复用；T03-T02/T03-T03 合同订立、T03-T05 变更、T03-T06 进度、T03-T07 结题验收、G06 成果处分/伦理、G07 财务和相关 T04/T07 结论必须由原 owner 的可信决定标识 F042 引用。该引用不可让 T03-T10 对上游写入、撤销或签名。
7. **人工作出有效决定：** 成果质量、违约性质、迟延后果、变更批准、争议裁量、签发人授权疑点一律待有权人；本模板仅可输出基于证据的 PASS_FACT、NOT_APPLICABLE 或问题状态。F043 的真实决定不得由 Renderer、申请人自填“批准”或 AI 规则结果代替。

| primaryResultCode | 精确语义及触发 | 禁止混用与待办 |
| --- | --- | --- |
| `PASS_FACT` | 该 R 的条件 T，指定事实在有效版本与可信证据范围内可追溯且比对无冲突 | 只显示“某项事实可核”，不表示合同完成、技术达标、校方批准。若必须由有权主体解释，则不能冒充本码 |
| `NOT_APPLICABLE` | 条件由权威证据证为 F；尚未进入该阶段、未来文书尚未产生或合同明确无此指标 | 不是“材料不齐”，亦不是永久豁免；后续事件触发 T 时重审 |
| `NEEDS_MATERIAL` | 条件 T，当前必须证明的事实无材料或合法替代，且没有已知权威系统可取 | 精确指出缺哪项 M/F、由谁持有；不能要求现在提交未来才产生的文书 |
| `CONFLICT` | 两个可定位证据在同一事实、范围、版本上互斥，暂无法按正式权威来源消解 | 保留双方原文与版本，产生对质/确认待办；不得按 OCR 置信度或文件时间自动择一 |
| `UNREADABLE` | 相关文件/源记录确实存在，但页、字段、字节、签章区或 OCR 文本不可读，妨碍核实 | 记录失败位置、格式和哈希，要求可读副本；不能推断材料没交 |
| `SOURCE_UNAVAILABLE` | 需校方/主管/相对方可信系统当前核验，但接口失联或拒绝访问，且无可靠合法替代 | 展示上次成功核验时间并标历史，禁标实时已核；待源恢复/人工正式原件 |
| `POLICY_UNCONFIRMED` | 项目类型、适用期间、现行校本原文、特别时限/条件无法证明 | 不把历史、外校或检索片段作为硬条件；交科研政策归口核有效文本 |
| `NEEDS_HUMAN_DECISION` | 权限真实性、技术质量、合同义务解释、行政裁量、争议处理或安全分流必须由有权人员决定 | 必须附决定问题、候选归口、授权缺口；审核程序不能生成签章或替代真实决定 |

**裁决顺序**：先判断条件三值与阶段；条件 F → `NOT_APPLICABLE`；条件 U → 用 U 的具体成因选 `POLICY_UNCONFIRMED` / `SOURCE_UNAVAILABLE` / `NEEDS_HUMAN_DECISION` / `NEEDS_MATERIAL`；条件 T → 按安全/权限风险、有效来源冲突、来源不可用、不可读、当期缺证、政策未知、人工裁量、可核事实依次分析。多种并发原因不合并为一个新码：选直接阻断本 R 的首要原因作 primary，并将其余列入 secondaryFindings；同一案不同 R 的原因独立输出。不接受 `PASS_FACT` 与其他 primary 码在同一规则实例并列。

## 11 补件、撤回、版本更新、复核与人工决定

> 这是**产品端拟议的案卷事件闭环**，不是已核实的成都理工大学行政办理规程。校方是否允许线上正式撤回、逾期补件、重新提交和申诉，须取得 SRC-006/013 等原文、实际合同和有权部门确认；在此之前只能安全保留请求与人工处理入口，不自行将校内审批改为自动生效。有效决定及撤销只能由原有权主体完成。

### 11.1 统一案卷状态与事件

| 内部状态/事件 | 含义及所需授权 | 可转移的条件、权威界限 |
| --- | --- | --- |

### 11.2 权限、补件和定向重审

1. **身份门禁先行**：所有提交、修改、撤回、复核、确认、批量结算事件由可信 Main/CaseAggregate owner 以认证主体执行；Renderer 不能传伪造 Actor、`teacher` 或 `approved` 获写权。单案仅由 CaseAggregate CAS 管理一套状态；需要新的 ReviewRun 时必须创建真实 runId 并绑定冻结 D2 Plan（planId、fingerprint、Checks×target/sourceVersion），批次 finalizer 还需合法 entryRunId。
2. **问题→材料→受影响规则图**：Issue 持有 `ruleId` 和所涉 M/F、合同/节点/批次、sourceVersion。补充 M006 的某成果新版本时，先找所有读取该成果 F021/F022 的 R009/R010/R015/R016/R019/R026/R027/R030/R033/R034 及必要的 R012/R013，并仅对其实际依赖的目标重审；更新 M022 的指标原始记录重点重审 R030/R033，更新 M023 的通知原始记录重点重审 R031/R032/R034；其他节点和 R002/R003 的可信身份核验无需无条件重跑。
3. **主依据变化向下游传播**：M002/M003 或真正生效的 M015 改变 F010/F012–F018/F046/F047 时，可能影响该合同覆盖节点的 R005–R018/R021/R026/R028/R030–R034；但不是自动把原合同下形成的签收/验收文书“撤销”。历史结果标 STALE，必须用事件生效时的版本重建适用基线，必要时请人解释过渡关系。
4. **扫描修复与材料复用**：同一 M 的可读替代件只使曾经 `UNREADABLE` 的目标重审；权威来源恢复只重核对应 `SOURCE_UNAVAILABLE` 规则；G50 只可复用文件解析、证据定位、签章线索，不重做已有效的上游决定。
5. **补件不追加未来义务**：A 不补 M011/M021，B 不补尚不存在的对方回执，F 未批准不补 M015，H/I 不以交全合同成果包作为受理事实请求的前提。对尚无法确定是否需要的资料先请经办归口说明触发条件，不填默认截止日。
6. **确认与更新决策**：技术达标、签署/收件授权歧义、合同解释及争议由原权限主体作出，保存有权签发身份和事件；T03-T10 的事实复核不能自动改变原有权决定的生效状态。任何人工确认必须留原问、所据文书、受理人和决定人身份链，不能简单把`NEEDS_HUMAN_DECISION`编辑成`PASS_FACT`。

### 11.3 撤回—重提—事实复核的闭环

- **提交后撤回**：申请人可信提交 `M016/F040` → R003/R022 核权 → 记录请求时间、对象与当前源版本 → 本预审队列可以暂停待处理动作。若真实校方制度要求受理/批准才能撤回，则保持 `WITHDRAWAL_REQUESTED`，不能提前宣称正式撤回成功。
- **撤回后重提**：同一项目/合同节点形成新的 requestRevision 与真实 Run，引用旧案卷的旧问题、资料及已知授权（只在效力未变时复用），旧 Run 归档并标明被后继版本覆盖；重新提交不使对方之前签收或验收意见失效。
- **复核**：针对原 Issue 的 ruleId、evidenceSpan 和 sourceVersion 提交 M017 新证 → 由可信身份核权 → R023 判定事实复核请求成立性 → 仅重算指向事实规则；如果挑战的是 M021 正式决定，生成给原 owner 的待办而非本模板复写 Decision。
- **禁止自动效果**：未见现行校本统一撤回窗口、补件 N 日、逾期视为同意/拒绝、行政申诉期限的原文，均为 `POLICY_UNCONFIRMED` 并交人工；合同另有通知/争议条款时仅在真实条款验证后提示相关期限和主体。

### 11.4 有权决定边界与异常恢复

- 可信认证失败：不得由 UI 自称项目负责人恢复；提供身份核验待办，读写权限保留最小。
- 权威来源失联：保留历史 provenance（含 lastVerifiedAt），不让旧 `PASS_FACT` 被标记为本次即时核验；R024/R025 仍可显示待访问状态。
- 有多个真实有权决定且范围矛盾：并列完整证据，`CONFLICT` + 人工待办，先查是否不同节点/批次/时段。
- 保密资料误入：停止普通内容提取与进一步传播，按有权安全流程处置；本轮不设计绕过权限的自动解密/迁移。
- 外部正式决定被撤销/改签：由其 owner 提供新的 signed revocation/superseding ref；R024/R025 在下一真实 Run 更新引用的当前效力，原决定历史继续可追溯。
