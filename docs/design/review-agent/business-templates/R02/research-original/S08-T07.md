## 01 唯一审核目的、申请人和负责机构

### 1.1 事项存在性与决定对象

成理研〔2026〕1号对全年拟申请学位研究生安排了毕业资格、论文预审、论文送审、学位答辩、分委员会审议等阶段，并表示相应工作通过学校“学位与研究生系统”办理（SRC-001）。2021年校级实施细则对答辩委员会组成、答辩程序、表决与重新答辩分别作了规定（SRC-002）。因此本模板只面向：

1. **答辩前**：特定申请人与拟答辩论文能否转入正式答辩程序、拟设委员会与公告/备案材料是否符合程序事实；输出为需交学校核准的事实核验清单。
2. **答辩后**：既定答辩是否举行、答辩记录、无记名表决材料、委员会决议及签署材料能否相互印证；为后续学位申请移交提供核验记录。

答辩委员会的学术判断、学院及研究生院的资格把关、校学位评定委员会的授位决定，**均非模型自动产生**。答辩前不能要求答辩记录、票据或决议书已存在；答辩后不能再以拟定名单代替实际出席与实际投票。

### 3.3 材料最小化、补件、撤回与复核原则

1. **最小材料以阶段为准**：A0不强制送审结论；A1需要**已存在**的前置事实；B才核委员会与公告备案；C/D才核真实记录与签章；D后的图书馆定稿不回灌成答辩前门槛。具体逐情形 F/M 映射见 7.3。
2. **无法直连不等于必须上传**：可由学校学位与研究生系统查询的学籍、培养、检测、盲评、委员会备案优先取其权威记录；若暂无接口，建立“授权人员查验/出具回执”替代，而不是盲目要求学生重复扫描。
3. **四类缺口分离**：当阶段必须且缺失=`NEEDS_MATERIAL`；已有却模糊=`UNREADABLE`；校方系统或网页不可达=`SOURCE_UNAVAILABLE`；尚不知是否必须=`POLICY_UNCONFIRMED`。未来才产生的材料当前=`NOT_APPLICABLE`，后到阶段再评估。
4. **撤回**只登记请求，不能使已经正式形成的委员会投票或决议被软件删除。**复核**按《学位法》及现行校本途径交有权机关；模型仅联动材料与审计证据，撤回及复核具体节点继续待核。

**读取/缺失速记**：每行的“学校权威记录”不等于已取得API；允许核权后的原记录/签认扫描档/有权人员查验回执，须具体溯源。`NM`=`NEEDS_MATERIAL`（到期应有）；`SU`=`SOURCE_UNAVAILABLE`（校方权威记录无法取到）；`PU`=`POLICY_UNCONFIRMED`（是否要求不确定）；`HD`=`NEEDS_HUMAN_DECISION`；`NA`=`NOT_APPLICABLE`（尚未到发生阶段）；`UR`=`UNREADABLE`（有件读不出）。每行缺失动作优先 `SU`（确知有校方记录但获取失败）而非强制学生补传；若还不知道是否须形成则用 `PU`。以下每个“证位”都是建议定位锚点（案卷材料页码/源记录ID），非预设数据库字段。

## 07 材料槽与证据目的

### 7.1 证据槽定义与优先顺序

以下连续 `M001–M032` 是**证明目的槽**而非2026年成都理工大学正式“必须上传32份附件”的清单。`必/条件/后`分别表示“**在对应阶段**为核实事实所必需”“仅触发时需证明”“本阶段尚未生成、达到后续阶段才审”；“必”不等于学生本人必须上传，合法替代为学校可信数据库只读记录、学校电子签章原件或经授权业务人员的查验回执。实际纸质表名称、份数和申报渠道需待SRC-009最新文件核准；SRC-011仅提供历史材料名称参照，故出现 `PU` 不设置自动拒绝。

统一归属/版本要求：每份M记录 `学生可信学号、F001尝试、论文F016版本（适用时）、出具机构、出具人及其F044授权证据、生成时间、来源ID、接收时间、文件摘要、有效/被替换状态、证据页码`。关联不明确则 `CONFLICT`。缺件 `NM` 仅当阶段适用且已确认必须形成；文件已上传但辨识失败为 `UR`；官方系统暂不可读用 `SU`，而不是责令申请人无理由再传。材料已生成但无法核验签认者真实性进入 `HD`，不能自动PASS。

## 08 审核规则逐条清单

### 8.1 规则解释与证据层级

`R001–R038` 为**研究性独立事实核验规则**，不意味着已注册为软件规则或学校审批规定。各行**T/F/U**分别指触发条件确认为真/假/未知：`T`才核该事实；`F`记`NOT_APPLICABLE`，但“事实未达到准入条件”**不是**“规则不适用”；`U`按该行明确的未知路径处理，绝不将未知当假/不通过。若T且所有核验维度真实可证、时效/权威已核、无有权裁量，才记`PASS_FACT`，**不是校方批准**。仅针对某项原始事实为假的情形，无`FAIL`自动拒绝码；对“正式源记录明确未通过”的事实，仍可`PASS_FACT`地准确记录“源业务未通过”，并据此挂起后续阶段，由原Owner或有权机关决定处理。

证据层级：`E3`=可验证学校原始业务记录/学位与研究生系统只读有效结论；`E2`=经服务端核权限的校方签署电子/纸质档及授权查验回执；`E1`=本人、导师或学院未经来源校核的上传件/截图；`E0`=OCR、模型提取、文件名及Renderer自报身份。E1/E0只供线索，不证明E3/E2意义上的“学校决定”。**政策有效性与证据真实性是两条独立轴**：SRC-002/005/010/011在2026年的时效未确认时，即便E3资料齐全，涉及独有硬阈值仍输出`POLICY_UNCONFIRMED`。SRC-012–014是技术去重证据，永不产生校本硬条件。

表中`P`表示`PASS_FACT`条件齐备时的默认输出；其余状态采用第10节互斥裁决器。`NM`、`SU`、`UR`、`PU`、`HD`、`NA`仅在表内作为`NEEDS_MATERIAL`、`SOURCE_UNAVAILABLE`、`UNREADABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`、`NOT_APPLICABLE`的缩写。证据列中的`Mxxx`可指学校系统对应权威记录而**不是向学生索要独立上传附件**。每个结果保留SRC条款/页、F值或遮蔽指纹、M文件页/区间、版本、角色及判断时间。

### 9.2 冲突优先级、失效和局部重审

1. **先身份后内容**：F002校方学号与F003学校姓名为主；申请书签名、论文封面、M014委员会名单上的同名文本不能跨学号共享。强比对`学生ID + 本次attempt + 论文版本 + 签发机构 + 有权角色`，任一不明不得自动合并。
2. **先权威签发后OCR**：可信学校正式结论与学生上传截图不符时保留两边原件及差异；若两份均来自看似合法的校方来源但互相矛盾，不自选“较新日期”或“更高级盖章”，而由两者所属Owner协调并签认适用版。
3. **论文主版本改变**：F016由送审稿V1改为提交委员V2或实际答辩V3后，M008–M012源结论是否仍适用须查其版本范围；受影响F017–F021置为`STALE_PENDING_RECHECK`，并由其原决定者确认，无需对不受影响的学籍F002重新审查。
4. **组织主版本改变**：M014委员会名单或M017场次更新后，原M019备案对新版是否适用须审；受影响F024–F031重核。会议之后的F032–F037始终绑定实际名单、当次原始票据；**旧批准名单不等于实际出席名册**。
5. **签章及票据被替换**：新M022–M024仅产生可审计修正记录，不覆写旧有效委员会决议；未取得委员正式更正/学校批准，旧决定的真实性和更正效力均需人工判断。不得用一张整合扫描件自动替代逐票核查。
6. **双时钟**：答辩组织截止与学位审议批次截止不同。F023授位批次改为下一批时只重审M031交接及确实受影响的学院期限，不推翻F036当次委员会历史结果，也不凭 SRC-001 原通知过期日期自动置失败。
7. **权限变化**：若F044授权撤销或F045代理超范围，相关审批引用须转`HD`，保留动作发生时授权快照，不因新角色自称补签而自动重做历史决定。
8. **源结论共享而非复算**：S08-T03/T04/T05/T06和G50的已生效、可追溯结论以`source_ref + source_version + scope + issuer`导入；本案发现冲突应通知原Owner复核，不向其写入“本案认为合法”的新结论。2026是否能读取G50数据接口尚无证据。

| `NEEDS_MATERIAL` | 适用阶段已到、已确认当前须形成该证据、且该材料/可信等效记录确实未提供 | 未来材料现在缺失；政策是否要求还未知 | 申请人或实际材料生成Owner（按M持有人） |

| `PASS_FACT` | 该规则触发为真；政策适用、身份、来源、版本、客观比较均已核实，并准确记录原事实（包括源记录中的否定结论） | **批准答辩、答辩通过、授予学位、已完成所有程序** | 无当前缺口；若事实要求后续学校决定，另生成`decision_gate`待办 |

**互斥求值顺序（固定、不可随文本随意变化）**：①已确认阶段未到或触发假→`NA`；②触发未知：先判政策适用未知→`PU`、关键原始来源不可达→`SU`、只能由人确定分类→`HD`，不得硬落`NA`；③触发真时：**明确冲突**→`CONFLICT`；**政策适用不确**→`PU`；**原权威源不可达**→`SU`；**有件无法读取**→`UR`；**确认当期必需但完全缺件**→`NM`；**剩余需裁量**→`HD`；否则`PASS_FACT`。若多缺陷并存，保留其他`diagnostics[]`，但`primaryCode`只一个；证据版本更替后旧结果先失效并启动定向重审，不复用旧码宣称现行通过。没有“事实核验失败所以学校拒绝”的暗含第九状态。

### 10.2 逐问题输出字段（设计契约，不宣称运行端实现）

| 字段 | 类型及必需含义 | 约束 |
| --- | --- | --- |
| `issueId / ruleId / targetObjectId` | string；唯一问题、R001–R038、本次事实目标 | 每个问题必须绑定一个有效R，不允许孤立“缺材料”文案 |
| `templateId / caseId / defenseAttemptId` | string；固定S08-T07、案卷、本次答辩尝试 | 旧答辩尝试的结果不能覆写新尝试 |
| `phase / scenarioIds / trigger` | enum、SC数组、T/F/U及识别来源 | 事件时间和业务阶段双校；未到阶段`NA` |
| `primaryCode / diagnostics / severity` | 8码之一、次级诊断、说明性风险级 | 严重性与是否批准无等价关系；`PASS_FACT`不进入“批准”总态 |
| `fact / expectedRelation / observedRelation` | 结构化比对事实与差异 | 必须能被人工依据材料复核；学术裁量不自动量化 |
| `materialRefs[]` | `{materialId,sourceRecordId,digest,version,ownerId,pageOrField,receivedAt,sourceTrust}` | 强制定位到M001–M032和准确页/字段；可为空**仅**内部案卷/无文件的R001/R037例外，须有授权系统记录替代 |

| `sourceBinding / actorAuthority` | 原签发机构、源版本、真实服务端授权核验结果 | Renderer自填`actor`永远不充当authoritative issuer |
| `nextResponsibleRole / suggestedAction / dueBasis` | 学生、导师、学院、学位办、秘书、委员、复核机关及建议动作和时间依据 | 没有可靠校本期限时`dueBasis=UNKNOWN`，不虚构“3日补件” |

| `decisionGate / publicLabel` | 是否需要正式校方决定及面向申请人的精确表述 | 例：“前置送审结论已核，可提交学院确认”而非“已准许答辩” |

### 10.3 阶段态、事实态与正式决定态三者分离

| 维度 | 允许的状态及进入条件 | 唯一可信拥有者 |
| --- | --- | --- |
| `phaseState` | A0意向→A1前置→B0组织→B1待举行→C举行→D整理→E只读移交；受理/退回/暂挂能保留原阶段 | 学校有权经办/实际发生事件；系统仅存事实镜像 |
| `reviewState` | `NOT_RUN / RUNNING / COMPLETE_WITH_ISSUES / FACTS_REVIEWED / STALE_PENDING_RECHECK`；按快照与R核查 | 审核系统Owner，绝不等于学校批准 |
| `schoolAuthorization` | `UNKNOWN / REQUESTED / RECORDED_APPROVED / RECORDED_NOT_APPROVED / SUPERSEDED_BY_AUTHORIZED_DECISION` | 学院/校学位办按现行校规的真实审批决定；只有正式授权来源能迁移 |
| `defenseDecision` | `NOT_HELD / HELD_PENDING_RECORD / RECORDED_PASSED / RECORDED_NOT_PASSED / CHALLENGED / AUTHORIZED_CORRECTION` | **实际答辩委员会**；状态从经核权的M024而非R的PASS派生，复核不得删除旧票 |

可展示给用户的**虚构**总览示例：“事实预审32/38条已核，5项需校方确认，1项尚未到阶段；答辩组织批准状态：学校回执未核；学位状态：不属于本审核。”数字仅用于演示产品呈现，不对应真实学生或本研究已实际运行的检查数。不得生成“100%通过所以已获学位”。正式决策动作最少需要`authorizedActor + institution + roleBinding + decisionId + targetAttempt + policyVersion + decisionTime + auditEvent`的服务端真实性核验。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 补件、换版与受影响规则定向重审

1. **登记**：每次M录入/替换先确定`caseId, defenseAttemptId, materialId, owner, source_record_id, source_version, digest, observed_at, received_at, authority`；不能确定学生/论文归属时禁止写入本案有效材料集，产生R002/R011的`CONFLICT`。
2. **保留历史**：旧材料M的内容、生成者、审核快照、相关R结果保留不可变索引，新材料作为新版本或可核的新来源记录，**不静默覆盖**。仅由有权源业务声明旧授权被撤销、失效、覆盖时可更新其有效状态。
3. **算受影响闭包**：读取下面M→R直接依赖；再根据共享F（例如论文F016、委员名单F024、签认权限F044）做传递闭包。仅对闭包内R建立新的冻结快照重审，其他R按旧已核版本继续有效；明确`recheckOf`指向原R实例，避免全案无谓重新跑。
4. **变更造成的行政效力**：重新核事实不等于撤销历史学校决定。任何可能改变正式答辩资格、委员会决议、档案有效性的影响，由原有权决定者以新合法回执形成**有版本的新决定**；软件只能标旧事实预审`STALE_PENDING_RECHECK`与发待办。
5. **材料来源缺陷**：官网或业务接口失联为SU；文件清晰度不足为UR；确认当前应有而缺失为NM；尚未知当前文件版本是否要求为PU。不得一律向申请人要求重新上传已有校方记录。

| --- | --- | --- |

### 11.3 可信人工决定写入门槛

建议的`DecisionEnvelope`必须具备 `decisionId, decisionType, targetCaseId, targetDefenseAttemptId, sourceInstitution, decisionMakerSubjectId, roleBindingId, scope, policySnapshotId, linkedEvidenceVersions, decidedAt, effectiveAt, result, officialRecordId, auditEventId`。决定动作只能由业务Owner验证的服务端会话/学校正式回执发起；未经真实授权，所有模型建议和Renderer输入只生成`NEEDS_HUMAN_DECISION`待办。

`decisionType`严格分为`DEFENSE_ORGANIZATION_AUTHORIZATION`（学院/学位办按职责）、`DEFENSE_COMMITTEE_OUTCOME`（实际委员会）、`WITHDRAWAL_DISPOSITION`、`REVIEW_DISPOSITION`、`HANDOFF_ACK`。**`DEGREE_AWARD`不属于本模板可写类型**。有权决定出现前，即使全部R=PASS也仅能显示“事实核查完成，待有权机构决定”；若决定记录与事实核验冲突，应挂复核问题而不是系统自动撤销正式决定。

### 12.2 永久不得由本模板自动裁断

- 答辩论文是否具有达到学位学术水准的原创性、答辩是否学术上通过、专家具体评阅等级的重新裁量，属实际评阅/委员会责任（SRC-003/006）。即使R028票数可算，也不能生成委员决议。
- 委员学术任职资格的争议、真实利益关系例外、涉密范围的授予或解密、签章真实性的最终鉴定，需具备职权和原始人事/保密/证书验证资料；OCR不足以构成有效认定。
- 开题、中期、导师选变及教师导师资格、科研成果认定/权属、论文预审/送审和后续授位均有独立源Owner：对应S08-T03、T04、S08-T01与T06-T01、S08-T05与G06、S08-T06、S08-T08。本模板**只读消费其权威结果与版本**，争议返原Owner；不构造重复审批表、二次授位或反向写入源业务。
- SRC-012–014和所有G50是技术能力与研究候选，不能作为成都理工大学制度原文或具有实体审批权的Actor。G01身份更正/专项用印已有独立授权目的，本模板只引用有效结论，不执行更正/盖章。
- 找不到可证当前校本阈值、截止或材料格式时，出`POLICY_UNCONFIRMED`并显示**确切需要学位办确认的问题**；遇真实签发权限或学术评价需裁量出`NEEDS_HUMAN_DECISION`。不因“AI推测大概率合理”自动PASS。
