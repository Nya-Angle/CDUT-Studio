## 01 唯一审核目的、申请人和负责机构

### 1.1 决定对象固定

本 ID 只服务于**已存在项目聘用关系**的同一人员、同一合同/协议生命周期中的续聘、期限延长或缩短、岗位及职责调整、薪酬约定调整。核心对象是一份可追溯的变更/续订申请，关联原聘约、拟变更条款和批准/签署形成过程；同一申请可组合多个变更项，但必须区分各项的证据和生效状态。

学校 2026 年核技术与自动化工程学院的项目科研助理公告明确属于合同制编外聘用，项目组承担报名资格审查、面试和拟聘建议，学院公示，人事处承担教职工准入查询，聘用手续后续办理（SRC-001，公告第四部分）。沉积地质研究院另一批次由研究院办公室资格初审、项目组面试，随后在研究院办理签约（SRC-002，第五部分）。**两者是首次招聘事实，不足以证明变更阶段也沿用完全相同审批链。**

### 1.2 申请人与机构（角色性质分开）

| 角色 | 本模板涉及的行为 | 可信度/待核边界 |
| --- | --- | --- |
| 已受聘人员（劳动者） | 发起或确认续聘/变更意愿，核对个人及拟变更内容 | 应与原合同及可信人员主档对齐；真实签名、意思表示需校验，不能用表单 `applicantName` 代替 |
| 项目负责人/项目组 | 说明工作任务、岗位必要性、项目持续性、资金需求或提出建议 | SRC-001/002 证实在首次招聘中有职责；SRC-004 第一条证实项目经费直接责任，但**无据可认定其有单独改变劳动合同的权力** |
| 所在学院/研究院 | 可能审核申请事实、组织内部协商或转报 | SRC-001/002 的录用阶段角色已核；续聘与变更的签批权需人事部门书面确认 |

## 02 适用、排除与邻接模板路由

### 2.1 适用范围

1. 有可信证据表明当事人是成都理工大学相关用工主体的**现有项目聘用/科研辅助人员**，存在可定位的既有合同或依法认定的劳动关系，且拟议事项是同一关系的续订/变更。
2. 将“项目层面”和“学校层面”科研助理视为**用工来源分支**，不能相互挪用批次规则：SRC-001 公告给出该项目招聘聘期 2026-09-01 至 2027-08-31；SRC-002 的项目批次按不少于 6 个月、起止时间由双方协商；SRC-003 学校层面为其单独批次设一年期限。上述均非所有项目聘约的通用期限阈值。
3. 如真实合同属于劳动关系，适用《劳动合同法》相关规定（SRC-007 第二、十二至十七、三十五、四十四至四十六条）。对劳动关系性质有争议、劳务派遣或第三方合同、合作协议等情形，先人工识别法律关系与实际用工主体。

### 2.2 明确排除/仅引用权威结论

| 邻接决定目的 | 路由边界与引用方式 |
| --- | --- |
| 项目/团队岗位设立与编制、经费立项 | 不是本 ID 的初始决定；这里只引用已生效岗位/项目/预算结论及其版本，不重新批准岗位 |
| 首次招聘、资格审查、拟录用、入职签约 | 另属首次录用决定；本 ID 读取其有效结果，不能用“申请续聘”建立新的首次录用 |
| 聘约终止、辞退/解除、离岗交接 | 属相邻独立决定；缩短期限若实质导致解除或终止，须升级人工辨识并路由，不把解除包装为普通期限变更 |
| 正式事业编制、学校教职工岗位聘任及事业单位聘用合同 | 转 `T02` 人事聘任等按 R02 的实际条目处理，不能将编制聘用的三年聘期及岗位工资规则移植给项目编外人员（SRC-009 附件第 1 页填写说明） |
| 博士后进出站、站内考核与待遇 | 博士后专门决定只引用权威结论；本模板不以“科研助理”口径替代博士后制度 |
| 项目预算、科研合同、项目经费/劳务费支付与薪酬发放 | 只关联已核项目状态、经费来源和支付/审批结论，分别由相邻项目/财务业务决定；不得因 SRC-004/005 允许某类经费支出而直接批准合同涨薪 |
| G50 共性审核能力 | SRC-010 固定 SHA 的 50 条技术候选 ID 已核，目录自称 `authoritativeSchoolTemplate=false`、`publicationAllowed=false`、`integrationStatus=NOT_TESTED_ON_UNIFIED_HEAD`；不可把 G50 `g08-t03` 与 R02 `T08-T03` 同号认领，前者原 workspace 名为“公共诉求受理与再次办理程序核验”。技术读取/一致性结果仅作线索，**不得引用 G50 候选结果作为项目用工正式决定**；具体规则级去重仍待 SRC-011/012 |

目前缺乏 R02 总账正文，**不擅自指定相邻 S/T 编号**。固定 G50 目录中没有名为本项目续聘/期限/岗位/薪酬变更的同 ID 模板；这只排除了**可见目录层面的直接同名/同 ID**，不足以替代 50 个工作区的逐规则及 R02 144 项完整语义去重。待核 SRC-011/012 后补精确 ID、去重判据和共享结果字段。

### 3.3 撤回/复核路径的分界

- **P1～P3**：提交者可提出撤回请求；系统保留申请快照，交当前负责机关核对是否受理。若申请已有他方实质承诺，不自动清除其证据。
- **P4**：已进入有权审议阶段，先查真实签批状态和撤回规则，通知有权经办人；未有校本程序则 `POLICY_UNCONFIRMED`。
- **P5～P6**：如书面合同已经签署或实际生效，不再定义为“删除申请”；需按劳动合同变更/解除、争议程序处理，原文本不可被技术操作撤销（SRC-007）。
- **复核**：事实提取错误可重读原材料；审批或合同效力争议必须交人事/法务或有权复核机关。申诉材料在提出异议之后形成，不列为原申请必需项。

| 复核/争议处理人 | 尚无校本变更复核制度；劳动争议按适用法 | 接收异议并由有权机关办理 | 不得凭系统管理员权限修改生效合同法律效果 |

### 5.2 数据来源优先级与三条互不替代的证据链

1. **法源/校本政策链**：可验证的国家现行法、校本原文/授权文件、有效版本及适用身份/批次（SRC-004/007/008）。相邻制度缺失时 `POLICY_UNCONFIRMED`，不得将 SRC-009 的编制人员岗位工资条款照搬。
2. **合同/人事链**：合同保管机构所持原件或合法签署文本 → 版本化补充协议 → 人事台账已生效状态；本人私存扫描件可辅助交叉验证，发生版本冲突时不能自行取“较新文件名”为准。
3. **科研/财务链**：正式项目任务及身份、经费台账及额度/类别、负责人的科研事实说明 → 财务审签或执行记录；它们证明资金相关性与实际支付，不证明劳动合同已变更。

三个链条需要按 **人／合同／项目／经费／申请/审核时间点** 交叉关联，任一链中缺失不能由另一链自动补足批准。外部劳动关系性质、派遣合同主体不清时先停下人工辨认。可信系统是否提供接口未获证，**不把“理论上有台账”写成“系统已经接通”**；可由有权保管人出具盖章记录或经核验的档案副本。

### 5.3 可信 Actor、签署和电子文件

- 申请者身份、操作者身份、项目经费负责人、实际审批者为不同字段。身份须由主进程/服务端认证会话、机构目录和正式授权记录绑定；前端字段、拖入文件中的人名、公章图片、OCR 文本、导入的旧结论都不能自行提升为真实审批人。
- 正式记录至少关联 `caseId + caseVersion + contractId + contractVersion + evidenceVersion + actorSource + decisionTime`。批准、双方签署及生效分别留记录；不得以“已盖章”图片单独断言合法授权。电子签名真实性、印章有效性、委托授权及纸质原件核验流程均为校本待核配置。
- 被替换的 M 证据保留哈希/文件指纹、来源、页码/单元格、签署时间、抽取版本和失效原因。旧事实结论不得假装仍指向新附件。无需改变的另一子项应按依赖图只重审受影响规则。
- 所有跨模板引用必须有相邻事项**真实已生效决定**及其来源版本，不能把历史的 `run@rev` 或预审 PASS 当作正式 Decision；SRC-010 技术目录已核，S/T 精确 Owner 仍待 SRC-011/012。

### 5.4 隐私与最小访问

本草稿的 `L0`＝可公开业务事实、`L1`＝校内普通业务、`L2`＝个人隐私/合同与工资、`L3`＝身份证件号、健康/心理、银行及高敏信息。默认只提取必要字段，显示时脱敏；不能将首招体检、心理测评、背景核查自动设为每次续聘必交。保存期限、授权可见范围和安全保密等级应由校方现行制度确认。

### 5.5 事实预审状态

`PASS_FACT`（已核事实成立）、`NOT_APPLICABLE`（条件不触发）、`NEEDS_MATERIAL`（该阶段必要证据缺失）、`CONFLICT`（权威版本/跨材料冲突）、`UNREADABLE`（材料存在但不可判读）、`SOURCE_UNAVAILABLE`（可信保管源暂失联）、`POLICY_UNCONFIRMED`（缺现行适用制度）、`NEEDS_HUMAN_DECISION`（身份/法律/裁量或正式签批待人工）。任何一项均不是“批准续聘/调薪”。正式决定以后才能出现于 P4～P6 的证据槽中。

## 06 业务对象与字段字典

### 6.1 字段模型约定

候选对象分为 `Case`（申请）、`Person/Employment`（人事关系）、`Contract`（合同及历次修订）、`Proposal`（变更请求）、`Project/Fund`（项目与经费）、`Decision`（有权决定/合同签署）、`Evidence/Dispute`（证据版本与异议）、`Policy`（适用来源及有效性）。`P0～P6/PX` 沿用 03 节阶段；`L0～L3` 沿用 05 节隐私分级。

**来源缩写：** `T`＝受控服务端/案卷和审计，`H`＝经认证的人事/合同保管机关，`W`＝经过核实的本人真实意思表示，`P`＝科研/项目权威档案，`C`＝财务/预算原始记录，`D`＝有权审批/签约档案，`U`＝申请者声明（仅作线索，不可信决定）。即使表写 H/P/C，也**不意味着已有接口**；不能读取时要求有权机关核证，不能强制申请人从未知系统截图。

**缺失码：** `N`＝当前阶段真实必要且缺失记 `NEEDS_MATERIAL`；`S`＝权威源失联记 `SOURCE_UNAVAILABLE`；`Q`＝该字段是否校本必需未确认，记 `POLICY_UNCONFIRMED`；`H`＝需有权人工判断记 `NEEDS_HUMAN_DECISION`；`L`＝留到后续阶段，不作为当前缺件。值不一致另记 `CONFLICT`；文件存在无法解析记 `UNREADABLE`。每个字段允许 `unknown`，不得把未知默认为 false 或通过。

### 6.3 类型和证据约束

- **时间、金额与身份**：日期保留公历及原时区；工资明确币种、税前/税后、计量周期、基本薪酬/津贴/项目报酬口径，不能用单一数字比较不同结构。证件编号仅保留受控匹配结果，正文显示脱敏值。
- **范围**：每个 F 有 `caseId + personId + contractId + contractVersion + scenario + sourceVersion` 锚点；如一项事实跨项目共享，应额外绑定项目及会计周期，不能将同名人、同一个项目组的另一份合同混入。
- **重算**：材料 OCR 得到的字段只先标 `candidate`，需按可信记录判定；替换 M 后更新 F040 并使依赖它的结论失效。F035～038 在 P1 阶段为 `NOT_APPLICABLE/PENDING_STAGE`，不是 `NEEDS_MATERIAL`。
- **未配置**：正式校本合同模板、数字签章/权限接口、额度或绩效阈值未取得；这些字段只定义需要验证的事实，不能以本表推导学校强制填报系统已存在。

### 7.2 同一时点的最小证据原则

1. **P0/P1 基础包：** 证明原聘约与本次拟议事项只需要 M001、M003、M004（如合同历次变更则加 M002；非本人代理提交按真实授权情况核 M026）；这些优先由保管机关核证/复用。F001～F005、F007、F009/010、F012～016、F020、F040～042 等是系统及证据抽取数据，**不是额外纸质申请表**。提出者为项目组不意味着员工事先必须另交同意书，M005 可以在 P2 核。
2. **P1 条件包：** 续聘需项目需要与项目/资金事实 M006～008、必要时 M011；期限改变需要准确提案日期与原变更链；岗位变更需 M009，涉及资格时 M014；调薪需 M010/011；多项目分摊才加 M015。一个材料若在原合同、科研/财务可信库已经完整可见，优先按授权读取/请求保管机关核证。
3. **P2 人工风险包：** 劳动关系性质、超期用工、缩期解除、历史工资等特殊情形可由有权 H/法务出具 M016/M024；不得让申请者自行断言法律结果，也不要求一般调薪案上传全套健康、背景材料。
4. **P4～P6 后续包：** M017、M018/019、M020/021 分别在有权审批、双方签约、归档/履行后才出现；P1 的缺件扫描**必须排除**这五类后置文件。M022/023 仅在撤回/复核真的发生后按先后产生。
5. **材料可判读性：** PDF 图片/扫描件保留页码；Excel 记录保留 sheet/行列；邮件或系统回执保留签发者和生成时间。`UNREADABLE` 说明无法识别的精确页段，不应凭模糊签章推定授权；不能读取权威系统为 `SOURCE_UNAVAILABLE`，不等于申请者没交。

## 08 审核规则逐条清单

**第三轮规则研究稿（R001～R032）。** 以下为**事实核查规则**，并非成都理工大学发布的审批规定。`P0～P6/PX`、`A1～G2`、`F`、`M`、`SRC` 的定义依 03～07 节。规则在其阶段到达且适用条件已判明后运行；未来阶段尚未到达时记技术性 `DEFERRED_STAGE`（非八种事实结果），不把 M017～021/023 报成申请初期缺件。每个 R 均要求 `targetId=personId+contractId+变更子项或项目账期` 和精确证据定位，不能把整个材料上传成功当作规则通过。

**统一求值约束（各 R 行省略的共同异常处理）：** 触发**真**时执行比较；触发**假**且由可信证据排除时 `NOT_APPLICABLE`；触发**未知**时依实际根因返回 `NEEDS_MATERIAL`（该阶段必要事实未提供）、`UNREADABLE`（材料已有但指定页/字段无法判读）、`SOURCE_UNAVAILABLE`（应由有权保管者提供的记录暂不可访问）、`CONFLICT`（两个可靠证据矛盾）、`POLICY_UNCONFIRMED`（现行适用规范或授权未证实）或 `NEEDS_HUMAN_DECISION`（法定/校内裁量、真实性待认定）。**不得用未触发或查不到代替“假”；不得用政策不明代替 `PASS_FACT`。** 各 R 在事实可一致核对时最多产生 `PASS_FACT`，并不产出批准。任一条若同时有不同缺口，应分别保留问题记录，主状态按 `CONFLICT → UNREADABLE → SOURCE_UNAVAILABLE → NEEDS_MATERIAL → POLICY_UNCONFIRMED → NEEDS_HUMAN_DECISION` 的案卷展示优先序归纳；**此序仅为待办展示，不是法律效果优先级**。

### 9.2 跨材料一致性、身份及版本规则

1. **同名不是同人**：`F007` 必须匹配人事主档的唯一人员 ID、既有 `F012` 所载受聘人、必要时 F008 的合法更名链。身份证扫描件号码 OCR 不同、曾用名未证明或两个同名员工并存，应将 M003/M013 标 `CONFLICT`；不把工资表姓名匹配作为身份认证。
2. **原合同不是随手一份 PDF**：合同档案保管者确认 M001 与 M002 的有效版本链，确定 `contractVersion` 及在拟变更日的有效条款。若 M001 显示 2027 年结束、后签 M002 已改为 2028 年，应以签署主体与法律效力核证决定事实基线，不以谁最后上传为准。
3. **签发权限按用途细分**：项目负责人说明用工需求（M006）、财务审核经费（M008）、学院提出意见、雇主授权者签署合同（M017～019）为不同决定动作。对“项目组负责人签字＝学校已批准调薪”输出 `NEEDS_HUMAN_DECISION`。
4. **拟议与生效分离**：M004/M005 是提案/协商线索；M017（可能的内部决定）、M018/019（双方签署）、M020（归档）、M021（执行）随阶段形成。只存在 M004 或有经费额度时，F036～038 不得置为“已生效”。
5. **经费有时间和种类**：F027～033 与 M007/008/011/015 必须校验项目期、资金额度、同一劳动成本的计费期间。两个项目都声称负担 100% 的同一期间，标 `CONFLICT`，不是按默认权重拆半。**代理权另有对象/有效期：** 不能以 M012 的项目批复或 PI 头衔取代 M026 的代办授权，也不能以 M026 的申请代办权取代 P5 的用人单位签约授权。
6. **SRC 的政策适用性是输入事实**：SRC-002 单批次“不少于 6 个月”、SRC-001/003 的一年聘期、SRC-009 正式教职工的三年聘期不得作为 T08-T03 通用条件。找不到本项目的现行用工办法，F041=`POLICY_UNCONFIRMED`，不能自动通过或否决。
7. **接入优先级**：已核权威人事/合同/项目/财务记录优先于申请者上传的截图，截图仍可用来提出冲突线索。若可信来源不可达，输出 `SOURCE_UNAVAILABLE` 并向有权保管者申请核证；不能把该情况误归责为申请人缺件。
8. **到期后实际用工证据不可空转**：A2 需以 F046/M025 定位期限届满后工作、用人单位知悉及异议情况，依 SRC-013 第 8～11 条提示人事/法务核法律风险；只有工资条姓名或“仍在群里”不足以自证实际用工及法律结论。

### 9.3 被替换材料与结论失效

- 每个材料 `Mxxx` 的每次版本绑定 `caseId、owner、source、sourceVersion、fileHash、抽取定位、入卷时间、证据有效时段`；一份案卷允许材料多版，但只有经核定的有效版参与最新检查。
- 改动 M001/002/003 时，使 `F007～019` 及依赖原合同或身份的 A/B/C/D/E/F 检查重新进入待核；改 M007/008/011/015 时，仅经费与受影响的续聘、调薪或跨项目项重审；改 M004/005 时重算拟议条款与意思表示，但不抹除历史签约。
- 旧结论标记为 `SUPERSEDED_BY_EVIDENCE_VERSION`（**研究性内部标签，非正式结果状态**），记录何材料和差异导致失效，禁止旧的 `PASS_FACT` 作为新决定的现行证据。
- 已由相邻 S/T 的**真实授权 Owner**形成可信 Decision 的，引用其 `decisionId + version + issuer + effectiveStatus`，本模板只核该事实的适用性；无原始决定只有模板名或旧 Run 不复用。固定 G50 **候选目录**已读取（SRC-010），它不保证任何一个学校正式 Decision；R02 正文未取得，精确 ID/Owner 映射仍待 SRC-011/012。
- 同时存在两份在审申请修改同一合同重叠期间，须核定先后效力与 CAS 式版本冲突；不可自动“最后写入覆盖”。如原案正式合同已变更，另一案以旧版为基础必须提示重提或人工复核。

## 10 结果状态、问题与待办输出契约

### 10.1 八种互斥事实结果与“正式决定”双轨

每个 `ruleId × targetId × stage × evidenceSnapshot` **恰有一个当前事实结果码**；若一个规则遇到多种缺口，分别产生 `Problem` 记录，结果码按 08 节展示优先级归纳，原始问题不得丢失。不同子项的 R 可同时一个 `PASS_FACT`、另一个 `NEEDS_HUMAN_DECISION`，案卷不因此变“部分已批准”。

| 结果码 | 唯一语义、不能误用的情形 | 自动下一步与目标办理人 |
| --- | --- | --- |
| `PASS_FACT` | **限定的事实**在当前证据版本、时间及 SRC 适用范围内核实一致；不是“审核通过/批准/合同有效” | 记录证据锚点；事实链齐也仅可送有权 H/D、PI/C 分别核定其法定/校内职权 |
| `NOT_APPLICABLE` | 由可信事实确定**本 R 条件为假**，例如 D 类调薪未触发；或 PX 请求从未发生 | 跳过本 R，不产生缺件待办；未来阶段未到改记技术 `DEFERRED_STAGE`，不可混用 |
| `NEEDS_MATERIAL` | 当下该条件实际触发且无法从可信系统/保管者核取必要事实；列明具体缺 F/M | 指向材料持有人 W/PI/H/C；优先内部核证，不盲目催个人上传 |
| `CONFLICT` | 身份、有效合同版本、期间、工资口径或多项目账的两份足可信证据冲突 | 按冲突证据对列，指向对两端有核实权限的 H/PI/C；保留原件，不自动选最新上传 |
| `UNREADABLE` | 文件确实存在，但特定页/签名/单元格损坏、遮挡或无法解析 | 指向原件保管者/人工识读人；待办写缺页和位置，不能当“没交” |
| `SOURCE_UNAVAILABLE` | 必须依赖的**可信源**暂时无法访问/查询超时、接口不存在或核证人未回复 | 指向真实数据 Owner/H/P/C；不能把源不可达归责于申请人缺件 |
| `POLICY_UNCONFIRMED` | 没有已核的**现行且本身份/批次适用**校本规则、表单、阈值、审批权或复核程序 | 向政策/授权机关发调查待办；人工不得凭“其他大学这么办”填默认 |
| `NEEDS_HUMAN_DECISION` | 事实可能齐，但法律关系、双方意思、签约权、保护待遇、追溯工资、资金准用等需有权者判断 | 指向真实有权 H/法务/C/D，并附已核事实及争议；**AI 不给正式批准或拒绝** |

另有技术/流程标记 `DEFERRED_STAGE`（后续才需）、`SUPERSEDED_BY_EVIDENCE_VERSION`（旧事实快照已被更新覆盖）、`PROCESS_PENDING`（等待真实经办），均**不得混入八个结果码或暗指审批状态**。正式学校决定独立为可信 `FormalDecision`：`DRAFT/UNDER_REVIEW/ISSUED_APPROVE/ISSUED_DENY/WITHDRAWN_BY_AUTHORITY/SUPERSEDED_BY_AUTHORITY` **仅示意系统适配**，不可据此声称成都理工大学官方状态枚举已核。`ISSUED_APPROVE` 只能由人事/用工主体合法权限写入，需真正有效的 `decisionId`、签批/合同等原件；不得由 R 统计或 Renderer 自报写入。

  predicate: true|false|unknown

上述 YAML 是**研究期输出契约样例**，不是已实现接口/提交数据文件。`Problem.nextOwner` 绑定 Main/受控服务端的可信组织角色；身份未知时只写候选部门 `nextRole` 并冻结自动流转，绝不由上传材料内的“审批人”字段赋权。严重性只用于提醒优先级，不能作为实体否决阈值。文档屏蔽 L2/L3 隐私，问题里保留安全证据指针，不把身份证号和全量工资在通知中广播。

### 10.3 一案多子项的汇总

1. 对同一申请的续聘、期限、岗位、薪酬逐项输出规则事实结果；`PASS_FACT` 仅表明对应**事实证据完整一致**，不生成“整案通过”。
2. 只要存在 `CONFLICT/UNREADABLE/SOURCE_UNAVAILABLE/NEEDS_MATERIAL`，生成可定位证据的待办；`POLICY_UNCONFIRMED/NEEDS_HUMAN_DECISION` 即使材料齐全，也须阻止 AI 推断正式决定。问题修复后重算**有依赖的 R**，不能自动修改独立业务 Owner 的决定。
3. 正式决定可能因子项分别形成不同效力范围；跨项一张合同亦要记录每个子条款的批准、签订与生效界限。无真实有权者签发记录时 `FormalDecisionLink=null`；不能把 `ReviewRun` 或旧 `run@rev` 映射为 Decision。

### 11.1 阶段状态与真实权限门禁

**单向权限边界：** Case Owner 可以对案卷、材料、事实规则、待办做可追溯写入；**不能**生成伪校方批准或代替双方签名。即便界面允许用户修改“审批人”或导入 PDF 公章，F035/036 只能来自真实认证权限与有权签发记录。服务端校验 `actualActor + businessPermission + delegationVersion + contractOwner + scope + effectiveWindow`，主进程不能接受 Renderer 角色作为事实来源。合同/人员/项目/资金原始主档由各自有权 Owner 管理，不能由此案卷反向改写。

| 被换材料或权威记录 | 至少使哪些 R 的旧事实快照失效 | 保留哪些不受影响结果；何时扩大影响 |

### 11.3 撤回、重提、复核的幂等处理

- **撤回请求**先记录 `requestId + authenticatedRequester + targetCaseVersion + targetDecisionId(if any) + requestedAt`，不是删除 Case。R029 的 `PASS_FACT` **只表示请求人及请求事实已核**；是否准撤及接受后的法律后果是另一个必须由有权机关完成的业务门禁，不得借事实码表达批准；未决定期间对相关正式签约流程加人工提示。
- **撤回后重提**作为同一人员/合同生命周期的**新案卷申请版本或关联新申请**，保留旧撤回记录与正式合同的原效力，不能复活旧 `PASS_FACT` 作为新证据；未有校本规则不能擅定“必须间隔 N 日”。
- **事实复核**只对所质疑 R 和相关事实依赖重算；正式复核须由原有权机关或规定复核机关形成 M023，旧决定保留不可篡改引用。对劳动争议的法定救济时限不由本研究稿代替正式告知。

### 12.2 不能由自动预审作出的裁量

法定无固定期限劳动合同资格、期满继续用工的效力、提前缩短/解除及补偿、追溯工资是否合法、派遣或多关联单位用工主体、签约代理授权真实性、经费特别限制及预算审批、最终续聘/调岗/调薪是否准许、撤回/复核受理及劳动争议均保留 `NEEDS_HUMAN_DECISION`。本项目没有权限设置公章、变更真实合同、划转项目资金、生成工资支付指令。SRC-013 的司法解释包含“一年累计延长”“超过一个月继续用工”等具体**法院适用规则**，在本研究稿中只作为法务风险提醒；绝不把其硬算为“学校自动批准续聘”条件。

### 12.3 校本未证实与业务边界的实际风险

SRC-001～003 **证明存在合同制社会用工及多批次聘期差异**，不证明学校已开设四项在职变更的统一线上入口；SRC-004/005 **证明项目经费和发放流程**，不证明财务人员能替雇主变更劳动合同；SRC-009 **仅证明历史编内岗位制度**，不得继承其岗位工资结论；SRC-010 **已核技术目录，但非校方制度或批准凭证**；SRC-011/012 尚未取得，无法完成真正的 R02 全量邻接去重。故这些缺口对上线均为需校方确认的前置条件，而非编程上可忽略的警告。

### 14.4 CATALOG-CHANGE-REQUEST 与交付结论

**暂不提出 `CATALOG-CHANGE-REQUEST`。** 目前没有任何已核且现行适用的成都理工大学正式文本证明“四类合同变更”必须按不同独立授权目的拆成四个模板。保留同一 `T08-T03` 下 A～G 多情形；如果未来校本原文明确另有独立签批对象，应提交证据、拟变更边界及与邻接业务的重叠分析，**不自行改 R02 编号**。

**最终审查评级：`REVISE`（研究性结构可交接，政策/权限不可上线）。** 已完成逻辑交付所需 00～14、来源索引、双向编号核对、状态与 15 场景模拟；主要校方现实条件仍无法形成“经权威校规验证的自动决定能力”。可用于后续校本核验和受控事实预审研发，不可表述为成都理工大学官方模板，也不可直接部署为准予续聘、调岗、调薪、解除或支付的自动决策系统。正式签批和双方书面合同必须源于真实有权机构；八事实状态永不等于学校批准。交接检查单与 ZIP 仅证明文档交付，不提升政策效力。
