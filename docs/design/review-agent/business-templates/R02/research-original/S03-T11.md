### 00.2 研究结论分层

1. **事项存在：已证实到项目层。** 成都理工大学 2025 年本专科资助政策明确列有使用校内和捐赠资金设立的“学费减免”等项目，申请时间和具体流程需向学院或学生资助管理中心咨询（SRC-002）；2024 级新生公开说明还写有特殊困难情形的减免申请（SRC-003）。这证明项目存在，**不证明** 2026–2027 学年有统一开放的独立线上审批事项。
2. **上位法支持申请权，但不直接推出批准权或金额。** 《中华人民共和国高等教育法》第五十四条载明经济困难学生可申请补助或减免学费（SRC-001）；具体身份、标准、资金批次和流程仍需要校本有效依据。
3. **主要归口可定位，最终审批权限未锁定。** 学生资助管理中心办公室具有政策执行、困难认定、校内学生奖助统筹等职责（SRC-004）。它不当然独占“学费减免最终批准”权；需取得专项实施办法或当期审批单。
4. **2024 新生口径不能全校全年套用。** 当年说明中的“无经济来源、未获任何资助的孤儿”和“烈士子女、优抚家庭子女”是有价值的特定线索（SRC-003），但对 2026 学年、非本科新生、研究生及不同资金来源均记 `POLICY_UNCONFIRMED`。
5. **三个相似但不同的决定链必须隔离。** 绿色通道缓缴不等于学费免除（SRC-005）；服兵役国家教育资助中的学费减免有独立政策和申报系统（SRC-010、SRC-013）；困难认定、助学金、临时困难补助及就业学费奖补均不能被本 ID 顺手批准（SRC-002、SRC-011）。
6. **专项经济资助的边界待冻结。** 学校 2025 年资助政策栏目可见“脱贫户（原建档立卡贫困户）本专科学生特别资助”历史批次公告（SRC-009），但其是否应由本模板统一承载、或属于独立财政资助决定，还需以完整通知、R02 总账及 G50 比对为准。不得将其中历史金额和年限推广给所有在校生。

### 02.3 专项经济资助不是无限兜底

“专项经济资助”可能有各自独立的发布机关、资金用途和财政规则。当前已检索到的 2025 年脱贫户特别资助公告涉及**特定历史入学区间**（SRC-009）；四川省资助管理中心 2023 年完整公告（SRC-021）则可确证：历史项目**学费与生活费各 2000 元**、学生经四川政务服务网申请、学校核学籍、县级部门会审公示、县级主管部门发款。由此可确认**至少 2023 年历史制度属于独立的省级教育扶贫资金链，学校并非该项发款的唯一决定者**；不能把此历史流程当 2025/2026 当期程序，更不能把历史款额移作成都理工普通减免标准。**每一个拟进入 C06/C07 的子项目均须先核发布机关、资金项目号、年度、发放用途、受理与签发权**；若属于外部财政项目，S03-T11 只分流并核验本校可证明的前置事实，不以本模板决定外部资助。如确证需目录变更，按第 14 节发 `CATALOG-CHANGE-REQUEST`，本 `S03-T11` 本身保持不变。

### 03.3 办理先后与可用性门禁

1. **阶段门禁：** P1 必需申请意愿和身份绑定，P2/P3 校方权威信息由校方提供或核验；P5 审核意见、P6 决定、P7 冲抵/退费、P8 复核文书均只能在其事件发生后出现。
2. **同学不同案：** 同一学生跨学年/项目可以存在多项申请；`F001+F002` 标案和版本，`F003+F014+F027` 识别受益对象/资助批次/费用期间，不能仅按姓名合并。
3. **多层身份：** C05 与 C01/C02/C03 可叠加；C08 是任一有效申请的交叉核对环节；C09–C13 是生命周期的处理情形，非新模板。
4. **来源失联：** 不把未取得学籍/财务/困难认定接口解释为申请人“不符合”，按 `SOURCE_UNAVAILABLE` 转有权部门核验，且可用校方正式替代凭证。
5. **版本影响：** 同一申请发生政策修订或补件，只复核受影响字段与结论，并保存历史版本；旧决定不因材料替换自动变为新决定。

### 05.2 可信输入的分层

1. `L0 申请陈述`：申请人/代理人填报，记录来源、上传者、时间与授权关系；只能证明“有人主张了某事”。
2. `L1 证据文件`：学校通知、身份原件扫描、带可识别签章的证明、申请表；OCR 结果须能回到文件页码和图像区域，遇低置信度标 `UNREADABLE`。
3. `L2 主管方事实`：由学校学籍主数据、财务核算、已有困难认定决定、正式专项项目台账或验证过的外部证明产生；记录系统来源、出具时间、校验渠道、效力区间。无法验证时标“待核”，不默认与 L0 等价。
4. `L3 授权决定`：经校方可信登录/职务授权、有效流程和签署文书绑定的批准、不批准、撤销、更正、复核决定；只有 L3 才可写入“正式决定”字段。正式财务执行须另有可信财务结果。

### 05.3 审核权限门禁与技术防伪

- 不接受 Renderer/UI 传入的 `actorId`、`role=teacher/admin`、姓名或证书截图作为可信审批身份；由**受信任的 Host/Main 服务端**从实际登录上下文与授权映射重新解析 Actor，校验任务/组织/项目权限。校方实际 SSO、岗位名和授权源尚待接入确认。
- 事实预审与正式决定分离：本模板运算只能产生 `PASS_FACT`、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION` 等中间状态；不得把 `PASS_FACT` 显示成“已批准”。
- 每次审核绑定申请版本、政策来源版本/生效范围、材料原件哈希或稳定 ID、引用的权威结论版本及审核时间。更新一份材料只复核与之相关的事实，旧决定/证据保留审计引用，不伪造已存在的真实 `Run`。
- 学费减免与资助资金涉及个人经济、家庭与身份敏感数据；只向有权经办人员展示必要信息，不将完整隐私信息写进公示或通用日志。公示是否需要、内容及期限仍待校本原文。
- 有权决定链尚未查明时，无论 AI 预审多肯定，均停止在 `NEEDS_HUMAN_DECISION`；任何金额不来自已生效且覆盖申请人/批次的政策原文和权威学费数值，均不计算、不落账、不指挥发放。

### 05.4 应对争议、冲突和错误来源

- 申请陈述与权威学籍/财务不一致：输出 `CONFLICT`，说明两个不同来源的原始事实及有效日期，交人工或发起校内更正流程；不能静默选择对申请人有利/不利的一边。
- 材料损坏/无从验证：`UNREADABLE` 或 `SOURCE_UNAVAILABLE`，不等价于不合格。
- 专项规则缺失/疑有新通知：`POLICY_UNCONFIRMED`，先停止自动否决/自动通过，再由归口人员确证政策版本。
- 对资格标准本身存在解释空间、名额/预算分配、家庭特殊情况及资金重复享受认定：`NEEDS_HUMAN_DECISION`；须有校方真实决定，AI 不得自行行使裁量。

### 05.6 主从材料、冲突与版本继承契约

1. **证据归属键：** 每份材料记录 `materialId / M槽 / caseId / applicantId / issuer / sourceDocumentId / revision / effectiveRange / receivedAt / supersedesId / digest / evidenceLocation`。同一学生的不同批次与学费年度，不能因为文件名相同而混为一份；同一次审查也不应将别人的证书自动关联。
2. **主从关系：** 权威决定、财务记录或外部证明为主事实来源；申请说明、复印件、OCR 摘要是其从材料。一个证件的多个页面归同一主件，一份扫描汇编里不同人员的证明须先拆出具体受益对象。申请人声明不能“覆盖”上级决定。
3. **姓名/身份匹配：** 首选权威学号与可信身份映射（F003），再对照法定姓名（F004）、身份期间、学段与证书上的身份要素。仅姓名相同不合并；姓名变更需校方身份变更记录。身份证号属于高度敏感数据，不在普通待办中完整显示。
4. **冲突优先级不是盲选：** 同日期不同值先查项目、学段、费用期间是否真的相同；同一对象同一版本冲突输出 `CONFLICT`。若真实系统过时也不得自动信任“看似更新的截图”；由原主数据责任部门更正。
5. **材料替换：** 新文件不覆盖旧文件字节，保留旧摘要、引用点、哈希、审查结果和替换原因。对 `F052` 所列受影响事实触发局部再审；绑定旧证据的 `PASS_FACT` 标为失效待重评，不把其他未受影响结论批量作废。已经生效的正式决定仅能由有权人员另作更正/撤销，不能让替换操作直接改写。
6. **跨案复用：** 符合校方访问授权、主体一致、项目目的兼容、未过有效期、原决定已签署的，可以用 `M006/M011/M012/M015/M031` 的原权威记录引用替代重复上传；若不满足任一条件，要求原持有人核验或标来源失联，不强制学生重新提交其无权获取的内部签批件。
7. **复核审计链：** 撤回（M021）、复核申请（M022）、原决定（M023）、新复核决定（M030）分别保留不同签发主体、时点及效力，不允许将撤回请求等同撤销决定，或复核意见等同财务冲抵。

## 06 业务对象与字段字典

### 06.1 对象与编码约定

- 业务对象 `Application`（申报案）、`StudentSubject`（受益学生）、`ProjectBatch`（项目/资金批次）、`IdentityEvidence`（困难/特殊身份）、`TuitionLedger`（学费事实）、`AwardLedger`（其他资助事实）、`MaterialRecord`（材料版本）、`IssueAndRemedy`（补件/冲突/撤回复核）、`Decision`（正式决定）、`Execution`（财务执行）。这只是设计对象，不声称学校现有接口/数据库同名。
- 类型：`str` 文本、`id` 不可混淆的对象 ID、`enum` 受控枚举、`date` 日期、`datetime` 时刻、`money` 金额及币种/期间、`ref` 权威记录稳定引用、`list` 关联集合、`bool3` 真/假/未知。`enum` 的未知值必须保留 `UNKNOWN`，绝不将无记录写为 `false`。

- 隐私级：`公开`（政策信息）、`一般`（申请元数据）、`敏感`（学籍/联系方式/经济信息）、`高度敏感`（身份号、特殊困境、原证件、银行/决定审查详情）。界面应尽可能引用或掩码显示。
- 缺失码：`NM`=`NEEDS_MATERIAL`（确需本阶段材料）；`SU`=`SOURCE_UNAVAILABLE`（来源失联、无接口）；`PC`=`POLICY_UNCONFIRMED`（尚无适用校规）；`NH`=`NEEDS_HUMAN_DECISION`（只能人工处理）；`CF`=`CONFLICT`（互相矛盾）；`NA`=`NOT_APPLICABLE`（条件不触发）；`WAIT`=后续阶段未产生、**不是缺件**。文档中 `Mxxx` 是证据位置，落地需具体文件页码/段落/字段坐标。

### 06.3 字段关系及未知时的处置

- `F001` 单个申请有多个 `F002` 版本；`F003` 是同一受益人，`F005` 可为代理人；`F014` 单个项目批次与 `F027` 学费期间共同决定适用口径。

## 07 材料槽与证据目的

### 07.1 材料制度、缩写与阶段必需性

本节“必需”是**为了本系统核实某事实的阶段性数据需要**，并非宣布成都理工大学法定材料清单；具体学生必须提交哪些原件由当期有效通知决定。状态：`当期必需`（进入相应核验阶段缺该事实不能作出结论；优先校方取得）、`条件必需`（仅相应项目、身份、争议触发）、`后续产生`（当前不存在不得催交）。`P1前置`、`P3按触发`、`P5后` 等按 03 节定义。学校能从可信渠道复用时，学生不重复上传。

材料记录必须具有 `caseId / applicantId / M槽 / issuer / owner / version / effectiveRange / submittedAt / validatedAt / fileDigest或权威记录ID / 原文位置 / supersedesId / 关联F`。缺失 `NM`、有来源但取不到 `SU`、可读失败 `UNREADABLE`、政策身份不明确 `PC`、只能有权认定 `NH`；`WAIT` 表示时间未到，**不算缺件**。

| M | 证明目的；持有人/签发人；材料类型/权威记录 | 必需阶段 | 合法替代、关联 F 与 SRC | 版本/归属；缺失或不可读 |

## 08 审核规则逐条清单

### 08.1 规则可执行层级与判定约定

- 以下 `R001–R038` 是**事实与证据核验规则**，其中必须取得校本细则或授权文件的前提记为 `P-LOCK`，未经校本配置核实**禁止输出政策意义上的资格合格/不合格，更不许自动批准**。`B` 表示现有校本事实可以验证；`G` 表示上位规范或独立通道边界；`D` 表示系统证据/权限设计控制，并非学校已发布的审批流程。每行列出的 SRC 是“支持的来源边界”，不是声称其包含具体系统状态机。
- 判定采用三值：`T`=本行触发命题被可信证据证实，`F`=有可信证据证实其不成立，`U`=事实未核/读不出/政策效力不明。**缺乏记录不能自动变成 F。** 行末的 `T/F/U` 分别给出唯一事实结果码及下一办理人；同一个 `R×target×sourceVersion×stage` 恰有一个主结果码，多个不同 R 可以并存。
- 核验窗口以 `F018` 的受理时点、`F027` 的费用学年、`F017` 的政策适用期、`F025` 的特殊身份效期、`F049` 的决定生效时点分别确定；**不得统一替换为“今天”**。L0 申请陈述、L1 原件、L2 主责部门核实、L3 有权决定严格按 05.2 节。
- `P-LOCK` 下的 `PASS_FACT` 仅限“该证据事实得到核实”，不包括“全部资格条件成立”。`NOT_APPLICABLE` 仅指本规则在此案不触发，不代表学生被官方拒绝。`SOURCE_UNAVAILABLE` 用于应有源但实际不可取得；`POLICY_UNCONFIRMED` 用于规则文本/版本/对象无从证实，两者可按不同 R 分别出现。

### 08.3 判定执行顺序、异常和阶段可达性

1. P0 先 R001/R007；P1 再 R002–R004/R010/R022–R024；P2 R005–R006；P3 R008–R014/R035；P4 R015–R021；P5 R022–R027；P6 R028–R029；P7 R030–R031；P8 R025/R032–R035。R036–R038 是跨阶段约束。**顺序是建议调度拓扑，不是已获校方授权的实际审批流程。**
2. R024 是逐 M 槽实例化的材料覆盖检查；其 `M001–M033` 是有限范围表示，不是全体 M 在 P1 都必需。是否触发须用 07.2/07.4 的阶段、角色和项目条件判定。`WAIT` 是内部时态，不属于八个外显结果码。
3. R004/R011/R012/R013/R023/R026/R029/R031/R034/R038 的 `U` 可能有几种不同成因：先按**具体失败对象**拆分为独立检查事件（材料不可读、来源断开、政策缺失、裁量未知各自独立），不得把一条规则同一检查实例输出两个码。三值状态在判定说明中保留原始 `truthValue`；结果码是对已选定失效成因的单值映射。
4. 某阶段政策 `P-LOCK` 仍未知时，只运行独立证据可得的事实规则，绝不生成“资格不符合”硬判断。L2 可核字段为真不会绕过 R028 的权限和 R029 的真实 L3。正式决定可能为批准、不予批准、退回等，**其 `decisionType` 只能来自真实 M027/M030，不由八个事实码推导**。
5. 有权部门确认政策版本后将确认证据写入 M032，再只解锁其确实支持的 R 条件。若来源依旧只有 SRC-003 历史新生说明、SRC-014 外校办事通知或 SRC-013 旧服兵役金额，则 R008/R009/R010/R021/R029 必须保持 `P-LOCK`。

### 09.2 证据层次、冲突归因、影响范围

1. 对同一事实先核“**同一人、同一项目、同一费用科目、同一学年/有效期、同一版本**”五维是否一致；任一维不同，先做归属澄清，不直接当作同源冲突。
2. L0 与 L2 相冲突：显示各自原文位置与日期，必须给当事人合理说明/主管部门复核的入口；L1 与 L2 相冲突：若 L1 是新的正式变更证明，由原 L2 责任部门核实更新。L3 历史决定只能由有权人正式更正/撤销，不能让 UI 新上传文件覆盖。
3. `SOURCE_UNAVAILABLE`（有权威来源但不可访问）、`UNREADABLE`（文件/影像无法取证）、`NEEDS_MATERIAL`（确有必需证据未提交）、`POLICY_UNCONFIRMED`（规范是否适用不明）、`CONFLICT`（两份可读证据不一致）、`NEEDS_HUMAN_DECISION`（裁量或权限未知）互不替代。

### 09.4 G50/S/T 决定复用的边界约束

2026-10-23 已取得 SRC-016 的 R02 原文及 SRC-015 冻结 G50 **顶层** JSON。已校验 R02 映射：`S03-T06` 困难认定、`S03-T07` 困难助学、`S03-T08` 贷款、`S03-T10` 应急救助、`S03-T12` 军人国家资助、`S03-T13` 缓缴与 `S07-T07` 就业补偿分别有不同决定对象。G50 顶层列 50 个技术 ID，不含与 `S03-T11` **同名/同 ID** 项，但仅凭技术 ID 不能证明某 G 工作区没有交叉材料或同一决定；其声明 `authoritativeSchoolTemplate=false`，且 G01–G08 8 个声明分片请求 404。故“**R02 明确邻项去重已核；G50 逐工作区语义去重未闭环**”，R038 在跨模板决定权限未验时仍 `P-LOCK`。

单向引用已有真实决定时必须验 `sourceTemplateId / authoritativeDecisionId / applicantId / issueScope / period / effectiveState / authority / version / evidenceUri`。同类材料可为多个事项提供证据，但每个事项的决定对象不同，不得“复用同一材料→自动复用批准”。如 G50 已提供某项学籍/费用事实，S03-T11 仅引用事实；服兵役资助已由 `S03-T12` 管辖，本模板绝不重复颁发相同国家专项决定。

## 10 结果状态、问题与待办输出契约

### 10.1 单个检查实例的八个互斥结果

| `resultCode` | 精确定义、何时使用 | 必须呈现的下一步；绝不能表示 |
| --- | --- | --- |
| `PASS_FACT` | 只表示当前版本某个**证据事实**、权限存在事实或正式原决定的真实性已被核实 | 展示已核事实及证据，不代表“资格通过”“学校批准”“到账” |
| `NOT_APPLICABLE` | 该 R 的触发条件经证据证明不成立，或申请明确属于另一授权业务 | 关闭该检查/正确路由；不得拿它作行政拒绝 |
| `NEEDS_MATERIAL` | 适用阶段、当期必需且合法可提交的具体 M 缺失或请求要素不足 | 指明 M 槽/原因/应提交者；未来才生成的材料不允许此码 |
| `CONFLICT` | 两个可读、有可比作用域的证据就同一实体/期间/事项给出冲突值，或显见跨案归属错误 | 两边证据位置并列；移交原数据主管，不能静默选一侧 |
| `UNREADABLE` | 有材料本体，但损坏、裁切、低分辨率、多页不清或无法定位待核字段 | 定位页/区域、请求重扫或人工阅读；不推断虚假 |
| `SOURCE_UNAVAILABLE` | 应存在的 L2/L3/原文源暂时无法访问，或没有可信系统连接与验真渠道 | 责任归学校/主管源持有人；不把系统失联记学生缺件 |
| `POLICY_UNCONFIRMED` | 是否有现行适用校规、批次、金额/窗口/流程、项目归属或追溯力无法确认 | 指出缺哪份 M004/M016/M032，交政策持有人；不能从历史/外校规则补齐 |
| `NEEDS_HUMAN_DECISION` | 需要行政裁量、例外决定、权限核查、正式批准/撤销/复核或人工争议解决 | 指定有权岗与待判对象，永不让 AI 代签、代驳回或代发款 |

**状态域隔离：** 上述八码属于 `FactCheck`。`WAIT` 是内部材料阶段状态，`NOT_RUN` 是规则尚未执行，不属于八码。另有 `Application.phase`（P0–P8）、`OfficialDecision.status`（**只能读真实 M027/M030**）、`FinanceExecution.status`（只能读 M028/M029）；三个域不得相互推导。即使 38 项事实检查均为 `PASS_FACT` 或 `NOT_APPLICABLE`，UI 仍只能显示“事实预审完成，等待校方有权决定”，不能显示“审核批准”。

### 10.2 每条规则输出及问题的最小结构（设计契约）

每个 `FactCheck` 至少：

`checkId / ruleId / caseId / applicantId / projectBatchId / stage / targetId / applicableTruth(T|F|U) / resultCode / observedAt / actorRef / policySourceId / policyVersion / policyEffectiveRange / sourceIds[] / fieldIds[] / evidenceRefs[{materialSlot,materialInstanceId,version,digest,issuer,owner,pageOrCell,fieldPath,validatedAt}] / finding / uncertaintyReason / supersededBy / affectedRuleIds[] / nextRole / nextAction / nextActionSource / reviewRunId|null`。

其中 `ruleId` 必须存在于 R001–R038；引用的 F/M/SRC 必须存在且匹配当前证据实例，不接受仅以文件名/姓名或模板名充当证据位置。`reviewRunId` 只有技术系统真实创建了符合 V3 约束的 Run 才可非空。任何从旧字符串拼出的 `run@rev` 不可冒充 Run。对于 policy unknown 的检查，可有 `policySourceId=null`，但要在 `uncertaintyReason` 写明正在请求的政策原件。

`Issue` 至少：`issueId / sourceCheckId / issueType / caseId / targetId / materialIdOrSource / relatedF[] / relatedM[] / originalEvidenceLocation / expectedOwner / raisedBy / raisedAt / status / dueAt|null / duePolicySource|null / resolutionMaterialVersion|null / resolvedBy|null / resolvedAt|null`。一件材料可因不同 F/R 形成多个问题；同一问题不应因 OCR 再跑而重复产生新待办（用 `caseId+ruleId+targetId+sourceVersion+issueType` 去重）。不能给没有真实政策的补件期限填默认 3/5/7 天。

`OfficialDecision` 是引用而非 AI 生成：`decisionId / sourceAgency / signatoryActor / authorizationEvidence / decisionType / beneficiary / projectBatch / tuitionPeriod / approvedAmountIfAny / effectiveAt / decisionDocumentRef / version / revokesOrAmends`。其发布、修改、撤销只允许校方授权流程，技术只持有可信来源指针和校验结果。

### 10.3 结果到责任待办的映射

| 触发结果/事件 | 下一角色与任务 | 系统可完成的动作 | 明确禁止 |
| --- | --- | --- | --- |
| `NEEDS_MATERIAL` | 当前合法材料持有人：学生/经授权代办，或**机构自身** | 列实际缺 M/字段、说明阶段和替代 | 把学校内部 M002/M005/M025 和未来 M027 作为学生必交 |
| `UNREADABLE` | 材料出具人、扫描/人工阅读岗 | 展示原图及不能读的坐标、请求新版本 | OCR 自信推断签发人或金额 |
| `SOURCE_UNAVAILABLE` | 学籍、资助、财务、原专项及档案源持有人 | 登记失联对象、尝试人工验真与后续恢复 | 归责学生“材料不齐”或认定不存在 |
| `CONFLICT` | 原事实主管部门/相关出证单位 | 双向呈证、冻结受影响结论、登记核正路径 | 无授权系统从两者任选写主账 |
| `POLICY_UNCONFIRMED` | 学校资助中心政策责任岗/专项发布机关 | 请求正式校规、当期公告、具体条款及生效证明 | 套用 SRC-003/009/014 的历史或外校门槛 |

| `PASS_FACT` / `NOT_APPLICABLE` | 下一事实检查/正确邻项，或事实汇总转人工 | 推进到下一可达阶段，保留来源和版本 | 视作已完成财务核销或救济结案 |

### 10.4 可见摘要不得合并成“通过/不通过”二值

- 按 `caseId` 聚合多个规则时，显示“事实核对：x 项已核 / y 项待材料 / z 项待政策或有权人”，并列原问题。不同错误码并列呈现，无隐含优先级覆盖；未知并非不符合。
- 如果当前没有真实 M027：官方决定显示 `尚无可信正式决定`，即使事实已核全；如果有 M027 而 M028 尚未出现：决定可显示按原文已作出，财务执行显示 `待核实/待执行`，绝不写“已退费”。
- 如申请撤回/复核，前台保留“请求已提交/待确认”与“原决定当前效力”两个独立标签；正式有效性只从原有或新的 L3 读。
- 身份、家庭、贷款、金融账号、医疗或优抚材料对非授权人员默认不展示原件；问题摘要仅展示最小必要信息，遵循 SRC-020。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 单案办理闭环（设计状态，不冒称成都理工大学校定流程）

| 事件 | 可变的工作状态 | 前置的可信事实/权限 | 保留不可覆盖的数据 |
| --- | --- | --- | --- |
| 申请或咨询 | P0→P1，必要时 C14 路由 | 学生诉求 M001、可信 F005；政策未核也可登记咨询 | 原请求原文、F018 收件时间，不能以 P1 表示学校正式受理 |
| 事实初核 | P1→P2/P3/P4 | R002–R024 适用切片；L2 无接口可人工验真 | 每条事实及未知独立记录，允许并行取得学籍/政策/财务 |
| 请求补件/补正 | P3/P4→P5，或 P5→P3/P4 | 只对确实适用的 M，依法有权通知者发 M019，申请方回 M020 | M019 原通知、M020 回执、原材料 M017 的版本；窗口不明不自造逾期 |
| 更换材料/纠错 | 任一事实阶段→受影响事实待重审 | 新 M018 与旧 M017 形成明确更正链、审查人验证 | 旧字节、OCR、核验结论不删除；`F052` 定位局部依赖 |
| 呈送校方决定 | 事实可陈列→P6（或保持待政策/裁量） | R027/R028 权限、当前 M032；有权人自行签 M027 | 前置学院/资助中心意见不得写成 M027；每次签批留授权证据 |
| 财务执行与通知 | 有真实 M027→P7 | 决定原文生效、财务授权、账务核查 R030/R031 | M028/M029 各自时间、金额、会计科目；账未出不冒称执行失败 |
| 提出撤回 | 申请前中后→P8 请求待确认 | M021 目标、可信本人/代理、原决定是否存在；R033 | 正式决定/账务不能因请求即删除；之后如发生有权撤销，另存决定 |
| 提出复核/异议 | 初审或正式决定后→P8 请求待确认 | M022 争点、目标 M023、真实时限与渠道另查；R034 | 原意见和生效决定继续作为有期限/效力的记录，不能自动覆盖 |
| 形成复核决定 | P8→复核结果存在/后续执行 | R028/R032+真正 M030，关联被复核 M023 | 原决定号、原效力、复核新效力与送达证据均保留 |
| 归档与下学年再申 | 已完成实际业务→归档/新申请版 | 档案责任人、保留期与访问授权待学校核定 | 案卷历史保留；新学年重新核政策与费用，不自动续期 |

**重要：** P0–P8 是研究用业务阶段，不是客户端状态枚举的现行实现证明；“受理、送达、生效、撤回、复核”各法律/校内意义要由学校真实规程填入配置。在无现行时限和审批权证据时，系统记录请求，不宣称产生程序性法律效果。

### 11.2 定向重审与旧结论有效性

1. `onMaterialChanged(newM,oldM)` 的前提是新旧均有独立材料 ID、哈希/权威记录版、受益人、学年/项目、变更原因与 `supersedesId`；相同文件名不够。先标失效的是**引用旧版本的 FactCheck 结果**，不是已经签发的学校决定。
2. 通过 `F052` 找出 `materialInstance/version → extracted F → affected R/target`；例如 M007 更正只重新评价 R005/R012/R013/R022/R024/R025 及其资格事实汇总；M005 财务变化重新核 R015–R021/R029–R031；M004 政策变动重新核 R001/R007–R014/R021/R027–R029/R035。其他未依赖检查保持原 `PASS_FACT` 与证据版本。
3. 若新增权威证据与旧原件矛盾且无法确认取代关系，则产生 `CONFLICT`，**不**按上传时间自动选较新照片。若旧 M027 的依据受影响，向原有权决定者提示“可能需要另行更正/撤销决定”；本模板不能在后台自动改状态。
4. 同一案件在撤回后再次提出申请，不沿用旧的“仍待审”状态；关联先前案卷，重新核受益人、项目批次与时间。学校是否允许原案恢复、另案或逾期补申未知，统一 `POLICY_UNCONFIRMED`→受理岗。

### 11.3 对权限及学校人类裁量的双重门禁

- AI 只生成事实问题/可追溯意见，不具有批准、驳回、签名、资金分配、销账、代理他人申诉之权。
- 欲写正式决定必须同时拥有：①可信 Main/Host 当次 Actor；②经学校确认项目/岗位/事项授权；③当前适用校本政策与额度依据；④真实签署流程和 M027；⑤审批的目标人、项目和费用期间与原事实对应。任一未知则保持 `NEEDS_HUMAN_DECISION` 或 `POLICY_UNCONFIRMED`，不落账。
- 对预算名额、特殊家庭实际需要、交叉财政项目、疑似虚假材料、有争议的时限例外等行政裁量，事实可列证据但**不提供机器作出的实质结论**。学校没有可验证的复核渠道时，仅提示联系归口，不能自创“5 个工作日内申诉”。

### 12.2 未知配置的默认行为

1. 不自行补齐任何金额、户籍条件、年龄/成绩门槛、名单名额、可领次数、申请窗口、补件天数、公示要求、审批层级或代理范围；留 `UNKNOWN` + 所需证据与学校确认责任人。
2. 普通减免的金额不存在经核当期标准时，只显示经财务核对的应缴、实缴和本人期望额，`F036` 继续 `WAIT`。历史脱贫户专项曾有“学费和生活费分项”，绝不把其某个部分挪作普通减免标准。
3. 研究生政策简介（SRC-017）仅直接支撑它列明的项目；研究生普通减免不能推定“有”或“无”。宜宾校区等身份同理，必须取得所申请项目当期对象条款。
4. 若某正式命名专项经济资助有独立的财政身份/决定权限/发放目的，首先报告目录归属冲突，而非用本 ID 绕过原专项审批。`CATALOG-CHANGE-REQUEST` 只有原始政策足以证明独立目的时才建议提交。
5. 数据交换遵守最小必要，已由学校掌握且可授权核验的身份/学费事实不要求申请人重复上传；无接口不等于可以伪造接口返回或直接拒绝。
