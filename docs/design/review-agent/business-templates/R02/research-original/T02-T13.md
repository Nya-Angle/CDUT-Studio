- **判断对象**：某名成都理工大学教职工或已退休教职工，在明确的办理情形、政策适用日期和人员身份下，退休时间事实、延退申请条件、返聘前置事实以及必经审核/决定材料是否有证据支持。**材料可核不等于应当批准，也不等于养老金已经核定。**

## 01 唯一审核目的、申请人和负责机构

### 01.1 本模板的决定对象及三类法律关系

| 办理类别 | 对象/触发（研究层） | 本模板可核的前置事实 | 不能由本模板作出的决定 |
| --- | --- | --- | --- |
| 到龄或弹性提前退休 | 达到经权威核定的退休时间，或本人依法选择弹性提前退休的在岗人员 | 学校认定的出生年月、岗位/人员类别、适用法规时点、告知及受理状态、养老保险经办所需材料的归属 | 法定退休时间的最终人事认定、批准退休、养老金核发或社保待遇核定 |
| 退休前延退 | 申请特殊高级专家延退、依法协商弹性延迟退休等仍在岗人员 | 本人意思表示、岗位和任务、单位审查、是否取得有权人事批准以及公示/备案的阶段性事实 | 自动同意延退、代替学校党委常委会或按干部管理权限作出的批准；将 2018 年条件误认为全部在岗人员的条件 |
| 退休后返聘 | **已经办妥退休**且拟因工作需要继续提供服务者 | 正式退休事实、拟聘任务、用人单位需求、返聘拟议或审批文件有无、后续协议签订事实 | 将返聘等同于延续原人事关系、替代单位签署协议、批准岗位/经费或认定具体劳务法律责任 |

其中，弹性延迟退休期间原劳动/人事关系继续存在，是现行国家《实施弹性退休制度暂行办法》第五条明确的制度事实（SRC-007）；已经退休后返聘则属于**另一个阶段的聘用安排**。退休登记 `F036` 与依法开始享受养老金或领取退休金 `F047` 是两个不同事实；不得将“达到年龄”“已办理退休”“已领取养老金”三者互相替代。特别是最高法《劳动争议解释（二）》自 2025-09-01 废止《解释（一）》第三十二条第一款（SRC-014），故**不能再援引已废条款声称所有返聘一律是劳务关系**。拟议协议与具体用工争议的法律关系、争议救济和报酬、保险安排均由有权人事/法务结合当期法律及个案事实确认（F048/R042–R043），不是 AI 审批输出。

### 01.2 申请主体和机构

1. **本人**：校本 2018 高级专家延退由符合对象的教师本人提出申请并签署校本审批表；其余退休选择与返聘能否由单位发起、是否可代理、授权委托形式，目前无已核校本统一规则（SRC-001 第五条、附表；SRC-007 第一至四条）。
2. **所在教学科研单位**：对 2018 高级专家延退作事实审查，经党政联席会或实验室主任办公会集体研究后报人事处；是否有岗位空缺和工作需要属于单位形成的组织事实（SRC-001 第三、五条）。非高级专家、行政/管理岗位与返聘场景的权限尚未证实。
3. **党委教师工作部（人事处、教师发展中心）**：2018 办法指定人事处审核延退材料及基本条件，提请校党委常委会审定，并对公示、上报四川省教育厅备案承接相应程序；现人事处官网列人事科、师资科、薪酬社保科等联系渠道，但**不据此自行分派审批权限**（SRC-001 第五、十一条；SRC-003）。2025–2026 校方公开的人才项目申报表述能够区分弹性延迟退休与另经批准延长退休年龄（SRC-013、SRC-018），但仍不能确认后者的当期审批表、签发链或效力。
4. **学校党委常委会 / 学校有权机关**：2018 具体高级专家延退走校党委常委会审定，公示无异议后由学校批准；如新国家政策或新校规改变该流程，应依现行有效文件及干部人事管理权限更新（SRC-001 第五条；SRC-007 第十三条）。
5. **四川省教育厅**：2018 延退文本是“上报备案”，不能将备案错误转成审批，也不能推断 2026 所有情形都走同一备案渠道（SRC-001 第五条）。
6. **离退休工作处**：公开科室职责显示其参与执行离退休管理及日常服务、证件办理等，不能据此把其视作退休资格或返聘批准者（SRC-005）。
7. **社会保险经办机构**：依法审核基本养老金领取申请，养老金发放资格不是校内人事审定结果的同义词（SRC-007 第八、九条）。

### 01.3 持续适用的审核限定

本模板是一套**资格事实和证据完整性预审**，输出疑点、缺件、政策版本冲突与待有权人处理事项。任何年龄/性别/岗位身份、年度绩效、职称层级、资金安排的判断，都要注明来源和校本适用性；不得仅依据申请表自填值作正式结论。

## 03 业务生命周期与办理情形矩阵

### 03.1 阶段、分支与时点

统一状态轴用于标识证据**应在何时存在**，不代表学校已上线统一审批平台：`P0 预核身份与适用政策 → P1 本人选择/申请或单位提出需求 → P2 单位核验/集体研究（仅适用分支） → P3 人事/干部权限审核 → P4 有权决定 → P5 公示异议/备案（仅适用分支） → P6 办理退休、社保申请或签署返聘协议 → P7 履行、归档、续期/退出/复核`。状态可跳过不适用节点，也可补件后回到原节点。每次变更记录 `F001/F003/F043`；真正生效的决定必须是另有来源的事件。

- 2018 校本高级专家特殊延退的原文路径是 `P1 本人申请 → P2 单位集体研究 → P3 人事处审核 → P4 校党委常委会审定 → P5 公示 → 学校批准/省厅备案`，具体先后依 SRC-001 第五条。**这不是 2026 所有延退情形通用的强制路径**。
- 人社部发〔2024〕94号：弹性提前退休由本人至少提前 3 个月书面告知；弹性延迟退休应由单位与职工协商一致并提前 1 个月书面明确；机关和国有企事业单位工作人员还需依干部人事管理权限报批；法定到龄者单位及时办理退休（SRC-007 第二、三、四、十三条）。上述时点在适用该国家规范且人员类别已核后使用，不能套到退休后返聘。
- 2018 校本高级专家文本规定首次/再延退原则上到龄或上一延退期满前 3 个月申请，原文并有岗位、考核、职级、每次延退期限等条件（SRC-001 第三至五条）；2025 年后适用性未核，**仅保留历史候选节点，不自动判迟报、超龄或不合格**。
- 公示后产生的异议处理、正式批准、备案凭证，养老保险受理/待遇审核、退休完成记录、返聘协议分别在其真实发生的 `P4–P7` 核验；一律**不是 P1 初次申请的材料**。

### 03.3 退回/补件/撤回/复核操作约束

1. **P0/P1**：身份或政策数据失联给 `SOURCE_UNAVAILABLE`，不是逼本人传完整人事档案。受理期本人申请签字或必交告知缺失才进入 `NEEDS_MATERIAL`；材料不可辨认则 `UNREADABLE`，保留上传版本。
2. **P2/P3**：单位会议、人事审核属于**相关负责人随后形成**的材料；审到对应阶段才提示承办部门办理，不向申请人索取尚不存在的 `M014/M015`。
3. **P4/P5**：决定、公示、异议、批准/备案分别有独立来源。2018 校本表格的“学校审批意见”栏在 P1 为空是正常状态（SRC-001 附表），不得视为初始材料不完整。
4. **P6/P7**：普通退休、养老金经办、返聘签约有不同主体。合同或养老金回执晚于申请是正常时序；旧结论仅在同一人员、同一情形、同一材料版本且仍有效时可引用。
5. **权利救济**：C08 保留“提出申请—受理确认—复查—结果通知”的研究状态，但成都理工大学统一撤回/复核窗口与期限**尚未核实**。只有有权人员明确受理后才能记录正式处理事件。

### 05.1 角色/动作最小矩阵

### 05.2 可信链与事件约束

1. **身份**：真实申请人、代理人及审批人的 `actor` 应由可信认证和服务端权限判定形成，不接受 Renderer/UI 自报的 `userId`、`role`、`teacher` 字段作为批准依据；不得从电子签名字样 OCR 结果判断签署人拥有审批权。
2. **材料归属**：每份证据必须关联 `caseId + personAuthorityId + scenario + sourceVersion + issuingUnit + observedAt` 的研究字段；身份证号、出生年月、职称、岗位不能仅靠申请书互相验证，优先引用学校有权登记数据；敏感身份证明、健康/社保数据限最小必要访问。
3. **授权决定**：区分 `本人意愿 → 单位意见 → 人事核验 → 集体审定 → 公示处理 → 学校批准 → 省厅备案/社保经办`，各自需独立时戳与原始证据。缺少最终批准只输出待办，不产生虚构 `approved=true`。
4. **政策版本**：按人员身份、到龄年月、申请/审批时点绑定有权发布的法规范畴；2018 条款与 2025 新规冲突时禁止“择一自动裁决”，交人事处与学校法务/干部人事权限方解释。
5. **复审与变更**：换页、重传、修改工作期限、替换单位意见、改变身份或任务、续期，都应标记影响字段与关联旧结果失效范围，只复核受影响事实但**不沿用失效批准**。
6. **失败与不可判定**：原件不可读为 `UNREADABLE`；应有证据未提交为 `NEEDS_MATERIAL`；真实证据互相矛盾为 `CONFLICT`；权威数据不可访问为 `SOURCE_UNAVAILABLE`；现行校规未核为 `POLICY_UNCONFIRMED`；法律/政策裁量、身份类型和有权决定为 `NEEDS_HUMAN_DECISION`。

### 05.3 高影响门禁

- **永不自动作出**：退休时间正式核定、年龄例外/高级专家认定、干部身份适用、岗位/编制可用性、延退/返聘批准、公示异议处理、养老金领取资格与待遇、返聘协议生效。
- **可自动辅助**：材料存在、页码/签名/印章是否可见、表内时间自洽、任职证明和单位意见之间的字段差异提示；这些只是在`证据描述层`形成可复查的提示。
- **审批事件真实性**：人事权威系统的已核记录或原始有权审批文书是来源；离线审核包或客户端缓存不能创造 Run/审批事实。若不具备可信数据接入，写明“待人工核真”，不得将本案的 AI 预审伪装成学校最终批准。

### 05.4 主从证据、签发权限与复用门禁（ROUND2）

## 06 业务对象与字段字典

### 06.1 对象、类型与缺失语义

- `Case` 案卷/情形/阶段；`Person` 人事身份；`Retirement` 退休时间选择与办理；`Expert` 专家延退条件；`Decision` 单位/学校/干部有权决定；`Rehire` 返聘需求与协议；`Evidence` 材料版本与救济事件。所有字段均为**拟议业务模型**，不是已证明存在的校方数据库列。
- 可信源写作 `校方人事/组织人事`、`院系有权单位`、`国家制度`、`社保经办`、`当事人签署`、`正式批件`，均需与 07 节 M 槽及 SRC 对照；没有接口时从人事处授权核对的原始记录提取，并非要求本人上传全部内部记录。
- 隐私级别：`I` 内部（一般业务）；`S` 敏感个人信息（身份、出生年月、社保等）；`H` 高敏（健康、干部权限、异议内容）；`P` 可公开的已正式公布内容。仅最小必要采集，健康情况优先只收“能否履岗”有权结论。
- 缺失编码：`U` 应来自权威部门却不可访问→`SOURCE_UNAVAILABLE`；`D` 当阶段由相应提交者应提供而未交→`NEEDS_MATERIAL`；`P?` 当期校本规则未知→`POLICY_UNCONFIRMED`；`H?` 需有权裁量/身份确认→`NEEDS_HUMAN_DECISION`；`L` 尚未到形成阶段→记录“未到期”，**不**判缺；`NA` 不适用→`NOT_APPLICABLE`。OCR 不能读始终先标 `UNREADABLE`，不等同于缺失。
- 表中“位置”以 `Mnnn:字段/页` 指向证据槽；所有 OCR 派生字段还须保存具体文件版本、页码/区域，不得仅留文本值。`P0–P7` 为 03 节阶段。

### 06.3 一致性与计算禁止项

- **不使用自填性别直接计算退休年龄**。`F009` 干部/岗位类别、`F010` 权威出生年月、`F011` 有权核定退休年月与 `F004` 适用政策版本必须成组可追溯；人社部计算器可作辅助核对，不能直接写 `F011`。
- `F018` 是现聘岗位等级，不是 `F017` 的职称等级；`F023` 项目未完、`F024` 学生在培也不等同于获得延退权。2018 第三条有“必要条件至少一种”的结构，但是否在 2026 适用待核。
- `F034/F035` 在 P1 必须处于“尚未发生/不适用”，不能标作用户漏交。`F037` 养老金审核不是 `F033/F040` 的校内人事/返聘决定。新增 `F047` 记录是否实际依法享受养老金/退休金，不得从 `F036` 自动派生；`F048` 只允许从有权法律审查得到，不能从“返聘协议”四字派生。

## 07 材料槽与证据目的

### 07.1 统一槽位规则

- `C` 当前阶段必需；`K` 触发条件成立才必需；`L` 后续阶段产生。表中同时列情形和阶段，例如 `C C02/P1` 表示仅 C02 到 P1 时应有；不是所有案件一开始都要求。
- 持有人是**最初出具或权威维护者**，不是必然上传者。人事档案、岗位、社保和会议决议由有权限主体调取或出具核验结果；未有接口或共享授权时，登记核验任务并标 `SOURCE_UNAVAILABLE`，不得令本人承担不合理的系统数据抄传义务。
- **版本/归属**列中，`人` = 人员权威 ID + 案卷 + 情形；`单` = 单位 ID + 人员 + 案卷；`校` = 学校签发机构 + 人员 + 案卷；`政` = 外部发文/经办机构 + 人员 + 案卷；`案` = 案卷事件序列。各槽必须保留来源版本/签发时点/哈希或官方记录号/有效期；同一 PDF 可映射多个槽但只保存一份物理副本。
- 缺失语义：`D` 现阶段应提交→`NEEDS_MATERIAL`；`U` 有权来源不可访问→`SOURCE_UNAVAILABLE`；`L` 未到产生节点，不计缺件；`P?` 校本是否要求待定→`POLICY_UNCONFIRMED`；`H?` 有权裁量/真伪审核→`NEEDS_HUMAN_DECISION`；`X` 已有件不可读→`UNREADABLE`。表中 `D/X` 的 X 仅在实际上传且无法读取时触发；权威记录访问失败为 U，不是 X。
- **合法替代**只能是同一证明目的的有权来源。如官方接口无法取得，可由主管处室盖章核验结论代替原始多页人事档案；申请人截图不能替代组织人事确认、会议决定、社保核定或学校正式批准。

## 08 审核规则逐条清单

### 08.1 规则解释与不可越权门禁

下列为**候选证据核验规则**，不是成都理工大学现行退休审批清单。每条只形成一个可追溯事实或“需核”输出，不作通过/驳回资格的行政裁决。执行顺序：先 `R001–R005` 确认人员、情形、政策与时点，再进入对应情形的规则，最后处理权限、外部结果及复审。第四轮补 `R040–R043`，只覆盖明确漏项，不为凑规则数扩张领域。

- **三值触发**：`T` = 该案、该阶段、该身份/政策下适用；`F` = 经可信事实确定不适用；`U` = 情形、身份、当前校本政策或触发权限未能确定。以下各行分别写明 `T/F/U`。如已确定在未来 P 节点才产生，当前阶段暂输出 `NOT_APPLICABLE`（准确含义为“本次评估未触发”，须留待未来重评），不形成缺件问题。
- **统一证据异常优先**：已提交但无法阅读为 `UNREADABLE`（联系出具者补可核件）；权威记录暂不能取得为 `SOURCE_UNAVAILABLE`（发内部调取待办）；当阶段明确应由申请人/单位交而未交为 `NEEDS_MATERIAL`；现行规范与适用条件不能证实为 `POLICY_UNCONFIRMED`；两个已验证来源在主体、时间或实体内容上冲突为 `CONFLICT`；实际资格例外、自由裁量、签发权限或尚待正式决定为 `NEEDS_HUMAN_DECISION`。这些异常先于行内“事实满足”的 `PASS_FACT`；OCR 自信度不足不能补造事实。
- **行内简写**：`T:通过` = 触发且可信证据满足可验证比较后 `PASS_FACT`；`T:异` = 触发但有异常时遵上述准确代码，而不是通用“失败”；`F:NA` = `NOT_APPLICABLE`；`U:P` = `POLICY_UNCONFIRMED`，`U:H` = `NEEDS_HUMAN_DECISION`，`U:S` = `SOURCE_UNAVAILABLE`。涉及是否符合旧校规实质条件的行，即使材料事实已证，**资格阈值结论仍为 P**。最后一列是下一办理责任角色，绝非系统自动委派的实名审批人。
- **比较基准**：人事/组织干部现行核定及原始发文机关 > 该事实主管部门的签发记录 > 经过单位核真的申请材料 > 非权威扫描、截图/OCR。从 `M035` 取案卷、人员、具体来源版本和审查时点；从 `M036` 取政策来源、效力区间、例外配置；任何来源变更都不得悄悄更改学校已经正式作出的决定。

### 08.3 准入结论的防误判

1. `R007/R008/R010` 的国家书面时限、最多三年、不得重复延长，**仅在 R004/005 已核政策适用及身份**后作事实对比。违反不能被 AI 直接输出“批准驳回”；由有权人事部门处理，待核路径及例外标 `NEEDS_HUMAN_DECISION`。
2. `R012–R027` 使用 SRC-001 时分层：文书结构、机构名称和 2018 流程是**可证历史事实**；其资格阈值、年龄上限、考核年限、岗位空额、公示期、备案要求在 2026 **尚不能硬判**。如果当前适用性是 U，规则的门槛判断返回 `POLICY_UNCONFIRMED`，不因某个 F 的实物可核而升级为“符合延退条件”。
3. `R030–R035` 的返聘校本流程没有有效官方全文。退休状态、本人意愿和协议是否真实可预审，**返聘资格本身、批准主体、经费条件和协议法律关系**始终为待政策确认或人工决定。
4. 所有 R 的 `PASS_FACT` 是“这项事实依某版证据核验成立”；学校有效决定只来自单独的**有权签发事件**，即使 R026/R033 判实物批准文书存在，也只是核真已产生的决定，不允许本系统新建、重签或撤销。
5. `R040` 纠正第三轮遗漏的 C03 缴费年限独立核查；`R042/R043` 分开“待遇状态事实”和“法律关系有权审查”。**司法解释 2025 年废止旧条是新法断代，不意味着所有返聘关系反向自动成立劳动关系**；争议处理仅供有权法务/仲裁/司法主体判断（SRC-014/015）。`R041` 是数据访问合法性门禁，不是让模型索要更多健康资料。

| G50/S/T 旧结果仅见“通过”字样但无决定 ID/版本 | F044；M035/M036 | `SOURCE_UNAVAILABLE/NEEDS_HUMAN_DECISION`；不将历史 run@rev 当真实决定 | 外部原授权业务 Owner |
| 已办退休 M021，但未取得实际养老金享受状态 M037，有人援引旧最高法解释第32条“一律劳务” | F036,F047,F048；M021,M025,M037,M038 | R030 仅证退休事实；R042 `SOURCE_UNAVAILABLE`，R043 `NEEDS_HUMAN_DECISION/POLICY_UNCONFIRMED`；**SRC-014 第21条已废旧引用** | 人事薪酬社保、学校有权法务/合同签约方 |
| C03 最低缴费年限误按预计延迟退休年份而非本人法定到龄年份取值 | F011,F012,F016；M003/M005/M019 | R040 重新绑定 SRC-007 第7条的对应年份，`CONFLICT` 或 `POLICY_UNCONFIRMED`；不得用多缴几年推自动符合 | 人事薪酬社保与社保经办 |
| 同一人员健康/医疗原件被无授权导出到案外或公开分享 | F025,F047；M012/M037/M035 | R041 拦截越权操作并保留最小审计；只发合法性复核待办，不展示敏感原文 | 人事数据持有人/合规授权人 |

### 09.3 材料/字段层反例与重审范围

1. **“六十周岁即退休”反例**：同一生日的两个人，M002 所属干部/女性高级专业人员身份不同，M003 却被客户端统一算作同一退休年月。`F009/F011` 冲突，必须询问有权人事部门并核 SRC-009；当前 `POLICY_UNCONFIRMED`。
2. **“新申请必须先有学校签章”反例**：高级专家 P1 只填写 M006 附表的申请人部分，人事处/学校栏尚空。此时 `F029` 可核，但 `M014–M018/M033/M031` 尚非当期材料，不能标为五项缺件。
3. **“有导师资格就应延退”反例**：M011 可证尚有在培研究生，但 M007 的现聘岗位与 SRC-001 旧对象不符，或 2018 现行性未核。`F024=事实可证` 不推出 `F033=学校批准`，只产 `NEEDS_HUMAN_DECISION`。
4. **“已退休+单位欢迎返校=返聘成功”反例**：M021 退休事实有效，M022 拟聘需求有效，但 M024 批件和 M025 双方协议尚无；`F036/F038=PASS_FACT` 并不构成 `F040/F041`。
5. **“附件页替换继续沿用旧通过”反例**：M006 第 2 页被替换后拟申请任务改变，原 F026 与单位 M014 对应旧版；将旧 M014 标为关联失配，重审 F026/F030。其他不受影响的身份事实可保留。
6. **“课程任教与返聘同一授权”反例**：M025 返聘协议只约定科研服务，外部 T06 授课资格结果尚未核。不得因返聘在校即自动安排授课，也不能将 G05 外事授权推为已取得。
7. **“材料失联=造假”反例**：M019 社保系统暂时不可访问→`SOURCE_UNAVAILABLE`；M004 应由本人提交却没有→`NEEDS_MATERIAL`；M006 扫描件模糊→`UNREADABLE`；校规缺失→`POLICY_UNCONFIRMED`。四者待办对象完全不同。
8. **“弹性延退期再加一年”反例**：C03 已确定延迟退休时间后有人提交 C05 续期表，不能以 2018 可再次延退条款直接放行，需有权机关判断是否为不同合法机制且可否转换。

## 10 结果状态、问题与待办输出契约

### 10.1 八种互斥的单规则结果

每个 `(caseId,ruleId,targetId,planId,evidenceFingerprint,evaluatedAt)` 评估仅输出**一个** code；同一案卷同时可有多条不同 R 的结果。发生换版，旧项被标为历史/失效但不删除；新的 `evaluationId` 不覆盖旧决定。**所有代码都不是 `schoolApproved`。**

| code | 精确定义 | 典型场景 | 下一动作与责任 |
| --- | --- | --- | --- |
| `PASS_FACT` | 在当前适用范围内，仅有可核证据证明特定事实成立 | 真实 M021 证明已退休、M005 双方书面协商存在 | 记录来源、时间、版本；进入下一个**应办理**节点，不隐含最终批准 |
| `NOT_APPLICABLE` | 当前情形/阶段已证不触发；也用于后续才应形成的节点，在本次评估跳过并注明重评触发点 | C04/P1 尚无公示 M018 | 不发缺件待办；保存“到 P5 时重评” |
| `NEEDS_MATERIAL` | 当前已到提交阶段，依法或经校规确认的材料由对应提供者应提交而尚未提交 | C02/P1 未交本人 M004 | 对本人或单位发补交请求；不能向申请人索内部会议文件 |
| `CONFLICT` | 已可读且可信的来源在人员/批次/时点/内容上实质不一致 | M001 人事 ID 与 M006 人员不同；在岗却声称已退休 | 冻结该冲突依赖 R；人事/原签发主体核正 |
| `UNREADABLE` | 已取得材料但关键页损坏、OCR无法可靠读取、核真无法完成 | M006 第2页模糊 | 由材料持有人提供清晰可核版本，保留旧版 |
| `SOURCE_UNAVAILABLE` | 应查的权威系统/机关当前未能取得记录，而非用户未上传 | M019 社保受限、M001 人事系统不可访问 | 派内部调取，记录故障与重试；不得认定无资格 |
| `POLICY_UNCONFIRMED` | 当前适用的规则、有效期、阈值、授权链或例外没有合格现行来源 | 2018 专家旧上限是否沿用2026，返聘专规未取得 | 人事政策/学校有权部门确认；不能自动放行/驳回 |
| `NEEDS_HUMAN_DECISION` | 证据可核但涉及真实审批、自由裁量、有权身份纠正或正式复核 | 单位会议待决定、干部报批、返聘准许或撤回复议 | 派给经可信授权的相应机关；AI 不模拟签发 |

处理顺序不是“一个全局错误覆盖所有规则”：先判触发/阶段，再分别检查**适用政策**、**权威访问**、**材料存在/可读**、**实体冲突**、**事实符合性/真实裁量**。若同一 R 有多个并存障碍，选当前阻断核验的一个 code 并在 `secondaryIssues` 保留其他问题；政策未知的准入资格不得被较低层的材料完整性掩盖。允许多次评估但不允许默默变更旧 code。

### 10.2 机器可读、可供人工核验的问题条目（拟议契约）

每条输出至少包含：

```text
caseId, evaluationId, planId, scenarioId, phase, ruleId, targetId,
triggerValue(T|F|U), resultCode(one-of-8), policyRefs(SRC-ID+effectiveRange),
fieldRefs(F-ID+observedValue+authority), evidenceRefs(M-ID+sourceVersion+
issuer+pageOrRecordLocator+personAuthorityId+checksum+capturedAt),
ruleEvaluationTime, cause, secondaryIssues, requiredAction,
nextRole, dueStage, dueDateSource, visibility, isCurrent, supersedesEvaluationId
```

- `requiredAction` 是“申请人补本应提供件/单位核证/人事核定/干部审批/科研权威核实/返聘授权签发/社保经办/政策解释/原审批机关复核”等**动作类型**；`nextRole` 来自可信权限表，不能让 Renderer 提交实名审批人的 role。缺校本期限则 `dueDateSource=null` 和 `dueDate=unknown`，不捏造倒计时。
- 对每个问题必须能从 `ruleId → F → M具体版本/页/原始权威记录 → SRC/条 → targetPerson/decisionId` 回溯。匿名化界面只显示必要信息，身份证明/社保、健康、组织干部资料限制访问；外部结果只保存决定 ID 与出处、有效状态，不无差别复制隐私原件。
- **定向输出样例（合成，非真实案）**：`{caseId:"SYN-RET-01",ruleId:"R040",targetId:"person/SYN-01/benefit-year",phase:"P1",resultCode:"CONFLICT",fieldRefs:["F011@v2","F012@v1"],evidenceRefs:["M003@v2","M019@v1"],policyRefs:["SRC-007#7"],nextRole:"薪酬社保科有权经办"}`；不能合并成“社保材料不合格”。另一条 `R043` 即使 `R034=PASS_FACT` 也应单独挂起校方批准/法律关系核定。
- `problemStatus` 可为 `OPEN / WAITING_SOURCE / WAITING_OWNER / RESOLVED_BY_NEW_EVIDENCE / SUPERSEDED / CLOSED_BY_AUTHORITY`，是工作待办状态，不是第九种规则结果。

### 10.3 汇总、正式决定与 UI 用语

- 汇总为**事实预审报告**：逐 R code、当前缺口数、待政策核定项、待有权处理项、可信外部决定引用状态；不输出自动“合格/不合格”字样。全部 `PASS_FACT/NOT_APPLICABLE` 只意味着“本次可核事实未见阻断”，**绝不是**退休/延退/返聘被批准。
- 真正学校批准独立记录：`decisionId, decisionObject, issuingAuthority, authorizedActor, decisionDate, effectiveDate, applicableTerm, sourceDocument, verificationMethod, currentLegalStatus, reviewOrRevocationRef`。必须由案外的正式有权机关形成；审核系统只可信引用并验证签发事实（R026/R033）。公示和备案、社保核定、协议签订分别有自身状态，不同意互相覆盖。
- 禁止将旧 `run@rev`、OCR“学校意见：同意”、待办“完结”、院系材料“审核通过”写成真实 `ReviewRun`、`Decision` 或批准。当前 V3 只有具有可信 Case/Run/Decision 所有权的后台可产生其技术事件；无对应数据与权限时输出“待人事机关确认”。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 一条案卷内的状态机（研究模型，非已核校方流程）

`P0核身份政策 → P1申请/选择/拟聘 → P2单位意见(若适用) → P3人事/干部复核 → P4有权审定 → P5公示/备案(若适用) → P6退休/社保或返聘签约 → P7履行与复核`。可带 `WAITING_MATERIAL`、`WAITING_SOURCE`、`WAITING_POLICY`、`WAITING_HUMAN` 暂停标记而**不移动到虚构的审批阶段**。C08 作为原案事件；C05 再延退与 C07 返聘续期创建新**期次/尝试**而非新的 R02 模板，旧历史保持可追索。

| 事件 | 前置、允许者与最小证据 | 状态变迁、有效性处理 |
| --- | --- | --- |
| 补件/新版本 | 当前 `NEEDS_MATERIAL` 或 `UNREADABLE`；该 M 原持有人/受理人提供有效新版，R001/R002/R036；M035 保存 `supersedes` | 同阶段待办重新开启对应 R，旧版本标历史，**只重算依赖 R**；不能回填先前学校签章 |
| 内部权威补核 | `SOURCE_UNAVAILABLE`；人事、社保、科研或原权威签发者提供认证结果 | 核源和比对时间后定向重审，人员基础字段改变时向下游依赖传播；不用让申请人重复上传 |
| 撤回请求 | 当前请求人/授权代理有可信身份及 M027，先核学校是否允许当阶段撤回；受理者必须有真实权限 | **请求已提交≠撤回生效**。正式决定前是否终止受理、是否撤销已形成的意见依校本政策；已生效学校批准、退休登记、协议不得由模型直接删除。结果经有权机关记录到 M028/M035 |
| 弹性延迟提前终止 | C03 本人与单位依法协商，SRC-007 第6条；M005 新书面安排及本人意愿 | 只能记录新协议和权威处理，不等同于专家再次延退，也不等同自动退休 |
| 公示异议/复核 | C04/05 已到公示时，可按 SRC-001 第5条研究异议；其他案需确认受理渠道、期限与申诉主体；M027 → 有权调查/正式 M028 | 有争议的依赖事实挂起，维持已签发决定历史；只有原有权机关/依法授权复核机构决定变更效力，系统生成待办与回执引用 |
| 重新申请/再次延退/返聘续期 | 先确认旧案撤回/终结的权威状态、原有有效决定或合同；本人及单位发起新期次 | 同一 Case 对象或依法要求的新案件编号由真实办事规则决定，但保留 `priorDecisionId`、`newAttemptId` 与证据主从；不直接复用旧申请人意愿、审批意见或批件 |
| 学校人工决定 | R004 身份政策与有权机关已核，所需前置步骤届期完成；学校独立正式文书/决议及认证 Actor | 仅凭原始文书引用决定的“批准/不批准/撤回批准/复核维持”等真实状态，具体法定效力与送达时间依文书；案卷事实代码不替代它 |
| 退休、养老金及返聘执行 | 退休手续 M021、养老金结果 M032、返聘协议 M025 各由不同法定/校本主体形成 | 三条结果单独登记，不能因为退休完成自动养老金已核定，也不能因为单位拟聘自动建立返聘关系 |
| 退休后返聘关系法律审查 | 实际已退休 M021，依争议需要核待遇状态 M037；拟签协议 M025 的特定版本与法律审查 M038；适用 SRC-014/015 | `R042` 只核养老金享受事实；`R043` 只核有权法律审查/签约主体。旧司法解释废止后不能自动标“劳务”或“劳动”已确定；有权合同签发/争议机构独立处理 |

### 11.2 版本失效依赖与最小重审

构建只读依赖 `M(sourceVersion) → F(observedFact) → R(result/evaluationId) → caseIssue`，并把曾引用该组事实的有权决定记为**需机关复核的外部引用**，而非自动重签。触发范围：

- `M001/M002/M003/M036` 人员类别、身份、生日或政策更新：重算 R002–R012 中确实依赖该字段的规则、专家是否适用 R012/R019、返聘法律关系 R030；此前正式决定仅显示“依据改变待复核”。
- `M006–M012/M029/M030` 专家申请、职称聘岗、任务与干部职务更新：重算 R012–R021；若 M014 单位会议明确引用旧申请工作任务，再加 R022；不重算无关养老金或返聘协议。
- `M014–M018/M031/M033` 审批意见、公示、批件、备案改变：分别重算 R022–R027；影响签发决定时通知原有权机关，**保持旧批件真实存在的历史**。
- `M019/M020/M021/M032` 社保、退休办理：仅重算 R005/R006/R028/R029/R030 等有具体依赖的项；不是每次缴费记录更新就重跑全部专家证据。
- `M022–M026` 返聘拟议、预算、决定、协议、变更：仅 R031–R035 及必要的 R030；新协议签署不修改原退休年月。
- `M037` 待遇状态/证明变更：只重审 F047/R042、受其版本约束的 R043；不能倒推 F036 退休状态。`M038` 法务审查变更：只重审 F048/R043 及其关联协议 R034/R035。`M019` 变化时区分 C02 的 R006 与 C03 的 R040，别把两种最低缴费年限适用年份混用。
- 任一高敏数据访问事件变更时仅评该 `accessEventId` 的 R041；无合法授权时阻止实际调取和导出。**研究稿不接收真实人事/社保病历，部署需合法处理依据与校方权限配置**。
- `M027/M028/M034/M035` 请求、复核、代理、归档变更：仅 R001/R036/R038/R039 以及其决议所明确涉及的事实 R；无需全案大面积重算。

**判定原则**：受影响 R 失效后，历史 `PASS_FACT` 不再是“当前事实”；未受影响 R 的证据指纹不变即可保留。本设计尚未宣称 V3 客户端已实现定向重审、学校审批撤销或用户自助复核功能。

### 11.3 受理权限及边界

个人/代理仅能提出请求或上传其有权提交的材料；院系仅能发本单位意见；人事、组织干部、学校正式审批、社保经办及双方协议签约各有独立权限，不跨层代签。撤回窗口、申诉期间、是否可重新受理、正式决定何时生效、批准后如何撤销或变更，未获成都理工大学当前原始制度支持时统一移入 `POLICY_UNCONFIRMED/NEEDS_HUMAN_DECISION`，**不模拟办结**。
