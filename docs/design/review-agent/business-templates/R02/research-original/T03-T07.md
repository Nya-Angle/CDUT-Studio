## 01 唯一审核目的、申请人和负责机构

### 01.1 确定决定对象

本模板的**审查对象是“结题/结项/验收及项目科研绩效材料所支持的事实和程序准备状态”**，不是“项目自动通过验收”。审查单位以 `project_id + 批次/计划/合同版本 + 申请环节` 识别一宗申请，并区分：

- **结题/结项申请阶段**：核对项目身份和负责人、获准期限及变更、实际完成内容、成果及佐证与约定指标是否可对应、申报材料是否符合本项目类别/当期通知；只形成材料待办和事实核验结果。
- **组织评审/综合绩效评价阶段**：核对专家评审或校内管理机构产生的记录是否存在且对应本项目，**不代专家评分，也不预置全校通用合格阈值**。国家重点（重大）项目的综合绩效自评及验收时序见 SRC-001 第三十～三十三条。
- **正式结题/验收结果阶段**：仅引用资助方、主管部门、委托方或校内获授权组织作出的正式结论及版本，不凭材料齐全生成“已通过”或结题证书。成都市社科规划项目有“线下结项后再线上结项”的反向材料依赖（SRC-008）。
- **科研绩效材料关联阶段**：核验任务/成果事实与绩效目标的引用关系；对于学校纵向科研绩效的**业务考核、分配方案、学院审批**等，仅转交权威结论和证据（SRC-003 第四条第三项），**不计算、批准或支付个人酬金**。

### 01.2 申请与代理

- 原则起点为**正式立项/任务书/合同所记载的项目（课题/专题）负责人**；国家重点（重大）项目明确了项目、课题、专题层级以及牵头/承担/参与单位差异（SRC-001 第二、三、五～七、三十一条）。
- 其他团队成员、科研秘书、学院办事员可代填或组织材料，但**代理上传不等于项目负责人承诺、学院审批或上级系统提交**；代理范围/授权方式尚无本事项通行校本原文，待核（GAP-02）。
- 特殊身份（离职/退休、负责人调整、跨单位承担、涉密负责人）不凭自然语言申报直接赋权；应先查正式调整文件、项目管理台账和授权链。项目负责人调整应对准各类资助计划当期权限，而不能把一种项目的调整条款挪给其他类别。

### 03.3 当前收件原则与特殊身份

- **最小收件按 `03.2 分支 × P 阶段` 计算**，其 F/M 精确索引见 07.4 覆盖表；材料槽允许引用经校方或资助方核实的记录，无可用接口时才要求出示原件/副本供有权人员确认。
- **委托/参与型**：参与研究者、科研秘书/代办人只能代为整理，不自动成为法定项目负责人。负责人离职、退休、死亡、调任或单位变更，先查获准变更/授权；没有效变更不得直接把新提交者视为负责人。
- **身份/学段**：教职工科研项目未见一套通用的学段条件。研究生、博士后、学生科研创新与教学建设项目若有独立归口，应按真实立项文件和 R02 路由；项目是否可由相关身份主持在 `F010/F011` 处标未知，不引入未经证实的自动拒绝。
- **阶段性状态**：`尚未评审/未发证` 不等于缺必交材料；`已签发但本系统暂不可读` 不等于未通过；`已撤回申请` 不等于正式撤项。

### 05.2 可信数据/证据层级

1. **高信源（仍需真伪校验）**：学校可信身份服务与岗位/委派授权、科研台账中项目与负责人、资助/主管机构有效系统记录、正式公文/证书且可核签发来源。电子签章、文件编号、原件扫描与业务对象的一致性均需有验证机制。
2. **中信源待比对**：学院上传的审核意见、项目负责人签名申请书、科研成果目录及佐证、任务书扫描件；只能证明“提供了相应材料”，不得推定签发者真实或已生效。
3. **不可信输入**：Renderer/表单自填的姓名、工号、角色、审批人 ID、项目号、PDF 中的“已批准”文字、OCR 抽取以及 LLM 归纳。需逐项回到高信源核验；尤其**Renderer 传入 actor 字段不构成身份凭据**。
4. **证据有时间与适用区间**：记录项目 `立项/任务书/变更/延期/结题` 版本链、签发机构、签署时点、批次。旧任务书不得覆盖经批准的变更；旧结题申请版本与新补件共存供复核，而非将“旧 run@rev”伪装真实审批运行。
5. **权限动作必须可审计**：正式审核意见、补件退回、通过/不通过、延期审批、撤项/终止、复核决定的操作者由服务端可信身份和授权校验确定；最小化留痕字段为 `actor_id/authority_basis/action/target/source_version/time/evidence_ref`（技术设计建议，**非校本表单要求**）。无可信身份链应输出 `NEEDS_HUMAN_DECISION`，不落正式学校决定。
6. **保密与个人信息**：涉密项目按 SRC-001 第九条执行独立保密路径，**禁止普通客户端/公开模型接收涉密正文**；教育部系统身份证号仅作为其官方系统历史办理线索（SRC-009），本模板不得依靠明文身份证号代认证，更不能自行索取超出业务所需敏感数据。

### 05.3 角色冲突与行政裁量

- **事实有冲突**（任务书负责人与台账不符、成果项目号不一致、证明文件年份前后矛盾）：标 `CONFLICT`，附双向出处，交项目归口管理人员核实。
- **材料缺失**：先查是否本环节依法必须提交；属于后产证书的标 `NOT_APPLICABLE`；本阶段必需而缺才标 `NEEDS_MATERIAL`。
- **政策不确定**：若没有对应项目类别/当期原文，标 `POLICY_UNCONFIRMED` 或 `SOURCE_UNAVAILABLE`，不借用临近项目门槛。
- **行政/学术裁量**（代表性成果水平、合理延期、专家评价、失信认定、绩效额度分配）：仅整理证据与疑点，交有权人 `NEEDS_HUMAN_DECISION`。`PASS_FACT` 只表示本项事实有足够证据，**绝非通过验收、批准结题或允许付款**。

### 05.4 阶段动作、签发权限和可继承结论

| 动作 | 发起/写入者的可信校验 | 本模板可持有的结果 | 不允许的状态提升 |
| --- | --- | --- | --- |
| 建立项目材料案、关联任务书 | 项目负责人或经校方确认的代办人；项目归属来自台账/原始批文 | `case + F003/F010/F012/F015` 及来源位置 | 表单自填项目号不能成为权威立项 |
| 申请结题/补件 | 当前有效负责人或授权代理，服务端重核受理权 | 申请版本、提交时点、具体 M 版本 | 代办上传不代表负责人签名；机器不得代签 |
| 学院/科研部门初核、退回 | 与项目/组织的授权关系须由可信单位/岗位目录或有权签署记录验证 | 初核意见及被退回版本，可要求受影响项重审 | 学院退回与资助方验收不通过必须分开 |
| 专家鉴定/专业评价 | 主办单位/资助方授权的专家组、真实签章或可信系统结果 | 鉴定意见、评价时间、对应指标及版本 | 生成模型的学术打分不可写作专家意见 |
| 财务决算/审计/绩效考核 | 财务、审计、学院各自的业务权限及有效签发文件 | 引用财务明细/财务验收、学院业务考核、分配方案审批（F027/F028/F037/F038） | 财务合格≠项目验收合格；项目验收合格≠个人绩效获批 |
| 主管/委托方终审、发证 | 主管部门、资助机构、合同委托方或有授权的校内机构 | 有效文号/编号、签发主体、签发日、结论状态（F031～F034） | `PASS_FACT` 不得自动变成 `APPROVED` |
| 撤回/延期/终止/复核 | 动作发起资格+对应项目制度规定的接受者、批准者 | 原申请/决定引用、新决定版本和生效日 | 申请人单方面撤回不能抹掉已签发的官方结论 |

**信源优先级及不可替代规则：**权威机构直签/可信登记记录 ＞ 可核签章的文件副本 ＞ 带上传人身份的当事人材料 ＞ OCR/AI。这里的“＞”只表示发生冲突时的人工核实优先级，**不是自动采信**：两个机关的合法结论若涉及不同决定对象，不可用一份覆盖另一份。凡真实连接尚不存在，记为 `SOURCE_UNAVAILABLE`，允许出示材料给人工查验；不得谎称接入已完成。

### 05.5 材料版本与人工复核的最小守恒条件

1. 每件材料至少保存本模板内的 `material_slot_id + project_id + holder/issuer + source_version + received_at + evidence_locator + supersedes_id + readable_status`；这些是**工程数据建议**，不能冒充学校公开办事字段。敏感字段仅允许授权查看，涉密原文不进入普通客户端。
2. 新任务书/变更批复覆盖的是其**有权决定的目标范围**，并非全项目历史。旧材料留痕；所有引用旧版本的成果对应、财务说明、学院初核意见均应标记“待核是否受影响”，不能自动沿用旧结论。
3. 复用 G50/G07、G06、T04、T07、T02-T07 的权威输出时，取 `业务对象ID + 决定类型 + 签发主体 + 生效状态 + 版本`，不复制其内部审核算法；过期、撤销、未核实签发者或对象不匹配，只能保留疑点与转办。
4. 若学校/资助方原本已有可查询结论，先引用其编号和来源；**不把“已有系统”误写成“已具备接口”**。跨系统暂不可读时允许受理材料供人工验证，但不能要求申报人在系统可取的同一权威数据上反复提交。
5. 行政复核只在被授权的程序内进行；本模板中的“申请修改/事实异议”是材料工作流，不应显示为法定申诉成功或原决定自动撤销。

## 06 业务对象与字段字典

### 06.1 对象、阶段及字段取值原则

`Project`（已批准项目） → `ProjectAuthority`（任务书/合同及正式变更链） → `ReviewApplication`（一次提交、补件或例外申请） → `OutcomeEvidence[]`（多成果、可重复查验） → `StageOpinion[]`（学院、专家、财务等不同类型） → `FormalDecision`（有权机关决定） → `DownstreamReference`（归档、绩效与外部业务）。这只是逻辑对象模型，不意味着客户端已有相应 API/表。

- 阶段缩写：`P0` 识别、`P1` 申请、`P2` 校核补件、`P3` 专业/财务评价、`P4` 正式决定、`P5` 后续引用、`PX` 延期/撤回/复核等；`ALL` 各阶段；`C` 条件触发。
- 可信来源缩写：`A` 获准立项/任务书/合同与正式批文；`U` 有权学校/资助机构可信台账或可核签发记录；`S` 申请人上传，仅作事实声明，需与 A/U 比对；`D` 有权单位签署的后续决定；`L` 本模板为审计保存的派生元数据，**不作政策依据**。若无实际系统接口，U 应为“待人工核实的权威出处”，不可默认为已读取。
- 隐私分级：`L0` 可公开业务信息、`L1` 校内限制、`L2` 个人身份/财务/未公开研究敏感信息、`L3` 国家秘密或另行保密内容（**不入普通客户端**）。复合字段依最高级管理。
- 缺失策略：`NM`=本阶段已核为必需时补件，`SU`=权威来源未取得/失联，`PC`=相应类别政策未核、待人工确认，`HD`=需有权人员判断，`NA`=尚未到产出阶段；不可读单列 `UNREADABLE`，不与缺失合并。

### 06.3 字段规范的硬边界

1. `F003` 与 `F001` 不同：同一项目可多次补件、不同阶段审查，但一个项目正式身份不因建新案变化。`F024` 是成果项身份，不以文件名作为唯一键。
2. `F018/F019/F034/F035/F040` 分别代表批准执行期、延期申请、延期批准、材料提交日期；不可互相替代。重大项目、2026校社科基金和专项有不同前置时限，字段结构通用但阈值依源配置。
3. `F031/F032/F033` 只能来自有权决定 `D/U`，不能由 `F023/F029` 的“已完成自述”推导。`F030` 的专家意见不等同 `F031` 的行政终审。
4. `F011/F013` 仅保存可授权校验的内部标识或令牌引用，不暴露身份证号等原始敏感值；`F043=L3` 的项目原件在普通 T03-T07 流程内为 `NOT_APPLICABLE` 并转专门保密管理。
5. 所有“可从 U 得到”的字段必须实际有可访问且有授权的来源；没有接口时接收人工核验记录并保留 `SOURCE_UNAVAILABLE`，不能制造数据已同步的假象。

## 07 材料槽与证据目的

### 07.1 材料槽定义与状态

材料不是“必须上传文件”的同义词。材料槽可由**可核权威记录、原件、受理回执或合法电子副本**满足。`现`=当前阶段明确必需（仅触发分支时），`条`=条件必需，`后`=仅达到对应后续阶段才产生或必需，`权`=优先引用学校/资助方权威系统；不等于已具有连接能力。未确认政策的槽只能为 `PC` 并人工确认。

缺失处理代码：`NM`=本阶段依法必交但缺失时补件；`PC`=校本/上级条件未核；`SU`=有权来源未取得；`NA`=未到产出阶段；`HD`=须人核。**对不可读一律先 `UNREADABLE`、定位具体页/图片/附件，允许补可读同源副本**，不可将其等同材料不存在。所有材料默认带 `F003/F041` 的项目与版本归属，下面各槽补充专有绑定。

### 07.3 持有人、可替代与收件顺序的约束

1. **M001–M005 属权威基础**：能从可信校内项目系统查取的先引用、留来源和访问授权；当下没有对接时，允许申请人提供原文，交受理人查验，不能把上传件直接标成可信库事实。M003 不索取身份证正反面。

## 08 审核规则逐条清单

### 08.1 规则阅读与判定约定

本节 R 是**研究级事实核验规则**，不是已装配的 V3 可执行 DSL；`ruleId` 只在 T03-T07 内唯一。每条的“真/假/未知”指**适用条件**而非核查结论：`真(T)` 激活比较；`假(F)` 该规则在此阶段或分支 `NOT_APPLICABLE`；`未知(U)` 不猜类型/政策/角色，由人工核实，主要输出 `POLICY_UNCONFIRMED`、`SOURCE_UNAVAILABLE` 或 `NEEDS_HUMAN_DECISION`。激活后，证据充分一致才输出 `PASS_FACT`，材料真的必需而缺 `NEEDS_MATERIAL`，有材料不可读 `UNREADABLE`，可信来源互斥 `CONFLICT`。具体结项合格与否始终由有权人决定。

### 09.2 一致性比对、版本失效和跨业务复用

1. **先定对象，再比内容。** `F003+F006+F008+F017` 定项目、批次、层级和目标版本；`F011/F013/F014` 定负责人和提交权；`F024/F026` 定每件成果归属。`M001/M002/M003` 彼此不符时标注两端字段、原始页码及核实渠道 `F044`，不可仅凭姓名一致自动合并两个项目、两名教师或两个课题。
2. **版本主从不是“新上传覆盖官方文件”。** 以有权签发的 M005/M032 的生效范围构造当前目标版本，申请方新传 M006/M007/M008 只是新申报版。`F041` 记录 `旧件→新件`、替代原因、接收人、页码及 hash；旧版保留历史可追溯，若新件仅修正第 3 项成果，则只标记直接关联 F024–F026、对应 F021/F022 的旧事实结论待重审，未受影响的项目身份事实可继承。**任何旧的正式 M015/M032 不因材料替换自动失效**，只有原有权机关的撤销、更正或新决定能改变其效力。
3. **权威结论必须同时匹配五元组：**`业务对象 + 决定类型 + 签发主体 + 生效状态 + 文书版本`。G06 科研诚信/伦理结论、G07 财务审核结论、T04 采购/资产意见、T07 合同权威意见、T02-T07 个人业绩等级可被引用到相关 F/M，不重做相邻业务的审批。未验证签发者/有效期、共享接口不存在、对象不一致时 `SOURCE_UNAVAILABLE/CONFLICT`，不得将“用户上传一张批复截图”作为权威决定。
4. **多主体意见不能简单比大小：**学院初核 M013、专家组 M014、财务验收 M012、外部正式验收 M015 分别回答不同问题；同一对象、同一种决定发生冲突才请求原有权部门澄清或更正。资助方项目合格不推出学校成果分级已认定，更不推出学院个人绩效已发放（F037/F038）。
5. **缺失四分法：**经适用政策和阶段确认当前必交、确实缺件→`NEEDS_MATERIAL`；有文件但无法抽取具体页→`UNREADABLE`；权威源或已存在附件接口暂失联→`SOURCE_UNAVAILABLE`；找不到当期有效条件/阈值→`POLICY_UNCONFIRMED`。其他阶段才会形成的 M012/M014/M015/M019/M027/M029/M030 应为 `NOT_APPLICABLE`，不得与缺失混计。任何疑点涉及真实性、实质学术成果或行政裁量再标 `NEEDS_HUMAN_DECISION`。

| 国家社科重大项目结项使用 2024 年度/青年/西部在线清单 | `R046` 检查类别与表版，旧校站清单或 SRC-015 参考 PDF 只能提示应找何文件，不据此判拒件 | 社科处、全国社科工作办及有效当期专属规定确认 |

对所有组合，**项目任务书/委托合同的可核批准版本优先定义目标**，但不能覆盖发文机关的法定强制条款；跨来源出现不同门槛时记录 `(issuer, legal_level, scope, effective_from, transition_clause, batch)` 并由政策 Owner 判断适用，模板不自造“取最严值”策略。若变更/结项成果有资金、采购、成果登记、合同交付多重关系，各事项仅引用权威五元组，绝不以 T03-T07 的总览状态反向覆盖 G50/T03 邻项决定。

## 10 结果状态、问题与待办输出契约

### 10.1 八种互斥的**逐 R 主状态**

一个 `ruleId × project_id × application_revision × source_snapshot` 只产生**一个主要事实状态**；不同 R 可以同时存在不同状态。重大政策争议和多处缺件通过**多条独立问题**表达，不能把一个状态数组伪装成单项结论。主状态不含 `APPROVED`、`REJECTED` 或任何学校正式审批动作。

| 唯一主状态 | 严格适用条件 | 不可混淆的反例 | 建议待办接受者 |
| --- | --- | --- | --- |
| `PASS_FACT` | 适用条件明确为真，当前应核事实从可信且可读的匹配证据得到一致支持；允许说明“已有签发决定的真实性已核”，**不代表该决定内容是通过** | 申请人自称“完工”，仅有 M006；不得转 PASS_FACT 的验收结论 | 归口经办人可继续；如涉及评价仍交有权决定人 |
| `NOT_APPLICABLE` | 已凭可信事实确定**当前阶段/类别**不触发该 R，或材料为后产（例如 F1/P1 无 M019） | 不知道是否有外拨经费≠无外拨 | 无需补件；有阶段变化时重新激活 |
| `NEEDS_MATERIAL` | 计划/阶段依据已核、**确为本阶段必交**，且材料槽没有合法有效替代或实际缺件 | 可从权威台账查得但接口断开；P1 缺 P4 才产生的批复 | 材料持有人或合法申请人；学校负责出具的材料不派给项目负责人 |
| `CONFLICT` | 两份及以上**可读且可定位**的有关材料/权威记录出现互斥的身份、项目号、目标、签发版、成果归属或日期事实 | OCR 无法读清一方数字时应先 `UNREADABLE` | 对应事实/文书的有权签发者、科研归口人员 |
| `UNREADABLE` | 应核材料已到且有归属，但某页/附件无法打开、页缺损或关键字段无法可靠抽取 | 已有可读文件但规则现行性未核≠不可读 | 材料持有人补同源可读副本，或授权档案管理人 |
| `SOURCE_UNAVAILABLE` | 本应查的**有权记录/原文/接口**无法访问或记录不存在于可访环境，尚不能确证业务事实；保留失联位置 | 申请人确实没交被明文要求的自持材料≠来源失联 | 系统管理员/科研部门/资助方核源，不强迫反复上传 |
| `POLICY_UNCONFIRMED` | 尚无该类该批次可证的现行规则、表格或审批权限，故无法确定是否必交或适用何门槛 | 已查现行政策且明确应交，申请人没交≠政策未知 | 校内政策 Owner 或资助/委托方确认并留版本 |
| `NEEDS_HUMAN_DECISION` | 基本材料可以呈现，但属于评价/真实性争议/风险/权限裁量，或无自动判定的合法空间 | 签发结项证书不是让模型“选择同意”的选项 | 相应专家、校方获授权人员、主管/委托单位或保密管理者 |

**同一 R 的稳定裁决顺序：**先按适用条件区分假→`NOT_APPLICABLE`，未知政策→`POLICY_UNCONFIRMED`（或未知信源→`SOURCE_UNAVAILABLE`）；适用为真时，先判断资料已提供但不可读、可信事实互斥、当前确必需而缺、需人工专业/行政裁量，最后才 `PASS_FACT`。一旦冲突已经由两份**可读权威证据**证明，即使第三份资料不可读，也应为独立不可读问题建单，不能清除冲突。所有状态转换须有证据、阶段或政策快照事件，不由自然语言随意改码。

### 10.2 审核问题、证据引用、待办的最小数据契约（建议模型，非已有客户端接口）

| 逻辑记录 | 必备要素与约束 |
| --- | --- |
| `FactCheck` | `templateId=T03-T07`、`ruleId`、`projectId=F003`、`caseId=F001`、`procedureStage=F002`、`applicationRevision=F041`、`sourceSnapshot=[SRC id,版本,适用区间]`、`condition=T/F/U`、`status=八码之一`、`checkedAt`、`checkerType=FACT_PRECHECK`；无假冒正式 Run ID |
| `EvidencePointer[]` | `slotId=Mxxx`、`materialId`、`holder/issuer`、`sourceVersion/hash`、`page/paragraph/cell/recordKey`、`evidenceFactField=Fxxx`、`authorityLevel=A/U/D/S/L`、`readable`、`verifiedIssuer`、`receivedAt`、`supersedesId`；所有问题都能回到原始位置；缺件用 expectedSlot 及应交 SRC 代替不存在的文件指针 |
| `Issue` | `issueId`、`ruleId`、`subjectKey`（项目/成果/人员/合同或申请版）、`primaryStatus`、`evidencePointers`、`conflictingEvidencePointers?`、`policySrc/locator`、`description`（明确待核事实）、`requiredAction`、`assignedRole`、`urgencyBasis`（具体通知/事件而非猜测天数）、`privacyLevel`、`affectedRuleIds`、`resolvedBy/at/evidence`；不得给 L3 原文公开 URL |

| `DecisionReference` | `businessObject`、`decisionKind`、`issuer`、`authorityBasis`、`signedDocumentRef`、`issuedAt`、`effectiveAt?`、`revokedOrSupersededBy?`、`verifiedAt`；**只引用外部/学校既有可信文书**，不存在时没有正式决定记录 |

**例子（非实案）：**`R026 / project=市社科-甲 / stage=P1-F1 / F031 未到产出阶段 / M019 expectedSlot / SRC-008 第4点` → `NOT_APPLICABLE`、无补证书待办；切到 `P5-F2` 后才检查 M019，若已发证却系统失联则 `SOURCE_UNAVAILABLE` 并指派社科处核证，不伪造资助方证书。

### 10.3 案卷级输出与正式决定隔离

- 对外显示“可核事实数、待补件数、资料冲突数、不可读数、政策待确认数、须人工决定数、未适用数”；总览可为 `READY_FOR_HUMAN_REVIEW`、`INCOMPLETE_EVIDENCE`、`PENDING_AUTHORITY_SOURCE`、`HUMAN_DECISION_REQUIRED`，**不是批准/驳回状态**。
- 某 R 状态为 `PASS_FACT` 只结束该事实核验；全 R 均 PASS_FACT/NOT_APPLICABLE，也**仅意味着现有事实核验无阻断**。项目结项仍由资助方/委托方/校内获授权主体签发 M015。
- 一个案卷能引用多个不同决定（项目验收、财务验收、成果等级、学院绩效），但对每个决定必须标明不同 `decisionKind + issuer`。不能把一份 “学院材料已核” 复制成 “学校结项批准” 或 “财务发放完成”。
- 问题可见性按 L1/L2/L3 和主体权限限制，审阅导出需脱敏；不存在的校园系统、自动接口和正式角色授权不得通过模板字符串伪装为已经接通。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 单案审阅生命周期与状态转移（业务建议，不代表学校已上线）

| 当前状态 → 后续状态 | 触发、前置证据与可信操作者 | 对本案的写入/禁行 |
| --- | --- | --- |
| `DRAFT` → `FACT_PRECHECKED` | 项目/阶段已识别 P0/P1；R001–R014 可运行事实预审 | 写规则/材料快照和问题，不写“受理完成”或正式 Run/Decision |
| `FACT_PRECHECKED` → `SUBMITTED_TO_SCHOOL` | 有效负责人/合法代理，若该计划存在受理途径；F013/F014 经可信服务核；有 P1 版本和 F040 回执 | 才记录校内提交；缺受理回执仅能记录待确认，不凭按钮点击自称已正式递交 |
| `SUBMITTED_TO_SCHOOL` → `NEEDS_SUPPLEMENT` | P2 学院/社科处/科发院实际退回 M013 并注明版本 | 对申请人只派其有权提供的 M；学校缺的 M027 等派校方；保留原提交版 |
| `NEEDS_SUPPLEMENT` → `UPDATED_FACT_PRECHECK` → `SUBMITTED_TO_SCHOOL` | 负责人/代理补 M034 及被要求材料的新版本；原受理人确认重交 | 执行 R014/R033 与受影响 R；其余 R 可继承带 sourceSnapshot 的原结论，不自动改正式结项状态 |
| `SUBMITTED_TO_SCHOOL` → `READY_FOR_HUMAN_REVIEW` | 当期适用事实核完，所有未解决问题已有受理角色和处置路径 | 只是可供校方或专家审阅，绝非学校“同意结项”；需校方服务端可信操作者再处理 |
| `READY_FOR_HUMAN_REVIEW` → `EXPERT_OR_AUTHORITY_PENDING` | 对应计划实际需要评审/财务验收/主管方结项；由有权机构签收 | 存 M014/M012 的**真实后产**意见引用；未签发不能由规则补出专家签章 |
| `EXPERT_OR_AUTHORITY_PENDING` → `FORMAL_DECISION_REFERENCED` | P4 得到校内获授权或外部主管方签发的 M015，R035 核来源、签署与有效时点 | 仅引用决定类型与原文，`PASS_FACT` 不变成“批准”；可记录原决定为通过/不通过/其他，但须归属于其签发者 |
| `FORMAL_DECISION_REFERENCED` → `POST_DECISION_LINKED` | P5 归档、F2 线上补录、I 项目绩效关联各自条件满足 | 只增添证书/绩效/财务权威引用；真正支付继续走 G07，项目案卷不双写其他业务决定 |
| H2-SC/P1 → `PROVINCIAL_ACCEPTANCE_PENDING` → `FORMAL_DECISION_REFERENCED` | R040–R043 激活；只有省科技系统实际收件回执和项目牵头单位/推荐单位意见，才能称进入主管流程；最终以 M037 确认 | 申请、审核/专家/自主模式、专家意见、系统证书不同版本分别留痕；**不存在校内授权/源失联时只保留研究待办** |
| H2-SC/PX → `PROVINCIAL_REMEDY_REQUESTED` → `PROVINCIAL_REMEDY_DECISION_REFERENCED` | R044，M039 载整改/二次验收或撤销申诉等真实事件、受理回执和原文书号，决定仅由科技厅/实际授权主体写入 | 不将二次验收、申请终止、撤销申诉、普通撤回合成一个“复议”；前一结论是否改变以新文书效力为准 |
| `DRAFT/SUBMITTED_TO_SCHOOL/NEEDS_SUPPLEMENT` → `WITHDRAWAL_REQUESTED` | 申请人就**本次申请**请求撤回，原受理机关是否允许、时点待核 | 暂记请求 M031/F036；只有有权机构确认才记 `APPLICATION_WITHDRAWN`，不抹除旧版或任何已生效 M015 |
| 任一有正式决定阶段 → `REVIEW_REQUESTED` → `REVIEW_DECISION_REFERENCED` | 有合法复核渠道、受理确认和原文书号；F045/M031，后续 F046/M032 由原有权机关签发 | 申诉/事实异议≠自动复核受理；旧决定仍在历史中，是否被撤销/替换依新文书效力，不由模型改判 |

**状态字段强制区分：**`applicationHandlingStatus`（草稿/校方收件/退回/申请撤回/确认撤回/重提）、`factReviewStatus`（八种逐 R 主状态/待人工）、`formalDecisionStatus`（无文书/核到何种权威结论/已更正或撤销）、`downstreamStatus`（已引用/待财务另办）。互相只通过“已核权威证据”关联，不做简单字符串同步；具体校本可用状态名称需后续确认。

### 11.2 权限和例外动作

1. **补件：**原件、补件和版本对照 M034 必须绑定 `caseId + F003 + subject + F041`。新文件可以弥补不可读或补证据，但不自动抹去对旧版的冲突，重交时由原校内受理角色确认是否被接受；补件期限必须指向真正的当批受理通知。
2. **申请撤回与再次提交：**在学校尚未形成外部/校内正式决定时能否撤回、能否重提、是否沿用原项目号及截止日期依资助方/学校制度；通用 T03-T07 只有“记录请求—人工核权限—收到受理确认—保留旧提交版—再提交新申请版”的框架。再次申请有新 `applicationRevision`，不生成新权威 `projectId`；旧正式文书若存在永不自动删除。
3. **延期与变更：**M031 证明已请求，M032/M005 才证明获准；只有核到有权批准及生效范围才能更新 F017/F019/F020/F035。D1/D2 的提前 2 个月/最长 1 年和 E1/E2 的最长 6 个月绝不跨批次复制。
4. **异议、复核、复议：**项目负责人可陈述材料事实异议，但学校/资助方有无制度性复核程序、受理机关、时限与次数须逐计划确认；`REVIEW_REQUESTED` 不是复核批准。新的 M032/F046 有文书号、主体、被更正版本、效力日起才改变后续引用，不 retroactively 改写旧报告。
5. **最终人工作出决定：**项目/课题验收、成果分级、审计财务意见、学院业务绩效、实际发放、科研诚信处分各归自己的有权主体。服务端校验 `actor + role + delegatedScope + project + action + sourceVersion`，审查上传者与最终签发者必须分别追踪；没有真实权限或接口只出待办不落正式决定。

### 11.4 最低闭环验收条件

一次办理动作完成事实核验闭环，应能从“材料/来源→F→R→八码→Issue→有权 Task→补件或人工核源→定向重审→已核文书引用”回溯每个节点；允许以 `POLICY_UNCONFIRMED`、`SOURCE_UNAVAILABLE` 或 `NEEDS_HUMAN_DECISION` **有依据地结束 AI 预审并移交人工**，不必伪造全 PASS。用户撤回/复核必须形成独立申请事件和有权处理意见；在真正收到授权决定前，不记录学校审批完成。

7. 涉密、未公开研究资料、个人财务和敏感身份信息——L3 原文拒绝普通 OCR/模型管线，分流学校专门保密受理；L2 最小可见与授权导出。
