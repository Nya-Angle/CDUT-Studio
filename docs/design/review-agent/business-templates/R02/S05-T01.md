## 01 唯一审核目的、申请人和负责机构

### 1.1 核验对象与唯一决定

本模板围绕**一个学生在一个适用培养/评价周期内，对其第二课堂项目参与记录、分类、积分/学时/学分或成绩单汇总提出的记载、补记、更正、认定或复核需求**，核对事实链与适用规则。一个申请可引用多项活动，但各活动应保留独立项目/场次/参与/授分记录，不能把不同项目的证据混成一个结论。

可做的前置核查：学生与记录主体一致性、项目和主办方可识别性、活动实际参与事实、源平台记录与证明互证、同项目重复记录、所申报类别与当期官方项目分类的一致性、用于换算的规则版本是否可确认、是否有尚待有权人办理的更正/例外。只有在取得适用的现行校本规定和可信记录后，才能核对具体学分/积分及门槛。

**不得形成的决定：** “该学生毕业合格/不合格”、活动举办许可、社团资格、志愿者工时确认、创新学分正式入账、评奖评优、推优入党、课程学分替代或学校官方第二课堂成绩单签发。这些决定只能引用本模板已经由有权机构确认的结果；本模板也只能引用相邻业务的权威结论，不自行替代（SRC-004、SRC-006、SRC-008）。

## 02 适用、排除与邻接模板路由

### 2.1 适用范围（条件化）

- 学生请求核对本人第二课堂成绩单的一项或多项活动记录、分类、累计与正式认定前置证据；**具体本科、研究生、来华留学生、中外合作、辅修/双学位、转专业、休复学学生是否同制及跨年级适用时间，均等待校本规则**。
- 活动组织方或学院在校本授权下，提交若干学生的记录清册或差错更正材料，仍以同一模板的**批量情形**处理，但逐人逐活动核查；不等同自动批量批准。
- 已经有成绩单或平台记录的补正、异议、复核与后续受影响项重审，保持本 ID，不另拆模板。
- 志愿公益、社会实践、竞赛、文体、团学履历等可能成为项目类型，但**只有当当期成都理工大学项目体系明示纳入时**，才纳入该项的学分口径；不能以国家“可纳入”的类目直接得分（SRC-006、SRC-008）。

### 3.3 时点与授权约束

1. **参加报名≠到场≠完成≠授分≠成绩单签发**。它们发生在不同事件时间，必须保留各自 `sourceVersion`。活动未结束时 `M006` 不可作为当前必交材料；学校还未认定时 `M017/M018` 也不可提前要求。

3. 代理和批量操作均要求可信 Actor 与受影响学生逐项授权/职责范围。上位允许自我申报不等于允许匿名代报。
4. 学生撤回/复核的请求意愿可记录，但校本撤回受理、已经生效结果是否可撤销、复核是否终局，须由有权角色决定。组织者更正原始签到也不会自动撤销已发行政结果。

## 05 角色、权限与可信数据边界

### 5.1 预审与正式决定分离

**可信身份约束：** Renderer 传入的申请人、辅导员或教师身份均视为未证实陈述。实际 Actor 必须由 Main/Host 按经过认证的会话、校内身份源及后台角色授权核对，绑定案件/活动范围后产生；每次有权限动作审计 `actorId / roleSource / authorizationVersion / action / target / timestamp / decisionRef`。同一人员可多角色，但不能用客户端切换下拉框改变其授权。匿名材料、图片上签名、印章 OCR 只构成证据文本，不构成认证事实。

### 5.2 数据来源可信度与冲突处理

1. **主张**：学生上传的电子证明、证书、截图、邮件、报名通知。保存原件哈希、来源和版本；可辅助定位，但不能直接认定后台授分。
2. **事实原始记录**：由当期学校授权的活动/志愿/成绩单平台或主办方签认提供的项目 ID、场次、参与状态、积分发放日志。需确认数据签名/接口范围和可查性；没有授权对接时标 `SOURCE_UNAVAILABLE`，不伪造“已查”。
3. **权威认定**：由校本明确授权机构通过可信后台或正式文书产生，附 `decisionId`、决定人真实身份、版本、有效时间及撤销/更正关系。此类资料可被后续综测或毕业审查引用，但不能与普通参与记录混淆。
4. **制度源**：规定的发布机构、文号、生效日、适用 cohort、变更/废止链。上位文件仅确定原则，校本没有明示阈值则 `POLICY_UNCONFIRMED`。
5. **冲突**：个人证书与系统记录不同、同一活动二次导入、姓名/学号不一致、撤销后的旧分数仍显示、志愿工时与二课分数混写，都必须保留两边数据和版本，向各自数据责任人发待办；不能简单“以最近上传者为准”。

### 5.3 结果预留与不可自动裁定

本稿的字段、材料、情形与 32 条事实预审规则仍不是可生产运行的学校决定程序：`PASS_FACT`（事实可核、非批准）、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`。学校现行阈值缺失时，**即使材料齐全也不能 PASS 为已获得学分**；存在专业裁量、特殊群体豁免、异常补记、历史跨系统合并、冲突时只能交可信有权人确认。

### 5.5 最小授权动作、证据边界与版本失效

1. **身份验证**：输入 `F003/F004/F012` 必须按经过认证的校内主数据或可核代理授权验证；用户上传一张学号截图只能成为辅助材料。无已认证 Actor 时可读材料，不得批准、改账、撤回或代他人提交。
2. **主从证据**：`M004` 是项目合法性/分类索引的主证据候选，`M005` 是参与事实主证据，`M006` 是完成事实候选，`M010` 是既有账主证据，`M017` 才是正式认定决定。彼此不同目的；以一张海报取代签到或以签到取代正式授分都属于错配。
3. **源平台并不预设可连**：`M002/M004/M005/M009/M010` 可以是有权限的接口响应、签章的官方导出或线下核实回函。只记录实际使用的访问方式和身份，不得伪造接口存在；后台不可达时是 `SOURCE_UNAVAILABLE` 而非学生缺交。
4. **替换不是覆盖**：一个 `M` 的新版本应有 `evidenceId`、`versionId`、`supersedes`、受影响 `F`、对象键和获取时间。依赖旧版的事实结论标 `STALE_RECHECK_REQUIRED`（内部重审标记，不是对学生的第九种结果），只重算依赖字段及跨活动累计，不删除旧证据审计轨迹。
5. **正式结论独立生效**：重审事实并不会擅自撤销已签发的 `M017/M018`。仅原有权人或校本指定复核单位可作更正/撤销/维持决定，之后再产生新版正式输出；对象与旧决定号必关联。
6. **邻接权威引用**：G50 场地/安全/校外活动、S03-T01 综测、教务创新学分、志愿工时仅能通过 `F031` 指向**对应制度持有人已正式有效的决定/记录**。没有正式结论时，记录其待确认状态，不以本模板建立平行批准。

## 06 业务对象与字段字典

### 6.1 数据字典阅读约定与对象键

- 本表是**研究字段合同**，不证明成都理工大学系统中已存在同名列/接口。`SRC-006/007/008` 支持记录与审查目标，`SRC-001–005` 仅证实相关部门/历史线索；未获校本专项阈值时对应字段仅用于定位，不驱动不利决定。
- 建议内部键：`caseId + studentStableId + academicContextId + periodId + activityId + sessionId + participationRecordId + awardRecordId?`。项目可有多场，场次可有多次参与事件，证书可涵盖多项目；不得以活动名称或姓名作唯一键。
- 隐私等级：`P0` 公共制度/活动名称；`P1` 校内工作信息；`P2` 学生个人学籍/参与记录；`P3` 身份认证、代理证明、正式决定等敏感授权记录。遵循最小可见与按对象授权，学生 A 不得读取学生 B 的批量清册。
- 缺失状态：`NM`=`NEEDS_MATERIAL`（可由申请人/合法持有人补充）；`SU`=`SOURCE_UNAVAILABLE`（已确认应访问的权威来源暂不可达）；`PU`=`POLICY_UNCONFIRMED`；`NH`=`NEEDS_HUMAN_DECISION`；`CF`=`CONFLICT`。`NA` 表示触发条件为假，不要求该字段。**尚未到形成时点**只做 `PENDING_LATER_STAGE` 内部状态，不输出 `NM`。

### 6.2 业务对象

| 对象 | 一对多/关联 | 主权威与边界 |
| --- | --- | --- |
| `CASE` | 一个申请/请求可含多个学生活动；H1 批量必须分离每名学生的对象和结果 | 系统案卷与经认证申请人，非业务批准本身 |
| `STUDENT_CONTEXT` | 一个学生可跨学段、年级、校区、学籍状态/政策周期 | 学籍与培养方案权威持有人；上传件不能改主数据 |
| `POLICY_PROFILE` | 一个学校有不同 cohort/年度/学段的条款效力切片 | 经确认的校本制度发布者、文号与生效链，当前待取得 |
| `ACTIVITY_PROJECT` / `SESSION` | 项目包含场次或完成节点，可由不同主办方管理 | 项目主办方/被授权平台；项目登记不等于安全/场地批准 |
| `PARTICIPATION` / `AWARD_ENTRY` | 每个学生-场次多个签到或成果记录；授分与参与事件不可混同 | 参与事实源与二课授分账分别存证 |
| `EXTERNAL_CLAIM` / `VOLUNTEER_ENTRY` | 外部证书和志愿工时独立持有人，关联二课但不双写 | 外部颁发者或志愿系统先核原始事实 |
| `OFFICIAL_DECISION` / `TRANSCRIPT` | 原决定、新决定、成绩单版本按时间相连 | 校本授权签发主体；不由 AI 产生 |
| `CHANGE_REVIEW` / `BATCH` | 一批包含独立学生、活动、变更/复核项 | 权限随目标逐项核验；不能用同一清册覆盖他人 |

### 6.4 校本配置占位（禁止硬编码）

`school=CDUT`、适用 `studyLevel/cohort/campus`、`policyId/version/effectiveFrom/effectiveUntil`、项目类别树、活动“完成”标准、签到等价凭据、发放单位及换算系数、单项上限/累计方式、重复授分原则、补录截止、撤回/复核机构与期限、账号/接口能力，均为**待权威制度/部门确认的配置数据**。没有证据的值为 `UNKNOWN`；不得填 3 分、6 分、200 积分等外校数字，也不得以参数为 `null` 时悄悄默认为零。

## 07 材料槽与证据目的

### 7.1 材料槽 M001–M020

术语：`现核`＝该情形当前核实事实所需的**信息/可信数据或等价材料**，不表示必须上传；`条件`＝触发特定分支才核；`后置`＝到活动完成、正式认定或复核决定后才产生；`已有后置`＝过去案件已产生，当前复核才引用。所有模板字段与本校实际表单名称仍须由校方补证核实。

版本/归属记法：`学生键/项目键/场次键/参与记录键/批次键`须精确绑定；`ver` 指原始记录/文件版本、生成时间、签发人或系统版本。没有原生 ID 时，使用来源＋日期＋活动/主体组合定位并标低置信，不以姓名作为主键。`UNREADABLE` 与真正缺件分开；可信官方接口可用时以接口回执代替学生重复提交。

### 7.3 材料要求的阶段顺序及受理反例

1. **仅报名还未开始**：可以有 M004、报名状态，不能因为没有签到 M005、完成 M006、决定 M017 输出 `NEEDS_MATERIAL`。对未来材料使用 `PENDING_LATER_STAGE`，到实际触发时间再检查。
2. **本人申请漏记**：若可信 M005 参与源已取得，应直接比对 M010 旧账；不能再强制上传同一记录截图 M007。若源已验证为不可达，则输出 `SOURCE_UNAVAILABLE` 并发系统持有人待办，而非学生“未提供”。
3. **一份证书多名获奖者**：M008 共用文件可以复用，但 F027/F028 的归属必须逐学生及成果角色核实；若证书仅列团队名，不能自动给每人相同学分。
4. **撤回后又提交新证书**：M011 撤回申请和 M007 新证书不能互相覆盖；先查原案状态及校本受理规则，再决定是否创建新版本或恢复审查。
5. **有签名图但没有受权身份**：M017 OCR 出现某老师姓名不等于 F038 可信授权，也不能替换 M016 代理权限；需 `NEEDS_HUMAN_DECISION`。

## 08 审核规则逐条清单

### 8.1 规则适用与证据可追溯合同

以下 `R001–R032` 是**事实预审/流程门禁研究规则**，不是已获得成都理工大学发布授权的生产规则。每条保留：`ruleId`、`caseId`、`targetKey`、`stage`、`applicability(true/false/unknown)`、`SRC` 版本、`F` 输入、`M` 源记录/页行/hash、`capturedAt/sourceVersion`、`resultCode`、`nextActor`。`T` 表示相应业务触发已证实；`F` 为明确不触发、输出 `NOT_APPLICABLE`；`U` 表示触发证据或校本制度尚无法确认，须按该行给定原因输出，**不得将 U 改为不合格**。后续出现真实校本制度，应先确认文件发布、适用人群、效力区间及撤废关系，再升级相应 R，而不是把研究假设赋值为硬阈值。

证据等级：`L1` 学校或具真实授权的原始系统/签发决定、校本制度全文；`L2` 被授权组织直接核验回函/认证导出；`L3` 学生持有证明、证书原件及可核查副本；`L4` 自述、截图、OCR 和海报。等级**按证明目的分别判定**：学籍源不能替代活动签到，签到源不能替代学分正式决定，志愿平台不能替代二课账。SRC-005 虽是学校制度全文，但 2026 版本效力未确认；SRC-006/007/008/009 是上位边界，均不提供本校具体授分值。只可在事实源完整、一致且阶段可达时用 `PASS_FACT`；该代码从不表示批准、入账或毕业资格。

### 8.3 证据门禁及不可执行条款

1. **条件为假**：只将这一条不触发的 R 置 `NOT_APPLICABLE`；其他 R 可独立运行。**条件未知**：按其成因输出 `NEEDS_MATERIAL`、`SOURCE_UNAVAILABLE`、`UNREADABLE`、`CONFLICT`、`POLICY_UNCONFIRMED` 或 `NEEDS_HUMAN_DECISION`，绝不合并为“审核不通过”。
2. **判定先后**：先确认阶段是否可达、认证对象及当前义务；对某一证据对象，明确为后续材料则不触发，已提交但读不出=`UNREADABLE`，可信源确已失败=`SOURCE_UNAVAILABLE`，当前合法材料未产生且应由持有人补充=`NEEDS_MATERIAL`，两个可读有效来源不一致=`CONFLICT`；事实齐备后仍无校本口径=`POLICY_UNCONFIRMED`，有合法程序需要人工决断=`NEEDS_HUMAN_DECISION`。最终只可对**已证实且不需要校本裁量的事实目的**返回 `PASS_FACT`。
3. **当前真正政策 BLOCK**：`R003/R006/R009（若完成标准来自规则）/R011（重复授分）/R014/R016/R018/R020/R024/R025/R030` 的校本条件目前未验证，**任何硬阈值分数、默认毕业资格、法定申诉天数、默认机构签批都没有可执行依据**。其余 R 亦须在真实来源接通和授权确认后才能在真实案件中跑事实核验。
4. **R 不替代正式决定**：本稿的 `R021/R022/R030` 只核已有签发链或提示有权人办理；不会生成合法 `M017/M018/M019`。技术 SHA SRC-011 只能防止误接线，不能创设学校审批权。

### 9.3 版本、撤回及复核的影响控制

1. 每个 M 及其下的行/页必须追踪 `evidenceId / owner / subjectStableId / objectKey / sourceRecordId / sourceVersion / capturedAt / hash / validFrom / supersededBy`。一个原件更换后旧件可追溯不可隐式覆盖；若原件无可靠版次，标证据链缺口，人工确认。
2. `affected(F,R)` 依赖以 08 节 R001–R032 和 F040/F042 登记：例如 M005 签到修正只使**相同学生、相同场次**的 R007/008/009/011 等旧预审核验待复核；不令其他学生的成绩或其全部活动自动失效。实际客户端是否已建立该依赖图并未实测。
3. 待复核的**AI 预审结论**可以随新证据版本标记 `STALE` 并重新计算；已有 M017/M019 **正式学校决定**只可以标“引用证据改变/待有权机关重新处理”，不可被系统自动撤销、重签或改分。
4. 撤回提交（M011）和撤回生效是两件事。到 ST-07 前后申请人可能变更材料、撤回请求或提出复核，先验证真实 Actor、受理时点和原案状态，具体程序效力均为 `POLICY_UNCONFIRMED`。复核后的 M019 不得作为申请 H3 时的“当前必需”。
5. 源服务故障使用 F041/M020 记录真实查询与失败时点，不为了填充完成率改写成 M 缺失。修复后再次抓取应产生新查询证据版本，变更了值时触发 F042 增量复核。

### 9.4 临界与复合反例（材料/字段级）

1. **B1×D1，周一报名、周五活动**：F018 目前只有报名、F017 未来、M005/M006 尚未出现，当前只核 M001/M002/M004；不能开“缺完成证明”待办或拒绝受理。
2. **B2×H4，活动编号重用**：新 M005 指向相同 F013、不同 F014；旧 M010 只有活动名。先查 F017/F019 与原活动编号历史，不能以同名自动清除旧分。
3. **C×H1，团队获奖**：M008 发证号属于五人团队，批量 M012 清册六人；逐人 F004/F027/F028 匹配后，第六人不能因在清册自动共享证明；是否团队成员、授分比例交主办方及校本主管核。
4. **E×F，志愿记录 16 小时**：F026=16 小时仅证明服务事实；F022 必须来自正式二课账及校本换算，教务 F032 另核，不可推出 16 个二课学分或毕业满足。
5. **G1×H3，旧制度与新制度相交**：学生从某 cohort 转入另一培养方案，有旧 M017，当前 M003 找不到过渡条款；原决定保留，转段效力由有权部门确认，不以最新阈值回算撤销。
6. **A×D2，数值一致但来源错**：二课积分截图和 M010 数字相同，M017 签发主体却无有效 F038 记录；不能以“结果相符”补足批准权限。
7. **H1×H2，批内只有一人撤回**：M011/F034 精确指向批次行和学生，F037 关联清册；不撤回其他所有人，也不因批办而忽略独立真实授权。
8. **G2×F，研究生申请毕业门槛核验**：F006 表示研究生，SRC-005 只适用本科；除非另有研究生培养/二课规定，不能拿本科办法判研究生不达标，需跨主管主体核政策。

**本节未确认的硬条件**统一转入 12 节配置待核和 14 节 GAP；即使已形成 F/M/T/R 表，也不许将未证实校本阈值写成自动执行常数。

## 10 结果状态、问题与待办输出契约

### 10.1 互斥结果语义（同一 R×target×证据快照仅有一个主码）

| 代码 | 唯一语义与触发时点 | 责任待办、绝不可等同 |
| --- | --- | --- |
| `PASS_FACT` | 某项**限定事实**可由当时有效、可读、归属明确且相互一致的证据证实；示例“截至核查时官方参与清册有该人”，不意味着授予学分。 | 可进入后续政策/有权决定；**不是 approved、资格合格或完整学校成绩单**。 |
| `NOT_APPLICABLE` | 触发条件已证实为假，例如纯本地参与记录核验无需外部证书。 | 不产生该项补件，不表示该申请不可办。 |
| `NEEDS_MATERIAL` | **当前已应形成且依法可向材料持有人取得**的关键信息缺失，且不存在已可直接读取的等效可信记录。 | 向正确持有人请求具体 M/位置，注明合法替代；不得要未来 M017/018/019。 |
| `CONFLICT` | 两个当前有效、可读、同一对象/目的/时点的来源结论不一致，或身份、版本不一致。 | 给各原始责任者双向指针；不得用较晚截图覆盖原账，也不以多数票选结果。 |
| `UNREADABLE` | 材料真实已提交，但指定页/表/二维码/印章/表格无法可靠读取。 | 请原材料持有人重传可读件或人工查阅；不得等同材料不存在。 |
| `SOURCE_UNAVAILABLE` | 需要且有资格访问的可信数据源在记录的查询时点故障、拒绝访问或无法取得正式导出。 | 学校数据持有人/授权岗恢复查询或出回函；不得归因学生未上传。 |
| `POLICY_UNCONFIRMED` | 事实可能已明，但**缺当前有效且适用人群明确的校本规范**以确定分类、分值、期限、身份范围或程序。 | 校本制度持有人确认条款、版次、生效链，不得发自动否决。 |
| `NEEDS_HUMAN_DECISION` | 证据链已足以提请有权人处理、行政/组织裁量不可自动化，或签发/授权真实性仍需人工确认。 | 给真实授权机关待办；不是模型建议自动转正为批准。 |

`PENDING_LATER_STAGE`、`STALE_RECHECK_REQUIRED`、`INTAKE`、`WITHDRAWAL_REQUESTED` 等只是**内部流程标记**，不新增对外第九种事实判定码。任一 R 的一个 target 在同一 sourceVersion 快照只有一个主结果，因多种原因可另建不同 `checkKey` 的发现项；不能把源失联和政策未知压成同一代码。事实 `PASS_FACT` 后即使 `R014=POLICY_UNCONFIRMED` 仍不可发分。

### 10.2 最小结果与问题对象合同

| 字段 | 要求/来源 | 隐私与可信限制 |
| --- | --- | --- |
| `caseId`, `reviewRunId`, `planFingerprint` | 来自真实案卷/实际 ReviewRun/冻结审核方案；未发生实际运行时 `reviewRunId=null`，不得造 `run@rev` | CaseAggregate/Main 业务 Owner 生成；Renderer 传入不可作权威 |
| `ruleId`, `checkKey`, `targetKey` | `R001–R032`；`studentStableId/period/project/session/awardEntry` 的最小必要组合 | 批量案逐学生分行，不同学生活动不能共一个 checkKey |
| `applicability`, `resultCode`, `stage`, `evaluatedAt` | 三值条件+本节八态之一，时间含时区 | 只陈述快照预审，不越级决定 |
| `Frefs`, `Mrefs`, `SRCrefs` | 逐条事实字段、材料槽和来源 ID，强制全部能在主稿找到定义 | 按权限输出最小链接，不把含 P3 证据公开给普通查询者 |
| `evidenceRefs[]` | 每项含 `evidenceId`, `owner`, `sourceType`, `sourceVersion`, `hash`, `capturedAt`, `subjectKey`, `objectKey`, `page/row/bbox` | OCR 位置可定位，但 OCR 签名不能作为真实签发身份 |
| `policyRef`, `policyValidity` | 有校本规则时记录文号/条款/版本/生效期间；现阶段允许 null + 原因 | 不能将 SRC-006 上位建议伪装成 CDUT policyRef |
| `factsCompared`, `reason`, `exceptions` | 清楚指明“哪个事实、谁声称、哪个源冲突/失联、是否过期” | 不给出算法臆造的学分和毕业不利结论 |
| `nextActor`, `todoKind`, `dueAtStatus` | 具体权威责任域：学生、主办方、校团委制度持有人、教务、源管理员、复核机关；时间未知标 UNKNOWN | 受权 Actor 由 Host 认证；无校本期限不得设逾期倒计时 |
| `dependsOn`, `invalidation`, `officialDecisionRef` | 依赖的 F/M 版本链；若有真实正式决定仅**引用**其不可变 ID 及效力状态 | `STALE_RECHECK_REQUIRED` 不自动撤销正式 M017/M019 |

对同一发现项稳定键推荐 `caseId + ruleId + targetKey + sourceSnapshotFingerprint`。材料更版会产生新审查快照；旧结果必须可见但标失效，不擦除历史。模板仅提供领域合同，不声称客户端已接好 Main/Case/Run/Decision/Outbox；决策事件应在真实可信 Main 有权路径形成，而非 Renderer 模拟写入。

### 11.2 申请撤回与重提的相容性

1. `H2` 未作决定前撤回申请意愿可记录，但**撤回何时生效、谁受理、是否可恢复、逾期如何处理**全需校本办事制度。在未确认程序时输出 `POLICY_UNCONFIRMED`，对实际处置用 `NEEDS_HUMAN_DECISION`，不自动变案为终结。
2. 学生撤回后以新 M007 重提，必须核：原撤回是否由有权人接受、原案是否已经决定、是同一活动新证据版还是不同项目、是否有有效的申报窗口。可在研究模型中以 `caseRevision` 或新的关联申请表达，但**不擅自断言校方必须重新受理**，不能销毁原申请证据。
3. 原有 M017 后的“撤回”与针对正式结论的“异议/复核”区分；如果诉求是恢复旧分、撤销决定或要求改分，进入 H3 的校本复核路径，不能用仅覆盖本稿的字段改写行政记录。

### 11.3 精确增量重审与正式决定隔离

| 变更举例 | 受影响 R | 不应受影响 | 正式结果如何处置 |
| --- | --- | --- | --- |

### 12.2 自动化边界与强制人工介入

- **可以先研究实现**：合法材料读取、归属标注、原件去重、可信身份查询入口、时点/单位一致性、不同来源互证、错漏提示、R 受影响项增量重审；但前提仍须真实获授权读到对应数据，不能声称系统已上线。
- **不能自动作学校决定**：是否批准二课学分、按何年级采用几分的毕业门槛、是否对外部成果破格采信、是否接受逾期补录、是否撤销已生效结果、复核是否成立、正式成绩单签发、志愿工时换算为学分、创新创业学分/综测/毕业资格的独立裁定。
- **系统失败并非学生过错**：实际未连通平台 `R028` 应记“访问能力尚未确认/授权缺失”而不是“学生不给材料”；学校可提供正式导出或签认回函作为等价来源。对外部敏感证书、多人清册实行按 studentStableId 权限裁剪、最小保存、审计访问。
- **跨政策效力**：校本 2019 学籍办法确于 2020-01-01 起执行（SRC-005），但旧版全文存在**不等于现行无后继**；其第 33 条创新创业学分独立，不能据此填写第二课堂必修要求。国家规范仅给学校制定具体办法的边界（SRC-006/009）。

### 13.2 覆盖复盘结论与未实测范围

1. `A/B1/B2/C/D1/D2/E/F/G1/G2/H1/H2/H3/H4` **14/14 均有显式演练行，共 24 个合成情景**，所有八个主结果语义均在事实层或政策层演示；其中 `NOT_APPLICABLE` 不等于无资格，`PASS_FACT` 不等于学校同意。覆盖是**设计情形覆盖**，不是 2026 校本真实业务办理测试覆盖。
