## 01 唯一审核目的、申请人和负责机构

**唯一目的**：根据赛事组织者的原始报名/获奖/成绩/团队记录和学校掌握的可信数据，核查一名学生对一个明确赛事实体所主张的获奖等级或名次、实际竞赛成绩、队员/队长/指导者等**参赛身份及排序**是否有对应且有效的证据，并形成带来源版本、待核问题和可供有权校内人员签认的**事实认定候选**。

1. **发起**：申请学生本人，或经校内授权的学院竞赛联络人/竞赛负责教师批量代录。跨学院队长可提出队伍事实，但不得冒用其他队员的个人授权。代录记录与个人确认记录分离。毕业后、转学后补录不自动拒绝；对应赛事当年学籍事实需回查可信历史记录（R003）。
2. **有权外部事实主体**：赛事章程指定的全国/省/校赛组委会或正式授予机构对该级别奖项、成绩及纠错/撤销具有原始决定权；校内新闻、导师证明和 OCR 不能改写主办方结果。例如数学建模竞赛全国评奖/公示/最终公告由全国组委会处理（SRC-014、SRC-015）。
3. **校内职责候选**：学校教务处公开科室职责包含大学生竞赛组织实施（SRC-005），具体届次承办学院/教务科/研究生院等可做事实核对。**但校内哪一级可签发统一获奖事实认定、是否存在中央登记主库以及研究生审批归口，目前均无统一公开依据**；保留 `competition_recognition_authority_map` 配置并将签认派给经可信后台验证者。特定学院推免专家审核小组只对该批次推免材料具有其文件列明的权限（SRC-010、SRC-011），不是全校竞赛认定的当然终审机关。
4. **实际签发**：仅有权赛事机构可发布/更正外部获奖记录；仅学校授权校内人员/正式业务后端可签发学校内部认定记录。学生、导师、客户端 Renderer、通用模型只能提供主张或核查建议。

## 03 业务生命周期与办理情形矩阵

### 03.1 状态与可逆事件

`DRAFT → SUBMITTED → FACT_PRECHECK → (WAIT_EVIDENCE | WAIT_SOURCE | DISPUTED | WAIT_POLICY | WAIT_AUTHORIZED_SIGNOFF) → FACT_READY → DECIDED → ARCHIVED`。

- `DECIDED` 仅因校内授权人签认可信 `decisionId` 才能出现；撤回/变更不得抹除原决定。`PASS_FACT` 不导致状态自动变为 `DECIDED`。
- 外部结果独立状态：`NO_RESULT / PROVISIONAL / FINAL / CORRECTED / REVOKED / UNKNOWN`；同届次不同赛段与不同主办方并行存在，**不能用校赛 FINAL 覆盖国赛 PROVISIONAL**。
- `WITHDRAWN_BEFORE_DECISION` 只终止本人的未签申请；已签认结果需要 `CORRECTION_REQUESTED → SUPERSEDED/REVOKED` 的有权更正程序。赛事撤奖为外部事实变更，触发关联事实/下游引用失效通知，并不允许模型直接抹掉学校档案。
- 证据更替：`sourceVersion`/`fileHash`/`participantRosterVersion`/`catalogVersion` 更新时重建依赖图；被影响的 Rule 和其结论失效，未受影响的检查保留。

### 03.3 门槛

提交时先满足“可识别申请人+赛事及届次+所主张事实+可处理的至少一项证据线索”；只有**当前申请情形**要求的材料才列必需。证书未发但正式获奖公告已出，允许官方公告作为合法替代；对赛方只公布获奖不公布分数的情形，不得因缺成绩单退件。赛事尚未闭幕不准按未来的签章/获奖证书进行缺件。延后获取 M017 是审批结果，不是申请材料。

**可信证据优先层级（同一字段同一赛段）**：有验证接口/签章的赛事最终记录 → 官方可追溯的最终公告 → 主办方正式证书（可溯源） → 主办方/承办单位的报名队伍记录 → 学校已签历史成绩/赛事台账（需核对来源） → 盖章的学院核对记录 → 个人证书图/新闻 → 导师/队友说明 → 模型 OCR。低层级不自动覆盖高层级；高层级相互冲突输出 `CONFLICT`，保留两边版本和责任人。组委会没有公开成员排序时，“证书成员展示顺序”不自动等于贡献排名；“队长”也不自动等于第一完成人。

**隐私与授权**：M002/M003 的认证信息仅服务端持有。队伍成员列表按最小必要使用成员学校身份映射 token 与同案角色索引；身份证号、联系方式、完整学籍截图、其他队员不必要隐私默认不采集。公开名单不等于授权抓取后向所有用户展示；团队代录需校方处理依据或当事人适当授权（SRC-002）。原件、证书、公示截图可涉及其他人，访问按 Case/角色/目的审计；跨学校、未成年、学籍状态信息不随意外发。存档版本 SHA-256、sourceURL、取证时间、签发机构、可靠性和处理基础，不存明文口令。

## 09 触发条件、冲突和复合场景

1. **来源与对象优先**：一人一案可有多项 `claimItem`，每项都用自己赛事 `(F007–F012)` 和人员 `(F001/F021/F022)` 绑定证据。不允许将 A 队证书+ B 队名单拼成同一奖。获奖证书与公告矛盾时，优先要求赛方核验，**不在客户端选择对申请人更有利的一份**。
2. **官方结果成熟度**：SRC-014 说明数学建模赛事先公示获奖初稿、受理异议再正式公布；在 PROVISIONAL 阶段可以确认“某版本公示拟获奖”，不能确认“已终局获奖”。其他赛事的公示长度来自**其自己的**通知，不能套数学建模 7 日。
3. **比赛级别双轴**：`F012` 为**赛方赛段**；`F013` 是学校为某用途某年度发布的**校本分类**。2026年成都理工电子设计校赛与“全国大学生电子设计竞赛”不能因赛事品牌名称相同变成全国奖。无校本目录时奖项和成员事实可以先预审，类别输出 `POLICY_UNCONFIRMED`。
4. **个人、团队和角色**：个人赛官方名单直接列个人可证个人获奖；团体奖给团队而个人是否为正式队员依组委会名单；队伍中的队长、队员、指导教师与作品作者、知识产权权利人、奖金分配人均为不同属性。“名单第一列”可能只是排版，不得自动推断贡献度。
5. **同名与跨校**：同名学生、参赛时已毕业、跨校组队（SRC-013 数学建模限定同校但其他赛事可不同）、本科研究生混编必须按当届章程判定。数学建模本科赛事明确不允许研究生参加，不能把这一限制扩展到 2026 研究生创芯或所有学科赛。
6. **多层奖项并存**：同一年度一个队伍可有校赛、省赛、国赛多个真实结果；若 downstream 不得重复计分，它自己在相应 S/T 政策中去重。本模板可以存不同赛段事实，但不能把国赛奖覆盖校赛奖的证据来源。
7. **公示后被撤奖**：组委会撤奖的官方决定证实后，所有同一 `awardFactId` 的旧认定派人工更正，Outbox 记录给下游的 version invalidation。已发奖励是否追回、是否处分属于其他有权业务，不能本模板自行决定。
8. **来源互相冲突**：个人证书写国赛二等奖，组委会现行最终名单写省赛三等奖：`R004/R007=CONFLICT`；即便导师称“肯定拿了”，也不能改为 PASS。若在官方撤奖后还能看到旧网页缓存，不应按缓存恢复奖项。
9. **政策冲突顺序**：全国适用法律/赛事主办方奖项事实/学校当期适用分类决定分别在各自权限内有效；对于校内用途，已发布且适用时间相符的学校规定优先于学院细则，具体批次学院细则只能在已授权范围内补充；跨校文件不参与裁决。学校旧版与新版时效矛盾派 `POLICY_UNCONFIRMED` 由制度持有人确认，绝不自创“新法覆盖旧法”的细节。
10. **一案多问题**：身份可信服务临时失联与证书扫描件不可读可同时发生，输出 R003 `SOURCE_UNAVAILABLE` + R005 `UNREADABLE`；补证只触发证书相关规则，身份重连仅触发身份依赖。

## 10 结果状态、问题与待办输出契约

每条输出为独立 `Finding`，禁止把“材料总体不合格”当作只有一句话的结论：

```json
{
  "caseId": "synthetic-case-001",
  "templateId": "S06-T03",
  "claimId": "synthetic-claim-1",
  "target": {"competitionKey":"contest-x", "edition":"2026", "round":"campus", "teamKey":"team-1", "subjectToken":"student-1"},
  "ruleId": "R010", "status": "NEEDS_MATERIAL",
  "problemCode": "TEAM_ROSTER_PERSON_UNVERIFIED",
  "evidenceRefs": [{"materialId":"M006","fileId":"placeholder","fileVersion":2,"sourceVersion":"official-unknown"}],
  "facts": {"claimed":"本人为获奖队员","verified":null},
  "nextActorRole": "student_or_authorized_college_clerk",
  "task": "提供本届本赛段官方队员名单或请赛事联络人发起核验",
  "humanDecisionRequired": false,
  "scope": "fact_precheck_only",
  "issuedDecisionId": null
}
```

| 结果语义 | 典型本 ID 场景 | 问题码示例、下一个办理者 |
| --- | --- | --- |
| `PASS_FACT` | 赛事正式结果/个人在队伍中被官方列明 | `FACT_EVIDENCED`；进入下一条规则，仍不得给“已校方批准”标志 |
| `NOT_APPLICABLE` | 个人奖无需团队名册；仅竞赛事实不触发学分政策 | `SCOPE_NOT_TRIGGERED`；无补件 |
| `NEEDS_MATERIAL` | 本人确主张队长，但无当前可核实角色证据 | `TEAM_ROLE_SOURCE_MISSING`；本人/赛事联络员定向补件 |
| `CONFLICT` | 成绩、奖名、赛段或本人名单与权威记录不符 | `AWARD_LEVEL_CONFLICT`、`ROSTER_IDENTITY_CONFLICT`；有权赛事联系人/学校审核人 |
| `UNREADABLE` | 提交的扫描件反光或文件损坏 | `CERTIFICATE_UNREADABLE`；上传者重传同槽 |
| `SOURCE_UNAVAILABLE` | 官方颁奖页面 412、查询 API 断线、历史学籍服务离线 | `ORGANIZER_SOURCE_OFFLINE` 或 `STUDENT_HISTORY_OFFLINE`；来源管理员/学校档案员，不得让学生反复传同一个有效 URL |
| `POLICY_UNCONFIRMED` | 没有该年赛事分类目录、适用学院/学段签批权限表 | `SCHOOL_CATALOG_UNCONFIRMED`；有权政策负责人 |
| `NEEDS_HUMAN_DECISION` | 非官方角色争议、只凭陈述认贡献、最终学校签认 | `CONTRIBUTION_REQUIRES_REVIEW`、`SCHOOL_SIGNOFF_PENDING`；有权业务人 |

每个待办带 `ruleId`, `materialId`, `targetKey`, `expectedSourceAuthority`, `sourceVersion`, `deadlinePolicyId?`, `scope`, `assignedRole`, `retryKind`。界面可在案卷工作区的“问题→材料→方案→决定”内直接定位；同一证书可能被 R005/R007 引用，但展示时只能按**同一槽/相同缺失原因**合理聚合，不能抹去规则级来源。`PASS_FACT` 与任何风险并存时，严格限定它通过的事实范围。审查结果不以“用户点击确认”或 20 秒模板自动选中视为有权学校签发。

## 11 补件、撤回、版本更新、复核与人工决定

1. **补件事件** `MaterialUploaded(M,version,hash,claimId,owner)`：新材料不能覆盖旧附件字节，旧 fileId 保留审计；新版本只使依赖 M/F 的 R 标记 stale。证书补图重跑 R005/R007/R009，不重跑无变化的身份 R003；官方团队名单补正重跑 R010/R011/R015/R017。
2. **来源纠错** `OrganizerResultChanged(eventKey,edition,round,sourceVersion,state)`：只信组委会正式更正/撤销或可信学校来源核查，必须记录来源签发/生效时间。回溯本项 `awardFactId` 的已签决定，对后续 S03/S05/S07/S08 引用发 invalidation，**不直接撤销其下游奖励或改成绩**，由各事项授权人决定更正。
3. **撤回** `WithdrawRequested(actor,caseId,reason)`：认证是本人或有权限代理、当前尚未签认才可撤回未签案；如已签认，转更正/复核申请，不物理删档。其他队员撤回自己 claim 不自动抹去全队事实。
4. **争议与申诉**：申请人可提交对名单、排序、分数、签认事实的争议证据 M015；赛方奖项异议由该赛事有权组委会处理（SRC-013/014，期限见该届规则），学校个人事实记录由校内指定有权部门复核。不得从教育部令第41号直接推导全部竞赛都有同一个申诉时限。复核成立后新增 `revisedDecisionId`，保留原签发及送达轨迹；不成立则保留原决定并记录理由和权威凭证。
5. **学校决定** `SignRecognition(authorizedActor,PlanFingerprint,CheckVersions,decisionTarget)`：冻结本次全部事实检查的 `sourceVersion + hash + policyRevision + claimTarget`，CAS 核 `CurrentCase/ReviewRun`，主端验证角色后单次写 `Decision`，再发 Outbox。Renderer 不持写权；回放旧 `run@rev` 不能代替新 Plan；Batch finalizer 必须关联 entryRunId。**这是研发接线合同，不宣称真实学校已授权**。
6. **回滚与并发**：同一 `awardFactId` 的变更不能以最后上传胜出，必须有可信最新权威结果与有权签发。网络重试幂等 `idempotencyKey=(caseId,claimId,sourceVersion,decisionAction)`；请求超时显示未知状态，不伪报“审批成功”。纠错必须通知所有仍持旧 revision 的订阅消费者。
7. **审计与隐私**：仅授权者可读取与其任务有关的学生/他人队员信息，保留处理基础与访问日志。客户端可导出匿名化问题报告供本人申诉，内部数据的导出权限由有权管理员控制；敏感原件不得用于公开模型训练。

## 12 校本配置、未知事项和不能自动裁定的边界

| 配置 ID | 尚缺的校本证据或选择 | 类型/默认安全值 | 有权确认/上线条件 |
| --- | --- | --- | --- |
| P01 `recognition_authority_map` | 谁可终审本研/跨学院的统一奖项事实；授权委托、盖章/电子签 | 角色 × 学段 × 学院 × 赛事 × 批次；默认 `NONE` | 教务处、研究生院等实际主管以校本正式文件确认；无则 `NEEDS_HUMAN_DECISION` |
| P02 `competition_catalog_by_year` | 赛事是否在各年度正式认定目录、版本、生效起止与例外 | 签发目录；默认 `UNKNOWN` | 学校有权竞赛分类管理部门；不得以竞赛排行榜直接套校内类别 |
| P03 `classification_mapping` | 国际/国家/省/校赛段、A1/A2/B1/B2/C 等校本等级如何换算 | 赛段与校本类别双字段；默认 **不换算** | 学校当期已签制度；不能用 SRC-010/011/012 跨院跨年推断 |
| P04 `roster_role_policy` | 队长、排名、正式参赛人和贡献度的授权证明何者有效 | 官方名单优先，贡献争议 `HUMAN` | 赛事规则 + 学校适用用途的有权专家 |
| P05 `record_scope` | 本科/研究生、校友补录、非全日制、跨校联合队伍的允许范围 | 不默拒、不自动通过 | 主办方对该届身份规则 + 学校有权职能部门 |
| P06 `official_source_registry` | 哪些颁奖网站、API、公章、电子证书签名及历史缓存可信 | 白名单/签名/网页快照；默认待核 | 组委会和学校信息系统管理员；不得仅靠域名字符串或 OCR |
| P07 `filing_deadlines` | 学校录入/补录/申诉时限与赛事自身公示期区别 | 分赛事、届次、受理阶段；默认 `UNKNOWN` | 赛事组委会与学校分别确认；SRC-004 两天仅对应该届校赛 |
| P08 `downstream_binding` | 什么用途可消费事实、是否含赛段和排序要求 | 按签认记录+revision 授权只读；默认不推导收益 | S03/S05/S07/S08 业务主体分别定义 |
| P09 `withdrawal_reconsideration` | 校内已签竞赛认定的更正/申诉路径和处理人 | 暂只开放人工待办与日志 | 学校有权主管发布规则 |
| P10 `personal_data_authority` | 团队成员数据采集、批量导入、跨校核验的数据处理依据和保留期 | 最小必要、不导入不必要身份证信息 | 学校数据控制者完成保护评估/授权 |
| P11 `provisional_result_policy` | 是否允许“待最终公告”的临时事实记录对外展示及如何标注 | 只可显示 PROVISIONAL，不签 FINAL | 赛事结果状态可信适配器+校内主管 |
| P12 `revocation_propagation` | 撤奖更正后哪些下游决定需通知、如何通知与复审 | 失效通知不直接改其他案卷 | 各消费业务授权人与审计后端 |

**原则性禁止自动化**：未获公开明确授权时，AI 不得决定赛事奖项真伪的最终处罚、擅自更换组委会名单、授权校内事实认定、确认贡献排序有奖学金/推免加分效力、计算奖金/转账、签发奖状、处分人员、撤销已签校内决定。历史 `SRC-010/011` 的 2026 届推免规则以及 **2027 年 1 月才生效的 `SRC-012`** 是最容易错用的三份材料。
