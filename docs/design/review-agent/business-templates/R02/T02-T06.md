## 01 唯一审核目的、申请人和负责机构

### 01.1 本案决定对象

唯一事务主键建议为“**真实教职工身份 × 被考核的具体岗位/约定任务 × 聘期起止与政策批次**”。本模板要回答的是：“已有的聘期合同/任务约定以及人事、教学、科研等权威记录，能否形成供考核组织审议的完整、可追溯的事实材料；是否发现需要补件、解释、核实、回避或正式人工决定的事项？”不是凭单一积分或材料齐全判定续聘。

可预审的事实类别（不是本轮确定的必交材料）：

- 人员身份、任职类别/等级、聘用单位、岗位存续和聘期起止；特别注意“双肩挑”、不同岗位类别、岗位中途变动及转入转出单位（SRC-001 第 6、10–13 条及附件 2 为历史形式；SRC-009 第 38–39 条为上位处理框架）。
- 本聘期经双方确认的岗位任务书、聘任合同及依法有效的调整版本；年度考核已形成的正式记录和有权部门出具的成果、任务认定结果（SRC-001 附件 1–2；SRC-009 第 18、22 条）。
- 是否存在尚未核实的履约原因、专项考核、申诉/复核、回避、争议、岗位撤并、退休等需人工处理情形；本轮不作负面推定。

### 01.2 申请人与提交人不是天然等同

- **被考核对象：** 与学校存在相应聘用关系的教职工；适用与否须从组织人事权威记录认定。2019 校本办法明示适用于事业编制教职工，人事代理人员可参照，属于**历史口径**（SRC-001 第 5、16 条），不得扩张为对所有编外合同工的现行统一规则。
- **可能的发起主体：** 学校/单位按批次组织考核，个人总结述职并提交个人证据；也可能由本人在合同到期前表达续订意愿。两者来源和授权不同。不能仅因页面有“申请人”字段就假设业务完全由个人在线发起（SRC-009 第 18、22、32 条）。
- **代理/经办：** 单位人事经办、受托人员可能协助材料报送，但需经单位实际授权。无权代理不能代本人同意续聘或代有权机构作考核决定。历史合同说明特别强调合同双方依法签署（SRC-001 附件 1）；现行授权清单待查。

### 01.3 归口、审议、最终决定

1. **归口候选：** 党委教师工作部（人事处、教师发展中心）。2019 文件将学校岗位工作组日常机构设于该部门并由其负责解释；人事处现行网站展示相关部门、服务电话（SRC-001 第 9、19 条；SRC-012）。这能确认归口线索，**不能确认 2026 年每一级考核档次的签发者**。
2. **单位初审候选：** 各单位（部门）岗位设置与聘用工作小组，历史职责包括制定实施细则、岗位聘用及考核（SRC-001 第 9–10 条）。现行组织名称、审议权限和签章要求待新版校规/本期通知确认。
3. **法定层级：** 事业单位/主管机关（部门）按干部人事管理权限实施考核，考核档次应按规定由相应领导班子或主管机关组织人事部门集体研究审定；聘期考核程序含述职、测评核实、实绩分析与确定档次（SRC-009 第 2、17、22 条）。对干部/领导人员另按有关规定，不由本模板自动套用普通岗位流程。
4. **续聘有效行为：** 聘期合格和岗位存续也仅是续订的相关前提；还需本人、单位协商一致及规定程序。聘期不合格的特殊续聘需主管机关（部门）审核同意（SRC-009 第 32 条）。模板的预审 `PASS_FACT` 绝不是考核档次、岗位续聘授权、劳动/人事合同成立或人事档案记录。

### 03.3 阶段依赖的证据分类

- **原始约定类：** 岗位聘用关系、合同、约定任务书及合法变更，适用于 L1 后；先有约定，后比对履约。
- **履约过程类：** 逐年度教学/科研/社会服务/管理等事实，逐项记成果来源、所属年度及归属关系，随 L2/L3 累积。
- **评议决定类：** 测评建议、考核组织定档、结果通知、复核/申诉结论和续聘合同，分别在 L4–L7 产生，不回溯要求早交。
- **不能预设的凭证：** 新版工作量/积分阈值、免考豁免、业绩折算、成果分类细则、电子签章样式、续聘审批表；须校本现行文件确认。

### 03.4 最小材料不是重复上传

- 每个分支的最小当前资料应按顺序尝试：①校方可确认的权威台账/正式记录（若实际授权查询可用）；②人事或所属单位核实的记录引用/办理回执；③本人持有的正式文件或扫描件，在真实性未核前标为待确认。**没有已核实接口时不得假装“已从系统取到”。**
- 对 `M002/M003/M004/M006/M009/M013/M015` 这类人事或业务主管方持有的文件，系统内若有权威结果则记录来源定位符、时间和证据指纹即可；不应向本人索取相同事实的再次上传。若系统未开放，由授权经办核源，不构成对教职工无条件补件。
- 系部、学院、不同校区、事业编与专项聘用不是“学段”差异。本业务涉及的是**教职工人事身份和岗位类别**；学生本科/硕士/博士学段不构成本模板申请人分支。与教学/研究生培养有关的学生材料只可能作为任务成果证据，绝不可混成学生审核。

### 05.2 可信身份和证据验真

- 权限主体必须由 **Host/Main 可信登录会话、学校人员与岗位权威台账、服务端授权检查** 联合确认；Renderer 上传的 `actorId`、`teacher`、`department`、`approver` 字段，以及 PDF/图片上的签名/OCR 内容均为**待验证输入**。不能据客户端自报字段建立批准权限。
- 重要动作至少记录：`caseId`、可信用户/组织标识、授权岗位与审批范围、批次/政策版本、所作用聘期与人员、动作类型、时间、证据指纹、前后状态、正式签署/回执标识。**正式决定由外部有权系统/签批结果导入**，预审 Run 不得充当“真实考核 Run/正式决定”。
- 多单位、跨岗位、任务变更时，记录原始事实的来源部门及权威版本，不以个人上传的同名材料覆盖官方数据；不能让多个入口分别写一套“当前聘期结论”。
- 工作量/成果量可做机器核对，但“正当理由”“绩效质量”“师德表现”“岗位存续”“例外续聘”等需人事评价、调查或行政裁量的事项一律标记 `NEEDS_HUMAN_DECISION` 或 `POLICY_UNCONFIRMED`，不得自创一票否决。

### 05.3 权限、隐私、争议控制

1. 教职工身份证号、合同待遇、健康和病休、处分与投诉、人员档案等按需最小化展示；前台可使用脱敏稳定标识，敏感材料按角色分级访问并留审计轨迹。材料提供给 AI 的范围按学校数据治理授权另核。
2. 有利害关系的考核、审批与人事争议处理人员必须走回避校验（SRC-008 第 39 条；SRC-001 第 14 条历史规范），**模型发现风险只能提示**，不自动作人事回避决定。
3. 复核或申诉期间保留争议标记、原决定与每次补证历史；不擅改已签发原结论。国家条例和考核规定保障复核申诉权（SRC-008 第38条；SRC-009 第36条），SRC-016 第12条规定依法适用人员的通常 30 日时效与正当延期，**但本人的知悉/送达、申请种类、实际管辖机关及特别法适用须核证**，不能直接由系统拒收。
4. `PASS_FACT` 只表示被检查的单项事实通过核对，不等于聘期“合格”；`NEEDS_MATERIAL`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED` 等不可被兜底模板转换为“学校同意续聘”。

### 05.5 数据可见性、签发与失效传播

- 隐私分级：`P0=一般内部业务元数据`、`P1=个人岗位/履历/成果信息`、`P2=敏感人事、考核意见、健康/处分/争议、合同待遇或证件号`。禁止把 P2 原文给没有该目的权限的单位经办、无关学院或通用模型；字段表写明默认级别。
- 来源优先序**不是盲目覆盖**：正式校级/归口人事记录、原签发部门的业务决定优先于本人扫描或旁证；存在两个均声称有效的正式版本，应记录为 `CONFLICT` 并核原机关，不按上传时间“最新即胜出”。
- 外部 G50、T02-T03、T02-T04、G05 等权威结论只存引用键、效力、来源和所辖人员/时间；本模板不再签发岗位/职称/出访许可。无法读取外部结论应 `SOURCE_UNAVAILABLE`，不得用内容相似的用户图片制造权威结论。
- 新增、撤换 `M003–M011/M025` 时重算与其映射的 `F`（及下一轮 `R`）的事实版本；任何此前 `PASS_FACT` 仅对旧证据版本有效。若已发生 L5/L6 正式决定，只提醒有权人事机构可能需要正式更正/复核，不直接修改签发原件。
- 官方审批人身份应与 `M022` 所指授权链/系统名单匹配，检查真实人事关系、机构调整与回避风险；不允许 Renderer 传入的 `approvedBy` 决定最终结果。敏感病休/产假材料只保留“依法确认的状态、期间、决定来源”供事实核对，除有权限必要场景不留诊断全文。

## 06 业务对象与字段字典

### 06.1 对象结构和取值语义

`Case`（一次事实预审案卷）→ `Subject`（可信教职工身份）→ `AppointmentEpisode[]`（某岗位/单位/起止期间的分段）→ `ContractVersion[]`、`TaskVersion[]`、`AnnualResult[]`、`AchievementClaim[]`、`AuthoritativeRecognition[]` → `AssessmentDecision`（后续正式决定引用）→ `RenewalDisposition`（后续双方/主管机关续聘结果）。同一教职工跨聘期不同案卷，不以同名同姓合并；双岗位可在同一聘期对应多个岗位分段与考核子结论。

- `未知` 不等于 `false`/零/不合格。日期不清、身份未核、政策版本不明、校本阈值缺失时保留三态并输出人工待办。
- `可信来源` 列中的“人事台账（待开放）”“业务系统（待开放）”仅指**拟向持有者核取的权威数据**，不是已证实 API。来源暂不可取时通过获授权经办人员复核正式文书并留下回执，不能伪装系统成功调用。
- `材料位置` 使用第 07 节的材料槽 `Mnnn.字段/区域`，或受控系统内部元数据 `Case/Batch`。个人自述默认不是有效官方考核结果。
- 缺失动作中“补正”仅要求该材料的合法提供者补正；涉及机构持有资料，原则上向机构核源，不直接向本人强行索件。

## 07 材料槽与证据目的

### 07.1 材料状态与最小化原则

以下是**证据目的导向的槽位设计**，不是学校公布的现行“必交材料清单”。`当前必要` 表示要完成该阶段事实预审，必须有相应可信事实或可验证的空值原因；不等于由本人上传。`条件必要` 仅在情形触发后要求有关责任主体核取。`后续生成` 在 L4–L7 相应动作之前不可要求提交。`系统记录` 是审计/版本证据，不是个人附件。`无可接入来源` 与 `本人未上传` 必须区分。

替代原则：同一事实若已有授权读取的原签发部门电子记录/核验回执，可合法替代纸质复印件；扫描、OCR、截图在未核发文单位前只是待验证证据；上位文件并未统一授权用某种非正式截图替代原件。每个 M 的“缺失”优先向**持有人/原签发者**核源，“不可读”需定位文件/页码/范围并申请该持有人重采，不能默认不合格。`M001` 的本期文件不存在可用副本时，停止政策阈值判定，而非让教职工自行编造文件。

### 07.3 材料层级、责任与“零上传”可能性

1. **先核权威主档，后接个人述职。** `M002–M004/M006` 可以由真实校方档案或获授权人事核源取得；若确实有可用、获授权的电子台账，申请人可不上传这些文件。`M007` 的本人陈述可能确需本人确认，但具体官方表式待 SRC 缺口补齐。
2. **证据引用优先于复印。** `M009` 引用教务/研究生院验收、`M005` 引用 T02-T03 岗位调整；不重复审批相邻业务。因未核到 G50 catalog，暂不承诺某具体 Gxx 槽有相同语义。
3. **有条件才取敏感件。** 例如近退休、外派、病休的 `M010/M011`，只在相应 F 条件成立时使用；优先读取人事“已核准期间”而非要求病历原件进通用审核库。
4. **后形成的文书不得前置。** `M012–M020` 按 L4–L7 逐步出现，例外 M019 可在正式考核后的争议发起；提交初始 L2 材料时一律不把未来考核结论、续聘合同、主管批准、复核决定作为未交件。
5. **“目前没有材料”分三类：** (a) 应由本人出具但尚未提交：`NEEDS_MATERIAL`；(b) 学校签发记录当前无法取得：`SOURCE_UNAVAILABLE` 或待归口核源；(c) 尚未到形成阶段：`NOT_APPLICABLE`（当前）并登记未来触发条件。旧版/新版政策冲突另为 `POLICY_UNCONFIRMED`。

## 08 审核规则逐条清单

### 08.1 规则运行约束与触发三态

- `T` 表示该规则的独立事实对象/办理阶段**确实适用**，进入比较；`F` 表示有可靠反证证明该分支**不适用**，只对这个规则发 `NOT_APPLICABLE`；`U` 表示是否适用本身尚未证实，必须生成核实待办，不能把 `U` 当成 `F`。表中“触发 T/F/U”均须在具体 `Case+Subject+AppointmentEpisode+policyVersion+evidenceVersion` 上求值，不对不同聘期共用缓存。
- 命中 T 不等于 `PASS_FACT`：仍要经过证据来源、归属、内容可读性、生效时间、相互一致性等检查。`PASS_FACT` **仅针对所列的最小事实断言**，不累计推出“完成考核”“合格”“有续聘资格”。缺校本政策时，即使合同和成果齐全，凡依赖政策的结果仍为 `POLICY_UNCONFIRMED`。
- 一条规则可以针对不同 `targetId`（某岗位、任务条目、年度、成果、人员）生成多条独立 `Check`。每条 `Check` 单一结果码；不同规则不相互覆盖。跨规则汇总只聚合问题/待办，不按优先级强行合成一个校方决定。
- 取证顺序：原签发机关/可信业务记录及核验回执（权威）→有签章且待核源的原件扫描（候选）→本人陈述/截图/OCR（线索）。正式版本冲突先 `CONFLICT`，不可盲选时间最近者。`SRC` 栏只是该检查**为什么合理的依据**；具体某人的有效权利义务仍要看 `M001/M002–M025` 的真正生效文件。
- 表中“缺”指到**当时应形成的材料/事实**；后续才生成的一律 `NOT_APPLICABLE`（当前阶段）并设置将来触发。`SOURCE_UNAVAILABLE` 是原权威来源查不到；`UNREADABLE` 是已取得原件但相关区域无法识别；二者不是本人没上传。授权、校本阈值、正当理由与实质评价不得由计算规则决断。

### 08.4 独立规则去重与阶段可达性复核

1. `R001–R029` 唯一连续，按“批次—身份—聘用关系—任务—履约—权威决定—救济”划分，不建立重复的“人事综合合格”规则。`R017` 检查证据可读、`R018` 检查版本影响；新增 `R028` 逐任务履行事实、`R029` 正当理由的有权认定，补齐 SRC-009 第20–21条最敏感的误判边界。
2. 独立决定边界：`R005/R008` **仅核已签岗位/变更**，正式岗位聘任归 T02-T03、跨单位流转归 T02-T08；`R013` 只引用教务/科研/研究生院等原批准，职称归 T02-T04、外事归 `g05-t04`、实际任课资格归 `T06-T04`；`R020` **读取**聘期档次而不定档；`R024/R025` 读取主管机关核准和双方合同而不批准或代签。R02 主目录与 audit 已实际核对，但 G50 冻结 JSON **未直接取得**，不能冒称完成 G50 源码逐条核验。
3. 到 L2 的可达规则主要 `R001–R018`（部分条件触发）；L3–L5 才评估 `R028/R029`，L4 才要求 `R019/M012`；L5 才可能 `R020–R021/M013–M014`；L6 才要求 `R022–R025/M015–M018`；收到异议或撤回才 `R026–R027/M019–M021`。R002/R004/R017/R018 横跨阶段；没有未来文书的 L2 不自动报缺。
4. **不能替代的人事裁量：** 即使基础事实以及 `R028/R029` 的部分证据 `PASS_FACT`，没有真实当期目标、授权评价和正式审定也无法判定目标是否完成、正当理由是否成立、聘期档次、岗位存续、是否续订；这些仍待人事考核组织依 `SRC-008/009` 和真实校本文件决定。上位《考核规定》第20–21条的“应当定档”规范受权单位，不是模型定档授权。

### 09.2 身份、版本、材料冲突协议

1. **身份主从。** `F005` 来自人事权威人员主键，`F006` 是展示名称。若本人上传的 M007 姓名为“张某”、M003 为“张某某”、M002 为另一个同名职工号，应先核更名/别名及真实合同当事人；**不准以姓名相近或身份证 OCR 自动合案**。显示 `CONFLICT`，人工补证或核人事主档。
2. **岗位/合同主从。** `M002` 权威岗位任命决定与 `M004` 聘期任务书按约定版本生效；`M003` 合同是合同关系及期限的权威。若 2024 起四年岗位任务与三年劳动合同同时出现，分别记录 `F010/F011`，不把合同日期改写成四年，也不直接宣布某一份失效（SRC-001/007/010）。
3. **任务版本。** M004 旧任务书被 M005 合法变更，只对生效日后的 `F014` 条目使用新目标；变更前事实保留旧目标。缺变更签发和同意记录不能让个人新上传的“调整版”覆盖原签署任务书。`M024/F042` 记替代链，旧预审 PASS_FACT 因版本变化失效。
4. **成果归属和合法重复使用。** M008 的一个论文/项目/课程可用于多个任务事实陈述，但能否重复计分应以有权细则为准；`F021` 保留人、岗位、年度、贡献角色，`F022` 必须有正式认定。不同案卷引用同一 `M009` 时保留相同权威 ID，不生成两个不同“已认定成果”。无法获证评分规则时 `POLICY_UNCONFIRMED`。
5. **评议与最终决定。** `M012/F026` 是单位建议；`M013/F027` 才是由有权组织形成的正式档次；`M016/F017+F030` 是意向/协商；`M018/F032` 是合同签署完成。四者不可互代、不可由 Renderer 传来的“审批人”自动触发。
6. **来源失联与不可读不同。** `SOURCE_UNAVAILABLE` 指无法获取学校/原业务系统或有效核验路径；`UNREADABLE` 指已取得文件但特定页/字段不可辨；`NEEDS_MATERIAL` 指由当前负有提供责任的人尚未提供应有文书；`POLICY_UNCONFIRMED` 指找不到现行办法/阈值；`CONFLICT` 指相互矛盾的两个有效候选证据。每项保留责任主体与下一动作。
7. **跨系统结论变更。** 若 T02-T03 撤销原岗位决定、研究生院更正 M009 的项目验收、年度考核复核改变 M006，则将由其派生的 F009/F019/F022/F024 标为待重审并生成具体影响清单。已正式定档的 M013 需有权人事机关评估是否更正，**本工具不自动撤销正式人事决定**。

## 10 结果状态、问题与待办输出契约

### 10.1 单条 Check 的八种互斥状态

以下为**事实预审状态**，不是“人事审批状态”。单一 `Check(ruleId,targetId,sourceVersion)` 恰有一个当前状态，且必须保留原输入和判定理由；多项问题只能建多条 Check，不得把状态码拼成含混的“部分通过”。

| 码 | 恰当含义和必要前提 | 不能这样使用；下一动作 |
| --- | --- | --- |
| `PASS_FACT` | 针对明确的小事实命题，有适用且已生效、可读、归属可信、无有效反证的证据；只表示该事实核对一致，如“2025年度考核结果记录存在” | 不能表示聘期合格、准续聘、学校审批通过；需要正式人事定档仍生成下一阶段人工办理 |
| `NOT_APPLICABLE` | 可靠事实证明**该条规则或材料在当前身份/情形/阶段不适用**，记录触发条件为 F 的依据 | 未取到记录、未来尚未到阶段、本人无上传不能一概当“不适用”；未来阶段标计划触发并保留规则 |
| `NEEDS_MATERIAL` | 当前阶段确已形成、提供义务明确的**本人或授权提交人**材料尚未提供/需要补正 | 校方已持有的合同、档次、签批不得随意让本人重复上传；待办直达本人/合法代报者与具体槽位 |
| `CONFLICT` | 两份均可能有效的证据在人/岗/期间/目标/权威状态上实质不一致，或身份/版本/签发链相矛盾 | 不能自动以“最新上传”胜出；待办交原签发机关/人事核冲突和生效版本 |
| `UNREADABLE` | 文件或权威副本已获取，但所依赖页/字段/签章区域无法读出，记录确切页、bbox、原因 | 不能推成政策不合格；请求持有人重采，其他可读字段的 Check 可继续 |
| `SOURCE_UNAVAILABLE` | 应从原持有机构/权威系统取得的记录目前不可达、无授权读取或查无核验通道，须区分“系统离线”和“官方未生成” | 不等于申请人未交或权威记录不存在；交原机构/系统管理者核源并保留重试依据 |
| `POLICY_UNCONFIRMED` | 事实可能可核，但计算资格、范围、期限、阈值或例外所需的**现行本校**依据缺失、冲突或时效不明 | 禁止把 2019 三年、改革报道四年、外校积分线硬编码；归口人事提供新版政策/解释后重评 |
| `NEEDS_HUMAN_DECISION` | 事实层已到有权组织审议/判断或核签的边界，或者正当理由、考核档次、岗位存续、续订、撤回效力和申诉结论需正式办理 | 不得让模型、Renderer、自填 approver 或普通经办代替校方签发；派给具有真实权限的组织/人员 |

**分流优先次序不是结果码高低排序：** 先判断当前阶段能否触发（若明确 F 则 `NOT_APPLICABLE`）→核材料是否确应由本人提供→核是否已产生且可取/可读→核来源权威、归属和证据版本→核是否存在现行政策→核是否要正式组织决定。任一关口有两个独立问题时分别开 Check 或待办；例如 M004 页损与 M001 政策缺失可在 `R007` 与 `R001` 并存。已签约的事实 `PASS_FACT` 不覆盖未取得当期政策的 `POLICY_UNCONFIRMED`。

### 10.2 结果对象与问题定位结构（设计契约，未证明客户端实现）

每一 `CheckResult` 最少须携带以下键及用途，禁止只返回一段 AI 总评：

| 键 | 约束 |
| --- | --- |
| `caseId, templateId, catalogRevision, batchId, policyRef` | 固定 `T02-T06/R02`，指向真实批次及已核政策版本，未知可空但显式 `POLICY_UNCONFIRMED` |
| `subjectRef, appointmentEpisodeId, contractVersionId, taskVersionId` | 通过可信人事主键与具体岗位/聘期/约定版本绑定；P2 权限管控 |
| `ruleId, targetId, stage, triggerValue` | 对应 R001–R029，`triggerValue∈{true,false,unknown}`；target 精确到人员、岗位、年度、任务条、正当理由争点或成果记录 |
| `resultCode, factAssertion, expectedEvidence, observedFact, comparisonBasis` | 明确最小事实命题、比对方法和法律/校本依据；未核的值不得伪造 false |
| `srcIds[], fieldIds[], materialSlots[]` | 引用真实 SRC/F/M；包括适用性和时效状态，不能仅以 URL 标题当正式政策 |
| `evidenceRefs[]` | 每条含 `materialId, holder, issuer, subject, issueTime, effectiveFrom/To, sourceVersion, hash, pageOrRegion, verificationStatus`；无法核源则显式不可达 |
| `dependencyFingerprint, evaluatedAt, runId, staleSince` | 标记冻结的输入版本与真 Run，后续重审可判过期；不能拿旧 `run@rev` 冒充本次审核 |
| `issueId, taskType, responsibleRole, authorizedActorRef, dueAt, dueSource, status` | 待办必须有目标责任人/机构、实际期限来源（未知则 `null`）、办理状态和通向当前案卷的问题/材料链接 |
| `humanDecisionRef, decisionAuthority, signedAt, appealState` | 仅导入真实有权签发的外部决定，区分 `suggestion`、`assessmentDecision`、`renewalDecision`、`contractSigned`、`appealDecision`；事实 Check 无权生成 |

两个直接约束：① `CheckResult.resultCode` 与“人事最终决定”是**不同字段/来源域**；② 每份 M 的旧/新版本皆保留，`oldEvidenceRef` 和 `supersededBy` 表示来源变化，不将原记录删除或回写后期决定。

### 10.3 输出层次与办理状态

1. **单项事实层：** 所有 R 对独立 target 给出八选一状态和证据坐标。即使全部为 `PASS_FACT/NOT_APPLICABLE`，只可出“本轮已核事实项”，不能显示“考核通过/续聘获准”。
2. **问题层：** 将同一缺失/冲突的多个 Check 汇总到一个可办理 Issue，但保留 `affectedRuleIds` 列表；例如 M004 第3页不清同时影响 `R007/R012`，可以发一项补清晰页的待办，不抹掉各自核验记录。
3. **案卷办理层：** 设计工作态 `DRAFT → FACT_COLLECTION → FACT_REVIEW → READY_FOR_HUMAN → HUMAN_IN_PROGRESS → DECISION_REFERENCED → CLOSED`；任何状态可进入 `ON_HOLD_POLICY/ON_HOLD_SOURCE/REWORK_REQUESTED`，其中 `READY_FOR_HUMAN` 只表示事实包可送审。具体校本审批节点由 M001/有权机关配置，不声称存在同名线上流程。
4. **正式决定层：** `AssessmentDecision`（聘期档次）、`RenewalDisposition`（是否续订及例外批准）、`ContractSignature`（实际签署）与 `GrievanceDecision`（复核申诉处理）分开引用。只有原机关核发的签章、正式接口/回执经过授权核验，才能更新此层。任一裁定可能存在而其他仍未完成。
5. **办结限制：** 可把本次**事实预审**标为完成，不得把校方尚未审议案件标 `CLOSED_APPROVED`；正式决定尚未生成时应呈现“事实预审完成，待学校办理”。复核中保留原决定和救济未决状态，不自行表示已撤销。

### 11.3 撤回、复核的范围不可混用

- `撤回个人附件/更正事实`：只影响该 M/F/R，具体受理依据仍待校本确认；`撤回续聘意愿`：不等于撤销学校发起的聘期考核，还须核合同效力。`撤回复核/申诉/再申诉`：SRC-016 第17条要求在处理决定前书面申请，受理单位可决定终结；SRC-017 第16–17条进一步明确申诉/再申诉书面审查、终结通知及**同一事由不得再提**。这些程序不同于普通事实材料撤回，不能用同一 UI 无差别自动执行。
- `复核聘期考核档次`、`申诉处理`、`岗位聘用争议`、`合同争议` 是不同救济对象。依法适用 SRC-016 的情形一般有 30 日申请期限、不可抗力或正当理由经批准可延长，且复核由原处理单位管辖、申诉另依该规定确定机关；**只由有权机关判断起算和是否准延/受理**。T02-T03 的岗位决定复核、外部司法/仲裁等仅引用权威结果。无有效知悉/送达凭据不能自动提示“申诉逾期”。
- **正式决定可信门禁：** 需原签发机关 ID、合法人员/机构授权、被考核者和聘期、决定文号与生效日期、核验成功的签章/正式系统回执、复核/撤销状态；任何缺项停在 `NEEDS_HUMAN_DECISION`/`SOURCE_UNAVAILABLE`，不生成合法决定。

### 12.2 不可自动裁定及人工责任

1. `SRC-001` 是 2019 历史校规，`SRC-003/007` 指向后续改革但不是新版制度正文。现行聘期长度、岗位分类、达标积分、近退休口径以及院系内部细则都没有可自动化的校本依据；不得以任何旧新闻或模型常识补硬规则。
2. `SRC-009` 的聘期合格/不合格与续订一般条件可作为上位程序边界，但**聘期目标是否达到、无正当理由、测评事实分析、单位和主管机关权限、特殊续订、评议中的回避**均需要有权人事考核组织判断。不得把 `R012/R013` 汇总成 `F027`。
3. 对编外/项目合同、专项人才协议，如现实中存在另一独立用工授权，先由真实人事归口确认适用性；不允许按本 ID 自动处理其合同续订。后续若取得另有独立授权目的的有效校规，才附 SRC 提 `CATALOG-CHANGE-REQUEST`，在此之前 ID 保持不变。
4. 不能确认系统已有正式数据 API、M001 的统一在线表单、Main 的授权实现或申诉操作权限；技术不可用要标 `SOURCE_UNAVAILABLE` 或 `NEEDS_HUMAN_DECISION` 并提供纸面/线下核验待办，不用“AI 已审核”掩盖缺口。

### 13.3 外校政策误用及闭环反例

**X11 外校阈值错用：** 某人上传另一高校“年度考核优秀且论文 3 篇即可续聘”的通知，与成都理工大学任务书 M004 并列。该外校通知只能视为不适用的外部参考，`R001/R007` 不得据此写校本阈值，输出 `POLICY_UNCONFIRMED` 给成都理工大学人事处；不是 `PASS_FACT`，也不应惩罚本人。
