# T01-T09｜实验教学、实习与实践教学安排变更审核

## 00 元信息与研究状态

1. **研究目的**：围绕 R02 固定事项 `T01-T09` 核实变更请求涉及的原安排、差异、教学责任、所需前置权威意见及决定链；仅做业务事实预审设计，不替代学校正式审批。旧 R01 `T01-T10` 仅作对照，不是交付 ID。
2. **已经确认事项存在的程度**：成都理工大学原始制度明确存在本科实验课、教学实习及实践教学组织，也明确实习计划确定后不得随意更改，任课教师不得擅自调停课或换教室。[SRC-001][SRC-002] **但尚未找到校级专门以“实验教学、实习与实践教学安排变更”为名的统一表单、线上办事项或集中审批办法**。因此本 ID 是项目业务模板，不能宣称学校已有同名办事服务。
3. **校本证据高点**：
   - 成理校教〔2022〕11 号《本科课程教学基本规范》第十五、十七、十九、二十二至二十四条界定归口、指导教师责任及课程运行；实践教学也应遵守教学计划与大纲。[SRC-001]
   - 成理校教〔2018〕20 号《本科学生实习管理办法》第三、四、七至九条界定实习计划、组织和备案；原文可核，但 2026 年是否仍为有效最新版需复查。[SRC-002]
   - 成理校教〔2022〕9 号《本科教学实验室建设与管理办法》明确实验室场所/建设的另外一条批准链，**不等于单次教学安排变更的批准**。[SRC-004]
   - 成理校发〔2023〕40号《实验室技术安全管理办法》2024-01-01 起施行，明确项目负责人（含任课教师）风险辨识、安全论证提交、人员培训和事故暂停责任；这是本轮对安全专项的关键新增校本证据。[SRC-014]
   - **确证的废止关系**：2022 本科课程规范第四十三条废止成理校教〔2018〕10 号教师规范，旧 [SRC-003] 已降为历史比较，不得再称其与 [SRC-001] 构成两个并行现行审批法源。[SRC-001][SRC-003]
   - 教务处官网列有“实践教学科”的本科实践教学组织与日常管理职责；不能仅凭科室职责推导其对每类变更都有最终签批权。[SRC-005]
4. **研究方法与限制**：承接已实际读取的 R02 第三轮主稿及审阅记录，以校方原文/教育部官网逐源复核；新增 [SRC-014—SRC-018]，核对废止条款、实验项目安全审核和跨校区职责。网页遇 412 时记录限制，只引用可核原文或明确将索引线索降低等级；G50 仅作技术边界，不把搜索摘要当作制度正文。
5. **本轮冻结口径**：一份主 MD、15 节、仅 T01-T09；03、05–13 已形成**研究性审查和办理契约**，F/M/R 是拟议字段、证据槽和核查规则，不表示学校已有对应系统接口、线上服务或自动决策资格；第四轮已作公开证据复查、反例重放及交接验证。任何校本时限、比例、审批岗位的不明项均保留人工确认，不以证据齐全推论已获批准。

## 01 唯一审核目的、申请人和负责机构

### 01.1 唯一决定对象

仅针对**既有、真实、可核对的实践教学安排**拟作出的具体变更，判断“变更是什么、由谁负责、与获准教学计划/大纲及现行管理要求是否一致、需要向哪些有权部门取得何种意见”。待核验对象包括：原课程/实习/实验项目与计划版本、原时间/地点/单位/师生/指导责任、拟调整内容和原因、学生教学权益与安全影响、有关前置校本决定的真实性与版本。

本模板不作出课程增删、人才培养方案调整、教师新任资格、实习经费拨付、危险作业准入、实验室建设/更名、个别学生请假及实践成绩认定等独立决定；若同次事实触及上述目的，只引用相关流程形成的可信结论。[SRC-001][SRC-002][SRC-004][SRC-007][SRC-009]

**本科实验安全的新增实证边界**：成理校发〔2023〕40号第七条明确实验项目负责人（含教学任课教师）对危险源辨识、风险评估和处置方案负责，第十条要求实验项目向所在教学科研单位提交安全论证材料；本模板核实“拟安排是否仍落在有效的项目安全审查范围”，而项目安全审查本身仍属 G04/本职实验室安全体系。[SRC-014] 对校外野外实习，不能把实验室条款原样扩为全部野外活动的具体批准程序。

### 01.3 有效决定的原则

正式决定须由**经学校权威身份体系确认、在特定事项/学院/学期有权的人员或组织**通过真实校务流程作出并留痕。研究草稿当前不能确认单一最终审批岗位，故默认结果应为“事实核验完成，待有权人员处理”，不得产出“同意实施”或相当于校方盖章的结论。原计划审批链与拟变更审批链不同之处见 14 节缺口。[SRC-001][SRC-002][SRC-005]

## 02 适用、排除与邻接模板路由

### 02.1 适用入口

- 适用：原本已排定的本科实验课/实训、课程设计安排、教学实习（认识、生产、专业、综合、毕业等）或其他有培养方案依据的实践教学环节，因天气、基地条件、设备故障、人员、时间、教学条件等发生拟变更；**情形属假设枚举，触发与可批准性须由校本规则决定**。[SRC-001][SRC-002]
- 以同一教学任务及同一个“原安排→拟安排”差异为中心；同一事件可包含时间、地点、单位、队伍、学时、实习形式多个变更维度，合并做一个情形矩阵，不擅自拆模板。
- 对已执行中突发变化记录“实际发生时间、临时安全处置、事后补报事实”，不预设追认规则；未取得所需批准时不能自动把实际执行视为合法变更。

### 03.3 申请时与后续材料的明确分界

1. **当前必需**仅指完成事实预审至少应有的信息，可以是可信学校记录引用，**不等于上传附件必填**；学校要求的真实法定申请表和提交时限在 [SRC-010][SRC-011] 取得前均待核。
2. **条件必需**仅在实际触发例如校外单位变化、危险作业、受托提交或实习费用变化时成立；G03/G04/财务在各自流程中产生的有效结论如尚未形成，只标待相关主体办理，不能用伪造签批补位。
3. **后续材料** M016–M019、M022 由相应有权者在 P4–P6/PX 产生，P1 不得缺件报错；人工决定不能由系统自动生成。[SRC-002][SRC-007]
4. **学段/批次**：本科实验课程与本科实习是有原文的主要覆盖；研究生、专科参照、宜宾/其他校区、不同学院规则仅做适用性分支待核。不因原文没有“资金批次”而编造资金批次；若同次实习费用含多经费来源，财务分别审其独立来源，教学安排仍一案。

## 05 角色、权限与可信数据边界

### 05.1 业务职权的现有证据与不确定性

- 对本科**一般课程调停课**，2022 规范第 24 条是“教师提前申请→课程组协调→学院（系）审核→报学校备案”。[SRC-001] 原稿援引 2018 教师规范第 15 条的“院系、教务处批准”造成假冲突，**现已据 2022 规范第 43 条纠正：2018 规范废止，只有历史参考价值**。真正仍未知的是实践教学专项变更是否另有现行审批程序、备案/批准的细分实施流程和校内岗位授权。[SRC-003][SRC-010][SRC-011]
- 对本科**学期实习计划**，2018 规则第 9 条明确主管教学院领导审定、教务处备案、不得随意变更；却没有给出本 ID 可直接落地的统一“变更申请审查批准”闭环。[SRC-002]
- 对**实验室建设或调整**，2022 办法第 5 条规定学院论证及党政决策、职能部门审核、分管校领导审批；这是独立对象，不得把相同审批链误装入每次实验教学时间变更。[SRC-004]
- **突发安全/场地/经费**均有可能发生跨部门管辖；本 ID 先核事实及外部结论是否存在。2023 实验室技术安全办法第 7/10/11/29–33 条直接支持实验项目安全论证、人员准入、暂停与事故处置的专项责任；未有 G04/G03 权威回执时绝不自动判定满足。[SRC-014][SRC-007]

### 05.2 可信源次序（设计约束，非学校系统已具备的声明）

1. **学校权限服务/人员主数据**：真实办理人由受信后端验证登录身份、岗位、学院隶属、授权事项和在任有效期；客户端/Renderer 传入的 `actorId`、身份、头衔、学院、签批意见只是待校验输入，**不能作为可信审批人**。
2. **教学权威源**：教务处/学院权威系统可验真的课程号、班级、学期、专业培养方案和大纲版本、原课表、实习计划审定/备案记录。上传扫描件需核签章与原始出处，不能仅因 OCR 识别到“批准”即给决定有效性。
3. **外部权威结论**：场地/校外基地许可、G04 安全准入、G03 场地/经费等决定须带来源系统、决定对象、适用时间、状态及撤销/过期信息，不能把申请人自填的“已通过”转为事实。
4. **材料证据**：保存原文件、来源、接收时间、文本提取质量及材料版本；任何冲突列为 `CONFLICT` 或 `SOURCE_UNAVAILABLE`，补件后仅重审受影响核验项。
5. **模型输出**：只做证据解析、差异列示、材料缺口与事项路由建议，不改变审批主数据、代签决定或绕过审批岗位。

### 05.3 审批与事实的隔离

将 `factual_review`、`required_external_decisions`、`school_decision` 三层分开。即使原计划、变更说明、安全与财务凭证齐全，也只能表示相应事实可核。校方有效决定至少需真实办理人/机构、授权作用域、决定时间、明确对象/版本、签章或权威系统回执；08/10/11 节已定义拟议验证结构，**但对校本最终审批机关与验签服务尚未完成实证，不能视为校方部署规格**。

### 05.4 数据冲突、申诉及版本

- 计划修订需保存原版本、拟版本、所引用外部决定版本和重提关系；不同部门结论冲突时停止自动正向结论，提交人工核实。
- 取消、撤回或复核均应限制在有权主体上，不由前端按钮/伪造身份改变已生效决定；撤回期限、正式申诉途径和复核层级尚无校本现行原文，列入 11/14 节校方待核配置，不阻断研究交接。
- 预留输出语义 `PASS_FACT`、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`，均非“学校批准/拒绝”的替代物。

### 05.6 可信引用与判定规范

- 所有参考证据存储 `{sourceOwner, recordId, version, evidenceLocator, capturedAt, verifiedBy, validFrom, validTo, subjectScope, status}`；若真实系统不提供此能力，只记 `SOURCE_UNAVAILABLE` 或人工核验，**不得宣称系统已经接线**。
- 一个权威结果仅在 `对象（课程/实习队/基地）+ 学期/日期 + 风险活动 + 适用学院 + 版本 + 有效状态` 匹配时可复用。OCR、上传截图、邮箱转发最多是候选，不能单独把“已批准”升级为权威决定。
- 姓名重名、学号/工号不匹配时不能按姓名合并；有权后端身份键与任务归属不一致则 `CONFLICT`，个人名单按最小授权展示。若两份“原计划”均号称最新，先到权威部门验证生效版本，不依上传时间或文件名决定。
- 更换 M001/M003/M004/M011/M012/M013 的任一证据后，明确识别依赖 F 与将来的 R，令相关旧检查结论失效；不影响的检查保留版本审计。正式人工决定若绑定旧版本，不因替换文件而自动延展到新安排。
- “撤回”在证据层只登记具名申请与时点；谁能批准撤回、已决行为效力及正式复核通道均为 `POLICY_UNCONFIRMED`，不实现可绕过院/校授权的自助撤销。

## 06 业务对象与字段字典

### 06.1 对象模型和字段表解释

概念对象：`ReviewCase`（一项原安排到拟安排的申请案）、`ActorAuthority`（可信身份/委托）、`TeachingTask`（课程或实习任务）、`OriginalPlan`、`ProposedDelta`、`AffectedPopulation`、`ExternalDecisionRef`、`SchoolDecisionRef`、`EvidenceVersion`、`ChangeOrReviewRequest`。**均为研究性命名，不断言 V3 代码已有同名对象或校方数据接口。**

- 阶段：`P0` 原计划定位、`P1` 申请、`P2` 前置核验、`P3` 补件、`P4` 决定、`P5` 执行、`P6` 归档、`PX` 撤回/复核（见 03）。
- 可信源：`I`=本审核后端生成并可追溯；`A`=真实学校身份/权限服务（仅在已接通并验真后）；`T`=权威教务/学院原始记录（未接通时需人工验源）；`D`=有权机关原始决定；`X`=G03/G04/财务/基地本职部门可验真回执；`U`=提交人上传/自述，**不能自己升级为权威**。证据位置列给候选 `M` 或记录键，不意味着接口已实现。
- 隐私：`L0` 通用事项元数据；`L1` 校内业务；`L2` 可识别个人身份/人员编组；`L3` 涉风险、敏感事故/个人特殊状况。后端按任务范围最小授权展示。缺失：`N`=`NEEDS_MATERIAL`（当前应有事实无据）；`S`=`SOURCE_UNAVAILABLE`（学校记录暂不可取得）；`P`=`POLICY_UNCONFIRMED`（校规不明）；`H`=`NEEDS_HUMAN_DECISION`；`C`=`CONFLICT`；`NA`=`NOT_APPLICABLE`（触发为假）；`POST`=尚未到生成阶段，**不报缺件**。不可读单独为 `UNREADABLE`，不能混成不存在。
- 所有日期时刻统一保存原文件时区与标准化时区；“实验学时、实习天数、学生人数”可作为数值**事实**，任何通过率、容差、审批提前天数不预设；存在 `value/observedAt/source/version/locator` 事实级元数据。

## 07 材料槽与证据目的

### 07.1 材料语义与有效替代

“M”是**证据目的槽**，允许权威源记录、回执引用和文件，不等同于强迫用户上传独立文件。标记 `当`=P1 当前事实预审所需，`条`=条件触发且在对应阶段需要，`后`=P4/P5/P6 或 PX 后生成，不得前置强制。`当前最小集` 可由多项同一权威文书满足，不要求按 M 数分别上传。所有 M 保留 `materialId/ownerCaseId/teachingTaskId/sourceOwner/sourceRecordId/version/digest/observedAt/effectiveRange/supersedes/locator/readability/verificationStatus`。无法取得源数据时向真实保管部门查证，不能伪造空值通过。下文“合法替代”限真实权限范围内、可溯源的同等事实，**是否符合法定学校规定由人工确认**。

## 08 审核规则逐条清单

### 08.1 规则执行边界、三值触发和证据顺序

下列 R001–R034 是**事实核查/业务路由/可信决定位验证**，不是学校授权该审核器执行审批的证明。每条均具有唯一对象，阶段只在 03 节相应时点可达。`T/F/U` 分别为适用触发条件 true/false/unknown；对非条件性的基础核验，`F` 意味着事实不成立或提交对象不属于本事项，**不得误用 `NOT_APPLICABLE` 表示缺证通过**。尚未到达阶段的 R **不产生结果行**（内部为 `DEFERRED`，不是第九种结果码）。

证据层级：`A` 校方可验真身份/岗位；`T` 校方课程与原计划记录；`D` 当前有权机关原始决定；`X` 外部本职主管有效记录；`U` 提交材料/抽取；`I` 审核案卷元数据。层级高并不意味足够覆盖不同的法定签批对象。若 `T/D/X` 没有可访问接口，以原件人工验真或 `SOURCE_UNAVAILABLE` 处理，不假定接口存在。每个 R 的判断绑定 `caseRevision + policyVersion + F版本 + M版本/locator + applicableDecisionVersion`；SRC 现行性未知的部分只能支持事实核查与 `POLICY_UNCONFIRMED`，不能生成否决资格的硬阈值。以下 `T/F/U` 是触发路径，其后证据比对仍可能产生八种不同事实结果。

| `SOURCE_UNAVAILABLE` | 应向已明确的权威记录源验真，但服务不可达、记录保管方暂无法获取或验签通道失联 | 将“用户没有上传原本可在校方取得的记录”一律打成缺件 | 权威记录保管人/系统 Owner 恢复取证或作合法离线函证 |
| `POLICY_UNCONFIRMED` | 适用政策版本、事项权限、期限、例外阈值或学校正式救济路径无可靠当前依据 | AI 猜测条款后判不合格，也不与一般补件混淆 | 教务处/研究生院/具体权威部门核校规，更新有效政策快照 |
| `NEEDS_HUMAN_DECISION` | 证据可核但需法定教学、安全、场地、财务或撤回复核主管裁量，或真实有权决定尚未形成 | 未提供普通附件；不能伪装为自动批准 | 有权人/组织处理，待**其本职权威来源**的决定回执 |

**分类优先规则**：先判断阶段是否到达（未到不产生检查结果），再识别触发 T/F/U。明确 F 仅对可不适用的条件性 R 返回 `NOT_APPLICABLE`；触发 U 必须查原因。对已触发的一项 R，先辨认“现行政策不明”“源访问故障”“文件关键部位不可读”“应有材料确缺”“证据实质冲突”“人工裁量”等**致因**，择其主阻断原因输出唯一 code；可在 `issues` 记录次要原因但不能给同一 `ruleId@version` 同时打两个结果。已证明冲突通常优先于因另件不可读而推断冲突，但不能凭低置信 OCR 制造冲突。所有问题消除才可对该 R 返回 `PASS_FACT`。跨 R 多个状态可并存且分别定位。

### 10.4 案卷汇总与校方决定不混合

- `factualSummary` 可汇总 `checked / notApplicable / needsMaterial / unreadable / sourceUnavailable / conflicts / policyUnknown / awaitingHuman`；**不设置**从 `PASS_FACT` 比例推算的“学校审批通过率”。
- `readinessForHumanReview` 仅表示现阶段可提交有权人阅读，不等于校方准予变更。只有真实 `SchoolDecisionLink` 经 R003/R024 核验并证明适用于当前拟方案，才可显示“校方原始记录显示：某决定”；未知或回执失效时不显示“已批准”。
- 同一案卷多次 Run 的旧结论按 F039/F040 和 11.3 的依赖重新判定，有效结果须指向确切真实 Run 和证据版，不允许把过期运行缓存显示为最新审核。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 项目侧办理状态与事件（不替代学校状态机）

| 起点→事件→目标状态 | 前置与有权角色 | 核查 R、证据变化 | 不允许的越权捷径 |

### 11.2 补件和权限门槛

1. `M004` 的申请主版本由**经可信权限确认的责任人**提交；学院/教务核验后依对应实际权限处理。材料持有人（基地、安全、财务）仅对**各自证据**负责，不应能写本案校方决定。
2. 每一 `ReviewTodo` 精确引用缺失的 `F` 和 `M`，注明“当前事实缺 / 需外部机关决定 / 后续阶段才产生”，并注明可替代学校源记录。没有批准/备案回执时转有权机关办理，**不是强迫申请人伪造盖章材料**。
3. 正式人工决定必须经受信后端确认 actor、岗位、事项与学院授权、决定时点、绑定方案指纹及生效/撤销状态；缺一项不得写入可信决定字段。模型能建议待办，不能写 `schoolDecisionLink.decisionStatus`。
4. 安全现场止险不等于教学调整同意；按现实安全处置优先控制风险，本系统只追踪事发/报告、拟修订、各机关处理三个时间序列（R019）。
5. 实验教学新增独立控制：在实验室开展项目的安全论证提交与处置由 [SRC-014] 所列本职单位办理（M025/R031）；人员实际进入操作前核对应训与现场培训（M026/R032）；事故或隐患被暂停的实验室即使教学补排已经决定，也不得由本模板变更安全状态（M027/R033）。以上均不得在 P1 当成已经出具的未来批件缺失。

### 13.2 对照 G50 和相邻模板的高风险反例

1. **实验室扩建批复≠实验课时段许可**：建设项目的审批目标与教学任务不等，M012 要核实际使用权限；R017 不借 G03 建设结果给当前课表盖章。[SRC-004][SRC-013]
