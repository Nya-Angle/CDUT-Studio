# S02-T05｜校外、跨校及交换学习课程学分认定审核｜业务模板研究主稿

> **非成都理工大学官方发布模板。** 本文件是 CDUT Studio Review V3 的业务研究交接稿；只支持资料整理、来源追溯、事实预核与人工办理准备，不产生学分认定、成绩入档或行政审批效力。保留原第四轮 15 节与 SRC/F/M/R 主体并作 2026-10-23 增量实证复审；研究稿可以交接，但校本政策与签批接线仍未验收。

## 00 元信息与研究状态

### 00.1 事项存在性结论与证据强度

**事项确有制度根据，不等于存在学校独立线上办事入口。**《普通高等学校学生管理规定》第十六条允许按学校规定申请跨校修读，成绩（学分）须由学校审核同意方可承认（SRC-001）。成都理工大学《全日制普通本科学生学籍管理办法》成理校教〔2019〕18 号第十三条明确涵盖外校、境外学校的课程与学分：本人申请、学院审核同意、教务处备案，并允许折算替代培养方案课程组（课程）学分（SRC-002）。学校还公开报道实际开展过校际学分互认及高水平国际课程认定（SRC-007 至 SRC-009）；这些是存在性旁证，不是某个申请人的审批依据。

**当前可据以作出的判断：** S02-T05 应围绕“外部课程的真实修读与合格成绩、获准修读/交流的前置依据、目标培养方案以及校内有权部门形成的学分认定结果”组织材料预核；不得直接计算为“自动认可”，更不能因收到成绩单就修改教务成绩档案。

**仍未闭环的现行性问题：** 2019 本科制度自 2020-01-01 施行、明确废止 2017 旧版（SRC-002），并在学校 2023 信息公开栏目中保留；但 2025 年学校又发布《学生出国（境）交流学习管理办法》，页面目录可查、正文请求返回 HTTP 412（SRC-005）。2026 年中外合作办学学生学籍制度也可检索到目录（SRC-006）。**第 3 轮新增重要校验**：学校 2024-04 会议纪要载有修订研究生学籍办法事项，研究生院 2025-09-09 在校生注册通知明确援引**成理校研〔2024〕29 号**（SRC-013/014）。因此 SRC-003 的 2021 第十条只能作为旧版历史线索，**不得再视为当前研究生课程认可审批依据**；2024 文件具体条款必须补原文。

### 00.3 设计声明与保守原则

1. 以来源正文、版本、适用身份和**申请发生时间**共同选取规则；旧规定可以证明历史，但不能覆盖更新特别规定。
2. “课程相似”“内容可对应”“成绩有效”“学分应折算多少”不能由语言模型独立定案；须获得学校认可的培养方案/协议及有权人员意见。
3. 来源可靠性与证明真实性是两回事：官网政策可靠不证明学生上传的外校成绩单真实；OCR 读取成功也不等于已与发证学校核真。
4. 仅形成供审核人员复核的事实状态，材料齐备不等于学校批准；未确定的条件一律待人核对。
5. 第 2、3 轮已建立研究用 F/M/R 契约，均非既有客户端 DTO 或已部署审批功能；不得把旧 Run、模拟判定称为真实审批记录。

## 01 唯一审核目的、申请人和负责机构

### 01.1 唯一决定对象

以**某申请人在特定学籍及培养方案版本下、某次校外/跨校/交换学习实际取得的一项或多项课程成绩与学分**为对象，核验其能否提交成都理工大学有权机构开展认定，以及学校最终认可的课程、学分、成绩与入档依据。一个申请可包含多门课程，但每门外部课程和目标课程组的映射须可独立追溯，避免重复抵扣或跨案串证。

该对象不是交流项目入选资格、出国（境）审批、签证、保留学籍，也不是毕业授位决定。那些有效结论如为前置条件，只读取相应权威记录。

### 01.2 申请与核验主体（按学段分开）

| 身份/情形 | 申请人及代理 | 有权处理角色与来源 | 第 1 轮可确定程度 |
| --- | --- | --- | --- |
| 普通全日制本科生（含获准校外课程、交换修读） | **学生本人申请**（SRC-002 第十三条）；他人代办的授权形式未查明 | **学院审核同意，教务处备案**；学院具体岗位/签字责任、教务系统录入责任尚须核验 | 学院审核与教务处备案关系有直接校本依据；不能擅自把备案改写为审批 |
| 研究生（全日制/非全日制） | 学生课程认定申请为研究对象；提交路径和代理权限待核 | 2021 旧规 SRC-003 第十条曾指向党委研究生工作部、研究生院；2025 校方通知已引用 2024 新规 SRC-013，**当前有权机构及程序必须依新规核定** | 2024 正文未取得，暂不固化当下授权链 |
| 来华留学本科生 | 仅在该学生申请**符合本 ID 的外部课程学分认定**时纳入；与普通本科学生不混同 | 2022 规定第十八条专门处理**学校认可的开放式网络课程**，学院审核同意后报国际交流与合作处备案（SRC-004）；不能把它自动推广至所有境外交换 | 2022 正文可读，但 2025 国际学生新制度及现行性待查 |
| 中外合作办学、双学位、联合培养项目 | 按个体学籍、合作协议和项目身份分流；申请人通常为学籍学生，代理制度未证 | 2019 本科办法第二条有参照适用范围；2026 中外合作办学制度已公布目录（SRC-006） | 必须先取得特别制度与协议，避免普通学院流程覆盖协议安排 |
| 课程授课教师、学院教务员、项目管理人员 | 可出具大纲、课程比对意见、核真记录或录入建议；**不是代替学生当然申请人** | 各自事实证明与技术操作权限由学校组织/教务角色核验决定 | 不因“教师”身份取得外校学分批准权，尤其不得触及另项教师成绩更改业务 |

### 01.3 决定层次

1. **前置事实与权威输入**：学籍、获准跨校修读/交换项目记录、有效培养方案、合作协议/课程互认清单、外校成绩单及其发证状态。
2. **事实预核**：申请人身份与课程记录一致性、外校课程的真实存在、修读学期、成绩表达、学分单位、是否已有认定结果、是否存在冲突；只产生可复核事实与疑点。
3. **专业学术判断**：课程内容/层次/学时对应、不同学分单位换算、专业必修/限选/通选归属，由学校规定的相关教学单位及授权负责人审查；模型可辅助整理比对，但不替代。
4. **学校效力决定**：本科依 SRC-002 为学院审核同意并报教务处备案；研究生 2021 旧条 SRC-003 已有 2024 新版存在性证据（SRC-013/014），不能照旧定当前决定链。特别项目若有新规定，从有效特别规定；以正式校方文件/系统已签权威记录为准。
5. **入档与更正**：教务/研究生权威系统依据有效决定办理；本模板无直接更改正式成绩、学籍、学分的权限。

## 02 适用、排除与邻接模板路由

### 02.1 纳入范围

- 成都理工大学在籍学生获准在**国内其他高校**修读课程，并在完成修读、取得课程成绩后申请认定（SRC-002 第十三条；SRC-001 第十六条）。
- 获准到**境外学校**进行交换、联合培养等学习，返校/取得成绩后申请课程学分折算或目标课程组对应；是否有特殊申报期限、协议优先顺序、成绩换算表，留待核实 2025 文件（SRC-005）。
- 学校已认可的**外部在线课程**涉及同一课程学分认定对象时可作为办理情形候选（SRC-002 第十三条；研究生 2021 历史条 SRC-003 第十条待依 SRC-013 更新；特殊国际学生 SRC-004 第十八条）。但不是所有平台结课证书均天然可认定。
- 已获有效认定后发现外校更正成绩单、映射重复或错误的**事实复核和重新提交建议**；学校实际撤销、改正、重新批准制度未明，不擅自承诺可自行改写。

### 03.4 共用横轴与节点定义

- **时间横轴**：派出/选课前、修读中、成绩签发后、校内批准后；证据只在实际生成后要求提交。
- **身份横轴**：本科/研究生/来华留学生/合作办学及项目 cohort；决定机构不得以普通本科条款覆盖所有类型。
- **项目横轴**：境内跨校、境外交换、校际协定、独立获准在线课程；是否可认定依正式校本许可和方案版本。
- **证据横轴**：纸质成绩单、学校直接验证的电子成绩、加盖章扫描件、外校更正通知、课程大纲；只代表材料形式，不预设同等证明力。
- **资助/批次横轴**：奖助、项目资金、批次可用于关联，不自动成为学分通过条件。
- **程序横轴**：首次受理、补件、更新、撤回、异议复核；每次保留谁、何时、依据何文件改变了什么的可追溯记录。
- **截止节点**：申请开放、最晚提交、补件回复、异议受理和档案写入分别单列 `deadlineValue=null`、`policyRef=null`；官方确定前不据超时自动拒绝。
- **版本节点**：L1 项目批准版→L2 选课变更版→L3 外校成绩签发版→L4 核真/映射工作版→L6 学校决定版→L7 复核/更正版，任何较后版本不应抹除前版。

### 05.3 推荐的技术信任契约（仅原则，非既有实现声明）

1. 身份从宿主可信认证上下文导出；Main/服务端重新校验会话、权限、当前学籍范围。Renderer 只能提交请求参数和材料，不可自行声明 `approverRole` 或 `decisionActor`。
2. 以申请人学籍 ID、外校发证 ID/课程 ID、目标培养方案版本、校内 Case/Run 和证据文件版本做关联；每一门课程识别单独事实归属，避免把同一成绩单自动套到其他人的课程。
3. 逐一保留 `issuer_verified?`、`institution_approved?`、`curriculum_match_approved?`、`grade_conversion_confirmed?`、`formal_decision_present?` 的**独立证据状态**。某一项为未知，不可以在汇总结果中“多数通过”补成真。
4. 最终学校决定应由可信岗位、权限、时间、决定内容、政策版本、签署依据构成；系统在记录有效决定之前只能输出 `NEEDS_HUMAN_DECISION` 或事实预核类结果。
5. 证据来源变更（外校修正成绩、方案版本修正、签章撤销）只标记受影响课程映射与旧决定供人工复核，不自动修改历史权威状态。
6. 不因“材料槽全部齐备”给予行政 `APPROVED`；也不因项目资金批次、学生国籍、成绩单外观、模型置信度设未经学校授权的拒绝阈值。

## 06 业务对象与字段字典

### 06.1 业务对象与共用约束

- `Application`：唯一案卷，持有主体、申请意图、受理阶段、A–H 子情形及撤回/复核请求；其状态不等于校方决定状态。
- `StudentContext`：有核验来源/时点的学籍、培养方案与学段，关联有效历史变动；每次核验保留快照版本。
- `StudyAuthorization`：既有学校批准的跨校修读/项目决定或校际协议，批准授权目的区别于本次学分认定。
- `ExternalCourseEvidence`：每门外校课程与签发成绩单中的逐项记录；复合成绩单须每行独立 `courseKey`，不能整份材料判同一结论。
- `MappingCandidate`：外校课程→本校具体课程或课程组、适用方案版的候选；一对多/多对一依有效政策与人工学术审查，不默认允许。
- `RecognitionDecision` 与 `ArchiveEvent`：可信学校签批/备案/入档事实；学分数须由正式记录证明，预核不会生成它。
- `EvidenceVersion` / `Issue`：材料生成时间、签发主体、哈希、版本、归属、验证方式及关联具体 F/R，旧版只保留溯源，不重复当现行。

字段均为**建议的业务数据字典而非已有接口/硬性校方表单**。下列“缺”列中 `待源`=`SOURCE_UNAVAILABLE`；`待证`=`NEEDS_MATERIAL`（该阶段证据确已产生）；`政策`=`POLICY_UNCONFIRMED`；`待人`=`NEEDS_HUMAN_DECISION`；`冲突`=`CONFLICT`。外部原始教育记录为 `P3`，只在有权业务内披露。`L6+` 表示该阶段形成后才有。

### 06.3 值、关联和可解释性约束

1. `F013–F020` 与 `F024–F026` 均按外校**课程行**及目标**课程组**定位，不能对整个 PDF 一次性统一通过；允许一个申请跨多个院系开具的 M006，但需每行明确 issuer、时间与课程 ID。
2. `F016+F018+F014` 形成外校课程事实键，`F024+F007` 形成本校目标键；两者均不能只依课程中文名。缺外校标准代码时，由核验员标注替代唯一键与根据，不自动合并。
3. 每个 F 保存 `value / sourceM / sourceVersion / extractedAt / verifiedBy / confidenceType`。`confidenceType=OCR` 只表明解析手段；不得写成 `issuer_verified`。
4. 数据最小化：验证报告如可由可信渠道返回真假与课程归属，不要求留存无关护照、出入境记录；如无接口，只提示人工持有效访问权限核查，不虚构 API。

### 07.2 材料不证明的事项

- M006 的出现只证实“有一份声称由外校出具的记录”；是否经核真看 M007；它不单独证明 M003 学校同意、M010 课程等效或 M013 正式认可。
- M003 只证明其**原授权目的**，外事派出/跨校许可≠学分认定；M004 协议存在≠某生某课已达成成绩要求；M009 同名大纲≠课程等效。
- M010 仅专业意见，若没有获授权签批人的 M013 不可当学院审核同意；M013 与 M014 亦须分别记录，备案不可以由 AI 代办。
- M015 更正使受影响旧事实过时，但学校决定是否撤销/重签依有权机构；M016 撤回“请求”并不当然终止已经形成的校方决定。

### 08.1 执行解释、三值触发与证据层级

本节是**待校方核准的业务事实核验规则设计**，不是可直接部署的自动审批政策。每个 R 针对 `caseId × externalCourseKey × targetCourseOrModule × evidenceVersion`（案卷级 R 不按课程重复）独立出结果。表内：

- `T`：前置事实**可证明为真**而规则进入；`F`：前置适用条件**明确不成立**，通常 `NOT_APPLICABLE`；`U`：缺法定身份/版本/项目适用性/当前有效规定，优先 `POLICY_UNCONFIRMED` 或相应缺证状态。对于触发为真的规则，比较值失败不等于申请被行政驳回，而是生成待纠错/人工核对问题。
- 证据顺序为**本校可信学籍/方案/决定**、**外校直接核真成绩及正式协议**、**可验证签发文件**、**其他上传材料**、**OCR 与模型分析**；后一类不能抵销上一级冲突。时效统一为当前申请及修读期两条轴，需同时核政策、培养方案、成绩签发及协议的生效范围。
- 默认异常：该事实到应生成阶段却缺证→`NEEDS_MATERIAL`；影像/文本不可读→`UNREADABLE`；本校或外校官方查询不可达→`SOURCE_UNAVAILABLE`；两份有效材料冲突→`CONFLICT`；校本规则/特别制度不明→`POLICY_UNCONFIRMED`；需学术/行政裁量→`NEEDS_HUMAN_DECISION`。这些不是自动否决或批准。
- 表中“下一角色”是**应通知的业务责任方向**而非已验证系统 RBAC 岗位；有权身份必须由学校可信认证二次核定。`SRC-010` 仅外校参考、`SRC-011` 仅技术边界，均不能充当资格阈值。

规则的 `PASS_FACT` 只指表内**单个事实**已按对应证据验证，例如“已查到学院正式决定”也不能推导其他缺失课程被批准。所有课程认定实质结论以有权限的 M013 为唯一证据；M010 是专业意见；M014 是后续备案。`SRC-005/006/012` 未取得全文时，相关情形不可因通用规则都无异常而自动“通过”。不制造校本 GPA、ECTS 换算比例、最低分数、学时占比、申请周数或一对多抵扣规则。

### 09.2 冲突定位与精准重审粒度

1. 文档级 `sourceVersion` 标记 M006/M015 的每次上传与外校签发版本；课程级 `externalCourseKey` 不随文件页码重排而丢失；目标 `targetCourseOrModule` 与 `curriculumRevision` 绑定。
2. 同一材料若包含五门课，更正其中一门，重审该门的 R009–R018/R023/R025（以及其共享政策 R004 或权限 R021 仅在对应依赖变动时重审），不得重做其他四门的独立事实。
3. M018 校本特别政策更新，按生效时间和适用 cohort 批量标记 R003/R004/R005/R014/R019/R026 相关受影响案卷，但不擅自改变既有正式 M013；主管机关决定溯及力。
4. 权威 M012 已认定学分发生变化，将依赖该目标组的 R018 标过时；若入档 M014 变化，对 R022 和其关联 M013 的一致性重核；不等于原学生成绩自动作废。
5. 争议分类分别保留“值冲突”“效力版本冲突”“签发身份冲突”“权限冲突”；多种并发可有多个 Issue，每个 Issue 仍必须唯一指向 `ruleId+材料版本+目标课程+下一角色`。

## 10 结果状态、问题与待办输出契约

### 10.1 唯一规则结果语义（同一规则实例互斥）

| 结果码 | 严格含义 | 不允许解释为 | 下一步 |
| --- | --- | --- | --- |
| `PASS_FACT` | 仅当前 R 的**特定事实**已用指定证据验证 | 学校学分批准、所有课程通过、已入教务档案 | 如仍需专业等效/签批，继续人工办理 |
| `NOT_APPLICABLE` | 有可靠事实证明此 R 对当前身份、项目或阶段不适用 | 缺材料、拒绝申请、审批通过 | 保留排除条件和路由原因 |
| `NEEDS_MATERIAL` | 该阶段应当已产生、申请侧可合法提供的证据缺失 | 需要未来审批人签章、系统库断连 | 说明需补哪个 M、哪个课程行 |
| `CONFLICT` | 两项以上可比较证据或权威值存在实质抵牾 | 自动按较新/较高值采信、纪律定性 | 发证方/业务主管核实并保留冲突双方 |
| `UNREADABLE` | 文件实际在场，但其被审核的关键页、字段无法可靠读取 | 假冒、文件不存在或政策失败 | 指定具体页/课程行重扫或人工阅件 |
| `SOURCE_UNAVAILABLE` | 本应查询的权威系统/正式签发方无法访问或不可验证 | 学生未交证明、系统中“没有记录” | 稍后重试或主管线下核验 |
| `POLICY_UNCONFIRMED` | 校本政策当前有效性、学段适用或阈值尚不可证 | 默认按外校/旧规判定不通过 | 由政策主管提供适用条文与生效版 |
| `NEEDS_HUMAN_DECISION` | 事实可提请但需学术判断、授权认定或程序裁量 | 模型审批、校方隐式同意 | 指派经可信核权的专业/审批人员 |

规则结果为`单值`，不能同一实例同时返回两个码。若存在多个独立阻碍，按不同 R 或不同 Issue 明确拆开；同一 R 的主要阻碍按“先判断适用条件→证据源是否可访问→材料是否存在与可读→关键值冲突→政策有效性→专业裁量→事实通过”的业务顺序记录，并在 `secondaryFindings[]` 保留尚未解除的风险；此顺序只用于展示，不取代各 R 的详细触发条件。`PASS_FACT` 不清除同一课程的其他规则未决项。

### 10.2 可审计事实结果与 Issue 最小契约

`FactCheckResult` （建议结构，非仓库现有接口）：`caseId, subjectStudentId, templateId=S02-T05, caseVariant, ruleId, scopeKey{externalIssuer, externalCourseKey, targetCourseOrModule, curriculumRevision}, triggerTruth∈{TRUE,FALSE,UNKNOWN}, resultCode, predicateDescription, observedValue, expectedEvidencePurpose, policyRefs[SRC+条款+版本], evidenceRefs[{materialId,sourceVersion,issuer,issuedAt,hash,fieldIds,pageOrRow,verificationStatus}], policyAsOf, checkedAt, planFingerprint, supersedesResultId, checkedByRole, uncertaintyNote`。不存在的权威值应显式 null，不能用模型猜测补位。

`Issue`：`issueId, caseId, ruleId, affectedScopeKey, resultCode, message, missingOrConflictingFIds, evidenceRefs(含 sourceVersion/page/row), sourceAvailability, targetOwnerRole, requestedAction, requestStage, dueDate=null, policyRefOrGap, resolvedByTrustedActor?, resolutionEvidenceId?, createdAt, supersededAt?`。对一份多课程成绩单应可生成指向同一 M006 不同行的独立 Issue。

`DecisionReference` 与事实输出强制分离：`officialDecisionId, issuingAuthority, verifiedActorId, formalDecisionType, effectiveAt, applicablePolicyRevision, coveredCourseMappings, evidenceSignatureOrTrustedEventRef, status, sourceSystem`，仅作为 M013 权威事件读入。`ArchiveReference` 单列 M014，不将“学院审核同意”和“教务备案”合并成一个布尔值。

### 10.3 待办、用户呈现和聚合禁令

- 申请人待办：已到生成阶段的 M006 缺件、材料不可读、本人申请版本不明；不应被催交学院未来签署的 M013、教务未来入档 M014。
- 外校/项目主管待办：M007 官方验真、M004 有效协议版、M005 改课说明、M015 外校正式更正链。
- 学院/研究生有权人员待办：M009 内容等效、M010 专业意见、政策版本确认，以及需 M013 的最终决定。国际学生/合作办学需先确认正确主管，不向任意教师推送“批准”按钮。
- 学籍/档案主管待办：M001/M002/M012 权威查询及 M014 记录核对；缺连接标来源失联，不转嫁给学生。
- 每条 issue 必有 `ruleId`、至少一条 `F`、对应 `M+sourceVersion`、课程归属、目标办理角色；没有实际期限原文时 `dueDate=null`，禁止“逾期自动驳回”。
- 聚合视图分三列：`事实预核状态`（可能部分通过/有疑点）、`专业与政策待决`、`学校有效决定`（只有 M013 才能表述，有 M014 才能展示入档）。一个课程通过不代表其他课程通过，整个案卷无 `AI_APPROVED`。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 案卷工作状态与官方决定状态拆分

研究建议的案卷工作状态：`DRAFT` → `SUBMITTED` → `FACT_REVIEW` → （`AWAITING_MATERIAL` / `AWAITING_SOURCE` / `AWAITING_POLICY` / `AWAITING_HUMAN`，可能往返）→ `READY_FOR_AUTHORIZED_DECISION` → `DECISION_REFERENCE_RECORDED` → `ARCHIVE_REFERENCE_RECORDED`。此为 V3 工作流的设计状态，**不是学校公布的学分认定程序或办结结论**。部分事实可先行通过；未处理 Issue 仍显示待办。

程序异议另以 `MOTION_REQUESTED` → `MOTION_ACKNOWLEDGED` → `MOTION_RESOLVED` 记录：包括补件、申请撤回、复核申请。`MOTION_REQUESTED` 不得直接将学校有效 M013 标为撤销；`MOTION_ACKNOWLEDGED` 也不能默认“受理合法/撤回生效”。校方是否允许撤回、撤回发生在决定前还是决定后、复核机关和期限都属于 SRC-005/003 等待核缺口。

决定状态独立保存为 `NO_OFFICIAL_DECISION`、`OFFICIAL_DECISION_EXISTS`、`OFFICIAL_DECISION_EFFECT_UNDER_REVIEW`、`OFFICIALLY_AMENDED_OR_REVOKED`，状态转换只来自有权来源的 M013/M016 新事件，而不是工作流点击或 OCR。备案状态独立为 `NOT_YET_ARCHIVED`、`ARCHIVE_CONFIRMED`、`ARCHIVE_DISPUTED`，以 M014 为据。

### 11.3 版本、重审与通知

1. 对 M006/M015 建 `materialId + sourceVersion + hash + issuerIssueTime` 不变历史；从字段反向索引到 `F→R→课程目标/案卷`。任何更正先检查签发方与旧版关系，而不是将新 PDF 覆盖原件。
2. 例如五门成绩中的课程 X 分数被改：失效 X 的 F019/F020、R012/R013/R014/R023/R025；若 X 影响课程替代与重复认定，则失效 X 的 R015–R018；R011 仅在签发真实性需复核时更新；其他课程 Y/Z 的 R002/R003 及学籍政策事实不自动重审。
3. M004 协议课程附件更新→重核受影响 cohort/目标课程的 R004/R006/R007/R016/R017/R019；M002 培养方案版更新→受影响 R015–R018；M012 入档记录更新→受影响 R018/R022。旧 `FactCheckResult` 仍可读但标 `SUPERSEDED`，绝不伪造原历史未存在。
4. 所有重审保留 `changeReason`、前后 `sourceVersion`、受影响 `ruleId[]`、执行可信主体、`planFingerprint`、相应 `runId`（确有真实 Run 时）。不得把 `run@rev` 占位包装成真实 Run。
5. 如 M013 已经包含 X 的正式认定，新 M015 仅生成“校方有权复核 X 的既有决定”的 Issue；旧官方决定的法律效力不因预核结果而自动改变。只有来源真实的新 M013/M016 才可标为校方变更。

### 12.2 不应由模型/模板作出的行政裁量

1. 学分**是否正式认定**、认定多少、认到哪一必修/选修组、研究生课程是否可替代、专业核心课程是否等效。
