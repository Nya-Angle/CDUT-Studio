## 01 唯一审核目的、申请人和负责机构

### 1.1 决定对象

本模板的事实预审对象是**校内二级单位以本单位名义建设或调整学校网站、使用/变更学校域名及其安全备案相关条件是否具备**，最后形成可供有权人员审阅的事实清单与问题待办。它不直接决定校级站点的建置、域名资源分配、网络开通或发布授权。

《成都理工大学网络安全管理办法（试行）》第二条把各类网站纳入信息系统；第十条（一）要求上线前信息系统登记备案并列举单位、负责人、管理员、域名/IP/端口等，第十条（四）要求单位信息门户/宣传类网站使用学校统一站群系统，第十条（五）规定新建信息系统经网络与信息化处安全测评通过后方可上线。对应材料模型主要以该校方原文及附件 1 为据（SRC-001）。

### 1.2 申请主体、经办人与有权角色

| 角色 | 研究阶段结论 | 权力或可信度界线 |
| --- | --- | --- |
| 二级单位（学院、部门等） | 校本规范多处以“各单位（部门）”为管理责任主体（SRC-001 第四、七、十、十一条） | 申请资格的**单位类别和清单**待取得现行校方规则；个人/学生社团不得自动视为可独立申请的单位 |
| 单位经办人/委托代理人 | 事实模型需要记录，具体代理授权表式待核 | 经办权限由可信身份及单位授权关系核验，不能由前端提交的职务字符串决定 |
| 单位主要负责人/单位负责人 | 第四条规定主要负责人承担网络安全第一责任，第七条要求明确网络安全负责人/管理员；附件 1 有单位负责人签字栏（SRC-001） | 单位负责人意见是备案相关证据，不等同站点/域名最终批准；是否须党政联席会等无据，不添加 |
| 单位网络安全管理员/站点技术管理员 | 第七、十、十一条及附件 1 有对应职责/字段（SRC-001） | 技术管理者不能代替单位负责人签字，也不能用管理账号存在证明获授权 |
| 单位网站/内容管理员 | 第十一条（二）要求专人负责信息发布审核、更新等；站群平台说明区分站群管理员、单位网站管理员、内容管理员（SRC-001/002） | 内容审核角色不天然持有 DNS 或网络安全最终审批权限 |
| 网络与信息化处/网络安全办公室 | 按 SRC-001 第六、十条提供监督与技术支撑，对新建信息系统实施安全测评；技术安全监管亦见附件 2 | **已知有安全测评职责**，但不能据此断言全部“二级域名”申请由该处某级人员独家最终审批 |
| 上级通信管理部门、学校备案统筹/接入方 | 仅在网站确实落入国家非经营性互联网信息服务范围且备案义务适用时，依法办理/核验其国家备案；公益性互联网络接入单位可依规定代办（SRC-009） | **国家 ICP 备案不是学校建站批准**；学校二级子域名是否依托主办单位既有备案、变更和注销责任归谁，须向校方备案负责人核实 |
| 学校网络安全与信息化建设领导小组 | 第五条为网络安全工作领导、决策机构（SRC-001） | 重要/重大事项决策角色与日常站点/域名批准流程需分别核实，不能每案自动送该小组 |
| 党委宣传部/各单位内容审核人 | SRC-001 附件 2 第四部分提到学校门户信息与舆论监管由党委宣传部负责，各单位监控各自站点内容 | 网信技术安全测评不是单篇新闻、宣传材料或信息公开事项的内容审稿/授权 |

**学校最终有效决定：** 仅以经校方确认的审批流程和可信决定记录确定。当前只能明确备案中的单位负责人签字与上线前网信处安全测评的职能，不足以指认“域名分配批准人”“新建站点最终批准人”；该点统一 `NEEDS_HUMAN_DECISION`/`POLICY_UNCONFIRMED`。

### 5.2 建议的技术信任合同（非既有客户端能力声明）

1. `Actor` 由 Main/Host 可信身份与服务端授权映射产生；业务动作核验 `actorId`、`orgId`、`roleGrantId`、授权范围、有效期。来自 Renderer 的 `actorRole` 和上传材料提取的岗位名称只作为用户主张。
2. `Case` 固定 `template_id=T07-T04`、业务对象 `siteId`（可暂空）、申请单位权威 ID、`requestKind`、材料 `sourceVersion`、文件归属与证据位置；同一申请改变目标站点应新建对象或显式关联，不能暗改旧案结论。
3. `Evidence` 保存 `issuer`、`documentNo`、`issuedAt`、`verifiedAt`、`appliesToSite/Domain`、`sourceVersion`、校验方式及审核者，按可读性/可信性/时效区分状态；跨系统 G50 决定以不可变 ID 引用，不重放授权。
4. `Decision` 仅由本系统可核验的有权签批来源导入或手工登记并标注证据；不允许 AI 自动签署，也不允许用户把“批准”作为字段直接覆盖最终状态。
5. `ReviewRun` 绑定证据版本。替换 M006/M007/M008 等后，受影响的旧事实预审 `PASS_FACT` **失去对当前版本的效力**，触发定向重审，不将旧 `run@rev` 伪造为权威批准。
6. 补件、撤回、复核与人工决定分别保留事件时间、操作者可信身份、决定出处。没有学校复核时限/程序时只创建“请求人工确认”待办，不自动推定受理。

### 5.3 最小权限与隐私

- 手机号码、负责人姓名、账号标识和单位内部联系方式按内部个人信息处理；安全报告、IP/端口、系统架构、后台地址和凭据按**内部敏感或受限**处理。不得在公开报告中完整导出；无需存明文口令、私钥、后台密码。
- OCR 可辅助定位，不承认 OCR 是签署人身份验证；使用校方权威台账免重复上传，缺接口时标 `SOURCE_UNAVAILABLE` 而非编造数据。
- 已复用的 G02 账号/权限结果仅说明某一版本授权，不表示对 `T07-T04` 网站建设事项有签发权限。
- 备案号、DNS 解析、`siteId` 和联系人是四种不同标识，不得凭同名字符串把甲单位的网站证据挂到乙单位名下。对公网的技术拓扑、入站端口、漏洞报告、用户采集字段不进入公开交接结果；来源权限不可得时只留脱敏的需求类型/引用。
- 站群编辑者、单位内容审核人、主办单位负责人、网络安全测试人员、国家备案主体与 DNS 操作人具有不同授权域。动作权逐项审计，撤回请求不能使 DNS 自动释放域名；站点生产执行记录不得由模型手写。

## 08 审核规则逐条清单

### 8.1 通用判定边界

本节 27 条是**可追溯的事实核验规格，不是学校自动审批标准**。适用范围先按 03 节 C01–C10 与 X-ICP/X-DATA 判定，再按 P0–P5 检查阶段；所有“签批、域名分配、上线安全合格”必须取校方真实有权记录。SRC-001 的规范正文已核但现行性未核，涉及其“应当”只能先作为候选，最终校本政策合规结论由 R019 阻断或人工核定。全国适用的 SRC-009 另按法定对象和适用情形评价，不能因校本规范未知而抹除。

- **T/F/U**：T=规则触发且进入核验；F=条件经可信数据证明不成立，则该 R 返回 NOT_APPLICABLE；U=触发条件本身不确定，先查询权威来源，仍未知不得默认真或假。对于全案基础规则（R001–R003、R019、R023），F 是“不属于该案/该阶段”而非自动驳回。
- **结果优先级不是自动裁决优先级**：每个 R 对自己的唯一核验对象只输出一个结果码；如同一对象有多个异常，先记录全部异常证据，再依 10.1 选择主码。不同 R 的结果可以并存，不做“全 PASS → 校方批准”聚合。
- **证据等级**：E1=按角色/对象/版本可核验的校方权威台账、签署或测评；E2=经有权单位确认的有效回执/备案表；E3=申请人声明、截图、第三方材料；E4=OCR/模型推断。E1/E2 优先于 E3/E4，但权威来源相互冲突需停下核查，不能简单“取最高一个”。E4 只能抽取待核字段。
- **时间效力**：每条 R 均绑定申请对象、审查阶段、执行时刻、政策版本、F 值版本和 M 的 sourceVersion/hash；P0 无法访问未来 P3/P4 记录并非缺件。材料替换、权限离任、域名迁移、备案变化、测评覆盖范围改变时按 R023 重算受影响规则。
- **通用异常**：已到阶段的必需申请材料缺失才给 NEEDS_MATERIAL；存在但 OCR/文件关键区域不可读给 UNREADABLE；校内权威台账/接口不可获得给 SOURCE_UNAVAILABLE；真实矛盾给 CONFLICT；规则/权限缺现行校本依据给 POLICY_UNCONFIRMED；超出机器判断权限或需要审批裁量给 NEEDS_HUMAN_DECISION。各条成功仅为 PASS_FACT。

### 8.3 阶段可达性和不得自动判定的硬边界

1. P0 能运行 R001–R007、R012、R019、R023/R024/R026 的适用部分；R008–R009 只有适时的单位意见阶段才核签；R014–R017 是 P3 上线前专门核验；R025 仅在国家备案适用且到指定阶段才核；R020–R022/R027 随正式决定、执行、关停后才可达。域名 R010/R011 在 P2 后方可要求权威台账，不能在初申阶段凭空强制 M009。
2. **P4 是逻辑上的正式决定/执行节点，不强制规定学校一定先在 P3 测评后才作建设原则批准。** 若真实学校流程有先批准建设、后备案测评、再上线的不同顺序，以原始指南为准；任何“准予建站”不得跳过真正上线前的安全门槛。
3. R019 政策时效未知时，可保存其余 R 的对象、材料、差异等事实核对观察，但不能汇总成“符合法规/已经审批”；R020 必须另取有效真实决定。若校方制度规定的审批链与本研究模型不一致，应修改模型而非修饰来源。
4. R024/R025 **国家备案**不代表 SRC-001 的**校内登记备案**；R025 的源失联不可归咎申请人。R026 的“无个人信息”不得凭开发商口头描述 PASS，至少要有责任单位可核方案；不同数据处理功能变更须使该规则重审。

### 9.2 材料/字段反例（研究测试素材）

1. **主从版本混用：** M005 旧备案站点 ID 指向甲学院，M006 变更说明却由乙部门提出；若无单位移交的权威依据，F003/F012 的对应为 `CONFLICT`，不能依据同名网站直接通过。
2. **旧测评冒用：** M008 测评报告为 `portal.cdut.edu.cn` 的上一版站点，而本案 F009/F017 改为另一域名/托管方式；F026 不能沿用旧 `PASS_FACT`，须按技术影响重新核或交网信处人工确认。是否法定“必须重测”的精确阈值待核。
3. **身份假匹配：** M003 签署人同名“张某”，前端 F013 角色为“处长”，但可信组织记录无法确认其在签署日期有负责人权限；输出身份不可信及 `NEEDS_HUMAN_DECISION`，不能按姓名字符串强匹配。
4. **申请表与备案表混淆：** 申请时提交 M001 载明拟域名，尚未有 F018 IP/开放端口或 M008 测评；不能因 M007 未形成而拒收 P0。正式上线前是否满足第十条必须另核。
5. **DNS 冲突：** 申请单位声称某域名“空闲”，M009 校方 DNS 权威记录显示被另一站点占用；以权威来源优先并保留申请人的异议，结果 `CONFLICT`，不是自动强行抢占解析。
6. **信息系统与新媒体混合：** 同案要求新学院网站和一个官方微信公众号；网站事实留 T07-T04，社媒账号授权送 T07-T05，不能把网站安全测评结论复用成账号开设批准。
7. **账号权限与建站授权混用：** G02 权威授权证明李某可以进入站群编辑后台，却没有网站新建/域名使用的正式决定；只通过 F015/F016 的对应事实，不得写入 F029。
8. **补件导致旧结论失效：** M006 v1 申请变更栏目，v2 改为服务器迁移；需对 F017–F022、备案/测评适用性定向重审。旧“无需技术复核”结论对 v2 不再有效，且不擦除原审计记录。
9. **来源失联：** 系统无法查询 M005 旧站备案，申请人有清晰 PDF；可暂作待核证据，但不得把 `SOURCE_UNAVAILABLE` 错判为“申请材料缺失”；保留人工查档待办。
10. **不可读取敏感结构图：** M013 关键架构图扫描模糊导致 IP/端口辨认不出；仅相关字段为 `UNREADABLE`，不要求申请人重交一份已能从可信备案台账得到的非敏感数据。
11. **校内备案与国家备案混同：** M007 已被校内受理，但境内公网新站尚不能由 M015 证实是否被学校现有备案范围覆盖；R014 可就 M007 事实核对，R025 仍 SOURCE_UNAVAILABLE/NEEDS_HUMAN_DECISION，不把新子域名直接认定“无备案违规”或“自动豁免”。
12. **外包数据采集暗门：** C09 自建/外包方案声称只发布新闻，M016 显示第三方脚本收集报名信息；R026 记录 F033 版本冲突并转数据/安全 Owner，R006/R013 的站群/托管事实不能覆盖个人信息合规决定。
13. **关停但旧解析残留：** C07 M011 记录网站关闭，M012 已备案；旧 FQDN 仍指向旧主机并呈现历史登录页。R022 的关停备案事实与 R027 的残留安全问题必须同时存在，不能把整体关停状态标完全完成。

### 9.3 权威结论引用与权限冲突

- 同一事项中，申请单位负责网站内容与管理人员，网络与信息化处按规范负责安全测评/技术安全监督；党委宣传部学校门户舆论监管并不当然替代二级站点的逐篇内容审核。各类“通过”必须保留各自授权范围，不能聚合成单一批准。
- 如果站群台账、域名台账、备案登记、单位负责人意见、G02 账号授权相互冲突，依据**事实类型对应的权威所有者**分别核查；不按文件上传先后或 OCR 置信度给行政决定排序。
- 如果校内来源时效未知，事实比对可以产生“资料一致”观察，但合规规则输出 `POLICY_UNCONFIRMED`；如果有真实争议或跨单位移交，交权威机构人工决定，不能将“补材料”替代行政裁量。

## 10 结果状态、问题与待办输出契约

### 10.1 八种互斥的逐规则结果

同一个 R、同一目标、同一证据版本、同一审查时刻只能有一个**主结果码**，但可附带多个可定位异常。以下“下一步”是建议待办，而非有权机关已受理的事实。

| 结果码 | 唯一含义/触发 | 不能表示什么 | 下一步责任 |
| --- | --- | --- | --- |
| PASS_FACT | 本条适用且有可追溯、当前版本有效的对应事实证据；如仅证实“资料一致”，应在 observation 中注明 | **不等于网站安全、域名分配、校方批准、允许上线**；R019/R020 未核仍不能汇总为合规 | 推进下一项核验或等待学校决定 |
| NOT_APPLICABLE | 明确证明触发条件为假，或该 R 对当前阶段不可达（reason=stage_not_reached） | 不是材料永久豁免或自动通过 | 后续条件变化时重新计算 |
| NEEDS_MATERIAL | 到达需使用材料的阶段，既无当前必需证据也无合法替代，且材料应由申请人提供 | 不包括未来才形成的决定/报告和校内源失联 | 申请单位/材料持有人补件 |
| CONFLICT | 同一目标/版本的权威记录与声明不符，或两个权威源相互矛盾、跨案归属冲突 | 不能由模型选择一个版本便视为解决 | 证据所有者及有权单位人工核对 |
| UNREADABLE | 文件存在且归属明确，但关键页/字段无法可靠读取 | 不是材料缺失、内容虚假 | 持有人换清晰副本或人工核原件 |
| SOURCE_UNAVAILABLE | 应查的校方权威台账/接口或正式记录不可访问，非申请人导致 | 不能凭申请人截图补成已核权威事实 | 系统/数据管理者恢复查询或人工查档 |
| POLICY_UNCONFIRMED | 校本现行性、资格、审批路径、例外或重测阈值没有有效原始制度证明 | 不能把外校规则或工程假设变成硬条件 | 网信处制度管理/有权业务部门核定 |
| NEEDS_HUMAN_DECISION | 事实已足或存在争议，但必须由校方有权人裁量、签批、确认权属、撤回或复核 | 不是模型自行否决，也不等于官方已经受理 | 经可信身份与授权核验的校方办理人 |

**单条规则求值顺序：**

1. 首先按对象与阶段判触发；明确为假或未来阶段才到达，则 NOT_APPLICABLE；触发未知先查证，不默认真假。
2. 有明确矛盾先保留 CONFLICT 证据；关键当前文件已交但不可读为 UNREADABLE；当前应交且无合法替代才为 NEEDS_MATERIAL。
3. 缺学校台账为 SOURCE_UNAVAILABLE；缺现行政策为 POLICY_UNCONFIRMED；事实核毕仍要裁量为 NEEDS_HUMAN_DECISION。
4. 只有核验对象的可信证据完整、无冲突且对应版本/时点有效，才给 PASS_FACT。多个异常同时存在时逐个保留 issue，主码体现根本阻断，不能吞掉次要异常。

### 10.2 输出实体与追溯字段（建议契约，不声称客户端已具备）

| 输出实体 | 必备字段与含义 |
| --- | --- |
| RuleFinding | ruleId、templateId、caseId、requestKind、phase、targetType、targetId/siteId/domain、triggerValue=T/F/U、resultCode、reason、policyRefs（SRC 条页）、comparisonMethod、checkedAt、policyAsOf、executorRole、observations |
| EvidenceUse | materialId（M）、fieldIds（F）、sourceId/sourceSystem、recordId、documentVersion/sourceVersion、hash、ownerOrgId、siteId/domain、pageRange/cellLocator、issuedAt、validFrom/validUntil、retrievedAt、trustTier(E1–E4)、readability、sourceAvailability、**accessGrantScope、redactionState** |
| Issue | issueId、ruleId、issueCode、严重性（流程阻断/提示，非法律裁量）、evidenceUseIds、矛盾字段值、当前阶段、受影响规则集、targetAssigneeRole、proposedAction、resolutionEvidenceId、resolvedAt |
| Task | taskId、caseId、ruleId、issueId、actorScope、assigneeRole、actionKind（补件/查档/政策确认/人工复核/签批/执行/备案）、stageDue（确有制度才填写）、status、createdAt、completedByVerifiedActor、completedAt |
| DecisionReference | issuerOrg、trustedSignatory、grantScope、decisionId、decisionType、decisionOutcome、effectiveAt、revokedAt、appliesToSiteId/domain/version、signatureVerification、evidenceUseId；与本模板事实预审结果分层 |
| RunSnapshot | runId、planId/fingerprint、entryRunId（如批处理）、frozenCheckTargets、sourceVersions、ruleSetRevision、createdByTrustedActor、createdAt、supersededByRunId；只反映真实 ReviewRun，禁止制造旧 run@rev |

**定位最小实例（均为合成数据）：** `Issue {ruleId:R025, targetType:domain, targetId:portal.demo.invalid, caseId:synthetic-01, phase:P3, sourceVersion:M015@unavailable, result:SOURCE_UNAVAILABLE, evidenceUseIds:[M002@v3], assigneeRole:SchoolIcpFilingOwner, action:check_authoritative_filing_coverage}`。这不是“申请人缺 ICP 证书”；台账恢复后仅重算 R025 及依赖其结论的上线状态。同一 C07 中 `R022/PASS_FACT` 和 `R027/CONFLICT` 可并存，不能并为“关停已合格”。

AssigneeRole 只是**建议办理岗**：UnitApplicant、UnitHead、UnitSecurityAdmin、UnitContentAdmin、SchoolIdentityAdmin、SchoolDnsOrSiteAdmin、NetworkSecurityOffice、SchoolPolicyOwner、AuthorizedDecisionMaker、HumanReviewCoordinator。缺真实授权时目标状态为“待校方分派”，不得按前端填的账号主动推送给假定人。

### 10.3 案卷汇总与正式决定分层

事实聚合层仅可为 FACT_REVIEW_READY（事实检查完成）、ACTION_REQUIRED（补件/冲突/不可读）、WAITING_AUTHORITY_SOURCE、WAITING_POLICY_CONFIRMATION、WAITING_HUMAN_DECISION。多阻断并存时保留全部 issue，不用某一 PASS_FACT 覆盖政策和身份风险。

**学校决定层独立：** NO_DECISION_RECORD、DECISION_CLAIM_UNVERIFIED、VERIFIED_DECISION_RECORDED、DECISION_SUPERSEDED_OR_REVOKED。只有 R020 对真实来源、授权、对象、版本完成核验才能进入 VERIFIED_DECISION_RECORDED；批准与否按决定原文显示，系统不代做判断。

**执行层再独立：** NOT_EXECUTED、EXECUTION_VERIFIED、CLOSURE_FILING_PENDING、CLOSED_WITH_FILING_EVIDENCE；按 R021/R022 权威回执认定。

对 C01，即使 R001–R019 的适用事实全部 PASS_FACT，也只能显示“事实预审完成，学校正式决定待核”，不能显示“已批准/已上线”。

### 11.1 案卷状态、前置权限与受控动作

以下是**拟议应用状态**，不声称学校 OA 已有这些状态或法定期限。所有事件采用 append-only 记录 trustedActor、roleGrant、timestamp、previousState、nextState、sourceVersion、reason 和相关 DecisionReference。

| 事件/动作 | 前置状态及可信权限 | 新状态和效果 | 禁止行为 |

### 11.2 三重权限与业务效力

1. **请求动作权**：经办人可发起补件、撤回或复核请求，需 Main/Host 可信 Actor 与所在单位、动作授权范围一致；代理只能执行明确授予的动作。
2. **业务处置权**：是否受理撤回或复核、争议域名如何处理，交真实校方有权人；审批链与时限未核，不能自动产生学校有效受理。应用记 WITHDRAWN 也不意味着既有校方批文已撤销。
3. **正式决定写权**：只有可核验的校方 Decision 系统或签发原件，经合法签发主体身份/权限校验，才能写入 DecisionReference。ReviewRun、BatchAttempt、前端角色自填无此权。仅有决定书截图而不能验签，保持 DECISION_CLAIM_UNVERIFIED。

### 11.3 定向失效与新 Run

**证据变了，相关事实预审失去对新证据版本的效力；其他独立事实不必全量重做。** 以 R→F/M/SRC 依赖索引求闭包，再判权限与结论是否仍然有效。

| 变更事件 | 需要失效/重审的 R | 未变且仍有效时可复用 |
| --- | --- | --- |
| 申请单位/经办人与代理授权变化（F003–F005、M014） | R002/R003/R004/R008/R009/R018/R020/R021/R023 | 纯技术配置事实，但不能保留旧签发权 |
| 域名申请/原域名变化（F009/F010、M006/M009） | R004/R010/R011/R012/R014/R017/R020/R021/R023 | 已核有效的单位与经办权限 |
| 站群、托管、IP、端口、版本变化（F011/F017–F022、M002/M007/M013） | R006/R012–R017/R021/R023 | 单位身份与无关内容责任 |
| 安全/技术/内容责任人员变化（F014–F016、M004） | R007/R008/R009/R014/R018/R020/R023，具体按签字关联裁剪 | 无关域名占用与 IP 技术事实 |
| 测评/备案新记录（M007/M008） | R014–R017/R019/R021/R023；若涉及决定前置则人工核 R020 | 网站目的与无关外部授权 |
| 公开访问/国家备案范围变化（F031/F032、M015） | R019/R023/R024/R025；若影响上线前门槛人工复核 R020/R021 | 组织身份、与国家备案无关的内容栏目信息 |
| 在线表单、用户登录、上传/第三方采集变化（F033、M016） | R005/R017/R019/R023/R024/R026；实际影响安全测评范围另交网信人员触发 R016 | 无关 DNS 占用核验及单位法定名称 |
| 关停执行、旧 DNS/重定向或旧入口状态变化（M009/M011，F010/F030） | R010/R011/R021–R023/R025/R027，必要时 R017 | 无关新站内容责任方案 |
| 规范生效、废止或授权矩阵修订（SRC） | R019 + 依赖相关 SRC 的所有规范性 R、R020/R023 | 原始字段抽取事实可保留，旧“合规”判断不得沿用 |
| 决定更正/撤销（M010），执行或关停回执变化（M011/M012） | R011/R020–R023，已实施状态交有权人确认 | 已核身份、计划等独立事实 |

旧 ReviewRun 的 Finding 保留历史与 supersededBy 指针，新 ReviewRun 冻结新的证据版本、plan fingerprint 和 Check×target；**不得把旧 run@rev 伪造为真实 Run**。即使文件字节不变，只要归属单位或站点改变，也要重核证据归属/签发范围。跨批处理引用必须绑定实际 entryRunId 和 sourceVersion，不能用错误 Run 的结果补本案。

### 12.2 无权由 AI 自动决定的事项

- 网站能否使用校名、校徽、官方品牌及指定二级域名；个人、学生组织、临时团体是否具备正式申请资格；
- 域名分配、跨单位移交和释放，站群非标准部署例外，重新备案或测评的行政解释；
- 校方安全测评是否通过、备案正式生效、网站准予公开运行；
- 信息稿件发布、保密审查、经营活动、数据采集或第三方运营的实体合规裁决；
- 撤回后既有批准是否继续有效、复核是否受理、原决定是否撤销。
- 国家 ICP 主办备案信息是否已覆盖新网站/特定域名、国家备案的报送/变更/注销应由谁办理；某一网站实际采集的个人信息能否合法处理、涉及保密或第三方外包的审查；旧域名是否可以转让或释放。这些都不得由网站材料预审自动签发。

**材料可被事实预审，政策却仍未知。** 制度效力、裁量和签发资格保留 POLICY_UNCONFIRMED/NEEDS_HUMAN_DECISION，而非补出虚假“批准”标签。

### 13.2 每个场景必须检查的共同不变量

1. 每个结果必须带 ruleId、目标站点/域名、材料版本、证据定位、可信源及下一办理角色；主码互斥，多个问题独立保留。
2. 触发为假、阶段未到与阶段已到但缺材料必须区分；同一 M 先后出现在不同业务时点不能做静态“永远必交”。
3. 有校内可信记录时优先合法引用，不无理由重复索要上传；无接口时为 SOURCE_UNAVAILABLE 而非制造接口。
4. 正式决定必须引用具权限核验的 M010；查询、事实核验、备案、测评、执行和最终决定相互独立。
5. 索引变更先求目标 R 的依赖闭包；未经权限确认的撤回、复核及跨系统审批均不得改变已生效校方决定。
6. 新增 X-ICP/X-DATA 的国家备案与校内备案、业务数据授权、外包合同、DNS/站群执行均各有 Owner；S13–S17 的失效规则须重审但不得倒逼 P0 提交未来 M015 或校外个人信息原件。每个反例需检查受影响 Finding 的 `sourceVersion`、`targetId` 与处理角色。
