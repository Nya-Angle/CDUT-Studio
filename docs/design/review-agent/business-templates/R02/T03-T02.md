## 01 唯一审核目的、申请人和负责机构

### 01.1 为什么是一个真实业务

成都理工大学科学技术发展研究院（下称“科发院”）于 2026-01-23 面向已立项的第一批省级科技计划项目负责人发布任务书签订/报送安排，要求其进入四川省科技管理信息系统填报；审核后下载有二维码、水印的任务书正式版，完成规定签字、合作单位盖章，再由科发院统一办理学校及教育厅盖章。[SRC-001] 2025-09-01 的第二批省科技计划通知亦呈现相似的“填报—审核—正式版签章—科发院用印”事实链。[SRC-002] 这足以证实**纵向立项后核验任务与承担责任**有真实业务基础，但不等于每个项目都有统一的校内“审批单”。

### 01.2 本模板核什么、谁决定

1. **对象**：一项确定的正式立项项目/课题/专题（需要项目批复或权威立项清单可追溯），其任务书、获准立项后具有约束力的申请书或其他主管部门认可的等效任务文本；对照研究内容、绩效/考核目标、项目周期、承担/合作单位、负责人、责任承诺、校内流程状态和版本。尚处申报推荐的项目不进入本模板的正式立项核验阶段。[SRC-001][SRC-004][SRC-006]
2. **申请/提供材料主体**：已立项项目负责人为主；科研秘书/助理可能协助提交材料，但其代理权限及委托证据需要另查，不以上传者自称代替负责人的真实签署。[SRC-001][SRC-004]
3. **归口机构**：自然科学与科发院管理的科技计划项目，依项目类别由科发院相应业务科室/重大项目办公室及教学科研单位配合；学校承担国家重点（重大）项目时，由重大项目办代表科发院管理，教学科研单位落实协同工作组，负责人履行直接责任。[SRC-001][SRC-004] 哲学社会科学事项还涉及学校社会科学处，不能全部指派到科发院。[SRC-007]
4. **形成有效决定的人**：资助/正式立项是否成立由**立项主管部门正式批准文件或授权系统记录**确定；学校负责按本校与当批规定完成审查、签章、备案/报送；正式任务书是否被主管部门受理生效、调整是否获批，仍以**有权主管部门/被授权系统的回执或批复**为准。科发院的校内审核意见和学校公章有其自身效力，但不能替代上级立项、任务书受理或后续重大调整批准。[SRC-001][SRC-004]
5. **核验输出**：出具可追溯事实一致/不一致、缺失/未读、政策待确认及有权人工决定待办；不自动承诺“立项成功”“学校批准”“项目负责人身份真实”。

### 01.3 适用性重要差异

- **四川省科技计划特定批次**：按 [SRC-001] 当批通知办理，并将其具体时间/份数视为**批次配置**，不得变成跨批次规则。其目标与申报书一致的要求应作同批专项核验。
- **国家重点研发计划、国家科技重大专项**：学校成理校发〔2025〕45 号，含项目—课题—专题层级与不同承担身份；任务书负责人认定、组织实施与变更由第 5–11 条具体约束。[SRC-004]
- **部分社会科学项目**：成都理工大学 2026 年校哲学社会科学研究基金申报通知明确立项后的《申请书》具有资助合同约束效力；应将“是否有独立任务书”作为项目品种条件判断，不能机械报缺件。[SRC-006] **校级项目本身不是本模板纵向外部项目的当然适用对象**，这条只用于论证文书类型差异及路由界线。

## 03 业务生命周期与办理情形矩阵

### 03.1 有来源支撑的阶段机

`L0 上级尚未正式立项或仅为拟资助` → **本模板排除或等待**；不得要求立项后材料。[SRC-012]

`L1 官方立项依据已可核` → `L2 按资助品种填写任务书/计划书或识别等效约束文本` → `L3 归口校内核验` ↔ `L3R 有依据的退回、修改、重新核验` → `L4 有权人员签署、合作单位签章及校方用印（若要求）` → `L5 报送后等待主管部门签批/接收` → `L6 引用有权受理/生效状态进入执行`。[SRC-001][SRC-002][SRC-004][SRC-013]

`L7 后续更正/调整/终止/复核` 只新建事件并引用有权结果，不覆盖 L6 历史；是否允许撤回、是“退回改稿”还是“撤销立项”，严格区分。[SRC-004]

**研究定义**：L1–L6 是证据和经办阶段，并非成都理工大学官方统一线上流程状态枚举。每个阶段的真实截止时间、撤回按钮、复核权须经当批/项目类型来源核定；未知记 `POLICY_UNCONFIRMED`。同一项目的多个课题、专题应有从属标识和各自任务书版本；不能把专题当另一份独立立项。[SRC-004]

### 03.3 第四轮新增的阶段与品种纠偏

1. **C00 国家社科2026公示**：SRC-019 是2026-10-08“立项名单公示”的标题；无有权最终立项通知/可查批准记录时仍是 **L0**，即使姓名出现在公示也不生成 M001 正式立项事实。SRC-018的2026年度申报公告能证明“获批后承担科研承诺”，但不是外部社科正式任务书与《申请书》等效合法性依据；C10仍需**同品种获批后**主管文本。映射 R002/R004/R029。[SRC-018][SRC-019]
2. **C04/C05 省2026第一批不同办理节点**：校内 M020 可核文字明确本校线上填报截止 2月3日；上级官网 SRC-011直开超时，SRC-021第三方全文转录列有**省厅阶段**2月5日填报、3月6日在线审核、3月13日送推荐单位、3月20日最终纸件送科技厅。此为**未获原版校核的候选阶段线索**，并非学校错年纸件日期的勘误，也不是可自动生效阈值；不同责任主体/节点须用不同 `deadlineKey`，不使用一个 F032 日期覆盖全流程。[SRC-001][SRC-011][SRC-021]
3. **2026 年新省自然基金规范**：另见跨校转载的川科政〔2026〕11号 SRC-020，可能影响后续省自然基金任务书品种和历史切换；未读科技厅正式原件与过渡条款前，**不逆推**其对2026年1月首批的适用，也不将其统一于其他四川省科技计划子类。映射 R003/R013/R020。[SRC-020]
4. **全校科研诚信承诺原则**：SRC-017对各科研活动实行承诺制，但实际哪个资助品种、由谁、在何阶段签哪一种有效表单，须在 F041/M023/R035 下完成条件分支。C02初填草稿不得因未见 M023 报缺；C04/C06/C08/C10等也不能未经校方实施文本就强制“第三份承诺书”。[SRC-003][SRC-005][SRC-017]

### 05.1 决定与证据的信任顺序（技术建议，非声称学校现有实现）

1. 先从主管部门立项批复/官方系统记录定位项目，凭项目唯一号、资助年度、承担单位及权威负责人，建立本案证据锚点。
2. 任务书、申报书、合作文件和承诺书逐项挂到相应项目与**文件版本**；OCR/LLM 提取仅生成“待核候选”，不得反向修改主管部门数据。
3. 对外部系统状态需要可追溯授权来源（接口、校内已验证的回执、人工复核）；一张“通过”截图不能等价于正式审批。
4. 校内审批人权限来自可信认证与部门授权，操作者、提交者、签字者和最终决定者可为不同人，记录真实 actor、职责、动作、时间、证据版本。
5. 任何结论遇到原始依据缺失、权限未知、签章真伪未核、项目编号冲突或涉密标识时，输出相应不确定/人工审查状态，不发出对外生效“通过”。

### 05.2 高影响人工保留事项

- 项目正式批准、任务合同生效及上级受理是否完成；无官方回执不得代认。[SRC-001]
- 科研工作者承诺的实际签署、负责人变动合法性、合作单位法人及印章、国家重点（重大）项目专题负责人认定。[SRC-003][SRC-004]
- 科学任务调整是否构成重大/重要/一般事项、是否违反考核指标、是否允许终止；须适用具体项目办法及有权行政裁量。[SRC-003][SRC-004]
- 涉密项目分级、脱敏与线下专门处理，不进入普通文件解析管线。[SRC-004]

### 07.1 当前材料、后续材料和缺失状态

1. **归属优先**：M001 的正式项目号及项目—课题—专题层级是统一关联键。材料没有项目归属或错挂其他项目，不能被“材料齐全”掩盖，输出 `CONFLICT`。
2. **取数优先**：M001、M002、M014–M016、M020、M022 能在有权限的主管/学校可信系统中查到时仅引用受控记录、版本和核验者，申请人不需无故上传第二份；**本研究不假定任何接口已接通**。
3. **未来才形成**：任务书草稿 M003、正式版 M004、国自然计划书 M006、纸质签页 M007、校章 M014、上级回执 M015 随 L2–L6 递进出现。前阶段缺少后阶段材料为 `NOT_APPLICABLE` 而不是 `NEEDS_MATERIAL`。
4. **四种异常分开**：应有材料却没有 `NEEDS_MATERIAL`；已上传但页缺失/扫描不可读 `UNREADABLE`；权威外部源失联 `SOURCE_UNAVAILABLE`；无法确认应不应该提交、是否现行 `POLICY_UNCONFIRMED`。两份可读材料实质矛盾才是 `CONFLICT`。
5. **合法替代不是随意材料**：仅同一有权主体出具/可验证的等效电子记录，或当品种规范明确允许的等效约束文本，可以替代纸件；私人说明、截图和其他学校表单只能作线索，不得代替审批。

## 08 审核规则逐条清单

### 08.1 规则执行及证据约定

**性质**：以下是有来源可追溯的**事实核查契约草案**，而不是已上线的规则或学校行政审批条例。规则触发先按 `C00–C15` 和 `L0–L7` 定位；同一案件可命中多个 C（例如 C04+C11 或 C06+C14），但不能混用不同资助类别的材料要求。没有取得 G50 正式清单、有效岗位权限表或当批原文的部分只保留人工待办。所有事实须关联 `projectKey + scopeLevel + materialId + sourceVersion + evidenceAnchor`。

- `T` = 有权项目类别、主体与办理阶段证据支持触发，**才执行**该规则；`F` = 有可靠证据证明不属于此类，输出 `NOT_APPLICABLE`，绝不报缺件；`U` = 类别、身份、阶段或政策无法核准，先按具体原因输出 `SOURCE_UNAVAILABLE` / `POLICY_UNCONFIRMED` / `NEEDS_HUMAN_DECISION`，不得以 U 当 F 或 PASS。
- **比对证据层级**：A = 有权主管部门正式决定、可核官方系统记录；B = 校方认证/用印及正式归档记录；C = 相应有权主体签署的当前版原件；D = 申请人上传的未经鉴真文件或 OCR 片段。A、B 有可信来源且版本匹配时优先；D 仅提供候选事实。某事实的政策依据可用校本已核制度/当批通知，但不表示技术数据自动变为 A/B。若有两份**同层级且有效**权威材料互相冲突，不能武断按时间最近覆盖，先 `CONFLICT`。
- **通用异常优先**：涉密先路由（R001）；阶段/政策不明先冻结该业务的判定（R002–R003）；当前应有的原证据缺失为 `NEEDS_MATERIAL`、权威源失联为 `SOURCE_UNAVAILABLE`、实际文件不可读为 `UNREADABLE`、同对象有效证据矛盾为 `CONFLICT`、需实质或权限裁量为 `NEEDS_HUMAN_DECISION`。`PASS_FACT` 仅表示该独立事实经可追溯证据核对成立，**不能综合成“学校批准”**。
- **有效时点**：政策按项目年度、类型、当批签批时点和来源有效期判断；申报书按**有权最终获准版**、任务书按**当前流程版**、已生效任务按**当前有效批准版**分别比较。改变某文件只重审依赖它的 R；已被替换证据对应的旧 `PASS_FACT` 不再作为现行可用结论。下表所有“下一角色”是**办理建议归口**，不指称未经核准的校方岗位具体审批权。

## 10 结果状态、问题与待办输出契约

### 10.1 八种互斥的逐 R 结果码

**一个 `ruleId × projectKey × scopeLevel × targetId × inputFingerprint` 的事实判定只产生一种当前结果码。** 同一个项目可同时有多个独立问题，不将所有异常挤成一个“总通过/总失败”。`triggerState` 仅记录条件 T/F/U，不是结果码。内部的 `STALE_NEEDS_REVIEW` 是**历史结论失效标志**，不加入八种结果。

| 结果码 | 排他定义、典型 T03-T02 例子 | 下一动作及绝不意味着什么 |
| --- | --- | --- |
| `PASS_FACT` | 当前触发适用，已找到可核的当时有效证据，**仅某独立事实**一致。例如 M001 权威项目号与 M004 同号、或 M015 确载“受理”事件。 | 保存具体事实、原文定位及核验者；**不等于学校通过审查、任务书已签章、上级已批准或项目合规的终局裁决**。 |
| `NOT_APPLICABLE` | 可证明规则本阶段或本资助类别不触发。例如 L1 未产生校章、2026 项目不触发 M010、校级项目不走此模板。 | 无需索相关 M；须保留“为何不适用”的 SRC/阶段证据，而非默认为无材料。 |
| `NEEDS_MATERIAL` | 触发已确认、**本阶段应有**材料或必要页不存在，且不能从已授权记录取得。例如 L4 当前省计划正式任务书 M004 缺失。 | 向当时责任材料持有人发起精准补件；不得要求其提交未来阶段签章/审批决定。 |
| `CONFLICT` | 两份可读、归属可核且在同一比较场景中的证据，关键事实相互不一致。例如正式任务书与批准申请书指标不一致，或同项目存在两份互斥“现行正式版”。 | 定位两个证据锚点，交科研归口/有权部门确认版本或审批处理，模型不得擅自选胜者；科学性分歧同时转人工。 |
| `UNREADABLE` | 应核文件**已经存在**，但缺页、损坏、OCR 无法确认关键页或图文不清；不能从可靠原文取得必要字段。 | 向持有人索同版清晰副本，保留原文件哈希及失败页；不得将解析失败当“没有签章”。 |
| `SOURCE_UNAVAILABLE` | 所需权威系统/学校归档事实源断连或检索无结果，且没有可用的其他权威记录。例如 M001 项目台账不可查。 | 请有权档案/归口人员核原始记录或等待源恢复；不能套用缓存截图伪造最新官方状态。 |
| `POLICY_UNCONFIRMED` | **是否适用、所需文书/时限、政策时效**缺可核现行依据。例如 C10 外部社科独立任务书未知、2026省计划纸件日期笔误。 | 标明具体政策 SRC 缺口，由科发院/社科处/主管方确认；不能设置臆测阈值或按外校政策否决。 |
| `NEEDS_HUMAN_DECISION` | 事实可能已齐，但仍需有权人判断**权限、印章真实性、科研重大调整性质、项目责任或行政选择**，或出现危险涉密分流。 | 指向有权角色及其可查决定记录，AI 不签发批准、撤回、复核结论；没有权限证明也不得把人工按钮视为审批。 |

优先顺序是**原因诊断**而不是全局简单排序：安全分流先行；`F` 明确不触发才给 `NOT_APPLICABLE`；`U` 先定位政策/身份/来源；对已触发的当前材料分别辨认缺、不可读、失联、相互冲突；事实齐但需行政/专业裁量时为 `NEEDS_HUMAN_DECISION`；仅所有本 R 事实已核且**不含未决裁量**才 `PASS_FACT`。同一 R 如同时有两种原因，主结果记录先阻断其判断的原因，并以 `secondaryProblems` 分项保留其他原因；不能隐藏冲突。

每项问题需具备以下字段（为**设计输出契约**，不宣称客户端 DTO 已经实现）：

| 字段 | 类型/必需性 | 约束 |
| --- | --- | --- |
| `caseId` / `projectKey` / `scopeLevel` / `targetId` | string / 必需 | 以立项编号与项目—课题—专题层级归属；不可用自然语言标题代项目主键。 |
| `ruleId` / `resultCode` / `triggerState` | enum/string / 必需 | `ruleId` 必须指向本 MD R001–R035；`resultCode` 恰选八项；`triggerState` 为 TRUE/FALSE/UNKNOWN。 |
| `scenarioIds` / `stage` / `policyRefs` | list + enum / 必需 | 对应 C00–C15、L0–L7、SRC；若法律效力未核记录未知，不能假写当期有效。 |
| `fieldRefs` / `materialRefs` / `evidenceAnchors` | list / 必需（可为空但须注明原因） | 引用存在的 F/M；每个锚点记录 `materialId/sourceKind/issuer/projectKey/scopeLevel/sourceVersion/contentHash/pageOrRecordKey/extractedAt/verifiedAt`；安全分流**只保存非敏感令牌**。 |
| `expectedVsObserved` / `conflictingEvidence` | structured / 适用时必需 | 指向两端实际文字或值和出处；若缺失不可读则明确未观察到，不伪造差异。 |

### 10.3 案卷汇总与待办优先级

1. **展示两条独立轴**：业务阶段（L0–L7/真实系统状态）与事实问题列表（八码）并排。案卷可“当前可核事实全部 PASS_FACT”且正式状态仍为“校内审查中/待上级受理”，二者不冲突。
2. **安全优先**：R001 触发即停止普通正文导入，屏蔽其后的材料预览；仅显示“已移交有权保密处理”，不暴露证据正文。
3. **主线待办**：`NEEDS_MATERIAL`/`UNREADABLE` 给材料持有人；`SOURCE_UNAVAILABLE` 给官方记录管理者；`CONFLICT` 给有权归口；`POLICY_UNCONFIRMED` 给政策负责人；`NEEDS_HUMAN_DECISION` 给可鉴权的决定主体。待办可直达项目、目标规则、材料及对应版本，而非打开另一套业务逻辑。
4. **不得自称完成**：仅可信官方决定对应的具体办理阶段才可展示“已完成该行政动作”；没有该决定，界面上最多展示“事实核对完毕，待有权审核”。
5. **不合并不同证据问题**：同一 C04 可同时有 R020 日期冲突 `POLICY_UNCONFIRMED`、R021 负责人签名待核 `NEEDS_HUMAN_DECISION`、R035 诚信承诺品种尚未确认；各自保留不同 SRC、F、M、项目目标层级、sourceVersion 与下一角色。已获立项不掩盖校内签章未完成，上级尚待受理不写成资助未批准。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 业务进程与内部草案状态

以下是**建议的内部状态转换**；不声称学校现有系统使用同名状态，且不改变 L0–L7 表示的实际业务阶段。内部记录与上级/校方正式状态必须分开：

| 进程/事件 | 必须满足的输入与有权角色 | 对案卷/事实结果的作用 | 禁止的跳转 |
| --- | --- | --- | --- |
| `CREATED → EVIDENCE_ROUTED` | 可信 Main/服务端创建案卷，R001–R004 有项目/安全路由信息；是否已获批由 M001 权威来源核 | 生成 L0/L1、C 触发及 M020 政策快照；未获批直接路由，无 T03-T02 实质审核 | 上传者自称“已立项”就创建有效任务书决定 |
| `EVIDENCE_ROUTED → FACT_REVIEWING` | 归口已确定，按 C 与阶段选取当前 M；负责人/授权代办者提供材料 | 冻结当前 R 依赖版本、生成逐条问题及待办 | 自动索取 L4/L5 才会产生的 M004/M014/M015 |
| `FACT_REVIEWING ↔ MATERIAL_FIX_PENDING` | R 输出缺、不可读、冲突等，办理人补对应 M 或校方修复权威记录 | 生成新材料版本；保留旧版本与问题，R033 使受影响规则定向重跑 | 覆盖旧证据，或把未修改的其他 R 历史结论全清空 |
| `FACT_REVIEWING → HUMAN_REVIEW_PENDING` | 高风险/权限/实质科研裁量仍存；真实归口与有权角色可信核验 | 附加审查意见、签名及权限版本；必要时要求 M013、M022 或上级原文 | 模型自动签发“校内审核通过”或靠 UI 按钮传假的 actor |
| `HUMAN_REVIEW_PENDING → SCHOOL_ACTION_RECORDED` | 已发生学校真实审查/签章/报送动作，M014 或同等权威台账核验；签署阶段材料已实际形成 | 把学校动作与其文件版、签发时间、权限号链接；该内部状态只表示**记录到校方动作** | 将学校盖章直接提升为“上级主管批准任务书” |
| `SCHOOL_ACTION_RECORDED → UPSTREAM_STATUS_REFERENCED` | M015 取得主管部门可信受理/生效状态 | 记录**上级原文状态**及对应任务书版；“待受理”不写为“生效” | 任何主体用自由文本/截图宣布上级已批准 |
| `... → FOLLOWUP_REQUESTED` | 已有有效版，负责人提出变更/延期/撤项或复核请求；事件 F033/M017 可追溯 | 原有效任务书继续显示有效；申请另设 `pendingChange`，只在有权决定后改变有效版本指针 | 未批申请自动覆盖 L6 承诺、终止原项目或改变负责人 |
| `FOLLOWUP_REQUESTED → OFFICIAL_FOLLOWUP_RECORDED` | 获得有权单位批准、备案或拒绝的 M017 权威记录且角色核对 | 依据生效日期建立新版任务/权威决定链，并定向重审 | 将校方“收到复核申请”自动转换为上级复核成立或救济成功 |

`SCHOOL_ACTION_RECORDED`、`UPSTREAM_STATUS_REFERENCED` 是**审计记录状态**而非学校官方批准语。终局是否存在及效力，只读取真实 `officialDecision`；如果某项目业务没有校内用印或上级受理环节，由核实后的品种配置跳过，不能为凑流程制造假动作。

### 11.2 补件、换版与影响闭包

1. **定向补件**：每个待办固定 `ruleId/fieldRefs/materialRefs/projectKey/scopeLevel/requiredAtStage/expectedIssuer/ownerRole`。负责人补的是 M002 缺页时，不能顺手要求 M014；档案可读性修复仍沿用原 `materialId` 但产生 `sourceVersion+hash` 新快照。
2. **来源与版本双轴**：`submittedVersion`（待审）与 `effectiveApprovedVersion`（有权生效版）分别指向证据；更换扫描件只更新可读性版本，不自动改变原法律生效版。若两份互称现行、同权威等级而无法核决定链，R015/R033 输出 `CONFLICT` 与人工核定。
3. **失效事件**：`MaterialReplaced(oldId, newId, actor, time, reason)` 使全部**直接读取该旧版**的 R 变 `STALE_NEEDS_REVIEW`；重新核查后才生成新的八码结果。旧观察保留 `supersededAt`，不可当新 RUN 的当前结果。
4. **传递依赖**：例如替换 M002 → R005、R012、R016、R018、R027（若属国自然）、以及其下游 `F008/F016/F022/F029`；替换 M003 → R005、R014–R017、R030、R033；替换 M004 → R005、R013–R017、R019–R023、R026（若适用 C11）、R032；替换 M022 → R001（仅涉密权限令牌）、R006、R008–R011、R021、R023、R031、R034。新增替换 M023 → **仅在已触发的 C 上**R035，以及经校方确认复用同件时 R025/R026；F041 与签署结果重算，不牵连不读承诺的项目号 R004。只以**实际 R-M 关联和 C 触发**计算，并非不分场景把清单全部重审。
5. **增补政策**：更新 M020/SRC 时仅使真正依赖该 `policyRef+version` 的 R 与 C 路由失效，再重算阶段义务；例如 SRC-011 截止日得到正式更正，先重核 R003/R020，不让无关的签名真伪 R021 自动重跑；SRC-020的原文/过渡条款补齐后重核其命中省自然基金类型的 R003/R013/R020，而不扩散到国自然 C08 或历史已批任务；SRC-017的实施表单被确认时重核 R025/R035，不撤销未受影响的立项事实。
6. **跨模板消费**：G50/T02/T07/G07 等官方结论本案持有的是 `authorityDecisionRef`；上游决定撤销、更正或过期，所有引用其 `decisionId/version/effectiveRange` 的 R034 与实际下游字段标为待重审。本模板**不重新决定**他模板原授权事项。

### 11.3 撤回、再提交、申诉/复核与最终决定

| 情形 | 条件检查 | 内部处理与真正有权结果 | 当前政策确认状态 |
| --- | --- | --- | --- |
| L3R 由科发院/主管系统退回改稿 | M016 有正式退回动作、具体项目草稿版本；经办权限可核 | 允许在**实际系统已开放的动作**范围重填 M003，旧稿不删；重新提交核受影响 R | SRC-001 可证明校内审核/填报业务存在；统一退回次数及截止待核 |
| 主动撤回尚未正式受理稿 | 本人/受授权代理身份、当期系统是否开放撤回、M016 对应事件 | 若尚无有权撤回记录，仅记录“撤回请求待确认”，不删除案卷、不撤销正式立项；获得有权事件后记录操作结果 | **主动撤回权限/期限未知**，`POLICY_UNCONFIRMED`/`NEEDS_HUMAN_DECISION`，不得伪造已撤回 |
| 撤回后重提交/补正 | 旧事件决定号、可重投规定、新草稿版本与授权主体 | 开新的 `submissionAttempt` 并引用同一项目主键和前次版本；重复材料可复用其仍有效事实，失效 R 重审 | 重提资格、次数与是否需新申请须由实际主管规定确认 |
| 已获正式项目后的撤项/终止 | 有权机关决定文件或专项办法列出的审批层级；M017 | 与任务书草稿撤回**严格区分**；只有主管/有权机关决定才改变项目状态 | SRC-004 第10–11条只对适用专项；通用项目未核条文不能自动办理 |
| 对事实抽取提出异议 | 指向 ruleId、当时材料版本、异议内容和提交人真实身份 | 允许**研发系统内部重新核验**事实，不将此称为已有学校正式申诉渠道；重新核后记录 reviewer 与证据 | 内部纠错可设计，校方正式救济权、期限与受理机关未证实 |
| 向有权学校/主管机构申请行政复核 | 当期制度已证明有申请主体、受理渠道、期限、签收号、回避/复核权限 | 只在有权机构真的受理时建立 `officialReviewRef`；未取得制度先标“人工转询/路径未知”，不自动受理、撤销或推翻原决定 | **尚缺通用校本与主管分类依据**；SRC-001/004 不足以推断通用复核权 |

**正式决定的严格前置**：必须有 (a) 适用品种授权的决定机关与权限版本；(b) 经真实 Main/服务端确认的 actor 身份及动作授权；(c) 该机关对应的签发/用印/电子受理原始记录；(d) 决定所指项目层级、文件版本、时间和可核编号；(e) 独立于事实预审的人工/主管程序。任一不满足只能产生`NEEDS_HUMAN_DECISION` 或相应来源缺口，**不能提交“已批准”决定**。即使 35 条 R 都得到 `PASS_FACT`，结果仍是“事实可核、等待真实有权决定”。
