# R02 模板质量修复结果（2026-10-25）

本轮**只处理 144 份业务模板本身**，不改 Main、IPC、Renderer、Pi、学校策略仓库或任何发布/审核执行门禁。源码基线为 PR #251 的 115 份集成候选，按已审计的原始 blob 和 PR HEAD 收拢 #252–#260、#262 中的另外 28 份；不修改上游作者分支。

## 输入与完整性

- **143 份真实候选 MD/TS 成对到位**，未新增空壳。第 144 项 `T02-T08`（校内调动、岗位流转）没有原始研究稿和可靠候选；本轮不伪造“历史文稿找回”，也不以相邻 T02 模板顶替。
- 研究模板均保持 `draft`、`policyVersionIds: []`、`autoPassPolicy.enabled: false` 和非官方来源说明；仅支持研究/事实辅助，不产生任何学校正式决定。
- 准确检查了 **143 个可装载模板对象、5,818 个字段、3,499 个材料槽、4,409 条规则标准**。定义对象中没有重复字段/材料/规则 ID、已知悬空条件引用、元数据规则挂空或当前来源指针哈希不一致。

## 已直接修复

1. **44 份**定义没有统一 `templateVersion` 导出：增加别名，保留原批次 API；不改字段、材料或规则实质内容。
2. **18 份**元数据中的 `sourceDocumentSha256` 与其明确指向的当前仓库文件不符：修正成当前文件字节 SHA-256，并在 `source-hash-differences-20261025.tsv` 单独保留 18 个原值；另为下述 S07-T02 文稿补充技术映射后刷新该文稿 SHA，台账共 19 条。均不冒称原值属于现行文件，也不修改原始研究文档。
3. **5 份** S06-B 研究定义没有统一的 `R02_RESEARCH_TEMPLATE_NONOFFICIAL:` 标识：保留原始说明原文、补前缀。仍不据此前缀声称官方发布安全门禁已集成。
4. 增加可重跑的 `quality-source-check-20261025.mjs` 静态质量检查器，及 Bun 端 `r02-quality-integrity.test.ts` 跨批次回归。该检查器不依赖上传、OCR、学校账户或模型。
5. **S07-T02** 原 ROUND1 只有 `F001/M001/R001` 占位，但 TS 已有 11 字段、6 材料槽、8 标准：在文稿附录补全真实技术键、阶段/权限和非执行边界对照，不追认原研究稿第 2–4 轮已经完成，也不填写未知授位阈值。

## 不能把这次修复当作业务规则质量 PASS

这些是真实的模板设计缺口，而非测试框架错误：

- **138/143** 个模板所有材料槽的 `minCount` 均为 0；尤其有大量条件/阶段性必需材料只写在文字里。这不代表必须强制所有槽为 1：需要按每一办理情形、P 阶段和材料来源构建可信 `requiredWhen/requiredAt`，不能盲目改成提交失败。
- **143/143** 没有 `dataCheck`。其中大部分是有意保留 `manual/semantic`、等候校方政策的研究规则；不能把写入 TypeScript 的自然语言标准当成已执行的自动检查。
- 学校现行细则、正式签发/授权链、某些批次效力未获可信原件的，仍只能标 `PARTIAL/UNCONFIRMED`。不得提升为 `VERIFIED`、正式规则或学校自动通过。
- `T03-T09` 涉密模板继续保持**普通联网客户端不得收件/OCR/上传**的边界；不能为了字段覆盖率把涉密研究字典扩展到普通电子收件。
- 没有对 4,409 条 R 逐条完成校本适用性裁决，也没有完成每模板 A/B/C 场景业务终验；**不存在可如实宣称的 144/144 独立质量合格**。
