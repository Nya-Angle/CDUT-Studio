## 01 唯一审核目的、申请人和负责机构

### 1.1 决定对象

本模板只回答：**在一项已经存在的课程教学任务中，拟由谁在何段教学活动中替代、接替或重新分担原已确定的授课责任，支撑该调整的事实材料是否一致且足以交由有权限人员处理。**

建议将“同一责任对象”定义为一份 `TeachingAssignmentPersonnelChange`（研究期概念名，不声称为学校系统实体）：

- 主键锚定 **学年学期＋课程＋教学班/教学任务书标识＋原任务版本**；同一申请内保存原任课教师、拟任课教师、主讲/助课/共同授课角色、受影响周次/课次/学时、拟生效时间和调整原因。
- 变更前后责任归属、实际授课安排与教学任务记录必须能一一对应；一份申请涉及多人可列多名变更当事人，避免将每一位教师再拆一个模板。
- 本科原授课任务依据：2022 年《本科课程教学基本规范》第 19、20、24 条，以及 2025 年特定学期教学任务通知关于“主讲教师”与多教师学时分配的要求。[SRC-001][SRC-002]

### 1.2 申请与承办角色（不得将推定角色写为学校法定流程）

| 角色 | 可确认事项 | 本轮限制 |
|---|---|---|
| 原任课教师 / 课程负责人 / 课程组 | 本科课程组组织任课教师；任课教师因特殊原因调停课须提前申请、课程组协调。[SRC-001] | “更换教师”由谁有正式申请权、是否允许教学秘书代办，未取得全校表单，不作统一确认 |
| 拟替换教师 / 合授教师 | 教师任课资格和既有任务安排是事实核验对象；本科主讲教师的基本条件见第 19 条；具体学期可能有额外岗位条件。[SRC-001][SRC-002] | 教师本人同意、单位意见的法定形式及其签署节点待查；本人填报不等于人事权威核验 |
| 开课学院（系）/基层教学组织 | 本科开课学院为课程管理主体，组织教师任课资格认定；学院（系）负责日常教学实施；本科调停课需学院审核并报学校备案。[SRC-001] | 第 24 条的**调停课流程不能直接当成“更换教师”完整批准链** |
| 教务处、学院教务科/教学秘书 | 教务处负责全校本科教学管理；某学院岗位职责包含教学任务书下达/回收、课表和工作量。[SRC-001][SRC-003] | SRC-003 仅证明该学院人员分工，不自动扩展到全校全部学院 |
| 研究生院 / 研究生培养单位 | 某学院 2026 年岗位说明证明研究生课表由学院相关岗位编排；2021 年研究生课程教学管理办法确有官方文件号线索。[SRC-004][SRC-005] | 研究生人员替换的申请人、审核链和有权决定机关**待取得成理校研〔2021〕11号原文后确认** |
| 校级记录接收者 / 最终有权决定人 | 本科“调停课”可核实学校备案节点。[SRC-001] | **人员替换究竟学院批准、教务处批准还是备案/复核**，不能在本轮作最终断言；必须由学校当期授权与业务日志决定 |

**有效决定的边界。** 审核代理只能出具可追溯的材料一致性、缺口及冲突报告；正式人员调整以学校授权系统的决定/确认/备案记录为准。若当前办理要求是学院审核和学校备案，应分别保存“审核意见”及“备案回执”，不能把“备案已送达”伪装为校级批准。[SRC-001] 如果人员替换另有单独权力路径，应以更具体且现行的校本规章优先。

## 02 适用、排除与邻接模板路由

| 情形 | T01-T02 边界裁决 | 原因 / 外部引用 |
|---|---|---|
| 某次课原教师不能授课，拟由另一位教师实际授课 | **纳入候选**，作为短时代课/顶替分支；是否准许及补办手续依据待核 | 改变了教学任务的实际人员责任；不可预设紧急情况可豁免批准 |
| 学期内中长期改换主讲教师、共同授课教师人员增减 | **纳入候选**，保留原、新负责人及受影响教学任务版本 | 第 19、20、24 条支持审查原责任和任课人员；但未单独确立审批链。[SRC-001] |
| 同课多人授课的学时份额或分工调整 | **纳入候选**，但仅在确实涉及“人员责任/学时归属”时 | 学期教学任务通知要求多教师授课学时准确分配、确定后不随意变动；具体学期强度不得泛化。[SRC-002] |
| 仅调整上课时间、地点、停课/补课，教师责任完全未变 | **排除→T01-T01** | 不得以代课名义吸纳纯时间地点调整；若同时换人，则 T01-T02 为主，时间变更引用 T01-T01 经权威确认的部分 |
| 教师是否具备新开课/任课资格的独立认证 | **排除独立资格决定→T06-T04**（以冻结总账正式名称为准） | T01-T02 仅引用有权管理单位的资格/任职/限制结论，不自授任教资格。[SRC-001] |
| 课程建设、课程设置、大纲或新开课程审批 | **排除→T01-T05**（以总账为准） | 课程内容和设置变更与既存教学任务人员变更目的不同；第 7、18、22 条另有路径。[SRC-001] |
| 学生成绩复核/更正或考试决定 | **排除→S02 对应模板** | 可保留受影响授课人的关联，不据此改动成绩或决定成绩申诉结果。[SRC-001] |
| 涉及安全条件/资质（实验、实习等） | **引用 G04 有权结论，不作安全审批** | 人员变更可伴生安全核查，但不能替代安全专业审查；G04 精确映射待原 G50 目录核对 |
| 教学事故认定、师德处分、绩效奖惩、人事聘任 | **排除正式决定** | 第 26 条确认教学事故责任追究制度，不代表本模板能作事故处分。[SRC-001] 工作量“记录一致性”可核，薪酬/聘任决定另走权威流程 |
| G50 已包含相同授课人/课程证明的通用核验 | **复用其有效事实或问题引用，不重办审批** | 尚未取到指定 SHA 的 `catalog.json`；待核重合 ID、输入/输出及 G50 更新效力，禁止凭名称构造去重映射 |

路由原则：**一套责任对象、一个主模板、多个必要的权威前置引用**。联合情形只因真正不同的决定目的才跨模板；纯粹附带材料不生成新 ID。针对当前未发现需独立授权目的的证据，**本轮不提交 `CATALOG-CHANGE-REQUEST`**。

### 3.3 不可先验要求的“未来证据”

- S0/S1 不要求 `M011–M016` 中尚未形成的协调、审核、备案、执行和工作量记录；材料槽存在不等于当前缺件。
- C02 的事后说明可在事情发生后创建，无法以“未提前上传”自动认定违规。行政问责另由有权部门处理。

### 5.2 代理与结果语义

- 申请人可以是课程责任人、原任课教师或被正式授权的经办人等**候选角色**，但具体谁可提交、谁可撤回，由本/研及学院当期流程确定；代理凭据须与真实主体、范围、有效期绑定。
- `Renderer` 的演员/身份参数不可信；Main/Host 服务侧必须从登录主体、受控组织角色和授权决策中获得 `Actor`，将人员和动作绑定至一次不可串改的案卷/运行/决定记录。此为安全设计边界，**并非学校规章原文**。
- 结果状态预留 `PASS_FACT`、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`。`PASS_FACT` 仅表示某项资料事实被充分支撑；**不存在“事实审核通过=人员更换获批”的转换**。
- 如果学校制度版本不明、人员资格数据不可用、原任务版本冲突、跨本研审批链不明，必须输出可处理问题和待办，并止于人工核查；对不具证明力的图片或声明使用 `UNREADABLE`/`CONFLICT`/`SOURCE_UNAVAILABLE` 区分，不用单一“失败”吞并原因。
- 建议记录源证据校验信息、有效期、提取字段置信度、权威原记录版本以及每次补件/撤回/复核的派生版本；依赖人工决定的事项不得被自动重审覆盖正式决定。

## 06 业务对象与字段字典

### 6.1 对象关系与填写口径

- `Application`（申请事件）：一项主教学任务可有多次申请/续期/补件；每次申请独立 `revision`，不能复写原有决定。
- `TeachingAssignment`（权威基线）：学期＋课程＋教学班＋教学任务号＋版本；`AssignmentPersonLine` 保存原/新教师与分摊学时；不能只用“课程名称＋教师姓名”定位。
- `LessonImpact`（变更范围）：课次、日期、学时、具体责任分工以及是否伴生时间/地点调整；后者的正式决定引用 T01-T01。
- `AuthorityTrace`（授权/决定）：申请人、代理、协调人、审核者、批准者、备案者分别有带时效的服务端身份和行为记录。
- `EvidenceLink`（材料谱系）：`Mxxx` 槽、原始源编号/版本、适用案卷/教学任务、获取时间、不可读与替换关系。字段为**业务数据设计，不是已获校方确认的线上表单**。

隐私级别：`P0` 公开课程制度；`P1` 校内教学业务信息；`P2` 可识别教师的个人/任职信息；`P3` 病假证明、敏感人事理由等高敏内容。一般只保存事实结论和最小必要索引，`P3` 由有权人员分权限查看。下表 `首要证据位` 表示 `M` 槽或可信系统的记录字段/位置；来源接口不可用时允许**校方受理人员的带签名核验结论**替代读取，不声称系统必有 API。`缺失=待补` 仅在该阶段和适用条件已满足时触发；未到阶段记 `NOT_APPLICABLE`，原始可信源断连记 `SOURCE_UNAVAILABLE`，不以空值自动作驳回。

## 07 材料槽与证据目的

### 7.1 材料槽登记口径

`当前必需` 是**事实预审的最小资料需求**，不等于校方依法要求教师上传的必交件；可以由学校可信记录读取或受理人员核验填充。`条件必需` 必须同时满足业务触发及经确认的政策适用；若后一个条件仍未知，标 `POLICY_UNCONFIRMED`，不擅自退件。`后续产生` 的材料不能出现在 S0/S1 缺件列表。`版本/归属` 均以“案卷—教学任务—学期—教师—课次”对应，允许一案多人员行，但禁止异案共享扫描件推定同人。材料不可读则 `UNREADABLE` 并提示具体页；材料不存在但当前确需补足为 `NEEDS_MATERIAL`；校内可信接口不可用为 `SOURCE_UNAVAILABLE`。涉及敏感病因只核有权部门确认的适用事实，不额外采集诊断细节。

## 08 审核规则逐条清单

### 8.1 规则执行共约束

以下 `R001–R025` 是**候选事实核验规则**，不宣称学校颁布了同编号规章。每条规则只验证一组独立事实/有权记录，不作是否同意换人的实体裁量。`T/F/U` 分别表示该条**触发条件真/假/未知**：`T` 进入比较，`F` 只对该目标记 `NOT_APPLICABLE`，`U` 暂停该目标判定、追查触发事实/政策，不能被隐式转换成真或假。已进入比较后的“证据相符/不符/不足”另输出 §10 的互斥状态。对于无校本规定支持的“必须签字、申请截止天数、次数上限、学时阈值”，即使材料字段齐全，也只允许 `POLICY_UNCONFIRMED` 或转人工。

**证据层级：** `E0` 校方可信业务源/原生审批决定及其有效版本；`E1` 可向签发机关核验的正式电子/纸质凭据；`E2` 申请人说明、上传扫描件；`E3` OCR/LLM 提取结果（只能定位待比对内容）。E0 不一定证明其**有权对本事项作该决定**，须同时校验部门/岗位/期间/适用学段；同级 E0 冲突也不能自行任取一份。各规则以 `F044` 附源系统、材料版本、原始页/字段、获取时间和身份关联；若官方来源断连，记 `SOURCE_UNAVAILABLE` 而非强令当事人重传。

### 8.2 输出边界与强度

- 每条 R 评估前先检查**阶段可达、触发条件、政策适用**，再读当前所需 M；某一办理情形尚未进入 S3/S4，则 R015–R022 中未来节点仅作 `NOT_APPLICABLE`，不能一律输出 `NEEDS_MATERIAL`。
- `R001/R002/R005–R009` 的客观一致性能够支持事前事实预审；`R011–R018/R023–R024` 依赖任课资格、组织授权、校规效力和行政裁量，事实项可 `PASS_FACT` 但**不会产生学校准许代课/批准变更结果**。
- 多独立事实可分别给出状态。遇有效政策缺口仍可以指出学期、教师、课时的可核事实，但对正式决定阶段持续挂 `POLICY_UNCONFIRMED` 与 `NEEDS_HUMAN_DECISION`。所有硬性门槛须有**适用且经校方确认现行**的 SRC/条款或可信学校配置，否则不计算“合规/违规”结论。

### 9.2 冲突优先级与证据谱系

1. **对象冲突**：`M001` 教学班/学期/任务号不等于 `M003` 拟变更范围，先标 `CONFLICT` 并让开课单位确认；不将其他教学班的教师资格、工作量、决定借来自动通过。
2. **身份冲突**：`M002` 姓名与 `M006` 人员 UID 不符，或两个同名教师 UID 不同；姓名、照片、OCR 是待比对内容而非真实 `Actor`。须以权威身份校验及签署时身份为准；身份目录断连 `SOURCE_UNAVAILABLE`。
3. **计划与执行冲突**：申请 `M003` 只换第 7 周两节，后续 `M016` 却记录第 7–9 周的另一人授课；记录“申请范围 vs 实际授课”事实差异，交有权部门决定补办、更正或调查，不自动改原申请。
4. **数量冲突**：原任务 `M001` 两名教师分配 16+16 学时，新 `M003` 报 20+16 或重复录入同课次；这只证明申报内部不守恒或与权威计划不一致，需要教务核对，**不在未知校规下直接判断违法**。工作量 `M016` 的结算周期和原任务不是同一口径时不得直接相减。
5. **权力冲突**：`M011` 的课程组“同意”、`M012` 的学院“已审核”和 `M013` 的校级“已备案”分别是不同动作；没有现行授权规则不得合并成一条“全部批准”。签名图片必须和服务端角色、岗位任期、课程归口绑定；前端字段不可信。
6. **政策冲突**：`SRC-011` 院级“更换教师使用调课申请表”与其他学院流程缺乏统一依据时，仅在该院且由学校确认当前有效后作为表单候选；2021 研究生办法原文未取得，不能拿 `SRC-008` 的 2018 旧规则填补。
7. **材料覆盖冲突**：新上传 `M004` 仅替换旧原因说明而不触及原任务和授课人时，只需针对依赖它的事实重审；新 `M001` 权威任务版本或 `M006` 身份改变，则重新核定位、范围、资格、学时及全部派生引用。任何旧 `PASS_FACT` 均与原 `sourceVersion` 绑定，不能被新材料无条件沿用。

| C02 已授课，尚无学校审核意见 M012/M013 | S0 缺件退回，因为没提前提供审批签章 | 接收 M021 事实时间线和可得实课记录；后续签署/追认由校本有权主体裁量 |
| M013 只有“备案成功”却在申请系统显示“批准通过” | 断定人员替换已被校级批准 | 按原签发动作 F031=`FILING`，提示权力语义不一致 `CONFLICT`，不得重写学校决定 |
| C04 申请学时 20+16 与原定合计 32 不一致 | 直接认定学校不能调整或工作量作弊 | F016/F017 事实 `CONFLICT`，核课程计划/特殊分工/原表口径后交有权岗位决定 |
| 已获决定的 C01 再上传一份更改课次的 M003 | 覆盖 M013 的既有决定，原已执行课次消失 | 保留原 M013 与执行记录，创建 F039 新修订，限受影响检查重审；更正/追溯另须新权威决定 |
| G04 仅提供实践安全培训通过记录 | 把安全培训等同于本课程任课资格 T06 | 只读 G04 适用结论，仍需独立的 F026/M007 任课资格结果，条件未知人工判断 |
| 学校教师目录不可用，但申请人上传身份证照片 | 认为自行提交即可证明在职与审批资格 | `SOURCE_UNAVAILABLE`，避免重复采集敏感信息；校方身份或人事经办人出具可信核验结果 |

### 9.4 补件后的局部重审界线

保留 `F044` 中每个 M 的持有人、源版本、取得时间、具体页/字段和 `replacesMaterialVersion`。同一材料重传先识别是“清晰度修复”还是“业务事实变化”：清晰度修复只重审相关字段，原任务/接任人/生效决定变化则扩展至所有依赖事实。`M017/M018` 是案卷后续事件而不是可编辑的旧决定正文；正式改动仍需学校有权签发。逐条 R 已列于第 08 节，材料到规则的失效映射在 §11.2，结果问题在 §10；这三处以 `ruleId/targetKey/sourceVersion` 形成同一事实回路。

## 10 结果状态、问题与待办输出契约

### 10.1 八个互斥事实状态

对同一个 `ruleId × targetKey × sourceVersion/revision` 的一次观察，`status` **只能取下列之一**；每一种障碍可用单独观察/问题并存，不能把八种状态混成“通过、驳回”两档。`decisionStatus` 与 `reviewStatus` 是另外的业务轴，不属于以下八个事实码。

| 状态码 | 唯一语义与典型情形 | 不允许的解释 | 目标办理方/出口 |
|---|---|---|---|
| `PASS_FACT` | 当前适用对象的某项客观事实已被相应层级证据一致支撑，例如 R007 的课次清晰 | **不是**“换人获批/合规/自动办结”，也不证明其他 R 通过 | 下一事实核验或学校有权人工审理 |
| `NOT_APPLICABLE` | 本次触发明确为假，或尚未到材料产生阶段：S0 的 M013、未来 M016，或纯时间变更对本模板 | **不是**缺件，也不意味着永久免除后置义务 | 仅记录触发依据；转相邻模板或等待后续阶段 |
| `NEEDS_MATERIAL` | 已触发、目前应有且申请/业务方有能力提交的证据客观缺失，如 M003 无变更课次 | **不是**官方系统断连或未来决定没上传 | 申请人/可信经办人补限定 F/M |
| `CONFLICT` | 同一目标、同一时间与口径的证据不一致或身份/对象/版本错配 | **不是**行政驳回或认定违纪；不同周期不可盲算冲突 | 开课单位、身份/任务管理岗核实差异 |
| `UNREADABLE` | 已有材料字节、页或字段因模糊、缺页、解析失败不能可靠读取 | **不是**材料不存在；OCR 失败不等于原件无效 | 材料持有人重取局部，必要时人工阅件 |
| `SOURCE_UNAVAILABLE` | 应由校方权威记录提供的事实目前访问失败、接口不存在或已确认暂不可取 | **不是**由申请人必然承担的缺件；也不是事实为假 | 校方源系统/受理岗位人工出具核验摘要 |
| `POLICY_UNCONFIRMED` | 决定“何人有权/何时必需/是否适用”的现行校本规则、版本或阈值无法证实 | **不是**自动用外校、旧院规、研究阶段阈值填空 | 教务处/研究生院/校本政策 Owner 确认后重审 |
| `NEEDS_HUMAN_DECISION` | 事实可完整呈交，但必须由有权人裁量：紧急补办、正式批准、撤回受理、申诉/复核 | **不是**软件代签、也不是默示准许或不准许 | 授权校方角色在真实系统记录决定和效力 |

**互斥决议顺序。** 先核目标归属及阶段：触发确认为假直接 `NOT_APPLICABLE`；触发未知则先定位所缺的是政策、源数据还是申请材料，分别产出相应状态。触发真后按证据问题的**直接原因**选择 `UNREADABLE`、`SOURCE_UNAVAILABLE`、`NEEDS_MATERIAL` 或 `CONFLICT`；事实无障碍而仅剩学校自由裁量才用 `NEEDS_HUMAN_DECISION`；比较到位且此 R 只问“事实是否一致”才可 `PASS_FACT`。一条 R 有“课次事实可核、批准权未知”两个目标时输出两个独立观察，不强行用一个码覆盖另一项。例如 R013 的学段事实 `PASS_FACT` 可与人员批准链 `POLICY_UNCONFIRMED` 并存。

### 10.2 单条问题与证据的最小输出合同（研究草案）

| 字段 | 必须表达的内容 | 约束 |
|---|---|---|
| `caseId / runId / planFingerprint` | 同一个可信案卷、一次真实执行 Run、所用方案指纹 | `runId` 必须真实存在并绑定 Run；不得把 `run@rev`、草稿序号伪装成 Run |
| `ruleId / targetKey / stage / scenario` | 如 `R006`、教学任务＋拟教师 UID、S1、C01+C08 | 多人多课次逐目标；不把一份文件的结论强加给其他教师 |
| `status / trigger` | 八状态之一；触发 `T/F/U`；可附 `triggerReason` | 与 §10.1 互斥，不能出现自动批准状态 |
| `sourceRefs` | SRC 标识、政策文件版本、适用学院/学段/学期、是否校本确认 | 未查证的 SRC 标明确切未知；不制造条款或许可阈值 |
| `evidenceRefs` | `materialSlot(Mxxx)`、`materialVersion`、`sourceVersion`、原始页/字段/记录 ID、hash、证据权属 | 对申请方与校方来源分离；可追溯到 F044，不能仅留 OCR 文本 |
| `fieldRefs / comparison` | F 编号、比较的两侧/时间口径、相符或差异事实 | 机器只存抽取、归一、比较事实，不写“已批” |
| `issueId / materialNeed` | 缺口、冲突或不可读细节、最小请求范围、是否当前阶段需要 | 禁止预先要求 M012–M016 等未来材料；校方数据优先校方获取 |
| `nextRole / requiredAuthority` | 申请人、教学秘书、课程组、学院、教务处/研究生院、人事或资格 Owner、学校决定人等**角色** | 角色通过校方配置绑定可信 Actor；模型不指定自然人或授予权限 |
| `dependencyVersions / reviewDisposition` | 使用的 R、F、M 源版本，重审原因、是否仅观察失效、是否需重新正式决定 | 重审结果不修改既往 M013；既有正式决定在另轨受控处理 |

任务单需给用户可操作的自然语言：**“哪一课、哪位教师、哪个材料版本、哪里不一致、请谁提供什么、目前属于事实缺口还是学校决定”**。对 P2/P3 个人信息按最小权限显示，普通申请人只能看本人/被授权对象的可见问题，病因等敏感证据不进入公开通知或导出摘要。

### 10.4 事实报告与正式学校决定的双通道

- **事实通道**：R 检查与 `ReviewRun` 观察，只能报告证据充分性、缺口和冲突及 `PASS_FACT`。即使所有当前适用 R 均 `PASS_FACT`，可向业务人员展示“当前事实材料可审阅”，不可显示“人员调整已获批准”。
- **正式决定通道**：需经 S3/S5 真实有权人确认权限及政策，留下独立 `decisionId + decisionType(APPROVAL/FILING/REVIEW/REJECT/RETURN 等以学校实际动作字典为准) + actorAuthority + signedAt + applicableObjectVersion + effectiveFrom + decisionSource`；这是权威记录**引用契约**，不是宣称 V3 运行代码已实现。没有校方决定则 `decisionStatus=UNRECORDED/UNKNOWN`，不由模型补全。
- **效力变化**：学校决定签发、撤销、变更和复核均须独立授权事件。R 重审不能私自覆盖 Decision/Outbox，也不能以新的 OCR 内容反向生成历史签名。

### 11.1 产品生命周期事件表（非学校官方系统状态）

| 当前阶段与事件 | 触发人及权限前置 | 下一状态/保存动作 | 不可越过的学校裁决边界 |
|---|---|---|---|

`FACT_REVIEW_OPEN` 等英文是**拟定产品可见业务阶段标签**，与院系实际办事系统字段、权限和终态不是等价声明。`ReviewRun`、`Case`、`Decision` 只能由 V3 服务端对应 Owner 管理，本文件不推定接口或代码已经实现；同一个 `caseId` 可多次有独立真实 Run 和申请修订，禁止旧 `run@rev` 冒充 Run。

**重审演算：** 变更事件 → 对比 `Mxxx:sourceVersion/hash/targetKey` → 计算 F 字段差异 → 取上表直接 R ＋其已记录的下游依赖闭包 → 只针对受影响教师/课次、处于可达阶段的目标建立**新真实 Run**（如运行架构允许） → 将旧观察标记“对当前材料已过时”并保留 → 新事实报告。若只有 OCR 识别信心变化而源文件字节相同，重跑读取失败的 R 子目标，不动其他签发决定。

### 11.3 补件、撤回与复核的特殊防错

- **补件**：待办必须指向 `ruleId + targetKey + M 槽 + materialVersion + 页/字段`。用户替换 M003 不能静默改变已签 M013 的决定范围；有权机关如需扩展授课周次，另出正式变更。
- **撤回**：明确 `REQUESTED`（当事人提出）与 `ACCEPTED`（有权机关依校规作出）两个不同事实；受理资格、时间窗未取得，故不得自动置“撤回成功”。已执行的授课学时记录 M016 仍存在。
- **重提/续期**：新 F039 指向旧案版与原决定，保留关联；若理由/教师/课次改变重审对应 R，并交新一轮学校决定；旧决定不因新申请存在而自然过期。
- **复核**：M017 显示原决定，M018 描述异议，核 `F021/F037–F042` 权限和版；正式复核由谁受理、复核有无回避/期限均 `POLICY_UNCONFIRMED`，交校方确认。
- **人工核验**：当有高敏材料、事实矛盾、权威源断连或校规不明时，受控岗位可添加核验结论及证据位置，但不得以人工文本充当具有批准权限的 Decision。所有活动保留原证据、来源、时间、操作者与修订链。

### 12.3 不允许系统自动作出的高影响结论

1. “学校批准更换任课教师”“学院同意即学校备案完成”“可以追认已经授课”“撤回已生效决定成功”。
2. “新教师具备任课资格”“外籍或特殊教师具备完整聘任/实践准入”，在未收到相应权威任职/资格结论前。
3. 以“已缺提前 N 天申请、单学期调课 M 次、每周学时超 X”为由自动驳回，其中 N/M/X 未有**当前有效适用**校本条款。
4. 教学事故、失职、学生成绩改动或工作量薪酬结算责任的实体判定。

这些情况在事实项可读时仍可出 `PASS_FACT`，但对应决定节点始终 `POLICY_UNCONFIRMED` 或 `NEEDS_HUMAN_DECISION`；算法不能以“全部资料齐全”覆盖人工关口。
