## 01 唯一审核目的、申请人和负责机构

### 1.1 一个主体、一个决定对象族

本模板的审核对象是**同一学生社团主体及其组织资格生命周期**。一次办理应选择一个当前事项：筹备成立、存续年度审核/续行登记、组织信息变更、负责人换届、主动解散/合并及注销，或对前述办理补件、撤回、复核。不得因为阶段或校区不同复制出第二套模板。

最终可核的核心事实限于：申请人和申请社团的关联；社团主体身份与已有登记状态；所申请的变更前后内容；章程及组织内部程序证据；成员、拟任负责人、业务指导单位、指导教师等**在该阶段且依据校本清单要求**的资料；校内业务指导/受理/审批/核准链的真实记录；上一年度审核、整改或注销结论的权威引用。具体强制字段和门槛尚待 SRC 的校本补证。

### 1.2 申请人和代理人

| 办理情形 | 初步申请主体 | 代理提交或授权关系 | 不能先验认定 |
| --- | --- | --- | --- |
| 新成立 | 具备学校资格的在读学生发起人及其筹备代表（上位规则允许学生成立团体，SRC-001） | 由发起人选定筹备联系人提交，需证明代表关系；是否必须指定拟任负责人待校本核实 | 发起人数、年级、学籍类型、纪律状态阈值、代理权限 |
| 年审/续行注册 | 已登记社团的实际在任负责人或获授权经办人，主体是存量社团 | 与学校保存的社团/负责人名册进行关联 | 仅凭学生自报「社长」就具有代表权 |
| 变更/换届 | 已登记社团及其当期有效负责人；候选人或交接双方能否发起待核 | 需核章程规定的内部授权与学校登记权限；不能用候选人自己声明取代 | 内部表决就是学校认可的换届或变更 |
| 解散/注销 | 已登记社团的有权组织机关或学校依法依规启动的处置主体 | 需匹配章程、成员决定或校方处置来源，机制待核 | 社团私下停办或账务清零即注销生效 |

**身份/学段边界：**本科生、研究生、来华留学生、港澳台侨学生、继续教育学生，以及成都校区/宜宾校区或分社是否可以独立发起、参与、担任负责人，须见校本现行制度及当前名册后逐类配置；本轮不以外校规定替代（SRC-001 第 2、66 条提供上位适用范围；SRC-005 呈现宜宾分社实际存在）。

| --- | --- | --- |

## 02 适用、排除与邻接模板路由

### 2.1 适用：同一社团的阶段性组织资格

- 成立筹备/正式成立结果、学年年审与登记存续。
- 不改变社团主体的名称、章程、类别、业务指导单位、指导教师等登记信息变更，以及负责人换届；**具体哪些变更须单独批准、哪些仅备案待校本确认**。
- 成员大会形成的解散意向、学校启动的终止/注销及其必要的后续交接、清算事实；**不预断何种事实足以注销**。
- 对前述同一申请的补件、撤回、纠错、复核；使用原申请和原组织主键的版本链，不新建模板。

## 03 业务生命周期与办理情形矩阵

### 3.1 研究用生命周期（不是已确认的学校网上流程）

`辨认主体/已登记状态 → 选择办理情形 → 学生提交当前阶段材料 → 受理与事实核验 → 必要时补件/异议/撤回 → 业务指导意见/校内评议（仅在校本确认后启用） → 有权机关人工决定 → 决定送达或公示 → 登记状态/年度版本变更及留痕`。

**时点原则**：成立时只提交成立所需草案与拟任材料；成立决定后出现的登记号/正式章程/签章不能设为申请入口硬门槛。年度审核先收上一周期事实再接本次年审结论。换届先核当前负责人和选举过程，下一任负责人的校方认可应在正式决定后入权威名册。注销前内部意向与注销后的资产处置、档案归档分别编号、分别判断。

### 3.3 特殊情形与阶段门禁

- **身份/校区**：成都校区、宜宾校区、分社；本科、研究生、国际学生等使用同一矩阵的配置维度。SRC-005 只证实存在宜宾分社项目，不证明分社独立法人、独立社团注册或独立审批权。
- **批次**：新成立与年度审核存在年度性公告线索（SRC-002、003），但申报开放时间、截止日期、补正窗口、是否随时受理均未知；系统不得计算虚构期限。
- **原状态冲突**：社团更名/换届不得产生「新社团」主键；若同名且不同编号、合并或新设分社，应先由有权管理单位确权。
- **补件/撤回**：事实预审阶段允许提交补件请求或撤回意向；是否可撤回已进入评议/公示/决策的事项、撤回有效时点和后果，须按校本规定人工确认。
- **投诉/复核**：成员对内部选举异议、组织对年审结论不服、学生对学校处理处分申诉不是同一个程序。不得直接套用第 41 号令第 60 条的 10 日期限到一切社团争议。

## 04 依据与来源证据索引

### 5.2 技术状态与人工作出决定的隔离

- Renderer 只负责材料呈现、OCR/抽取结果供人核对，不提供可信审批身份或签章。Main/Host 必须校验真实 Actor、权限和业务对象版本；同一社团的 `Case/Run/Decision` 不应被页面或附件内容伪造。
- 审核引擎可输出 `PASS_FACT`（已见且相互一致的事实）、`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION`。`PASS_FACT` **不是** `APPROVED` 或 `REGISTERED`。
- 若缺现行校本规则、当前授权、学校主数据、意见真实性或出现裁量争议，应停止自动正向结论，输出对应待办并引导有权人处理。对解散、强制注销、资格不续登记等不利决定，保留申辩/送达和救济规则的人工核实点（SRC-001 第55、59–66条须先判断具体适用性）。
- 实体主键应使用学校登记的社团 ID；未成立者建立筹备临时 ID 与幂等关联，正式批准后再绑定组织 ID，不能把新旧名称当两个社团。年度审核、变更、换届沿用主键；每次输出固定事项类型、申请版本、证据来源、结论来源与生效日期。
- 学校其他系统/相邻 G50/S/T 结果为只读权威引用；只有有权机关所产生的正式变更记录才能推进社团有效状态。出现相互矛盾的年度名册/指导教师记录须 `CONFLICT`，不可按最新上传文件覆盖学校台账。

### 5.3 角色待落实的授权检查清单

`AUTH-01` 实际受理者及能发起补件的岗位；`AUTH-02` 指导教师、业务指导单位的意见和签章校验；`AUTH-03` 评议委员会是否存在、具体成员及有效授权；`AUTH-04` 学校最终审批/登记/注销生效机关；`AUTH-05` 异议、复核、撤回、变更的有权办理人；`AUTH-06` 成都/宜宾跨校区归口及分社地位；`AUTH-07` 与宿舍/安全/财务等其他许可的签批边界。这些全部先标 **未核实**。

## 08 审核规则逐条清单

规则均为**单一事实或证据一致性核查**，不存在“通过审核”的自动规则。通用三值触发：`真`进入核验，`假`为 NOT_APPLICABLE，`未知`先按条件来源标 SOURCE_UNAVAILABLE 或 POLICY_UNCONFIRMED。真且证据一致仅 `PASS_FACT`；证据缺失 `NEEDS_MATERIAL`（只对已证需交的当前材料）、相互矛盾 `CONFLICT`、不可读 `UNREADABLE`；资格政策/表单不明 `POLICY_UNCONFIRMED`；需裁量/内部决议效力/签批 `NEEDS_HUMAN_DECISION`。每行“异常”给优先分支，其他异常按本段通用映射。下一角色：申请方补件（申）、登记/身份/财务数据管理员（数）、归口社团业务办理人（业）、有权决定/复核者（决）。SRC-009 只作对照，不产生本校强制义务。

## 09 触发条件、冲突和复合场景

触发判定采用 `F001 × F003 × F005 × F021 × F025`；任一前提未知不得当成 false 跳过，而按 R025/R007/R012 提出政策或数据待办。`NEW` 不要求已存在 F002 正式登记号；`DISSOLVE` 不应在学校注销前假设组织已不存在。事务关系如下：

| 组合 | 依赖、冲突处理与结果 |
|---|---|
| 年审+换届并行 | 同一 F002，年度成员快照冻结各自截止日；换届未被正式确认时年审应引用原权威 F011，输出 R009/R013 CONFLICT 或人工确认，不偷偷覆盖 |
| 换届+指导教师变更 | 两种变更分别留事件但仍是同一模板；R005 查教师聘任，R014 核内部换届，学校是否允许同步办理标 POLICY_UNCONFIRMED |
| 更名/分社+新成立 | 名称相似不构成同一 ID；先走 R007/R011/R016 的主体识别，不重复创建正式登记主键；跨校区资格走 R025 |
| 年审整改后注销 | 原年审 F019 不被注销申请抹除，R010/R018/R019 分别核整改、启动权、存续债务，最终冲突由有权部门决定 |
| 注销中活动和财务未结 | S05-T05 活动、G03 场地、G04 安全、G07 财务各出具自己的结论引用；R019 只记录存在性和责任，没有“自动清账” |
| 多社团合并 | 每个原 F002 各有独立事实链与决议 M014；承继/新生效的组织关系由同一事项内的多个**权威决定对象**记录，不伪造单一合并自动审批 |
| 校本不同版本冲突 | 以行为发生日、申请受理日和有效日期选择适用文本，冲突标 POLICY_UNCONFIRMED 并交业务专家；不能直接取检索最新页 |

当材料 A 显示某人已换届、权威登记 B 仍为旧负责人，不取“更近日期”的 A 覆盖 B：`CONFLICT` + 由登记主管查真实效力。章程条款对投票比例、任期、校区有不同解释时只记计算中间事实，效力一律 `NEEDS_HUMAN_DECISION`。没有授权时不能推断学生纪律、国籍、就业状态等资格否决。

## 10 结果状态、问题与待办输出契约

每个命中的 R 产生独立 issue，不把多问题压成“审核未通过”。JSON 逻辑合同示例（仅研究示意，不作为用户上传 JSON 的入口）：`{caseId, organizationId, scenario, stage, ruleId, code, fieldIds, materialSlotIds, evidenceRefs:[{evidenceId, sourceVersion, ownerId, hash, page}], sourceIds, predicateState, detectedFact, requiredAction, assigneeRole, policySnapshotId, reviewedAt}`。每条 issue 保留实际 target（社团、个人、年度、变更字段、前后任期），以免对错人。

| 互斥事实结果 | 用法与待办 |
|---|---|
| `PASS_FACT` | 在规则当前触发、证据可读、关联一致且有足够依据时仅确认该事实；决定仍为独立操作 |
| `NOT_APPLICABLE` | 阶段或情形确定为假；尤其 M018–M020 未到决策阶段，不提前催交 |
| `NEEDS_MATERIAL` | 当前应提交、可由申请人取得且已确认必需的材料缺失，定位槽和所有人 |
| `CONFLICT` | 同一目标同一有效时点证据冲突、旧值不符、跨主体混件，进入人工核对 |
| `UNREADABLE` | PDF/图片损坏、页缺、签章区域无法辨认，保留原件及页码再补传 |
| `SOURCE_UNAVAILABLE` | 学籍/登记/聘任/签章等可信后端暂不可用；不得以用户上传截图补真值 |
| `POLICY_UNCONFIRMED` | 强制清单、校区资格、窗口、阈值、审批还是备案未有现行校本证据 |
| `NEEDS_HUMAN_DECISION` | 争议事实、内部决议效力、学校批准/注销/复核等需要有权人实际决定 |

例：`R013 CONFLICT` 可展示“提交人称已任社长，但登记簿版本 v17 仍记载原社长”，同时引用 M001、M007 的两个证据 ID，并派给社团主管；不展示“换届失败”。结果集合按每规则互斥；不同规则的结果可以并存，页面按事项聚合但不丢 issue。禁止用 `PASS_FACT` 转换成 `APPROVED`。

## 11 补件、撤回、版本更新、复核与人工决定

1. 申请与计划：Main 以可信 F004/组织 F002 建立 CaseAggregate；冻结 `planId+fingerprint+Check×target/sourceVersion`。Renderer 只传操作请求，不写 Decision/Outbox。每一决定事件带 `entryRunId`，不接受旧 `run@rev` 冒充真实 Run。
2. 补件：针对 issue 的 `ruleId/materialSlotId/target/evidenceVersion` 指向具体所有人；新增文件为不可变 v2，保留 v1 的 hash、上传时间和错误说明。不可读先让同一材料所有人重传；身份源断连则由管理员恢复，不索取无权限敏感截图。
3. 定向重审：依赖图 `F/M/version→R`。M013 变更触发 R015、相关 R024，若负责人可信记录也更新触发 R013/R009；不重新评判无关财务 R019。服务端对比 CaseAggregate CAS，过期版本不可覆盖新结论。人工决定已形成时改件只生成新申请/复核事件，不暗改原决定。
4. 撤回：记录撤回**请求**、Actor、理由、阶段、时间；仅授权人员按已核学校规则确认撤回生效。正在公示、已决定、涉及多社团合并的撤回可否准许未知，标 POLICY_UNCONFIRMED；撤回不能删除签发历史或同步注销组织。
5. 决定：有权机关的真实 `decisionId+roleGrant+签章+生效日期` 经 R021 核验后，服务端幂等记录决定；R022 再独立核登记簿更新。公示、拟通过、内部表决和 OCR 印章都不是签发。学生客户端只读呈现正式状态和证据。
6. 复核/申诉：对 F023 的原决定和争议范围登记申请、接收新材料、由校本实际复核机构决定维持/变更/撤销；新决定指向旧决定，不删除旧记录。教育部 41 号令涉及学生处理处分的程序并不能不经分析就套用所有社团年审/内部换届异议；具体渠道、期限、救济应由校方确认。
7. 通知/归档：决定与送达分事件，含版本和受领人；Outbox 重试按相同事件 ID 幂等，避免多次注册或注销。生产身份授权与敏感证据访问不属于本研究成果的已运行功能。
