## 01 唯一审核目的、申请人和负责机构

审核对象是**同一名研究生、同一份已确定个人培养计划、一次具有明确差异集的变更申请**：核实变更身份、理由、旧新课程和培养环节安排、适用培养方案、已有修读及成绩、导师与培养单位意见及学校实际授权决定。它不审核研究生学位授予，也不替教师调整全校课表。[SRC-001][SRC-002][SRC-003]

- **通常发起人**：在籍硕士/博士研究生本人；导师、学院教务人员可建议或协助发起，但“代申请”须有可信授权，不能把仅持有扫描件的人当本人。系统对休学、联合培养、硕博连读、直博、非全日制等身份作分支，真实办理范围依校方当期规定配置。
- **建议及审查角色**：指导教师（专业合理性、进度建议）、培养单位研究生培养管理人员和实际受权审核人（资格及培养方案落实）。2018 年原始通知要求变更经导师及学院同意、研究生院（部）审批后才能修改；跨校/跨学院/跨专业选课当时还有学院学位评定分委员会专门讨论环节。但**2026 年的岗位、步骤与例外授权尚需核对**，不能据此自动指派具体个人。[SRC-003]
- **最终有权人**：由校方有效文件和可信后端权限表确定的研究生院/培养单位受权主体。模型只能给 `PASS_FACT` 或风险/待办，签批事件由有权人员或校方系统出具。无有效授权链时输出 `NEEDS_HUMAN_DECISION`，不能写入正式生效版本。
- **业务产出**：`change_request`、差异化课程与培养环节事实审查、条件材料待办、权威意见链、正式决定引用和 `effective_plan_version`。未获学校决定时仅是草稿或研究建议。

## 02 适用、排除与邻接模板路由

| 条件/意图 | 本模板处理 | 另一审核对象、转交规则 |

| 培养方案本身修订、教师授课资格、开停课/调课与成绩更正 | 仅消费已签方案/教学/成绩记录 | 学科培养方案制定/修订由 `T05-T01`；正式开停课或调课由 `T01-T03/T01-T01`，成绩更正由 `T01-T08`、学生成绩复核由 `S02-T06`；教师导师/任课资格由 `T06-T01/T02/T04`，本模板不改这些决定 |
| 外校课程、联合培养课程 | 审是否写入本人计划及其学分归属的条件事实 | 真实出访另走 G05，专业变更走 S01/S08-T09；课程外选审批权限需当期校本核定 |

**路由优先顺序**：真实审核对象 → 学段与现有效学籍 → 已有签发决定 → 有无“个人计划内容差异”。若只是“我要本学期选一门计划已列的课程”，无需本 Case；若多个模板可能命中，提示用户选择，不能擅改冻结 ID。[SRC-001]

## 03 业务生命周期与办理情形矩阵

| 情形 | 主体/学段/子类 | 前置与触发 | 申请时要求；后续才产生 | 结果与下一角色 |
| --- | --- | --- | --- | --- |
| C01 首次制定计划附带核验 | 硕/博、学术/专业、不同入学批次 | 有入学和导师关系，但尚无批准基线 | 候选计划、培养方案；导师及校院批复后形成 | 与首次计划流程兼容，校方若已有业务系统则只读/转系统；不把首次制定假成“变更” |
| C02 常规课程替换/增减 | 在籍研究生，学位课/非学位课/补修课 | 基线存在且有实质差异 | 新旧课程清单、必要理由；导师、学院、研究生院意见在下一阶段 | 事实核查→授权审批→版本生效 |
| C03 开课取消、时间冲突、开课学期调整 | 在籍研究生，选课与培养计划不一致 | 官方开课事实支持实际需求 | 课表/停开通知及候选替代；不得先要求未来开课完成证明 | 课程安排合理性与对应权限核查 |
| C04 跨学科/学院/高校选修 | 在籍研究生，含联合培养条件 | 拟选课程归属不同机构 | 外选理由、课程信息；批准、官方成绩认可按阶段产生 | 跨单位意见/学校授权→计划更新；未获批准不算已认学分 |
| C05 休复学、研究方向/专业调整衍生修订 | 硕/博、学籍状态或专业已变 | 先取得合法的身份/方向决定 | 上游决定与新培养方案，之后修订本人的课务计划 | 不重审学籍/方向决定；新旧方案差异待人工确认 |
| C06 已修读课程重认、课程等效或补修安排 | 成绩已录入的硕/博 | 已修读课程无法直接对应新计划 | 官方成绩、原课程属性、合法认可凭证 | 原成绩不能删除；等效学分计算需当期规则和授权 |
| C07 培养里程碑后追改课程计划 | 已开题/中期或临近答辩者 | 追溯改变已完成要求的风险 | 阶段已签结论只读，说明追改范围 | 锁定历史，人工研判；不能靠重写计划重置里程碑 |
| C08 未形成真实差异的常规选课 | 已列课、普通增退选无计划变更 | 教务系统已有流程 | 不另要主稿或证明 | `NOT_APPLICABLE`，指向正式选课入口 |
| C09 申请补件/更正 | 原 Case 待办中 | 同源补正或新版本提交 | 被点名的 M 槽；其它有效材料保留 | 定向重跑相关 R，不新建同义 Case |
| C10 撤回/复核/纠错 | 已提交、待审/已签 | 可信撤回或异议事件 | 申请说明和决定证据按阶段形成 | 撤回申请≠决定撤销；已生效方案只能由有权部门作变更/更正决定 |

状态机：`DRAFT → SUBMITTED → FACT_REVIEW → {AWAITING_MATERIAL|AWAITING_POLICY|AWAITING_DECISION} → DECIDED_{APPROVE|DECLINE|RETURN} → {EFFECTIVE|CLOSED}`。`WITHDRAW_REQUESTED` 和 `REVIEW_REQUESTED` 为并行事件，需有权回应；`SUPERSEDED` 仅在新的有效计划版本签发后设置。任何状态的精确定义与时限依校方配置。特别强调 **事实审查完成不等于获批**。

| 研究生院/校方受权人 | 按当前授权表作审批、备案或驳回，并签发有效计划版本 | 依 AI `PASS_FACT` 自动批准 |
| 开课单位/成绩主管部门 | 课程目录、开课状态、成绩/学分及更正决定 | 本模板下达改成绩、创建课程/任课权限 |
| V3 Main/可信后端 | 根据已验证身份令牌和 scope 查询系统快照、签名、sourceVersion，CAS 写状态和事件 | 信任 Renderer 自报 teacher/admin、OCR“章已盖”作为签发权 |
| Renderer/AI/Pi | 文本提取、材料建议归类、指出差异、形成待办 | 使用学生截图冒充官方数据；直接决定行政结果 |

**敏感数据**：学号、姓名、成绩、导师关系属于受保护的个人教育记录；健康/休学理由、经济和家庭证明若出现则提高敏感级别并最小化采集。只保留本次规则必需的字段、授权读权限、访问用途、哈希/版本和审计记录。跨案不得复用学生学籍、成绩和签字。来源失联与“查无成绩”不同：前者 `SOURCE_UNAVAILABLE`，不能按未取得学分处理。[SRC-010]

## 08 审核规则逐条清单

## 09 触发条件、冲突和复合场景

1. **取值与集合**：当前义务集 `Req(programVersion, track, cohort, degreeType)`；拟计划课程集 `Proposed(planChangeVersion)`；正式成绩集 `Earned(transcriptVersion)`。分别计算 `plannedByBucket`、`earnedByBucket`、`remainingByBucket`，后者不能由未考课程充数。一个课程只能按可信等效规则映射到允许的一个或多个类别；若重复计分规则未知保留未知，不直接累计。[SRC-004][SRC-006][SRC-010]
2. **必修与选修**：按课程代码+目录版本判断学位课程/非学位课程/补修课/培养环节。补修课在旧校方表单中不计学分仅提示不同种类；任何 2026 数值采用绑定方案，不可套用表格常数。[SRC-004]
3. **跨院/跨校**：先检查计划修改意图，接着申请与课程归属、导师、学院和学校实际审批；成绩入账是后续不同事实，不提前要求完成。外校门数、增退选时间和换算由当前校本制度配置，绝不搬用 UCAS/ZZU 的数字。[SRC-003][SRC-012][SRC-013]
4. **已完成培养里程碑**：计划调整可能影响后续开题、中期等，但 S08-T03/T04/T06/T07/T08 的原已签决定不自动作废；若需重新开题须走该事项，历史链保留。[SRC-005]
5. **冲突优先级**：可信系统不同版本冲突→先查签发时间及更正决定；用户表单与系统冲突→标位置/行/来源、核验签发；两个校本规定冲突→记录受影响 cohort/专业/生效日期，移交 H；官方系统不可访问→`SOURCE_UNAVAILABLE`，不可用推理补事实。
6. **同一申请混合变化**：一次申请可含多门课、多学期、多类学分，逐项生成独立 issue；一门课失败不吞掉别的事实正确的结论。若变更包含另一个模板决定，生成依赖引用，**不拆/复制审批**。
7. **政策时效及例外**：旧表单、旧学科培养方案、当期新方案同时存在时选择由校方指定的有效版本，不执行“取最新网页”或“统一最大/最小学分”。豁免、替代、特殊学籍由有权人决定，模型不给豁免结论。

## 10 结果状态、问题与待办输出契约

输出单位为**一条规则 × 一个学生 × 一个课程/类别/阶段目标 × 当前材料版本**，而非“全案审过”。最小事件：

```json
{
  "templateId":"S08-T02",
  "caseId":"SYN-CASE-01",
  "ruleId":"R009",
  "subject":{"studentId":"SYN-2026-001","courseOrBucket":"专业必修学分","programVersion":"SYN-PLAN-A"},
  "status":"POLICY_UNCONFIRMED",
  "facts":{"planned":8,"required":null,"unit":"credit"},
  "evidence":[{"materialId":"M004","fileId":"SYN-FILE-4","sourceVersion":"v3","hash":"sha256:synthetic"}],
  "sourceIds":["SRC-004","SRC-006"],
  "nextRole":"H",
  "issueCode":"S08T02_PROGRAM_THRESHOLD_UNCONFIRMED",
  "action":"由研究生培养部门确认该生适用方案及分类学分要求",
  "decisionId":null,
  "reviewRunId":"SYN-RUN-01"
}
```

**八种互斥事实结果与待办**：

| status | 用法 | 下一操作 |
| --- | --- | --- |
| `PASS_FACT` | 事实与可信证据吻合，**不等于申请获批** | 送下一受权角色 |
| `NOT_APPLICABLE` | 不满足该规则触发，如普通选课或非跨校 | 解释路由/跳过 |
| `NEEDS_MATERIAL` | 当前应由申请人提供的具体事实材料缺失 | 指向单个 M 槽与申请人 |
| `CONFLICT` | 两个证据或认证身份存在矛盾 | 指向冲突双方的 ID/版本，交主管核对 |
| `UNREADABLE` | 已提交材料格式损坏/无法辨识 | 仅重传问题材料，保留其他证据 |
| `SOURCE_UNAVAILABLE` | 权威系统/文件链接无法获取 | 重试可信源或人工调取；不可假判不合格 |
| `POLICY_UNCONFIRMED` | 当期制度、权限、阈值、例外缺证 | H/校方补证或配置化，阻断硬性判定 |
| `NEEDS_HUMAN_DECISION` | 需要导师、学院或学校受权裁量/签发 | 发给具体有权角色，静待决定 |

`issueCode` 示例：`S08T02_STUDENT_SCOPE_CONFLICT`、`S08T02_PLAN_VERSION_STALE`、`S08T02_REQUIRED_COURSE_GAP`、`S08T02_CREDIT_BUCKET_GAP`、`S08T02_TRANSCRIPT_SOURCE_DOWN`、`S08T02_EXTERNAL_APPROVAL_PENDING`、`S08T02_MILESTONE_IMPACT`、`S08T02_DECISION_PENDING`。相同课程多项失败也应分别带 `ruleId`。`issue.target` 精确定位 `materialId/fileId/page/row`；无源时指向应取的服务接口。不能将“缺培养计划证明+不可读成绩+待审批”合成一条无证据的“缺件”。

最终业务判定是另一层 `BusinessDecision{decisionId,authorityActor,roleScope,decidedAt,sourcePlanVersion,approvedDiffHash,outcome,signature}`，只从可信有权系统接收；即使所有 R 都为 `PASS_FACT` 仍保持 `AWAITING_DECISION`。

## 11 补件、撤回、版本更新、复核与人工决定

1. **建立**：Main 校验身份，固定 `baselinePlanId/sourceVersion`、programVersion、受权 scope；提交生成一次申请 Case；一案附多个目标课程，不对每份文件另建案。
2. **事实核查**：生成冻结 Plan（检查点 × 学生/课程/类别目标 × 证据版本）；规则与模型同一 ReviewRun，观察值带 `reviewRunId`、`materialVersion`、`status`；需要补件时列明受影响行而不中断其它事实核验。
3. **补件**：学生替换 M002/M005/M007 等当前材料，更新 `sourceVersion/hash`，按依赖图只重审相关规则：例如重传 M007 → R010/R011/R014/R016，而不重审无关导师资格或表单身份。官方数据更新亦如此。
4. **审批**：仅在有权人完成其阶段后产生 M011/M012/M013；当前制度尚未证实的签发步骤保留配置门禁。作出批准后以 `(baselinePlanVersion, signedDecisionId, approvedDiffHash)` CAS 写 M014；若并发旧版本、字段超出批准差异、同步失败，拒绝生效并产生运维/有权人待办。
5. **撤回**：申请人发出 `WithdrawRequested` 不等于 `WithdrawAccepted`。待决申请是否可撤、撤回后何时闭案依校方当前流程。已签决定的撤销/更正需要新的校方决定，保留旧 plan 和不可变审计事件，禁止删除历史。
6. **复核/申诉**：对本次计划变更的异议定位原决定 ID、受争议 R 和证据。2021 年培养环节办法第49条对**培养环节考核结果**有复议路径，但不能自动作为计划变更的专门期限。[SRC-005] 由校方确认计划变更的有效救济入口、时限、受理权限后执行；复核中已有课程/计划不得被静默回滚。
7. **定向重审与结案**：新证据触发 `ObservationInvalidated`→仅相关 R 复跑→新事实报告→必要时新人工决定；最终输出 `effectivePlanVersion` 与旧版引用、通知对象和责任主体。使用者可浏览旧结论但不得把旧 `run@rev` 当成当前有效结论。

## 12 校本配置、未知事项和不能自动裁定的边界

| 配置项/缺口 | 需证实的证据与责任归属 | 缺证行为 |
| --- | --- | --- |
| `POLICY_CURRENT_PERSONAL_PLAN_CHANGE` | 2026 现行研究生个人计划变更办法、废止/修订情况、适用年级；研究生院培养科 | `POLICY_UNCONFIRMED`，不得套 2018 通知的全部流程 |
| `APPROVER_CHAIN_BY_TRACK` | 导师、学院受权人、分委会、研究生院及代理规则；学校有效权限表 | 阻断自动签发，路由 H/G |
| `PLAN_CHANGE_TIME_WINDOW` | 申请/增删课程截止及非正常窗口例外 | 不得照搬郑大前2周、国科大各时限 |
| `PROGRAM_VERSION_MATRIX` | 学院+学科代码+学位类型+年级+培养方式的有效方案/过渡条款 | 不允许用全校统一学分或混年规则 |
| `CREDITS_BY_BUCKET` | 必修/选修/公共/补修/实践学分计法、成绩映射、跨类别复用与豁免 | 仅做事实差额，结果 `POLICY_UNCONFIRMED` |
| `COURSE_EQUIVALENCE_APPROVER` | 新旧课程替代、跨学科/外校/联合培养成绩认可机关和凭据格式 | `NEEDS_HUMAN_DECISION`，不得自动记学分 |
| `COURSE_SCHEDULE_OWNER` | 公共课/学院课排课与停课事件的可信发布服务及更新时间 | `SOURCE_UNAVAILABLE`；本模板不下达调课 |
| `STUDENT_STATUS_EXCEPTIONS` | 休复学、硕博连读转换、专业调整、超年限与离校学生的申请资格 | 标未知/路由 S01、S08-T09 |
| `DECISION_WITHDRAW_REVIEW` | 本事项撤回、复核、受理人、时限、原决定效力规则 | 记录权利主张，不套其他事项申诉期限 |
| `FORM_VERSION_AND_SIGN` | 当期官方表单、电子签名/线下备案并行机制 | 无凭证不能认定签字、备案已完成 |
| `MILESTONE_IMPACT_RULES` | 改计划涉及开题、中期、答辩前后效力与是否需重审里程碑 | 交 S08 对应受权人，不能自动更改结果 |
| `PRIVACY_ACCESS_MATRIX` | 成绩/健康/导师身份权限、保留期限、访问审计和最小化 | 无授权时停止真实数据调用，不影响合成研究 |

**禁止自动批准**：AI 认定学分“差不多”、OCR 识别公章、某导师在截图中写“同意”、旧方案数字达到阈值、教师助理代签、系统曾有旧 run 通过，均不是学校行政批准。未证实的校本阈值不得设置默认为“宽松通过”。
