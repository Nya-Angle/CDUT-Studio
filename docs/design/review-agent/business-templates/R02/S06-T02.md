## 01 唯一审核目的、申请人和负责机构

### 01.1 审核对象与决策对象

- **申请人/申请主体：** 对应赛事通知允许的成都理工大学在校学生个人、学生团队，或以学院为单位组织的报名主体。团队存在队长/负责人、普通成员、指导教师等角色时，须依赛事现行规则核对角色及关系。并非所有竞赛都允许学生个人直接提交学校推荐申请。例如 SRC-002 说明学生自愿报名、学院推荐、指导教师遴选；SRC-003 规定团队参赛；SRC-004 规定该赛事面向在校本科生。
- **代理/报送人：** 可存在团队负责人、学院赛事负责人或承办学院统一报送；**是否允许法定代理/委托代办尚无校本统一依据，不得默认代理可代签、代承诺或代替教师确认**。
- **本模板的决定对象：** 一条由“具体赛事 + 赛道/组别 + 届次/年度 + 校内批次 + 申请主体/队伍 + 当前阶段”限定的 *资格事实核验记录*。对学校推荐再单独关联**有权机构形成的推荐决定/名单及版本**；不得把资格核验当作推荐决定。
- **不作决定对象：** 赛事最终报名成功与否（如由外部平台决定）、官方选拔成绩、最终录取及获奖；仅将其有来源的回执/结果作为后续关联事实，不能由当前审核自动生成。

### 01.3 事实核验的最小目标

初步确认：赛事、届次和批次是否明确；申请身份与学段/专业/组别是否匹配；团队成员和参赛角色是否与当期有效规则一致；指导教师的身份和接受指导关系是否需要且已获可信确认；报名时间/渠道/材料是否符合当前节点；若涉及推荐，是否有正式名额、遴选依据和有权人员的名单/决定。**缺乏相应 SRC 或授权来源的字段，只能标“待核实”，不可自动拒绝。**

## 02 适用、排除与邻接模板路由

### 02.1 纳入本模板的情形

1. 校内单人/团队报名资格事实预审，含本科、研究生、跨专业/跨学院等**由具体赛项允许**的变体；“师生混合组”“教师组”是否纳入，需先依据当期赛项定位及 R02 总账复核，不能自动扩展为教师人事评审。
2. 需要学院审核、导师确认、学校统一报送或校内选拔的前置事实核验。
3. 校内选拔结束后，核验推荐名单、名额占用、队伍身份与外部赛事报名要求的一致性；只引用原生排名/公示/正式决定，不重算名次。
4. 与原报名同一业务目的相关的补件、名单纠错、候补、撤回、异议/复核、身份/队伍变动，以及不同届次再申请，均为**同一模板的办理情形**，不新建模板。

### 02.3 路由警戒

- 作品从报名到实施、参赛、结项/结果归档属同一赛事活动生命周期；“实施作品制作”和“成绩公示”不是自动生成第二个 S06-T02 审核目的。
- SRC-006 证实特定竞赛允许跨校组队且须公示，SRC-003/005 的具体赛事又禁止跨校组队：**差异必须用赛事实例与批次范围解释**，不是同一政策版本之间的冲突，也不能拟一个全校跨校禁令。
- 承办方可以在**同一 S06-T02 申请/赛事对象**内记录从报名、培育实施、选拔、推荐、对外报名到归档的事件，但比赛后获奖或参赛角色的**新认定决定**转 S06-T03；不以“生命周期合并”为由吞并独立授权目的。
- 奖励/荣誉结果可能在时间上晚于校赛资格认定。申请伊始不得索取尚未产生的成绩单、推荐公示或获奖证书。

### 05.2 单案与可信身份/决定边界

1. **受信身份由 Host/Main 建立。** Actor 的用户 ID、角色、所属学院、授权范围、会话有效期和审批能力不能来源于 Renderer payload/文件内自填字段；Renderer 只能提出操作意图。校验失败或无权限时停留事实预审，不得伪造教师确认或学校决定。
2. **决定与事实分层。** `资格材料齐全`、`学籍事实匹配`、`申请提交成功`、`候选名单出现`、`学校推荐生效`、`赛事官网接收` 是不同事件。只有有权人的签发事件能改变正式推荐状态；AI 输出不得写成行政批准。
3. **版本锚定。** 每次核验绑定赛事/赛道/届次、通知来源及具体版本、队伍成员快照、批次与当前可信资格快照；若队伍变更/截止日变更/撤回/名单异议发生，只重审受影响项并保留原版本。
4. **两阶段引用。** 学籍/在职信息等事实应来自校园权威系统或可信盖章文件，不因截图或用户手填即成为可靠事实。赛事成绩/官方名额必须引用原审批/发布文件，禁止“旧 run@rev”冒充真实 Run 或模拟官方回执。
5. **隐私/最小化。** 学生证件号、联系电话、身份证明、学籍状态及教师信息只存必要属性与安全指针；是否可向第三方赛事平台自动报送，须单独核验授权和合规性。SRC-006 公示中的个人数据不用于测试样本。
6. **异常态默认人工接手。** 赛事规则不明、名额冲突、学生/教师身份与平台冲突、来源失效、署名/原创性争议、裁判复核等，必须形成可追溯待办，不能以模型自信度代替授权判定。

### 06.3 空值、隐私和改版规则

- `UNKNOWN` 不等于“不符合”。来源/规则缺失映射 `POLICY_UNCONFIRMED` 或 `SOURCE_UNAVAILABLE`；应提供而未提供的现阶段材料才是 `NEEDS_MATERIAL`。
- F006—F013、F023—F024 涉个人或身份/处分争议信息；不将真实身份证号、完整学生个人档案或教师敏感资料复制到模型提示中。可核验接口指针的访问权由 Host/Main 负责。
- 任何对 F001—F005 的变更均可能改变本届规则适用性；F009—F013 改变重审团队和导师相关规则；F016—F019 改变推荐相关规则；不得在已签发决定上静默改写。

### 07.1 证据层级、缺失语义及去重

- **T0**：经受信 Host/Main 身份和授权校验的学籍/人事/签发审计/校内接口原始记录；**T1**：来源、签发日期可验的当届校方或赛事官方规程/名单/回执；**T2**：可验签公文、学校档案或校内承办机构原生记录；**T3**：申请人填报、截图、扫描件或 OCR 文本。T0 和 T1 在不同事实维度各有权威性，**不以技术层级压倒现行法律/赛事规程**。
- 未到该材料产生阶段：`NOT_APPLICABLE`；该阶段依法/按赛事规则必须交但未交：`NEEDS_MATERIAL`；已提交而图像不可读：`UNREADABLE`；受信接口或官方已知来源无法访问：`SOURCE_UNAVAILABLE`；可信证据相互矛盾：`CONFLICT`；不存在可核验当前义务：`POLICY_UNCONFIRMED`。
- 若官方报名系统、学籍系统、签发系统已能受信读取，**优先引用其稳定 ID**，不反复索要截图/证明。不能把 G06 权属决定、G07 支付决定、G03 场地决定、G05 出行决定或相邻 S/T 的事实再次在 S06-T02 内作第二次批准。

## 08 审核规则逐条清单

### 08.1 规则求值总约束

- **逐条三值触发：** `T` = 在该业务阶段且赛事/赛道/届次适用该检查；`F` = 已证实不适用，该 R 唯一结果 `NOT_APPLICABLE`；`U` = 缺少现行规则或适用范围无法确认，优先 `POLICY_UNCONFIRMED`，而非假定强制适用。下列 `T/F/U` 均指触发本身，**不是**事实是否符合。
- 触发为 T 后再对事实求值。相同 `R + targetId + sourceVersionSet` **只输出一个互斥主结果**；其他异常保留为旁附 `diagnostics`，不产生互相冲突的多个主结果。详情见 §10。
- 比较对象是已证实当期有效的赛项要求，**绝不以 SRC-003 的“3人/导师1–2人/不超过10队”、SRC-004 的“新文科2队、新工科1队”跨赛事复用**。历史 SRC 可用于设计演练但不证明 2026-10-22 仍可报名。
- 如来源内容仅是 SRC-001 的制度名称或 SRC-007/009 尚未复核全文，则**不得硬判**；只有在正式拿到适用期、章节与机关权限后才能启用对应政策分支。
- 校方/组委会可调整名额、处理争议、确定入选名单；R 对事实的 `PASS_FACT` 不属于任何行政决定。证据等级见 §07.1；每条规则必须记录具体证据 `materialId/version/sourceSpan`，不能仅记“来源为 M001”。

## 09 触发条件、冲突和复合场景

### 09.1 规则选择顺序

1. 先识别 `F001/F002/F003` 的**唯一赛事实例**与 `F004` 阶段，再读当届 M001 的签发机关、修订版、适用日期和各赛道条款。R001 无法确定时其他资格数值 R004—R014 不得套用“相似赛事”条件。
2. 在当届规则绑定后选适用分支（个人/团队，本科/研究生，学院/教师/校级报名，直选/校选/限额推荐）。每个 R 都按 `T/F/U` 单独求值；**不是所有 R 必须 PASS_FACT 才能进入人工决定**，仅本阶段确实适用的 R 才构成预审范围。

4. 对 R015 的正式推荐、R017 的外部受理、R019 的复核结论，只有**来源机关原生事件**可使权威状态变化。R 的自动输出至多证明源记录和关联关系匹配。

### 09.3 异常优先与争议

- 若同一 R 同时有证据冲突与材料缺页，以**已能确证的冲突**给 `CONFLICT`，在 `diagnostics` 标记缺页；证据不足以确认冲突则改用 `UNREADABLE` 或 `NEEDS_MATERIAL`。
- 当期政策本身不可得时不可输出确定“不符合”，应留 `POLICY_UNCONFIRMED`；如已知一份官方必须核验的文件/接口但暂时连不上，则 `SOURCE_UNAVAILABLE`。
- 撤回或复核可能产生新的业务事件，但不能反向擦除原签发事实；对原权威决定的效力，由有权机关按原流程撤销、变更或维持。
- **已知缺失 vs 现行不明：** `NEEDS_MATERIAL` 只能在 M001 已核明本阶段、该身份确实有交付义务时出现。若只有以往校赛示例、SRC-010 索引或 2019 目录，先 `POLICY_UNCONFIRMED`；不可用推测的“常见报名材料”制造缺件。
- **材料存在 vs 源失联：** 申请人已上传扫描但 OCR 不能辨认对应材料时为 `UNREADABLE`；若 M003 学籍接口、M011 签发原件或 M015 官网回执的**已确定权威系统无法访问**，即使有截图也为 `SOURCE_UNAVAILABLE`，截图只可辅助核查。

## 10 结果状态、问题与待办输出契约

### 10.1 八种互斥事实结果的确定语义

| 主结果码 | 唯一语义 | 典型下一步/绝对不得表达 |
| --- | --- | --- |
| `PASS_FACT` | 该 R 的**可核事实**在相应来源、版本、阶段内比对一致。它可能是“已有正式推荐决定可核”的事实，但**不是由审核器作出推荐决定** | 记录证据；如果另有权威签发事件可引用它。不得把单条或全部 PASS 显示为“校方已批准” |
| `NOT_APPLICABLE` | 适用触发 **F**，本阶段或本赛事无此检查义务 | 不出缺件；例如 B 阶段 R015/R017 不适用 |
| `NEEDS_MATERIAL` | 适用触发 **T**，当阶段被正式要求提交/可取得的材料**尚未提供**，且责任对象明确 | 通知当前负责提供者；不能要求尚未产生的推荐名单/获奖证书 |
| `CONFLICT` | 已有可核资料彼此矛盾，或与明确适用的赛事资格条件不符，含同一权威版本身份不一致、名额冲突 | 展示对照证据及差异并提交有权核实，**不等于学校已经作出拒绝决定** |
| `UNREADABLE` | 材料已存在但 OCR/扫描/文件损坏使关键项不可可靠提取 | 原文件重交/人工读件；不得误报成“没有提交” |
| `SOURCE_UNAVAILABLE` | 已确定需要查询的官方文件、签发原件或受信接口当前不可取得 | 重试或有权人员核原件；不能用学生截图代替权威事实 |
| `POLICY_UNCONFIRMED` | 本届规则、生效范围或是否必交、由谁批准等政策条件仍未核实（触发 **U**） | 承办/校级管理人确认政策和版本；不得按 2019 目录或历史赛事数字硬判 |
| `NEEDS_HUMAN_DECISION` | 事实材料已达到可审阅程度，或存在必须由有权机关解释、裁量、签发/复核的事项 | 人工待办；模型不能裁定名额、例外、真实性争议、推荐/撤销/复核效力 |

**互斥求值顺序：** 先判是否适用（F → `NOT_APPLICABLE`；U → `POLICY_UNCONFIRMED`）；T 时核是否缺少已确定的官方源（`SOURCE_UNAVAILABLE`），再检查已交材料是否不可读（`UNREADABLE`）、应交材料是否缺失（`NEEDS_MATERIAL`）、已知证据是否相冲突（`CONFLICT`）。能比较但需行政裁量则 `NEEDS_HUMAN_DECISION`，仅确定事实符合则 `PASS_FACT`。**已可靠确认的冲突**不因另有次要附件缺失而被掩盖，例外按 §09.3 记录。每条 R 的最终结果只有一个，整案可包含不同 R 的不同结果。

**对该顺序的安全限定：** 它不是机械的“缺源永远盖过冲突”。若已持有经核原生签发且能确证两个权威版本矛盾，应输出 `CONFLICT` 并把其他失联信息列诊断；如果本阶段的适用条款尚无法确认，优先 `POLICY_UNCONFIRMED`，不得假设该材料属于必需。`PASS_FACT` 仅表示本条事实维度可核，不能合并成整案“通过”。

### 10.2 问题、证据与目标办理人契约（拟议语义）

| 输出字段 | 要求 |
| --- | --- |

| `evidenceRefs[]` | 每项带 `materialId(Mxxx)`, `materialVersion`, `contentHash`, `pageOrCellOrSpan`, `issuer`, `observedAt`, `trustLevel`；证据必须归属于目标队伍/成员 |

| `nextActorRole`, `authorizedActorRef`, `taskKind` | 明确申请人补件、教师确认、学院核实、主管部门确认规则、裁判/推荐机关决定、外部平台核验等 |
| `affectedRuleIds[]`, `inputFingerprint`, `sourceVersionSet` | 支持局部重审；任一 M 变更不默认重跑全部，过期的结果标记 stale |
| `decisionRef?`, `decisionAuthority?` | **仅可引用**另一可信决策通道生成的决定 ID、签发人和版本；没有则省略，绝不虚构 |
| `reviewRunRef?` | 只填系统真实运行产生的 Run ID；不把历史 `run@rev` 或模型会话拼接成真实 Run |

问题以 `issueId + ruleId + targetId + materialVersion` 定位；**待办不脱离案卷工作区**。点击补件应直达对应 M，身份待核直达 R003/R008，推荐/申诉待办直达 R015/R019 及其原生决定证据。出具可审阅结果时要显示“资格事实核验”与“有权决定”两个维度，不能混成绿勾。

### 10.3 事件与决定的边界

- **事实审查事件**：`CHECK_RECORDED`、`EVIDENCE_CHANGED`、`RECHECK_REQUIRED`、`CHECK_SUPERSEDED`；AI 可以建议，写入事件仍由业务 Owner 按可信命令处理。
- **人为业务事件**：`APPLICATION_SUBMITTED`、`WITHDRAWAL_REQUESTED`、`REVIEW_REQUESTED`、`RECOMMENDATION_SIGNED`、`RECOMMENDATION_REVOKED`、`APPEAL_DISPOSED`、`EXTERNAL_RECEIPT_LINKED`。签发、撤销和复核必须经 Main/Host 身份授权与对应批次规则校验。
- 最终显示 **“学校已推荐”** 的唯一门槛是 R015 核查到有效的签发决定且其效力未被后续权威决定取代；显示 **“外部已受理”** 需 R017 官方回执。前者不推出后者，后者不推出获奖。

### 11.3 撤回、复核与正式决定的不得越权规则

- 申请人可表达撤回/更改/复核意图；**能否生效**须看所处阶段、当届规定和已有学校/外部决定。单方点击不自动释放限额，不自动使外部报名失效。
- 对补件，发送精确 `ruleId + materialId + version + whyNeeded + nextActorRole`；补件上传应先检查是否已有权威来源，避免重复索要。
- 对复核，固定争议的原决定 ID、队伍/成员、原因、受理机关、受理时点和正式答复版本；谁原先评分、谁有复议权由当届规程确认，不臆造独立复核委员会。
- 签发、撤回确认、推荐名单替换、公示异议裁定、政策解释属于**人工作出的权威业务动作**。权限失效、签发主体无法验证或并列名额争议时保持 `NEEDS_HUMAN_DECISION`。

### 11.4 逆向权限复核及旧结论失效条件

1. 申请人在 **B/C** 修改 M002/M004，系统记录受信提交者及前后版本；资格规则变化仅重跑真实被改变的目标成员与关联队伍 R，**不触碰不相关成员**。如果官方报名平台已锁定名单，发起请求仍可记录，但是否批准修改需原赛项授权人决定。
2. 在 **D/E** 已有 M010 评审或 M011 学校推荐决定的，任何身份、名单、导师或名额修订都只让 R013—R016 的关联校验过期，不自动改写评委打分、不销毁原名单、不释放推荐指标；生成 `needsAuthorityRevalidation` 待办，载明原决定版本。
3. 在 **F** 已有外部 M015 时，学校后续改荐不意味着外部官方回执自动失效；外部机构回执效力另核。对撤回的“请求已送达”与“学校确认撤回”“外部平台取消成功”保留三个不同事件。
4. 在 **G** 复核中，复核受理人、被复核原签发者、最终复核决定人三者是否同一或需要回避属于赛事/学校章程授权问题；R019 仅核受理与回执事实，未核章程时不自动排除某人也不自动接受其审批。
5. **可信事件前置：** `actorId` 必须来自 Host/Main 服务端验证，`decisionAuthority` 必须与 `competitionEdition+track+batch+action` 的授权记录匹配；签章和决定只能从业务 Owner 的有效签发通道落地。Renderer 请求、OCR 文本、学生截图、旧 run@rev 都不能直接推动推荐、撤回确认、复核处置状态。

### 12.1a 可实现但尚未校方批准的参数形状（研究合同）

`policyBundle` 至少携带 `issuer`、`documentNo`、`sourceUrlOrArchiveId`、`originalFileHash`、`issuedAt`、`effectiveFrom/Until`、`supersedes`、`applicableEdition/track/group/stage`、`sourceRuleSpan`、`verificationState` 和 `authorityVerifier`。系统不得只按“文件上传较晚”确认优先级；待主管部门解释同届主通知、附件、补充通知何者有效。

`registrationWindow` 应逐条为 `windowKind=INTERNAL_APPLICATION | INTERNAL_SELECTION | EXTERNAL_REGISTRATION | ROSTER_FREEZE | OBJECTION`，同时保留 `rawDeadlineText`、`timezone`、`inclusive`、`channel`、`serverReceiptId`。当时区、端点语义或补录权限未知，仅保留材料事实和 `POLICY_UNCONFIRMED`，不自动发出“逾期不予受理”的行政裁定。

`decisionAuthority` 应按 `issuerOrg + eventAction + edition/track/batch + actorRole + delegationDocument + effectiveInterval` 配置；一个部门发布通知，并不自动拥有评分、公示异议裁决、校内推荐名单签发或外部赛事录取的全部权力。各决定状态的可信源和撤销链分别存储，过期授权不得继续签署。授权记录不可访问时以 `SOURCE_UNAVAILABLE` 记录取证失败并派 `NEEDS_HUMAN_DECISION` 待办，不回退为 Renderer 自填角色。

### 12.2 不能由本模板自动裁量的事项

1. **学校是否推荐、推荐几个、谁是候补、成绩并列如何处理**：裁判/组织/推荐机关决定；R013/R014 只是读取官方结果和名额的一致性。
2. **参赛者是否获得赛事录取/晋级/获奖**：外部组织方决定；R017 仅验证受理回执。
3. **跨校成员例外、专业跨类别、特殊学籍或导师任职争议**：明确对应规则后交有权机关解释、核实或例外批准。
4. **原创性、知识产权归属、科研成果许可**：G06 相关权属结论，不由“提交原创承诺书”推断拥有权利。
5. **报销/资助/收费、场地/设备与安全、校外出行、学分与评奖**：分别引用 G07/G03/G04/G05/相邻 S/T 原生决定；学生创新创业扶持资格分支另见 S06-T08，不在 S06-T02 重新判定同一个批准对象。

### 12.3 G50 与相邻 S/T 的实际去重状况

- 已对**授权目的**做边界检查：R003 只核参赛前置学籍事实而非再次办理学籍；R011 只核承诺/授权材料的存在性而非 G06 权属；R015 只验“既有推荐决定”而不再签发；R017 只验外部回执；R020 只管理审核版本，不复制别的决定。

### 13.1 场景结论与可达性检查

- **已覆盖** 正常事实、缺件、来源冲突、不可读、定向重审、撤回/重提/复核六个要求场景，并增加跨校错用、身份冒用、未来材料、名额裁量、外部回执错推、政策空白、双窗口、赛级名额混用、赛后申诉错路由、换人旧签章共 **16 个合成场景**。
- B 阶段只能合法触发 R001—R011（R011 受作品阶段条件限制）；D 才触发选拔 R012—R014；E 才可能有 R015/R016；F 才可能有 R017；G 或专项事件触发 R018/R019；R020 是任何材料版本变化后的技术性检查。
- 这些演练验证了**规则语义与业务边界**，不构成系统端到端运行测试，也不证明 OCR、Main 决策门禁或外部平台已实现。仍需以校方签发样本、真实测试用例和技术合同再验。
