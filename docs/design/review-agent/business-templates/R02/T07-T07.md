## 01 唯一审核目的、申请人和负责机构

**唯一目的**：对*具体一件校方保存的信息*，核验申请是否进入学校信息公开路径、信息能否定位、应当提供哪些可公开部分、哪些需保密或第三方权益审查，以及有权办公室是否已签署该次答复。它既不是一篇宣传稿的内容编辑，也不是通用档案利用、科研成果发布或个人证明用印。

**谁可以发起**：公民（包括在校学生、教师、其他职工、毕业生及校外公民）、法人和其他组织可以依教育部令第29号第9、19条及校方公开指南申请相关学校信息（SRC-001/007）。学生/教师身份可以辅助业务归类，但不能设成申请资格的必要门槛；法人/组织需可信证照或授权代表材料。代理申请需有权代理与被代理主体的身份核对；此为安全研究候选，校方是否接受代理以及格式待配置。

**主管分离**：成都理工大学信息公开办公室（校方指南所载）统一受理、协调与答复；具体信息**持有部门**核对原件、形成事实和建议；学校保密工作责任机构或依法有权定密主体完成保密审查/请示；可能受披露影响的第三方表达意见；有权签发人按实际授权作最终决定。院系员工、申请人和 AI 都不能自授公开批准权。教育部令第29号第11、16、18条是角色与疑难事项报请的上位依据（SRC-007）。

**完成物**：一份经有权人员确定的申请答复及其可披露范围、受众、内容版本、送达证据；不自动生成“准予公开”签发。具体“公开”的范围可能是告知已有链接、指定申请人可获得的摘录、部分遮盖的复制件、说明不予公开的理由，也可能是转介或不存在告知。

## 03 业务生命周期与办理情形矩阵

阶段是 Case 状态，不是独立模板：`P0 识别/路由 → P1 申请校验/登记 → P2 信息定位/持有者核实 → P3 保密、第三方与可分离审查 → P4 人工签批答复 → P5 指定受众提供/送达 → P6 补正、撤回、复核/投诉、纠错的分支 → P7 留痕归档`。P6 可返回 P1/P2/P3/P4；若已经提供，不能回滚已发生的披露，只能登记撤回、纠错/补救和新的决定。

| 情形 | 申请主体/岗位/学段 | 子类型与触发 | 当前阶段的事实和条件材料 | 下一角色/决定与后续 |
| --- | --- | --- | --- | --- |
| A 主动公开信息查询 | 公民/组织、任意学段 | 已有已授权正式公开链接 | P1 申请表/身份（若转正式受理）；P2 版本化 URL | 办公室核对受众、链接有效后 P4 有权答复，P5 告知路径 |
| B 依申请提供普通学校信息 | 同上 | 明确的一项尚未主动公开文件 | P1 申请、身份；P2 持有部门原件；P3 范围审查 | 信息公开办公室/有权审签人决定提供方式 |
| C 混有保密、商业秘密或个人信息 | 同上 | 原件部分可分离 | P3 保密结论、第三方权益意见、最小化副本 | 有权人员决定全拒/部分提供/范围限定；不能模型放行 |
| D 涉及本人数据、更正 | 信息主体/法定代理、任何学段 | 请求本人有关记录/发现错误 | P1 身份及关系；P2 原记录；P6 更正证据 | 更正由记录主管/G01 作决定；公开办公室答复路径 |
| E 法人/组织或授权代理 | 法人、组织代表/代理人 | 企业查询本单位相关资料 | P1 证明与授权；P3 合同商业秘密/第三方利益 | 核权后按普通程序；代理权限未知不能透露 |
| F 不存在/非校方职责/超加工请求 | 任意申请人 | 无持有记录或要求新分析统计 | P2 持有部门检索轨迹、原样状态 | 有权办公室说明不存在/不属职责/现有形式，不新造数据 |
| G 已答复重复申请 | 同一可信申请人 | 同信息同版本无正当理由重复 | P2 既有答复和版本指纹 | 人工确认同一性后按29号令第18条处理 |
| H 已移交档案/科研专用信息 | 任意申请人 | 持有者归档或科研专项 | P2 转移凭据或已签专项结果 | 档案/G06/T03 等有权部门办理，办公室告知转介 |
| I 期限、补正与第三方征询 | 任意申请人 | 表述模糊/待回复/申请延长 | P1 补正告知；P3 第三方意见；P4 延期批准 | 由办公室通知申请人；冻结、暂停和延期按可核时点计算 |
| J 撤回与复核投诉 | 已有 Case 的申请人/合法代理 | P1–P5 撤回，或P4–P5 对答复异议 | P6 撤回/复核请求及原决定版本 | 尚未提供则核撤回；已提供仅登记；争议送有权监督/原签发机构 |

**阶段严格性**：`M008–M014` 等保密意见、第三方意见、脱敏副本、正式决定、送达凭证，只在进入对应 P3–P5 后条件形成；P1 初次提交时绝不因“尚无批准签字”报 `NEEDS_MATERIAL`。P1 必须材料通常限 `M001/M002`；代理案才触发 `M003`。本设计不把证明“个人特殊需要”的证据机械加为每个申请人的提交门槛，是否需要补证应由办公室根据具体申请审查。

| 保密责任主体/定密责任人 | 依法判定密级、知悉范围，形成审查意见/请示上级；不能将无定密授权的自述当正式定密 | 可信保密结论及其签名版本 `M007/M008`；该角色具体任命权待校方验证 |
| 第三方权利人及隐私保护/法务职能 | 表达同意/不同意、权利依据、最小化意见；学校再作法定判断 | 同意并非自动解除国家秘密限制；可记录“未答”但不得推断“同意” |
| 最终有权签发/复核人 | 审定答复类别、范围、受众、时间、形式，作正式决定或复核 | 只有服务端授权名册加不可抵赖的决策记录生效；Renderer Actor、文档签字图片均不可信 |
| V3 自动审核器 | 提取字段、识别矛盾、列待办、保持 `rule × target × sourceVersion` 证据链 | 不能签发、解密、替第三方同意、向外网传原件、调用无授权后台 |

**数据分区**：普通级 `D0`（公开链接、制度标题）、内部 `D1`（受理信息）、个人 `D2`（联系方式/学号/实名）、敏感 `D3`（证件、健康、财务、未成年人、举报身份等）、涉密/待定密 `D4`。`D4` 仅保存不包含秘密正文的工单标识、隔离状态、法定人工线索；**不能进通用模型、云 OCR、外部对象存储或普通日志**。`D2/D3` 字段仅后端最小必要访问，加密存储；输出给申请人的答复必须绑定本人/有权代表身份及用途，禁止“公开申请”等同“互联网公示”。任何第三方敏感数据发送到模型需合法基础、评估和数据处理授权，本研究不假定已满足。

## 07 材料槽与证据目的

缺失分支默认：当前 `REQ`、触发后 `COND` 而缺 → `NEEDS_MATERIAL`；合法可信服务端存在但取不到 → `SOURCE_UNAVAILABLE`；材料有字节却 OCR/解析失败 → `UNREADABLE`；与别源矛盾 → `CONFLICT`。`LATER` 在产生前统一 `NOT_APPLICABLE`，不能强迫申请人预交学校将来作出的决定。所有材料必须附 `caseId + owner + target + sourceVersion + hash`；D3/D4 只允许安全代理/最小元数据，不能将原始机密塞入 ZIP 或模型。

## 08 审核规则逐条清单

**约定**：`真/假/未知` 是对“本行唯一事实”进行判断。`真` 不意味着案卷批准；本行给出常见 T/F/U 及下一角色。`NOT_APPLICABLE` 专用于触发条件为假（不属于本行子情形）；事实不成立而需要改正/转办时使用具体问题码+`NEEDS_HUMAN_DECISION`、`NEEDS_MATERIAL` 或 `CONFLICT`，不可把失败伪装成 `NOT_APPLICABLE`。当可信数据不可达用 `SOURCE_UNAVAILABLE`，文本不可读用 `UNREADABLE`，制度/授权不明用 `POLICY_UNCONFIRMED`。一行规则必须绑定当前 `targetId` 和 `sourceVersion`。

## 09 触发条件、冲突和复合场景

1. **已公开 URL + 个人明细**：同一文件“政策正文已公开”不代表附件中的学号、健康信息可互联网发布。R006 可通过，R013–R017 仍必须审查针对申请人的受众；只输出经核链接或批准删节件。
2. **合同 + 学校公开申请**：合同实质属于 T07-T02/T04-T03/T03-T03，学校持有版本属 M006，商业秘密范围用 R012/R014；本模板只作本次信息公开决定，不重新批准合同。
3. **科研论文 + 公开申请**：G06 已签科研公开意见≠默认全社会获取所有原始试验数据。依法信息公开在 T07-T07 单独审披露受众，并消费可信 G06 决定；可能涉密的科研资料在隔离环境/保密机构处理。
4. **证明 + 信息公开**：当目标是为自己办“一份证明”，优先 G01；当目标是获得“某校方已形成规章及其变更记录”，继续 T07-T07；同一人同时提出两项需拆为两个业务对象，避免一个案卷的审批结论覆盖另一个。
5. **多材料冲突**：身份证姓名与校方可信记录冲突先 R002；文件标密与公开网页冲突先 R010/R011 触发保密隔离；同意书授权邮件与受众不一致触发 R014/R017；源文件更新与脱敏旧版冲突触发 R028。不能任选有利版本。
6. **不同规范冲突**：国家法与教育部规章/校内制度不一致，标 `POLICY_UNCONFIRMED` 并交法务、信息公开办公室按效力层级审定。政府信息公开条例的行政机关20工作日不得覆盖高校29号令15日。校方2023指南旧文出现“收费”并不代表可在2026按旧额收费；合法标准缺证不自动收费。
7. **无/错密级**：保密标注不存在不能自动等于“非涉密”，真实保密审查尚未结束用 `NEEDS_HUMAN_DECISION`；可信保密后台掉线用 `SOURCE_UNAVAILABLE`；普通系统不得缓存涉密附件。
8. **公共利益/第三方同意例外**：不得自动判定“公益价值更大”或把第三方沉默作为同意。严格由学校有权主体依法衡量并记录理由、必要性和实际受众；国家秘密不因私人同意即解除。
9. **重复申请**：必须校验主体和源版本是否变化及是否有新正当理由；不要用同一标题哈希草率关闭。
10. **期限暂停与补正**：只有校本/上位依据支持的时段可以暂停/延长；R020 分开记录第三方征询、中止、审批延期、告知日期。未知细则不依赖“AI算了15天”直接作违规结论。

## 10 结果状态、问题与待办输出契约

每个 `Finding` 必含 `{caseId, planId, ruleId, targetId, stage, evidence:[{slotId,ownerId,sourceVersion,contentHash}], policySourceIds, status, reasonCode, rationale, action, nextRole, createdAt}`；无材料槽时显式 `evidence:[]`，但需 `policySourceIds`，不可编造文件引用。每个问题只针对一个具体事实、材料槽或目标版本；不同第三方、不同附件、不同 R 的问题不能合为“资料不完整”。计划冻结后规则 Check 必须与 `target/sourceVersion` 绑定；新材料只影响相关子图。

| 主状态 | 展示话术范式 | 待办及权限 |
| --- | --- | --- |
| `PASS_FACT` | “R006：原件版本 X 对应的链接可访问” | 等待其他 R 和最终人工决定；不得显示“申请已批准” |
| `NOT_APPLICABLE` | “R004：非代理申请，代理授权材料不适用” | 不要索要该材料 |
| `NEEDS_MATERIAL` | “R003：所需信息名称不明确，请补充具体文号/时间” | 申请人补 M001/M005；写明目标字段，不要求提供保密签批 |
| `CONFLICT` | “R017：拟发送附件 hash-B 与获批 hash-A 不一致” | 学校办公室停止发送、核对版本 |
| `UNREADABLE` | “M001 电子文件无法解析，尚不能核对申请事项” | 申请人合法重传；不得判信息不存在 |

## 11 补件、撤回、版本更新、复核与人工决定

**事件账模型**：`ApplicationReceived`（附 `M001/M002` 版本）→`IdentityVerified`→`Registered`→`CustodianLocated`→`ConfidentialityReviewRequested/Completed`→`ThirdPartyConsulted`→`RedactionApproved`→`ReplySigned`→`ReplyDelivered`→`Closed`。任何阶段可 `CorrectionRequested`/`MaterialSuperseded`/`AuthorityChanged`，按 R028 使关联核验失效并重审；不删除历史、也不覆盖旧事件。

- **补正**：仅 P1 客户提交缺项产生 `NEEDS_MATERIAL`；一次明确指出 M001/F007 等字段、截止日需校本核定。若基本完整且只差某后续资料，可先完成可核事实和初审，把后续材料挂待办，不把整个案卷视为失败。M008/M014 属学校未来动作，不向申请人索取。
- **撤回**：可信申请人/代理在披露前请求撤回，形成 `WithdrawalRequested`；有权办公室确认后关闭未执行动作。若已经 P5 发出，不可能“撤销下载”；保留日志、限制继续分发并由校方确定后续处理。撤回个人信息处理同意与撤回公开申请是两个不同法律动作，不能混同。
- **正式决定**：只有后端验证的 `authorizedRole + authorityScope + policyVersion + signature + decisionTime + exactApprovedContentHash + recipientScope` 才能生成 `ReplySigned`。签发后 material 版本变化需重新判断是否必须重签，旧批准不可冒用。
- **复核/投诉**：不满意答复者可使用教育部令第29号第26条的学校内设监察部门、省级教育行政部门等监督路径；校内是否有独立复核会/复核期限/申诉表尚未证实，不能假设有强制内部二审或自动申诉成功。需同案追踪 `F031`，与实体业务（G01/G06等）的原决定救济分开。
- **定向重审**：建立依赖矩阵：`M002/M003→R002/R004/R025–R027`；`M005/M006/M017→R001/R006–R009/R024`；`M007/M008→R010/R011/R018/R021`；`M009/M010/M011/M012/M013→R012–R017/R021`；`M014/M015→R018/R021/R022/R025/R027`；`M021/M022→R018–R020/R028`。此外关联 `F014/F023/F033` 变化必须级联检查下游 `R017/R018/R021/R022/R028`，不能只复跑编辑材料对应的孤立规则。
- **批处理及离线**：多个申请人/多个目的只可分别生成 Case 及独立正式决定；ZIP 导入不得混用身份证/案卷附件，离线导出仅可存放最小化非涉密证据与引用。恢复后全部可信身份/授权/密级/源版本重新核对，离线缓存不能成为决定源。
