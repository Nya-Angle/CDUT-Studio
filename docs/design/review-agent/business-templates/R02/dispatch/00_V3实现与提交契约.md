## 128 项范围与缺失项

128 份正式 Markdown 是本轮实施对象。16 个缺失源文件保留在缺口清单中，不得用相邻模板代替、不得生成空壳假模板，也不阻塞 128 项。

每份模板交付三类内容：

1. 审阅后来源文档：`docs/design/review-agent/business-templates/R02/{TEMPLATE_ID}.md`
2. V3 运行时模块：`apps/electron/src/main/lib/review/r02-template-catalog/definitions/{TEMPLATE_ID}.ts`
3. 批次测试：`apps/electron/src/main/lib/review/r02-template-catalog/definitions/{BATCH_ID}.test.ts`

批次审查报告/问题台账放在 `docs/design/review-agent/business-templates/R02/audits/{BATCH_ID}.md` 和 `.tsv`。模块、来源文档与 ID 必须一一对应，模块需记录来源路径与源文档 SHA-256。

## V3 运行时要求

- 使用仓库已有 `TemplateVersion` 和 V3 C0 Plan / Run / Main 门禁；不得另造第二套 Case、Run、Decision、Batch 或 Outbox。
- 每份模板保留正式 `templateId`、名称、适用范围、字段、材料槽、分项/criteria、阶段、异常路线和输出。字段类型/阈值不清楚时不猜。
- 每条模板 criterion 都必须映射到 V3 可追踪检查计划，拥有稳定 checkKey/target binding，并被纳入 plan fingerprint。不能只显示在模板库中却不参与运行。
- 明确区分“模板内审查项”和真实 `PolicyVersion`/校本政策规则。不得伪造 `policyVersionId`、PolicyVersion、政策确认人/时间或学校授权。若现有 C0 契约不能表达模板内审查项的来源类别，由集成 Owner 增加显式来源类型/证据状态并做向后兼容；不得把模板标准冒充学校政策。
- 未确认政策仍可进行材料解析、事实提取、证据覆盖核对和审阅建议；政策合规结论必须转为待确认/人工复核，不得让语义模型的 pass/fail 直接成为正式合规结论。
- 128 项初始 `autoPassPolicy.enabled=false`。最终决定必须经过现有 V3 Main 可信身份、expectedRevision/CAS、Run 新鲜度、Plan fingerprint、材料版本和决定门禁。Renderer 不可信，不能传入可信 Actor。
- 阶段角色用通用本地 `reviewer`/`teacher` 等角色；不根据部门名称推断校方签批权，不伪造学校系统写回。模板卡片/说明显示“本地研究模板 / 非校方正式模板”；规则待确认时显示警示。
- 研究 MD 的 SRC 是研究来源索引，不是案卷材料 `SourceRef`；不可伪造为材料证据引用。来源不确定不阻止代码实现。
- 本地文件存储优先，不新增依赖或数据库，不复制共享业务逻辑。不要修改 `README.md` / `AGENTS.md`，除非用户另行授权。

## 文件所有权

批次会话只能新增/修改自己分配的来源 MD、模板模块、批次测试、审查报告和问题 TSV。禁止修改共享注册器、`builtin-templates.ts`、`template-store.ts`、共享类型、V3 Main 写入服务、IPC、preload、renderer。集成 Owner 独占共享接线与跨模板问题修复。

## 每批必须做的事

1. 从 `feat/v3-r02-template-library` 当前 HEAD 按固定 ID 读取分配的全部原始 Markdown：`docs/design/review-agent/business-templates/R02/research-original/{TEMPLATE_ID}.md`，并完整阅读，不得只看摘要。原始 ZIP 不是输入前提；若已有 ZIP，可作为辅助交叉校验。
2. 审查来源/时效、范围、字段/材料/规则/角色、异常、隐私和跨模板边界；记录官方 URL/文号/条款。授权或校本文件缺失只标证据状态并继续。
3. 修复有依据、低歧义的正文问题，保留 GitHub `research-original/` 原件只读；审阅后版本写入 `docs/design/review-agent/business-templates/R02/{TEMPLATE_ID}.md`。已有批次 ZIP 只能作为可选辅助材料，不得要求用户提供或等待 ZIP。
4. 每份模板转为 `TemplateVersion` 模块；所有不确定政策规则不得设置为确定性自动判定，所有模板关闭自动通过。
5. 测试 ID/名称、字段与材料引用、分项/criterion 唯一性、阶段合法性、来源元数据、auto-pass 关闭、未确认政策不会产生自动正式通过。
6. 执行批次专项测试、`bun run typecheck`、`bun run check:boundaries`。不能执行则如实记录，不可伪报通过。
7. 提交分支并创建 PR 到集成分支；PR 必须包含实现代码、审查报告、问题台账、测试结果与剩余事项。ZIP 是辅助交付，不能替代 PR。

## 集成验收

- 128/128 ID 唯一，源 MD/运行模块/测试登记完整。
- 128 项都在 V3 模板库可发现、可创建案卷、可编译 V3 Plan 并执行真实 V3 Run。
- 每个 criterion 均绑定稳定检查；未执行检查不得算覆盖完成；Plan fingerprint 绑定模板、criteria/source metadata 和材料版本；旧 Run 不可用于新版本决定。
- 不伪造学校政策/授权；未确认项只能输出建议/待确认，不能自动正式通过或拒绝；128 项 auto-pass 全关。
- 业务写入仍由唯一 Main/C 服务负责；不增加第二 Case/Run/Decision 写入点。
- 16 项缺失源文件独立列明，不造假模板。
- 一次集中跑 128 项结构测试、V3 Plan/Run 专项回归、typecheck、boundaries；再统一运行一次全量测试。子批次不重复跑全量 CI。
- 最终一个集成 PR 指向 main，附最终报告、问题台账、变更映射、测试证据与缺失清单。

**学校授权/内部制度未确认，只影响政策证据状态和自动判断能力，不阻止研究、实现、测试、分支提交或 PR。** 交付目标是本地可用的 V3 研究模板库，不是声称学校已正式采用。
