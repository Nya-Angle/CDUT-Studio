# R02 V3 实现：文件所有权与协作规则

## 批次会话可写范围
- `docs/design/review-agent/business-templates/R02/{分配的 TEMPLATE_ID}.md`
- `apps/electron/src/main/lib/review/r02-template-catalog/definitions/{分配的 TEMPLATE_ID}.ts`
- `apps/electron/src/main/lib/review/r02-template-catalog/definitions/{BATCH_ID}.test.ts`
- `docs/design/review-agent/business-templates/R02/audits/{BATCH_ID}.md`
- `docs/design/review-agent/business-templates/R02/audits/{BATCH_ID}.tsv`

## 集成 Owner 独占范围
- `apps/electron/src/main/lib/review/r02-template-catalog/index.ts`（统一注册）
- `apps/electron/src/main/lib/review/builtin-templates.ts`（播种/目录接线）
- 模板内 criterion → V3 C0 Plan 的共享编译器与 metadata 契约
- 必要的 shared 类型、Main 服务、IPC、preload、renderer 和集成测试
- 跨批次问题、统一状态、最终报告和面向 main 的最终 PR

## 不得触碰
- 批次会话不改 `case-store-v2.ts`、`run-store-v2.ts`、`review-v3-t05-main-service.ts`、Batch/Decision/Outbox 写入路径；不创建第二份业务真值存储。
- 不修改 `README.md`、`AGENTS.md`，不更新依赖锁，不加依赖，不把研究来源 ID 当案卷材料引用。
- 不把模板显示为学校官方模板；不自动通过；不编造 policyVersionId、确认人或校方回写。

## PR 流程
- 批次分支 `feat/v3-r02/templates-{BATCH_ID}`，从 `feat/v3-r02-template-library` 建立。
- PR base 必须是 `feat/v3-r02-template-library`。
- 每批只提交独占文件；共享接线留给集成 Owner。
- 最终集成 Owner 完成集中回归后，创建唯一最终 PR 到 `main`。
