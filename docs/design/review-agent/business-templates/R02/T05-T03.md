## 01 唯一审核目的、申请人和负责机构

### 1.1 决定对象及事实边界

**唯一审核目的**：对一项处于特定公开批次的「课程建设/精品课程/在线课程建设**立项申请**」进行真实性、材料对应性、人员与课程资格、建设类别、申报团队、阶段目标、推荐或前置审核手续的事实预审，向对应归口机构提供问题清单和证据定位。对象是一项申报记录而非课程开课资格、项目结题、成果等级认定或资金报销。

项目的申报资格、材料份数、经费、截止时间、建设周期必须绑定 `项目子类 × 学段/教学体系 × 批次 × 有效公告`；没有可识别批次时只能列出待确认事项，**不能借用别的类型的数值**。本模板可容纳同一课程不同项目批次的申请，但各批次应形成独立申请记录，防止把旧立项结论覆盖新申请。

事实预审包括：材料是否可读、字段及跨件一致性；课程与本批次建设目录或培养方案的关联；负责人及团队的自述与学校可信人事/教学记录是否一致；已有资源、平台证据、知识产权承诺是否有来源；前置学院推荐与审查是否真实存在。专家对建设必要性、教育质量、价值导向和择优排序的判断不能自动裁定。

## 03 业务生命周期与办理情形矩阵

### 3.1 生命周期：分阶段对象和材料时序

1. **批次设立/申请入口识别**：主管单位发布当期通知、类别、适用群体、申报目录与期限；校本公告不存在或无法验证时停止自动资格判断。
2. **申请准备**：教师与团队形成项目申报书、建设计划及已有基础证明，承诺材料与知识产权真实性；只要求**本阶段**通知规定且合理存在的材料（SRC-002、004、005）。
3. **学院初审及推荐**：学院核验课程、团队、材料和必要性，形成推荐与排序/汇总（各批次具体要求不同）；不得要求尚未评审的立项文书作为申请材料。
4. **归口部门形式审查、专家评审**：根据来源分支完成材料审查、专业评价、名单/排序建议；专家建议与系统事实核验分离。
5. **公示与异议核查（条件）**：凡当批实际有公示程序，登记公示版本、期限、异议及复核状态（SRC-004、005、007）；“公告计划公示”和“已见公示原页”分开，B 的 2026 最终结果公告（SRC-016）不能反推独立公示页已取得。
6. **有权机构正式决定**：按具体批次录入学校正式立项文件、经授权部门/会议审定并公布的建设决定或不予立项通知及其签发主体。C 公告明确正式发文，B 有党政联席会审定并公布的线索但会议原件及授权待核；不能强加所有学段同一种校级批件。AI 不能由专家意见或材料齐全自动生成批准。
7. **后续履约关联**：中期、建设、平台上线、验收、优质课程遴选、绩效及经费属于立项后的业务事实，允许**只读关联**（SRC-003、005、006）。本阶段决定不能反写或篡改原立项依据。

**阶段准入与证据时序**：`公告核定 → 负责人拟稿 → 学院初审推荐 → 归口形式/专家评议 → {公示/异议，若实际存在} → 有权审定及正式结果（文书形态按批次） → 后续建设`。B 的后段可能为评议→会议审定→公布，不应机械套 C 的正式发文链。保留 `F008/F009/F052` 版本链；`M001/M002` 校方供给，`M003/M008` 教师现时件，`M004/M016` 到学院阶段才形成，`M017～M021` 仅在对应事件真实发生后形成，`M022` 只用于后续履约。

**补件与撤回**：发现缺失时先列明 `M/F`、来源和责任人；逾期补件许可、申请者可撤回的阶段和撤回生效形式，**各批次源文件尚不支持统一确定**。系统可以接收 `M023` 的请求并冻结受影响结论，但由有权部门的 `M024` 确认办理结果。对专家裁量或公示异议的复核同样不得由事实预审自动批准。

### 5.2 可信边界及预审输出

1. **身份可信边界**：Host/Main 端从学校认证会话、组织/人事权威数据解析 `actorId`、单位、岗位、权限和授权时效；Renderer 传来的 `actorRole`、申请教师、签章、学院名称均为**待核陈述**。每一次学院审核、推荐、归口审查、最终决定，都须后端校验实际操作者与案件、批次、阶段匹配。
2. **事实可信边界**：培养方案与课程目录来自教务/研究生/继续教育权威版本；人事职称来自人事系统；既有项目与立项文号来自正式公文/项目库；平台课程 ID 和访问/挂载等统计来自授权平台接口或可核签的数据导出。表单、PPT、截图、扫描印章、第三方平台网页仅是待核材料，不能以 OCR 成功代替外部真实来源校验。
3. **版本边界**：预审必须固定批次通知及校本政策的文号、URL/哈希、适用期和版本；申报书、课程资源、平台报表与学院意见各自存不可混淆版本。补件后重新核验受影响事实，不覆盖先前评审证据，也不把旧 Run 标记为新决策。
4. **阶段边界**：`PASS_FACT` 仅表示在限定来源/版本上某项**事实预审通过**，不表示已立项。`NOT_APPLICABLE`、`NEEDS_MATERIAL`、`CONFLICT`、`UNREADABLE`、`SOURCE_UNAVAILABLE`、`POLICY_UNCONFIRMED`、`NEEDS_HUMAN_DECISION` 为预留细分状态；不在第一轮替代校方正式结果。不读取校方名单或人员授权时，必须保留人工办理待办。
5. **批次边界**：2025 本科项目的「原则上已纳入 2025 版培养方案」与 2026 继续教育「中级及以上职称」、研究生校企课程的双负责人资格各属特定批次。不得合成为一个全校通用的布尔资格规则，也不得将后续验收资源挂载率当作立项先决条件。
6. **裁量边界**：课程建设价值、示范性、必要性、意识形态审读、学术质量、优先推荐、是否批准、异议复核、特殊情形豁免属于有权人员/委员会的职权。模型最多给可溯源的事实与冲突提示，不能替学校决定。

### 5.3 第 1 轮可确认与待授权之分

- **可确认**：校本项目真实存在；各分支的申请、学院推荐/审核、专家评审、公示和正式发文链存在差异；课程平台具备相关功能；申报与验收产生不同阶段材料（SRC-001～011）。
- **未确认**：统一跨体系审批权、学校本期所有类别的现行有效政策、真实接入能力、合法代理和撤回权限、公示异议统一时限、签章验真方式、最终校级立项文件获取接口。不得凭程序设计推断学校已授权本系统代办。

### 5.5 可信证据优先级、同名匹配和失效传播

1. **对象键**：以 `F008` 申请唯一 ID + `F003` 批次 + `F019` 课程权威 ID + `F012` 人员权威 ID 组合定位。不同课程 ID 不因同名合并；有同名、重名、改名时，以经授权的人事和课程主数据做关联，无法核实输出 `CONFLICT`，不得用姓名模糊匹配自动认领他人资格。

## 06 业务对象与字段字典

### 6.1 模型说明及采集边界

本节 F001–F054 是**审核所需证据事实的数据字典**，不是宣称已经读到某张学校申报表的全部栏目。每个字段必须绑定 `applicationId + sourceVersion + 适用情形 + evidenceLocator`。`M` 位置优先指向原件页/表格单元格/可信结构化记录；对文档仅能索引页/段和原始文件哈希，不准凭 OCR 构造权威数据。

对象缩写：`B` 批次与政策，`A` 申请卷宗，`P` 人员与团队，`C` 课程，`D` 建设方案/数字资源，`W` 学院与评审流程，`J` 正式决定/后续事件。阶段 `T0` 公告、`T1` 教师拟报、`T2` 学院、`T3` 归口/专家、`T4` 公示、`T5` 正式决定、`T6` 后续/纠错。

隐私：`L0` 公开政策，`L1` 校内业务，`L2` 可识别个人/合作组织信息，`L3` 受限评价/异议/身份鉴别。缺失策略：`N` 该阶段且适用时提示 `NEEDS_MATERIAL`；`U` 权威源不可用提示 `SOURCE_UNAVAILABLE`，不能要求无依据的个人重复上传；`P` 政策不明提示 `POLICY_UNCONFIRMED`；`H` 冲突或裁量由有权机构人工处理；`—` 未到产生阶段不查。优先从可信数据源取得；括号列明 `M` 是承载位置/条件替代。不存在已证明的实时接口时，可信源只表示**应向谁核验**，不代表已接通。

### 6.3 可配置与三值判定

- `true`：本批 SRC 已确定适用且可信证据满足条件；`false`：确定适用但可信证据证明不满足；`unknown`：公告、身份、版本、来源或例外未定。**未知不等于 false。**
- A 分支「原则上纳入 2025 版培养方案」「优先支持」及 2025 学院基本名额，不变成全校拒绝门槛；B 的中级职称、C 的双负责人及学时模式、D 的项目限项仅当时当类生效（SRC-002/004/005/006）。精细阈值配置应记录 `F001～F005` 的完整版本元组。
- `F028～F030` 描述拟建成果；`F049` 是实际完成成果，二者不得混同。`F026` 没有授权数据只能形成来源缺口，不能把申请人截图断言为虚假。

## 07 材料槽与证据目的

### 7.1 材料定义、时点及合法替代原则

`M001–M027` 指**证据槽**，可由权威系统/官方网页/机关登记填充，不等于 27 份申请人必须上传的文件。材料要求记为：`前` = 申请当时当前必需；`条` = 分支或事实触发才需要；`续` = 推荐/受理/评审/公示/决定或后续履约产生，**不得对前阶段要求**。每槽必须记录 `caseId, batchId, ownerId, sourceId, file/hash或recordId, sourceVersion, collectedAt, effectiveAt, evidenceLocator, supersedes, accessScope`；纸电两版如内容相同可作为同一证据的不同载体，不能默认其校验值一致。合法替代必须有**同一有权来源和同一证明目的**，不能以未经核验的截图替代正式决定。

异常简写：`缺` = 适用且到阶段但未提供，`读` = 原件打不开/OCR 无法定位，`源` = 官网或权威系统不可达，`冲` = 多个版本/主体冲突，`政` = 通知效力/必交性未知。前二者可请求补件或更可读同源文件；`源` 不合理要求申请人重复上传校方原始数据；`冲/政` 须归口人工核定。无各分支明确条件时，不把候选材料变为必交。

## 08 审核规则逐条清单

### 8.1 规则解释、证据等级与异常出口

本轮建立 **R001–R031，31 个独立核验目标**（旧第三轮实有 R001–R030；第四轮依据 SRC-005 增补 R031）。规则是设计稿，**不是已配置运行的执行器或校方审批规范**。每项只评价指定 `caseId×批次×课程/人员目标×材料版本` 上的事实；仅采用第 04 节可见政策，绝无隐含校方规则。

表格 `SRC → F → M` 列为节省宽度将 `SRC-002/SRC-004` 写成 `002/004`；每个三位数都严格指向第 04 节同编号 `SRC-xxx`，不能解释为无编号的外部依据。字段与材料则保留 `Fxxx/Mxxx` 前缀，范围写法如 `F001–004` 意为包含 `F001,F002,F003,F004`。没有对应适用批次的规则不能从相邻来源继承门槛。

- 阶段：`T0` 校方发出批次公告；`T1` 教师拟报；`T2` 学院推荐和受理；`T3` 归口形式/专家；`T4` 公示异议；`T5` 正式决定核验；`T6` 后续履约或纠错。`G/H/I` 是对原案的补正/撤回/异议动作而非新立项。
- 触发列的 **真** 表示当批次与阶段条件已证实，才实际求值；**假** 表示本项在本阶段不适用，`NOT_APPLICABLE` 且不索材料；**未知** 表示分支、阶段或前置条件没有可靠政策/事件支撑，先 `POLICY_UNCONFIRMED` 或在权威事件不可取时 `SOURCE_UNAVAILABLE`，不能把“不确定”判成资格失败。
- 证据等级：`E0` 本批当前有效的学校官方规则/归口授权，`E1` 主管部门或学校系统权威原始记录、正式公文/受信签发，`E2` 机关可核签学院、企业或教师申报原件，`E3` 无签名截图、OCR、宣传网页和个人自述。`E3` 可用来发现冲突，不可单独证明人员资格、平台统计、审批权或正式批准。`E0` 决定**判断标准**，`E1/E2` 决定**事实来源**，两者不能混用；所有证据还须在被核事项的**生效日**有效。
- 共通异常分流：真正应由申报者/本阶段经办者提供而未有的 `M`→`NEEDS_MATERIAL`；已收到而不能读取→`UNREADABLE`；校方/第三方权威源无法访问→`SOURCE_UNAVAILABLE`；同一对象不同可信原件冲突→`CONFLICT`；规则有效性、适用范围或门槛不明→`POLICY_UNCONFIRMED`；专家、争议、豁免、处罚或审批权裁量→`NEEDS_HUMAN_DECISION`；事实、版本、权限均可核仅得 `PASS_FACT`。若多个独立问题并存分别建问题，绝不用一个总分覆盖缺口。没有 `FAIL_FACT` 或“AI 不批准”状态；单项不满足已核资格事实，记录原值及政策差异，由有权人作决定。
- 表中 `→角色` 是**问题受理/下一办理者**，不代表授权其形成最终立项决定。某项涉及未来阶段时不能用 `NEEDS_MATERIAL` 催要尚未产生的证据。SRC-013/014 是**未取得的技术对照文件**，不能成为政策判定依据。

### 8.3 规则层绝不输出的结论

即使 R001–R031 当前适用者全是 `PASS_FACT`，也只能形成 **“指定版本的已知材料事实核对完成”**。是否推荐、是否采纳专家意见、是否立项、是否豁免或处罚、是否准许撤回/复核均由各批次已授权机关在人工作业与正式权威文书中作出。A 的课程入方案“原则上”与评价“优先”是人工判断；B/C 明示的资格也不能由本规则表独立代替审批机关的最终裁量。

### 9.2 材料级反例（已映射至第 08 节 R 规则）

- **反例 X01：姓名匹配假阳性**。`M003` 写“张某、信息学院”，但 `M006` 查询同名两人；即使 `M003` 与 `M004` 名字一致，`F012` 仍为 unknown，不可 `PASS_FACT`。处理：以人员权威 ID/单位生效日确定；不能输出谁持有有效职称。
- **反例 X02：后续材料前置**。`A1` 仅申请知识图谱立项，系统要求 `M022` 结题表和“资源挂载率≥90%”；这是把 SRC-003 的验收规则错误用于 SRC-002 申请。处理：`NOT_APPLICABLE`，不形成材料缺失。
- **反例 X03：纸电不一致**。同批 `M003` 扫描版负责人为甲，学院 `M004` Excel 为乙；不能选 OCR 识别率高的一份。处理：指向具体单元格/签章版，冻结 F012/F013，学院和负责人核实。
- **反例 X04：承诺等于授权**。`M011` 只有“无侵权”自述，却含未标来源的第三方视频；自述存在不等于知识产权事实通过。处理：`NEEDS_HUMAN_DECISION`、缺具体授权来源时补件，不自动侵权认定。
- **反例 X05：签发越权**。学院“推荐”`M016` 盖章，尚无 `M021` 正式文书；不能将 `F044=approved`。处理：标仅“学院推荐完成”，后续等待真实决定。
- **反例 X06：内容变更后旧意见复用**。改写 `F029` 教学方案，原专家 `M018` 仍指旧 `M003@v1`；新审核必须将原评审对受影响部分标过期，由有权专家确认能否继续采信，不假装本轮重新评审过。
- **反例 X07：来源失联不等于未提交**。学校官方 `M005` 系统临时不可用，教师已填课程 ID；不能报“教师缺材料”，应 `SOURCE_UNAVAILABLE` 由教务处人工校对。
- **反例 X08：公示与异议**。E 分支 `M019` 仍在异议窗口，有书面 `M020`；无正式 `M024/M021` 前，不能“无异议”自动确认立项，更不能公开异议人敏感身份。

### 9.3 冲突处置与状态传播（本轮非可执行规则）

1. 以 `M + 版本 + 定位` 形成事实证据边；冲突记录两端原值、来源可靠性、业务有效期，不消除原值。
2. `M003/M008/M011/M014` 更新，自动标记其直接依赖 F 需要复核；若 `M016/M018` 引用了旧申报版，则只让相关审查结论过期；新 `M024` 等正式机关动作能重新明确效力。
3. `M021` 新决定不能抹掉旧决定，变更、撤销必须有相应权威签发文书及因果指针；AI 输出不改变学校真实状态。
4. 无源、不可读、政策未知三类分开呈现：`SOURCE_UNAVAILABLE` 是权威系统不可访问，`UNREADABLE` 是文件已有但内容不可辨，`POLICY_UNCONFIRMED` 是缺少有效本批规则；不得一概叫“缺件”。

## 10 结果状态、问题与待办输出契约

### 10.1 互斥规则状态；与行政决定两套账

下表 `reviewStatus` **每个规则目标在一次 Run 中恰取其一**，不是案件/学校正式批准状态。相同规则如有两个独立冲突点，以不同 `targetId + issueKey` 分开留痕；不能为压成一个“总体通过”隐藏其中任一问题。历史批次政策时效与身份变更时点必须单列。

| `reviewStatus` | 严格语义 | 对应动作及不可混淆项 |
| --- | --- | --- |
| `PASS_FACT` | 所核**事实**在本次固定规则、适用时点和可信证据版本下可被支持 | 标已核事实、可提供给下一有权经办；**不表示合规审批或校级立项通过** |
| `NOT_APPLICABLE` | 规则被证实不属于本分支或尚未到材料生成阶段 | 不建“缺材料”待办；需要保留触发条件为何为假、参照批次 |
| `NEEDS_MATERIAL` | 本阶段确属应提供的申请/学院材料仍缺，且不存在可用的合法同目的替代 | 指明 M、持有人、缺少的具体事实或页栏；未来才产生的 M 不属于本码 |
| `CONFLICT` | 同一目标在权威/受理材料之间存在互不相容的 ID、版本、时点或值 | 留冲突两边的原值和证据定位，由负责权威源的组织核实，不自动选 OCR 更可信的一边 |
| `UNREADABLE` | 材料**确实到达**但文件损坏、加密不可开或关键信息无法可靠识读 | 请求同源清晰件或人工阅件，保留文件哈希；不是“未提供” |
| `SOURCE_UNAVAILABLE` | 需要查的学校/平台/公文权威记录暂不可访问、无接口或原页失败 | 归口单位人工从合法权威渠道核查；不要求申请者无理由重复上传官方人事或课程数据 |
| `POLICY_UNCONFIRMED` | 规则本批适用性、现行有效性、名额、替代/时限授权未得可信校本规范 | 暂停对应门槛硬判和申请人强制材料清单，待政策 Owner 确认 |
| `NEEDS_HUMAN_DECISION` | 事实有争议、资格例外、优先性、专家质量评价、是否受理逾期/撤回、异议、公示或正式批准等需有权人裁量 | 显示归口角色与需裁量问题；不会自动生成批准、驳回或撤回生效 |

**同一目标结果分配顺序**：先核 `stage/trigger`；真且已有有效 `E0` 才查当期 `E1/E2` 证据；若目标发生多个类型的问题，每个事实或证据关系分别产生 Issue，不可把“来源失联”伪装“缺材料”。例如 B 分支教师职称 `M006` 官方库不可用且申报书扫描模糊，可对权威记录目标给 `SOURCE_UNAVAILABLE`、提交件目标给 `UNREADABLE`，而不是强给“不具中级职称”。不存在一个全案 `PASS` 能覆盖这两项。

| `Task`（待办） | `taskId,issueId,assigneeOrg,assigneeRole,authorityRef?,requestedEvidencePurpose,actionType(补件/查源/学院核实/专家裁量/异议办理/签发核验),status,actorAudit`；角色匹配需可信 Host/Main 验证，Renderer 只可表达申请或意见 |
| `DecisionRef`（外部正式决定，**非 Run 产物**） | `decisionId,decisionType,issuingAuthorityId,issuerSignatureRef?,documentNo,decisionAt,effectiveAt,subjectCaseId,courseId,batchId,officialSourceVersion,verifiedBy,verificationAt`，仅从当批**真实授权** OA/正式文件或受信人工核签导入；无此字段不可标“校方已批准” |

**去重键**按 `caseId + ruleId + targetId + effectivePolicyVersion + evidenceSetHash` 界定同一次事实；同一材料重复 OCR 不生成平行问题。材料版本被替换后保留旧 `observationId/issueId`，新 run 产生新对象与因果指针；不得覆盖旧审查痕迹。导出给用户的是材料名、缺页位置、修正责任人和处理状态，非内部 JSON。

### 10.3 汇总、待办和正式决定状态分离

`casePrecheckSummary` 仅汇总“适用规则数、事实可核数、未解各类问题、需要人工作业数”，不得输出 `approved=true` 或 `rejected=true`。官方立项状态另设：`未有可信正式决定`、`已有受信正式立项决定`、`已有受信正式不立项决定`、`已由有权机关后续变更/撤销`；每次变化必须具有 `M021` 或其有权后续文书/正式处理结果及 `F045/F053` 权限来源。公示状态和专家结果分别展示，不推导终局。不同批次/子类由不同正式文书确认，不能跨批复用。

### 10.4 问题文本示例（不声称真实个案）

- `R005 / CONFLICT`：申报书 `M003@v2` 第 1 页负责人工号指向人员 X，学院汇总 `M004@v1` 第 4 行指向人员 Y；待办→所属学院与人事部门核同一申请。**不得自动替人改工号。**
- `R012 / SOURCE_UNAVAILABLE`：申报书声明访问量，但当前没有可核的平台授权导出 `M010`；待办→平台归口核签相同课程 ID、周期和统计口径；**不得提示“访问量造假”。**
- `R024 / NOT_APPLICABLE`：申报仍在 T1，`M021` 尚未产生；不生成“缺校级立项批复”待办。
- `R028 / POLICY_UNCONFIRMED`：申报人请求撤回，但本批允许撤回的阶段和代理权限未证实；先由归口确认受理规则，系统不得标为“已撤回”。

## 11 补件、撤回、版本更新、复核与人工决定

### 11.1 内部办理状态与职责门禁（非校方现行流程的直接复刻）

| 内部事件/阶段转换 | 最少前置及信任边界 | 结果和不允许的推断 |
| --- | --- | --- |
| `DRAFT→SUBMITTED`（T1→T2） | 当批公告 M001 已绑定；教师或可信授权代理操作；申报版本 F037 和送达记录 F010/M017 需可核 | 申请“已提交”只指可追踪送达；发送邮件不等于学校已经受理 |
| `SUBMITTED→COLLEGE_REVIEWED`（T2） | 后端校验学院岗位、申请所属单位、批次权限 F053；学院 M004/M016 指向本次申报版本 | 只成立学院初审/推荐事实，不得表示专家/学校批准 |
| `COLLEGE_REVIEWED→EXPERT_REVIEWED`（T3） | 归口组织受理，真实受权专家组针对有效申请版本出具 M018 | 仅评审事件有效；缺委派信息交归口人工核 |
| `EXPERT_REVIEWED→PUBLICIZED`（T4，适用时） | 公示义务由当批来源证明，机关实际发布 M019、确定真实窗口 | A/D 未见公示要求不强加；公示有异议不自动否决，公示无异议不自动立项 |
| `…→OFFICIAL_DECISION_VERIFIED`（T5） | 按批次核真实受权机关 `M021` 与 F044/045/053，同批同课程、同申请/名单版；C 为正式发文，B 的审定公布需核会议授权及名单 | 只记录**外部已有的有权决定**；不能由 PASS_FACT 签发、把 B “公布”强制塞入 C “学校发文”模型 |
| `OFFICIAL_DECISION_VERIFIED→POST_STAGE_LINKED`（T6） | 独立验收/履约业务的 M022 与立项文书合法关联 | 仅只读承接结题信息；SRC-003/015 验收规则绝不倒灌到 T1 |

上述阶段名称是供产品内部维护的**候选状态**，没有证明成都理工大学使用相同系统或状态词。B 的正式立项文书链、E 原制度与 A/D 是否公示尚未核，不可强制所有分支沿同一全序前进；未到阶段按 `NOT_APPLICABLE` 排除后生文件。

### 11.2 补正及版本变更的业务闭环

1. `R019/R020/R014` 等生成 Issue，列具体 F、M、证据页码和有权补正人；申请人**提出** M023 补正与同目的新材料版，系统先核 `R028` 权限、公告补正许可。**许可和时限未知时只能等待归口**，不能默认无限补件或直接拒收。
2. 新版 `M003@v2` 不能抹掉 `M003@v1`；保存新哈希、归属、来源和 `supersedes`。`F052` 计算从材料到 F 再到 R 的影响闭包，只将依赖旧值的 Observation 标 `superseded`，冻结旧评审/推荐的效力主张。与之无关的已核事实可沿用**原来源版与有效期**，不能沿用过期来源。
3. 若学院 `M016@v1` 或专家 `M018@v1` 对应被修改的核心目标/团队/课程，产生“需有权人确认是否继续采信或重签”的待办；系统不能替学院/专家重评。只有机关真实核签的 `M024` 或新 `M016/M018` 能解除这类人工状态。
4. 在新固定 `planId/fingerprint + Check×target/sourceVersion` 下形成**新的 ReviewRun**，只重跑受影响 `R`，另增对其当前依赖新增/过期权威来源的检查。`R027` 记录变更本身，但不把“已上传 v2”自动视为已被学校接收或采纳。

**可执行前置性的例子**：仅 `M011` 的第三方授权附页由 v1 改 v2，且课程、人员、目标都未变化，则必重跑 `R013` 与核 M011 关联的冲突/版本事件 `R027`，只在关联 `F028/F036` 的推荐/专家评阅需要重认时触发 `R020/R022`；保留依然有效的 `R005,R009,R010,R014`。若 `M003` 的课程 ID/建设目标同时改变，则相应触发 `R002,R009,R010,R014,R019,R020,R022,R021` 的有关目标，受理机关决定是否接受修订；不是机械全量重跑 30 项。

### 11.3 撤回、再提交与公示异议/复核

- **撤回申请**：由本人或可核代理提交 `M023/F047`；`R028` 校验阶段、行为主体及当批处理规则。在有权部门真正签发/登记 `M024/F048` 前，只显示 `WITHDRAWAL_REQUESTED`（内部待办），不可标“已经撤回”，不得删除原材料、旧正式决定或对外公示史。
- **撤回生效后的重新提交**：仅当当批明文允许重报且期限、主体仍适用，建立新的申请/送达事件或学校认可的续报版本并留原案链；**不得**用原 `runId` 复活旧评审结果、不得把正式决定“回滚”。是否允许仍属 `POLICY_UNCONFIRMED`。
- **公示异议**：B/C 有公示但具体异议处理时限、机关未证实；E 的 SRC-007 仅能证明 2025-06-04～10 的书面异议窗口。若 `M020` 出现，由归口有权人接收、限制隐私范围，记录所针对的 `M019` 版；`M024` 处理结论及 `M021` 正式决定是**之后**才可能产生的文件。
- **正式决定复核或纠错**：申请者提出复核申请不等于具有当然复核权；先由主管部门确认渠道与范围。维持原 `M021` 原件和后续修改/撤销机关文书的双向指针，只有经核验的有权机关正式行为更新官方状态。模型/经办人自述无效。

### 11.4 角色冲突、越权与保存原则

Host/Main 端可信认证或经机构核签的离线流程记录是进入办理动作的必要条件；来自 Renderer 的 `role=approver`、自填工号或图片盖章都不能成为 `F053`。课程负责人能申请/补件，不得生成学院意见；学院能推荐，不得代专家评审；专家能给专业评价，不得代校级发文；受理机关只执行当批授权动作。按案件/批次/版本保留撤回请求、处理意见、正式决定与后续改变的**不可篡改审计链**。敏感异议、处罚、成员证件仅向获授权的处理人可见。

### 12.3 强制人工裁量与禁止自动执行清单

凡涉及课程教育质量、立项竞争排序、建设必要性、创新性、示范性、资源版权纠纷、同名人员实质确认、跨单位代理和签章效力、企业资格等效、历史处罚、学院名额豁免、异议是否成立、延期补报、撤回是否生效、正式立项/不立项、后续验收/撤项及资金拨付，都只能进入 `NEEDS_HUMAN_DECISION` 的待办或通过正式权威结论**被引用**。原件/规则不明则先 `POLICY_UNCONFIRMED`、`SOURCE_UNAVAILABLE`，不以模型推断填充硬阈值。审计资料仅说明系统如何呈递供审查，不证明学校已接入或认可。
